# MINIDORA Product Prototype v1

> 成立済みMINIDORA 模型核へ日常利用向け能力モジュールを追加し、製品として使えるチャットAIを構成する実装。

## 目的

1. MINIDORAを最低限のチャットAI製品として成立させる。
2. ニュース→要約をデモする。
3. ローカルPCから外部Web Dataを検索し、参照付きで後続処理へ渡せるようにする。
4. GPQA以外の日常タスクでも、模型核再学習なしの能力モジュール追加が実効能力増加として成立することを確認する。
5. 全応答について「なぜこの応答になったか」を、後付け説明ではなく実行経路として追跡する。
6. 長期目標としてGPT-4級の一般チャット使用感を目指す。これは現時点の性能同等宣言ではない。

## 構造

```text
Browser / API Client
        ↓
MINIDORA Product Chat
        ↓
能力登録簿
 ├─ 基本会話 能力モジュール
 ├─ ニュース 能力モジュール
 ├─ Web検索 能力モジュール
 ├─ 要約 能力モジュール
 ├─ 文脈変換 能力モジュール
 ├─ 情報抽出 能力モジュール
 ├─ 計算 能力モジュール
 ├─ 知識参照 能力モジュール
 └─ 既存 MINIDORA 模型核
        ↓
Response Composer
        ↓
Governance Ledger
```

能力能力モジュールは共通契約 `名前 / 版 / 優先度 / 判定 / 実行` を持つ。新能力はレジストリへ登録でき、製品チャットや模型核の再学習を必要としない。

## 起動

```bash
python -m pip install -e .
python -m minidora.製品版 --serve
```

ブラウザで `http://localhost:8080/` を開く。

API:
- `POST /api/chat`
- `GET /api/trace/{trace_id}`
- `GET /api/capabilities`
- `GET /health`

## HDSの基本チャット入口

HDSの一般質問・提示文章・会話継続の入口は、次の指定で起動します。

```powershell
python -m minidora.製品版 --HDS --基本チャット --serve
```

ADK経由で同じ入口を使う場合は、固定依存を導入した環境で `--ADK` も指定します。依存とCloud Runの手順は [配備案内](../deploy/CLOUD_RUN.md) を参照してください。

基本チャットの管理者方針は `MINIDORA_RETRIEVAL_POLICY=auto|off` です。`--基本チャット` を指定した場合、未設定は `auto` で、HDSが必要と判断した公開取得を許可範囲内で計画します。`off` は外部取得を禁止します。基本チャットを指定しない従来入口の契約は維持します。

APIの `external_read` を省略すると管理者方針に従います。`false` はその質問だけ外部取得を禁止し、`true` も管理者の `off` を越えません。指定する場合の値は真偽値で、`null` は省略として扱いません。画面の任意指定は「この質問では外部検索しない」、CLIでは `--検索しない` です。当回の禁止は次の質問へ継承しません。

ローカル既定の取得器は日本語・英語のWikipedia記事を扱います。`--HDS --ADK --基本チャット --CloudRun --serve` のCloud入口は固定Google通常Search・ADC・送信予算設定を使い、候補と本文の両方を、現構成では `www.mext.go.jp`、`www.mhlw.go.jp`、`www.env.go.jp`、`www.stat.go.jp` の4完全ホスト名へ限定します。全Web・全 `go.jp` を許可する構成ではありません。管理者が `off` にしてもCloud固定構成の検査は省略しません。

自動方針に従うAPI例：

```json
{"message":"調べたい主題についての質問","session_id":"会話識別子"}
```

この質問だけ取得を禁止するAPI例：

```json
{"message":"提示した資料についての質問","session_id":"会話識別子","external_read":false}
```

同じ会話では、採用済みの有効な原資料を追質問に利用できます。候補・本文・通信・容量・時間には有限な上限があり、取得元の記載は資料として扱います。

提示文章の説明・要約・比較には外部検索許可は不要です。検索結果の見出しや短い説明だけを事実の根拠にせず、回答の主要な主張を取得本文へ対応させます。構文や根拠が不足する場合は、保留と不足条件を返します。起動や採用状態だけでは一般チャットの品質成立を意味しません。

会話状態と監査台帳はメモリに保持します。新しい会話IDでは以前の会話を参照できず、サーバの再起動では失われます。Cloud Runでは旧a38の本人認証付きD03実演に続き、main `d2397cc3fc08330c9be59eb76211299c65f8e0ee`、revision `minidora-adk-verify-judge-d2397cc3fc08-7234f7`の審査用Basicのみの実HTTPS検査を確認しました。本人承認により対象サービスのCloud IAM呼出許可を公開し、全画面・API・healthのBasic認証を維持しています。審査用URLは [リポジトリREADME](../README.md) を参照し、資格は審査員向け非公開欄で提供します。直接ブラウザの資格入力から回答表示までと、再起動をまたぐ会話継続は別の未確認事項です。

この基本チャットは一般品質の受入前の開発版です。2026-10-13のCloud上のD03では、藻場の実本文に対応する回答と同じ会話の引用形式への追質問、算術の入力変更、保留と拒否、ADK通過・監査の対応を一回観測しました。算術後の「詳しく説明して」はSUSPENDです。詳しい入力・出典・配備版は [リポジトリREADME](../README.md) を参照してください。新Basic入口ではGoogleの本人OIDCを使わないHTTPS検査19件と実応答3件が成立し、[180秒のYouTube動画](https://youtu.be/q7hF26QBabI)も公開しました。動画は旧a38の実画面と図を収録したもので、d2397では同じHDS本体へHTTP認証境界を追加しています。直接ブラウザの資格入力から回答表示、独立品質Q全数、応募受付は、この限定受入だけでは成立としません。局所検査やこの実演を一般質問の品質合格へ算入しません。Qの未成立を実機・提出の開始前条件にせず、未達を成立済みとは表示しません。

## 従来のローカルWeb検索

Web検索 能力モジュールの標準検索基盤は、同じPC上のSearXNGです。MINIDORA本体には検索APIキーを持たせません。

SearXNGは次で起動できます。

```bash
docker compose -f deploy/searxng/compose.yml up -d
```

標準接続先:

```text
http://127.0.0.1:8888
```

MINIDORAは `GET /search?q=...&format=json` で検索し、タイトル・URL・検索結果本文を `参照資料` として保持します。SearXNG側ではJSON出力を有効化したローカル設定を同梱しています。

別ポート・別ホストを使う場合:

PowerShell:

```powershell
$env:MINIDORA_SEARXNG_URL="http://127.0.0.1:8888"
```

bash:

```bash
export MINIDORA_SEARXNG_URL="http://127.0.0.1:8888"
```

停止:

```bash
docker compose -f deploy/searxng/compose.yml down
```

`deploy/searxng/compose.yml` は `127.0.0.1` のみに公開するローカルデモ構成です。外部公開用の配備設定ではありません。

現行Web検索 能力モジュールは **検索結果のタイトル・URL・スニペット取得** を責任範囲とします。検索先ページ本文の取得、JavaScript実行、ログインが必要なページの操作等は別能力境界であり、将来のPlaywright等のブラウザ操作能力モジュールへ分離します。

## ガバナンス

監査対象:
- 入力
- 能力候補
- 能力モジュール選択
- 能力モジュール版
- 能力モジュール入力/出力
- 外部参照識別子
- 能力モジュール不成立時の透過
- 応答構成
- 会話状態更新
- 最終応答

各イベントをSHA-256 hash chainで接続し、前応答のroot hashも次応答へ接続する。

`MINIDORA_AUDIT_LOG` を設定するとJSONLへ追記し、`flush + fsync` まで行う。WORM化・外部署名・外部anchorは配備層の責任であり、現時点のローカルファイルを改変不能と主張しない。

## 能力拡張実証

`tools/製品能力モジュール実証.py` は同一模型核に対し、能力モジュールをOFF/ONして日常タスクの差を測る。

サンドボックス段階では代替模型核で機構確認を行う。公開する正式値は、現行MINIDORA 模型核へ還元した後に同じランナーを実行して確定する。

## 性能目標

GPT-4級は**開発目標**。現時点で同等性能を主張しない。

到達度は、会話継続、要約、知識参照、比較、推論、計算、変換、検索、コード等の実利用能力を追加し、退行を監査しながら反復測定する。


## 追加の汎用会話モード（第18バッチ）

従来の既定経路を変えず、目的計画・複数資料比較・確認・訂正の新しい会話系を明示的に選択できます。

```bash
python -m minidora.製品版 --汎用
python -m minidora.製品版 --汎用 --serve
```

画面は `http://127.0.0.1:8080`（PORT設定時はそのポート）です。汎用モードのサーバはローカル限定で、別の生成元からのブラウザ操作を拒否します。インターネット公開用の認証サービスではありません。

会話例:

```text
資料「A」を登録:{"売上":75,"費用":50}
資料「B」を登録:{"売上":60,"費用":40}
この2つの売上を比較して
単位は円です
訂正:属性は費用です
それを詳しく説明して
```

ファイルを指定する追加CLIと、外部通信なしの人工資料デモもあります。

```bash
python tools/汎用チャット.py --資料 A=a.json --資料 B=b.json '資料「A」と資料「B」の売上を比較して'
python tools/汎用会話デモ.py
```

検索記載の取得には設定済みSearXNGと公開HTTPSへの接続が必要です。利用者が `--外部読取` を明示した場合だけ要求起点の取得を実行します。取得できない情報を作って補いません。

現在は局所日本語、数式、JSON/CSV、有限の数値記載が対象です。一般的な原因推定、自由作文、任意の会話理解、GPT-4同等性の完成ではありません。
