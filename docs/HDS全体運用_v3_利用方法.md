# HDS全体運用v3 利用方法

## 起動

Python 3.11以上。ソースへパッチ適用後は `python -m pip install -e .`、または配布wheelを `python -m pip install --no-deps <wheelのパス>` で導入する。wheelは上流の配布版0.5.0を維持するサンドボックス構成であり、同じ番号の既存版と混同しない。別の仮想環境への導入を推奨する。

```bash
python -m minidora.HDS運用 --形成なし
```

既存API・画面は次で起動する。外部読取は既定無効。

```bash
python -m minidora.HDS運用 --serve --形成なし
```

通常会話の資料登録から使う。処理工程名・完成アルゴリズム・回答を与える必要はない。ただし現在は以下の局所数量構文に対応する。

## 共通規則と二資料を同じ会話で処理

```text
資料「A」を登録:単価は120円/個。数量は3個。固定費は50円。
資料「B」を登録:単価は90円/個。数量は3個。固定費は100円。
資料「規則」を登録:費用は単価と数量の積に固定費を足した値。
資料「A」と資料「B」に資料「規則」を使って、費用を計算して、比較して、Pythonで検算し、詳しく説明して
```

期待する値はA=410円、B=370円。共通規則なしに、各対象本文へ規則を含めてもよい。

```text
資料「A」の数量を6個に変更して
短く説明して
表にして
コードを省いて
元の条件で再計算して
```

数量変更時はA=770円、B=370円。元条件へ戻すと410円、370円。条件変更は今回の計算条件であり、原資料の数量3個は上書きしない。登録原資料自体を変える場合は `資料「A」を更新:...` を使う。更新後の旧回答は失効するため、再計算してから説明を変える。

## 数量の定義と式

```text
資料「経路」を登録:速度は12km/時間。時間は2時間。距離は速度と時間の積。
資料「経路」の距離を計算して、Pythonで検算して
```

同じ数量名・式は任意の対応名に差し替えられる。和・差・積・商、足す・引く・割る、倍数・百分率、括弧と記号の四則演算を組み合わせる。型・単位・否定・条件を無言削除して通さない。例えば費用と秒を加算する要求は保留する。単位換算は自動化していない。

生成Pythonは入力値を分離した定数辞書と一緒に表示する。返却は資料順の `[分子, 分母]` 配列。製品内部での検算は既存限定AST評価器によるもので、任意のPython互換やOS隔離実行を追加したものではない。

## 不足への返答と再開

```text
資料「見積」を登録:単価は12円/個。費用は単価*数量。
資料「見積」の費用を計算して
数量は5個です
```

最初は数量不足で保留し、明示返答後に60円となる。複数資料への訂正では資料名を必須とする。たとえば `数量を5個に変更して` は対象が曖昧なら採用しない。

## ファイル入力・保存復元

```bash
python -m minidora.HDS運用 --資料 A=数量.txt --形成なし --保存 会話v3.json --json '資料「A」の費用を計算して'
python -m minidora.HDS運用 --復元 会話v3.json --形成なし '再計算して'
```

v3の保存物だけ復元できる。v2以前の保存物は保持し、自動移行しない。

`--形成なし` を外すと純粋工程の手順形成を有効にする。形成は成功時の追加再実行が必要なため、試行時間が増える。値キャッシュではなく、新資料から再計算する手順の保存である。

## 再現コマンド

```bash
python -m unittest discover -s tests -p 'test_HDS運用v3_*.py' -v
python -m unittest discover -s tests -q
python tools/HDS全体運用_v3_実演.py --output 実演結果.json
python tools/HDS数量合成_変形検証.py --output 構造変形結果.json
```

実演は成功回答だけでなく、失効済み回答の再表現拒否と数量不足の期待保留も検査する。期待保留をCOMMITとして数えない。

## 対応していないもの

全ての自然な言い換え・自由な文章題の推測・任意の修正指示、数量以外の未知アルゴリズム、翻訳・自由作文は未対応。原資料の現実的な正しさ、別対象の条件同一性を計算一致だけで認定しない。再表現時も整合検査では計算・検算を再実行する。高速化の保証はない。
