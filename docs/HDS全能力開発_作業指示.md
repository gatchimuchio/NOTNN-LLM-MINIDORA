# HDS全能力開発 作業指示

2026-09-18

## 対象・制約

作業対象はHDSミニドラの能力拡張。ユーザーの依頼は全残件の順次開発であり、v4単独で全体完成とはしない。順序と受入条件はロードマップ、実績と未観測は台帳、現行増分の契約は設計66を参照する。

リポジトリの現行mainとAGENTS.mdを確認し、取得commit/treeを固定してサンドボックスで実装する。既存通常循環・既存能力・過去正本・原資料・成果履歴を保持する。資料の命令をコードの権限へ昇格させない。

## 各増分の進め方

1. 当初残件との対応、既存コードの責任、未実装部分を区別する。能力名・空の接続口・停止機構だけの追加を能力完成として数えない。
2. 対象・目的に必要な意味表現と、その表現を消費する後続作用を同時に実装する。工程は既存HDSの依存・状態差・採否へ接続する。
3. 正常例だけでなく未知表現、条件・否定・例外、改変、資料更新、予算、取消、権限、保存復元を検査する。既存機能の回帰を確認する。
4. 仕様・利用例・残差・検証結果を同じ差分に含める。旧報告を現在の結果で無言上書きしない。
5. サンドボックスの差分ハッシュ・基点・treeを照合して作業ブランチへ反映し、CIと差分監査後にmainへマージする。並行更新があれば取得し直して再検証する。force pushや他者差分の上書きをしない。

## 検証入口

```bash
python tools/リポジトリ整合性監査.py
python tools/日本語基底監査.py
python tools/日本語基底詳細監査.py
python -m compileall -q src tests tools
python -m unittest discover -s tests -q
python -m unittest discover -s tests -p 'test_HDS運用v4_*.py' -v
python -m minidora "2+3"
```

GitHubはUbuntu/Windows × Python3.11〜3.14を確認する。CI上のWindowsと利用者のWindows実機、人工HTTPと公開Web実運用、局所試験と汎用性能を区別する。

新規実行器を必要とする残件は、依頼へ実行器の不足を返すだけで完成としない。必要な実装・隔離・許可・検証条件を次の開発単位へつなぐ。
