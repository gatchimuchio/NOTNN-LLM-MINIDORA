# MINIDORA 第23バッチ — 有限能力の会話統合契約

## 位置づけ

第22バッチの部分成果物を継続したサンドボックス実装である。基点commitは `aaf9281446d4583cdb0d1626f1a8bdb12f815433`、基点treeは `944fd2a2d34f6ad2cca87ed8534eeb3ae26adef9`。全treeを取得したものではない。GitHubへの書込み、PR作成、push、CI起動は行っていない。

第22バッチの有限仮説・明示ブール介入・有界命題検討を、実際の既存役割計画器、統合セッション、長文脈庫へ接続する。未取得の全能力factory、HDS、GUIをスタブで置換して動的合格にすることはしない。新しい汎用的世界知識や自由作文能力の完成を意味しない。

## 実行経路

単独入口は `監査改善会話セッション`。定型日本語の要求を全文解析し、種類付き資料と目的変更を分離する。目的から既存 `役割計画器` が三工程（検討・説明・原要求照合）を構成し、既存 `統合セッション.準備/実行` と `能力合成器` が採用する。単独入口で登録するのは取得・実装済みの5能力だけ。これは明示した部分構成であり、全能力が存在するふりをしない。

最終照合は回答の再計算だけでなく、原要求の全Data、能力種別、表示詳細、本文、根拠、参照との一致を検査する。自己整合している別の問いの回答を採用しない。実行が合格でも、命題の「未確定」や仮説の「説明候補なし」は解答成功へ加算しない。

## 会話行為と資料

`仮説資料「名前」を登録：...`、`介入資料「名前」を登録：...`、`命題資料「名前」を登録：...` で資料を登録する。更新には `更新` を明示する。登録自体は資料の真実性を認定しない。資料中の命令文は実行権限にならない。

仮説資料は事実・規則・候補・任意の観測、介入資料は外生状態・非巡回ブール構造式・任意の介入/観測を持つ。対応JSONの直接登録もできる。未知欄、重複欄、空の列要素、非有限JSON値は拒否する。行ごとの原文位置を保持する。意味検討に必要な観測・介入・問いが欠けると確認待ちに戻り、後続返答で同じ目的を継続する。

命題の問いに複数解釈がある場合は候補選択へ戻す。資料側の解釈で結論が分岐する場合も確認し、番号・資料版を結び付ける。読みが複数でも結論が共通なら、読み未確定を残したまま回答する。確認中に資料が更新された場合、旧候補番号は流用せず `もう一度` で検討をやり直す。

`観測を「Wet」にして`、`候補を「Rain」に訂正して`、`介入を「A=偽」にして`、`問いを「Q」にして`、`照応距離を3にして` を対応する目的へ適用する。未対応な意味・構文を解釈済みにしない。意味解析が失敗した目的も保持し、明示訂正を受け付ける。

## 状態・採用・失効

統合器が返す `採用記録ID` に会話成果を対応付ける。資料更新は実長文脈庫の明示失効へ帰還し、旧資料に依存する成果とその再説明を失効する。原記録と当時の回答は削除せず、現行採用履歴からだけ除外する。

再説明は保存された元報告を二工程（説明・原要求照合）で再構成し、元成果IDへの依存を追加する。失効後に短縮説明を要求しても、古い成果を無断で復活させない。`もう一度` で現行資料から新たな成果を採用する。別資料の変更、同一内容への更新は無関係な成果を失効させない。

既存 `統合セッション` に `基底能力=None` を追加した。Noneでは元の全能力factoryを遅延読込し、明示tupleでは指定した実能力だけを登録する。型・版・外部許可・起点・採用検査はどちらでも同じ実統合器を通す。追加の `依存記録` も計画印へ含め、旧状態・失効済み依存を拒否する。

## 保存・復元

単独会話の発話操作をハッシュ連鎖で保存し、復元時に純粋な実能力で再実行して各返答・状態を照合する。所有IDと実行時間は新しくなるが、全回答意味・本文・採否は照合対象とする。別セッション、異版、破損、重複JSONキー、期待した再実行と一致しない保存物は拒否する。

共有統合セッション全体の保存機能ではない。共有時は部分会話だけの保存を拒否する。単独時でも外から統合状態を初期化・失効等で変更した場合、会話の発話だけでは再構築できないため保存を拒否する。署名や秘密鍵は使用しないため、ハッシュは真正性・作者認証を保証しない。再構成結果まで一貫して全面改稿した保存物を暗号学的に検出する仕組みではない。

## 通常汎用会話への接続

`汎用会話セッション(..., 監査改善=True)` で同じ統合セッションへ新能力と補助会話を接続する差分を追加した。既定はFalse。通常資料と追加資料の同名衝突は止める。別話題へ移った後の「短く説明して」等を古い補助会話が奪わないよう、会話焦点で振分を制限する。

この通常接続は原本に基づくコード実装・構文検査まで。全依存未取得のため、通常汎用入口全体の動的試験は未実施。実HDSコンパイラを呼ぶコードと原文保持は接続したが、新しい有限会話契約と一般HDS意味監査の完全照合は未完了である。原文一致を意味一致の証明として扱わない。製品チャット/GUIからこの新しい有効化引数を設定する機能も未接続。

## 上限と停止

入力発話8192文字、発話数128、資料数16、資料保存300KB、会話操作履歴1MB等の上限を置く。各下位エンジンと実統合器の上限も維持する。上限に達したとき原文を自動削除したり問いを簡略化したりしない。停止は処理境界で検査し、採用前に停止した場合は成果を確定しない。下位エンジンの一呼出しを任意の時点で強制中断するOS分離機構ではない。
