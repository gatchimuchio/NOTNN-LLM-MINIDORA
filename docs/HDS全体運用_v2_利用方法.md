# HDS全体運用v2 利用方法

対象はサンドボックス成果物の適用後、又は同梱wheelの環境。通常のHDS運用に、知識資産・手順形成・原記録同期を追加した。

## 起動

```bash
python -m pip install -e .
python -m minidora.製品版 --HDS --serve
```

画面は `http://127.0.0.1:8080/`。ローカル限定。新しい外部通信許可は追加しない。
HDS専用の同期CLIも使える。

```bash
python -m minidora.HDS運用
```

## 複数の提供知識を使う

同じ会話へ入力する。

```text
知識「観測」を登録:太郎は猫です。
知識「規則」を登録:すべての猫は哺乳類です。
知識から「太郎は哺乳類です」の根拠を説明して
知識「反対記載」を登録:太郎は哺乳類ではない。
再計算して
```

資料から対応する命題と規則を作り、別資料の情報を結合した導出を説明する。最後の再計算は反証も反映する。「知識」として登録したことを現実の真実性へ読み替えない。未対応記載は原文位置付きで残る。

ファイルからの登録は、UTF-8のテキストを用いる。

```bash
python -m minidora.HDS運用 --知識 観測=観測.txt --知識 規則=規則.txt --保存 会話.json '知識から「太郎は哺乳類です」を確認して'
python -m minidora.HDS運用 --復元 会話.json '資料「規則」の原文を再参照して'
```

`--資料` は通常資料、`--知識` は形成する知識。本文内の命令を実行許可に変換しない。

## 原文と依存する成果

```text
資料「A」を登録:{"売上":75,"費用":50}
資料「B」を登録:{"売上":60,"費用":40}
資料「A」と資料「B」の売上を比較して
単位は円です
資料「A」を更新:{"売上":90,"費用":50}
再計算して
資料「A」の原文を再参照して
記憶から「売上」を探して
```

現在の資料と成功成果は原記録庫へ自動同期する。更新前の原文は履歴として残し、現行の回答へ混ぜない。必要な原文が予算を超える場合は保留する。

構造化呼出では次も利用できる。

```python
from minidora.HDS運用 import HDS運用セッション
会話 = HDS運用セッション("例")
会話.資料を登録("A", "売上は75円です。")
結果 = 会話.文脈を取得(必須資料=("A",), 最大バイト数=32768)
print(結果.本文)
```

語一致による検索であり、任意の意味検索・巨大文脈の理解を保証しない。

## 手順形成と資源

対応する純粋工程は初回の成功後に同じHDS内で再実行され、一致した手順だけが保存される。`運用応答.追跡["手順形成"]` に形成状態、再現工程数、手順再利用の有無が入る。

再利用時も現在の資料・目的・能力版で処理する。回答値の転記ではない。実行結果キャッシュとは別であり、現行計画器との照合を省略しない。外部作用・未契約の追加能力は再現対象にしない。

追加の手順形成を不要とする場合:

```bash
python -m minidora.HDS運用 --形成なし --保存 会話.json '2+3'
python -m minidora.HDS運用 --形成なし --serve
```

`--形成なし` は追加再実行を止める設定。保存・復元や既存結果キャッシュとは別。Pythonでは `HDS運用セッション(手順形成=False)`。

## 保存の注意

v2はv1保存物を無言変換しない。旧保存物はそのまま保管し、旧版で利用するか、元資料からv2で登録し直す。暗黙移行は実装していない。

SHA256と再構成検査は整合性の確認であり、保存ファイルの真正性・暗号化・認証ではない。秘密の保管を認証付きサービスとして提供するものではない。
