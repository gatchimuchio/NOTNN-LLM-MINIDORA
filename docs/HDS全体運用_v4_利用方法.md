# HDS全体運用v4 利用方法

v3の数量・知識資産・手順形成・原記録を保持し、資料文章の経路と旧保存の明示移行を追加した。能力の全体範囲と残件は [全能力開発ロードマップ](HDS全能力開発_ロードマップ.md) を参照する。

## Pythonで資料を読む

```python
from minidora.HDS運用 import HDS運用セッション

会話 = HDS運用セッション("資料説明", 手順形成=False)
会話.資料を登録("A", "# 保守\n年一回点検。\n# 注意\nただし故障時は停止。\n# 雑記\n色は青。\n")
会話.資料を登録("B", "保守は月一回。寿命の記載は未確認。")
回答 = 会話.応答("資料「A」と「B」を保守と寿命の観点で比較し、確認事項を提案して")
print(回答.状態, 回答.本文)
print(会話.応答("前者の保守について説明して").本文)
print(会話.応答("文章にして").本文)
```

これは観点に対応する記載と未確認事項の対照である。実物の優劣や採用案を無根拠に決める処理ではない。`手順形成=True`（既定）は純粋工程の追加再実行を伴う。

資料の全体を対象にする場合は `資料「A」を根拠付きで要約して`。登録された全資料から選ぶ場合は `登録資料から保守について説明して`。明示された主題の記載が見つからなければ保留する。

更新には `資料を登録("A", 新本文, 更新=True)` を使う。依存回答は失効し、`再計算して` で再評価する。全資料対象の回答は新しい資料を追加した場合も失効する。

## 公開資料を読む

```python
会話 = HDS運用セッション("調査", 外部読取許可=True, 手順形成=False)
回答 = 会話.応答("公開資料で保守について調べて、根拠付きで説明して", 外部読取許可=True)
```

検索供給器の設定・実ネットワーク到達性が別途必要。既存の `取得器=` 注入にも対応する。二つの許可が揃わなければ取得しない。取得結果の保存・再表現は最新性の再確認ではない。今回の新規試験で用いた公開本文は人工HTTP供給であり、実サービスの性能実測ではない。

## CLI

```bash
python -m minidora.HDS運用 --形成なし --資料 A=資料A.md '資料「A」の保守について要点を整理して'
python -m minidora.HDS運用 --復元 会話v4.json '文章にして'
```

画面/APIも従来どおり `python -m minidora.HDS運用 --serve`。ローカル限定の既存製品境界を変更しない。

## v1〜v3の明示移行

旧原本を残し、**未作成の別ファイル**へ保存する。

```bash
python -m minidora.HDS運用 --移行元 会話v3.json --保存 会話v4.json --json
```

このコマンドは移行だけを実行して終了する。元と同じ保存先、既存の保存先は拒否する。通常の `--復元` は旧版を暗黙移行しない。

```python
from pathlib import Path
from minidora.HDS運用 import 旧保存を移行

原本 = Path("会話v3.json").read_text(encoding="utf-8")
会話 = 旧保存を移行(原本)
会話.保存先へ書く("会話v4.json")
```

Pythonの `保存先へ書く` は従来どおり通常保存先を置換するAPIなので、呼出側で新しい保存先を選ぶ。移行関数自体はファイルを書き換えない。

元のJSON全文・履歴・依存は新保存内にも残る。旧成果は失効、旧手順は非実行の原本内で保持する。再計算後に現行の結果を採用する。独自能力を追加した未知の旧目録は自動移行しない。外部許可がある旧保存では呼出側も同じ許可を明示する必要がある。
