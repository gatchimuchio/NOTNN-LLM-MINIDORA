# MINIDORA Core還元監査 — 2026-09-15

基準: `main@4fe0793999b18ae516fc345605a29621a05801c7`
目的: 第22〜26バッチ、Core改善1/2、Core計画/回復/境界改善から、Core単体へ戻せる一般機構と、Core外へ残す責任を再分類する。

## 1. 判定原則

Coreへ入れるのは、分野名・benchmark名・製品入口・外部権限を除いても成立し、入力意味から新しい内部構造・候補・計算・説明を作る一般作用だけとする。

Core外へ残すのは、最終採否、目的変更、権限、外部作用、永続記憶、セッション正本、物理I/O、製品Routingである。

```text
Core = 意味化 + 内部表現 + 候補生成 + 推論 + 計算候補 + 仮説 + 予測 + 説明候補 + 残差
J    = 目的・要求・禁止・最終採否・許可・停止・rollback
M    = 正本記憶・証拠状態・系譜・永続化
境界 = 外部取得・ブラウザ・GUI・ファイル・実世界作用
```

## 2. 今までの実装からCoreへ還元する要素

### A. Core閉包・残差

由来: Core採否問題、部分読解、失敗分類、要求被覆、HDS射影終端。

- Core自身が `成立 / 入力意味不足 / 参照不足 / 競合 / 矛盾 / 未確定` を返す。
- HDS/J語彙の APPROVE/SUSPEND はCore外で単純変換する。
- 候補別の支持・反証・未観測・矛盾を残差として保持する。
- 未解釈入力を候補除外で一意化しない。
- 予算不足・未対応推論・意味不足・証拠不足を将来別残差へ分離する。

### B. 意味構造化・定義作用化

由来: 明示述語別名、命題構造、部分読解、`うぽ`失敗、HDS意味IR。

- 表層差と意味同一性を分離する。
- 定義・別名・属性・関係を出典付き内部関係へする。
- 新しく与えられた操作定義を既存計算作用へ降下する。
- 未解釈残差を捨てず、部分一致だけで定義成立にしない。
- 否定・条件・量化・帰属・引用scopeを保持する。

### C. 候補・仮説生成

由来: 有限仮説探索、候補共同参照、状態差循環。

- 外部から候補を全て与えられる前提を外す。
- 観測へ至る規則を逆向きに辿り、既知閉包で説明できないfrontierを仮説候補化する。
- 観測そのものの自己説明を禁止する。
- 循環や候補爆発を残差として止める。
- 生成候補は既存有限探索へ渡し、包含極小性・整合性・証拠DAGで評価する。

### D. 証拠と意味の閉包

由来: 取得意味境界、原文範囲、異種資料比較、同一Data非増幅。

- 同一意味Dataを出典ID数で票数増幅しない。
- 原文範囲・使用根拠・未解釈範囲を分離する。
- `未観測 != 反証` をCore規則として維持する。
- 対象・時点・条件・実体同一性・数量加算可能性を意味状態に持てるよう拡張する。
- 参照の独立性・転載関係は、外部メタデータを入力としてCoreが評価可能にする。

### E. 推論一般化

由来: 命題推論、有限仮説探索、有限因果モデル、数量系。

- 等号、関数項、量化、条件、対偶等を採用論理体系と前提を明示して拡張する。
- 言語命題・数量・実体同定を一つの関係グラフへ接続する。
- 因果モデルは「与えられたモデル内介入」だけでなく、文章/観測からモデル候補を構成する段をCoreに追加する。
- モデル内予測と現実妥当性は分離する。

### F. 新規解法・計画候補生成

由来: 役割計画、回復方針、コード/数学残件。

- 登録作用の名前を選ぶだけでなく、既存の原始作用を組み合わせて新しい解法候補を構成する。
- 目的・制約・損失・不確実性・検証負荷を候補属性として見積もる。
- 未知失敗から原因仮説、追加観測、修正候補を生成する。
- 最終採用と外部実行許可はJ/境界へ残す。

### G. 説明・再表現生成

由来: 根拠説明、短縮、原要求照合。

- 導出DAGから、必要根拠・条件・仮定・留保を選択し説明IRを作る。
- 意味と根拠を保った要約・言い換え・抽象度変換・翻訳候補を生成する。
- 長文生成では主張間の否定・条件・留保の整合を追跡する。
- 事実説明と創作/比喩/例示のモードを意味上分離する。

### H. 純粋計算の再利用と探索効率

由来: 純粋再利用、状態差循環、仮説枝刈り、Core改善1/2。

- 入力意味・作用版・依存が同一な純粋計算結果を再利用する。
- 状態差がない限り再作用しない。
- 現在首位を成立境界から落とさず再評価する。
- 関連性による枝刈りは行うが、上限超過を無断削除で成功扱いしない。
- 検証強度を保持したまま重複計算を減らす。

## 3. Core外へ残す責任

- 現在依頼の正本、要求被覆の最終完遂判定、禁止事項、権限、最終採否: J
- セッションの採用履歴、旧成果失効、永続保存/復元、課題を跨ぐ定義保持: M/J
- 外部GET/POST、ブラウザ、GUI、PDF/DOCX/XLSX解析、画像/音声/動画取得: capability adapter
- 外部作用のexactly-once、Transaction/Resume、idempotency、rollback: execution boundary
- 製品入口・mode routing・GUI: product shell
- 取得時刻/HTTP/URL/ファイル真正性の観測: adapter。Coreは与えられたメタデータを推論するだけ。
- 現実世界で行動を許可するか、因果モデルを採用するか: J

## 5. 根本不足へ圧縮

75項目はCore側では次の10根へ圧縮できる。

1. 表層から一般意味構造へ落とす能力が有限文法依存
2. 新しい定義を内部関係/計算作用へ形成する能力が弱い
3. 外部から候補を与えられないと探索できない
4. 量・実体・条件・論理・因果を同じ内部関係へ再結合できていない
5. 未閉包理由がCore結果の第一級状態になっていない
6. 課題構造から新しい解法/計画/アルゴリズムを合成できない
7. 導出から回答内容・説明・再表現を一般生成する能力が弱い
8. 長距離文脈/長文/多数資料で意味状態を階層化できない
9. 純粋推論の再利用・枝刈り・増分再計算が局所機構に留まる
10. Coreの意味状態と外部J/M/adapterの責任境界が歴史的実装で部分的に逆流している
