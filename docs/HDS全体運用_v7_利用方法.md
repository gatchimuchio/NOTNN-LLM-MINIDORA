# HDS全体運用v7：資料を結び付けて説明する

## 実行例

```python
from minidora.HDS運用 import HDS運用セッション

共通 = '識別体系は「工場台帳」である。時点は「点検前」である。適用条件は「通常運転」である。'
会話 = HDS運用セッション('資料横断', 手順形成=False)
会話.資料を登録('観測', 共通 + '対象「設備A」の識別子は「設備01」である。設備Aは有効である。')
会話.資料を登録('規則', 共通 + '対象「装置B」の識別子は「設備01」である。装置Bが有効ならば装置Bは稼働する。')
回答 = 会話.応答('資料「観測」と「規則」を結び付けて、資料「規則」の「装置Bは稼働する」かどうか説明して')
assert 回答.成立, 回答.本文
print(回答.本文)
```

両資料を単独で読むと問いは未確定だが、宣言された同じ対象・時点・適用条件で接続すると支持できる。回答には、実際に使用した2資料の原文と条件適用が現れる。対象名が異なっても、共有識別子「設備01」と各表記の対応を確認できる。

## 成立範囲

2〜8資料を明示して、どの資料の表記で問いを読むかを指定する。各資料の先頭に識別体系・時点・適用条件・対象識別子を宣言する。語尾は`である`または`です`。宣言の一致は利用者が提供した接続前提であり、世界の対象同一性や信頼性を自動認定したという意味ではない。

同名でもIDが違えば結ばない。同じIDでも識別体系・時点・適用条件が違えば結ばない。宣言が足りない、競合している、宣言に例外がかかる、本文後に宣言される場合も接続を保留する。文字列の類似度や常識で補完しない。

`を結び付けて`を指定しない従来の関係依頼は、引き続き資料ごとに判定する。外部取得資料を登録資料へ自動接続する機能は追加していない。

## 更新・保存・再表現

```python
保存物 = 会話.保存()
復元 = HDS運用セッション.復元(保存物)
print(復元.応答('文章にして').本文)

会話.資料を登録('観測', 共通 + '対象「設備A」の識別子は「設備02」である。設備Aは有効である。', 更新=True)
assert not 会話.状態()['前回有効']
再計算 = 会話.応答('再計算して')
assert 再計算.成立, 再計算.本文
assert 再計算.結果.データ['構造']['横断']['判定']['判定'] == '未確定'
```

ID変更前の支持を再利用しない。未確定という説明を完了することと、問いを支持することは異なる。指定外資料の登録だけで既存の対象範囲を拡大しない。

## 旧保存の明示移行

```python
from pathlib import Path
from minidora.HDS運用 import 旧保存を移行

旧原本 = Path('旧保存.json').read_text(encoding='utf-8')
会話 = 旧保存を移行(旧原本)
新保存 = 会話.保存()
```

標準v1〜v6に対応する。旧原本と履歴を保持し、旧成果と旧手順を採用しない。通常要求を横断要求に変換しない。再計算が必要で、独自追加能力の目録は未対応。外部読取権限は呼出側と一致させる。
