## 第27バッチ：共通通常運用の実装

基点は `4067f2ee32efb5d4f3f091095e1fa61412ea0792`。開発と一次試験はサンドボックス。別コアの得点改善ではなく、HDSが既存能力を通常の依頼から使う全体運用を対象にした。

今回接続したものは、共通能力目録、自然文の既存意味射影、HDSによる各能力の直接実行、回復契約、回答照合、同一案件の訂正・資料更新・再表現、JSON保存復元、CLI・JSONL・HTTP・既存画面である。仕様は `設計/63_MINIDORA_HDS通常運用_v1.md`、実測は `評価/HDS通常運用_第27バッチ_2026-09-17.md`。

### 起動

リポジトリで `python -m pip install -e .` を実行した後:

```bash
python -m minidora.製品版 --HDS --serve
```

ブラウザは `http://127.0.0.1:8080/`。外部公開用ではない。

対話CLI、保存復元、資料ファイル指定:

```bash
python -m minidora.HDS運用
python -m minidora.HDS運用 '「x**3」をxで微分して' --保存 session.json
python -m minidora.HDS運用 --読込 session.json 'それをxで微分して'
python -m minidora.HDS運用 --資料 本文=sample.txt '本文から数字を抽出して'
python -m minidora.HDS運用 --一覧
python tools/HDS通常運用_実演.py --出力 demo.json
```

同じ会話の例:

```text
資料「A」を登録:{"売上":100,"費用":60}
資料「B」を登録:{"売上":80,"費用":45}
資料「A」と資料「B」の売上を円で比較して
訂正:属性は費用です
詳しく説明して
資料「A」を更新:{"売上":100,"費用":50}
前回の依頼を再実行して
```

APIは `POST /api/chat` の `message`・`session_id`。同じ `session_id` で継続する。GET `/api/trace/{id}`、`/api/capabilities`、`/health` も利用できる。起動時の `--外部読取` だけが実外部取得を許可する。資料内の指示や保存JSONは権限を付与しない。

### 残る開発と依存

| 対象 | 今回 | 続けて実装するもの |
|---|---|---|
| HDS通常運用 | 既存能力の共通起動と会話まで接続 | 複合目的の対応範囲と型付き中間成果の横断利用を広げる |
| 言語・概念基盤 | 既存有限文法・構文化の範囲を使用 | 高度構文化器の残差・多義性と通常運用を直接接続し、未知表現を構成する |
| 知識・能力の供給 | 明示資料と既存能力契約を供給 | 資料から知識・規則・能力契約を形成し、版・条件付き資産として登録する |
| 内容生成 | 既存回答構成、根拠説明、再表現 | 任意主題の説明・比較・提案・創作・立式・アルゴリズム構成を拡張する |
| 長文脈・経験 | 案件資料と採用成果の保存復元 | 既存原記録庫との同期、意味選択・圧縮、純粋性を確認した経験形成を接続する |
| 外部作用 | 明示許可の読取境界と停止 | 取得済み成果を保持した再計画、実取得検証、取消不能境界を含む運用を広げる |

次の開発を個別モジュールの追加だけにしない。実際の依頼が入口から成果まで通る単位を広げ、その過程で必要な意味・知識・操作・表現を形成する。今回の48登録を全能力の自由文接続完成やGPT-4性能同等へ読み替えない。
