# 第24バッチ：入出力境界・保存安全性・意味比較

## 作業基点と範囲

会話中の第23バッチの部分成果物を基点にしたサンドボックス変更。完全なmainの取得物・Windowsでの実行結果ではない。未取得依存をスタブで置換しない。GitHubへの書込み、commit、push、PR、CI実行は行わない。

## 修正した入出力

全ツールの日本語出力をUTF-8/strictに固定。引数解析前に設定するのでヘルプ・引数エラーにも同じ契約を適用する。import時には設定しない。呼出し元の標準ストリームを交換・閉鎖しない。壊れた入力を置換文字で受理しない。

`基点差分再現.py`は比較対象のPYTHONPATHを維持するため、後発のminidora補助モジュールを先行importせず標準ライブラリだけで同等の起動設定を行う。

保存・出力は同ディレクトリの一時ファイルにUTF-8/LFで書き、正常に書き終えた後だけ公開する。非上書きは公開時のhard link作成で競合を拒否、明示上書きはos.replace。途中失敗で旧ファイルを切り詰めない。出力先のsymlinkを拒否し、異名hard linkの入力・出力衝突も確認する。既存試験の日本語fixtureも符号化を明示した。期待値の引下げはしていない。

通信入力不正が一つでもある場合、終了値は2。JSONL出力ファイルと保存状態を公開しない。標準出力は逐次送信され、既送信の内容は巻き戻せない。合法な依頼の「保留」は通信不正と別であり、保留目的を正常に保存・復元する。

各ファイルは単独で原子的。出力ファイルと状態ファイルをまとめた一括原子性はない。出力確定後に状態保存が失敗すれば、出力だけ確定した状態となり終了値2を返す。ファイル本体のfsyncは行うが、停電時のディレクトリエントリ永続化保証、敵対的な親ディレクトリ差替えへの完全耐性、FAT等hard link非対応FSの受入は対象外。

## 追加した入力入口

`--発話`で日本語発話を順番に直接渡せる。JSONLの手書きは必須ではない。既存の意味解釈・確認・推論・採用・説明ループをそのまま通す。`--入力`との併用は禁止し、最大128発話・各8192文字を事前に確認する。

`--契約`は、対応形式、意味契約版、上限、実行可能な日本語例、保留境界をJSONで表示する。状態操作・ファイル出力と併用しない。意味構文を拡大したわけではない。対応外の自然文は保留する。既存の保存会話の契約版と再生規則は変更していない。

## 意味と計測

既存の純粋再利用器を依存の小さい`純粋再利用.py`へ移し、既存factory内の`_再利用能力`名はimport aliasで保持する。キャッシュの採用対象は従来どおり明示された純粋能力のみ。別世界知識や生成AIへの置換はない。

`統合応答.意味辞書化()`を追加。状態・本文・理由・全出力・解釈情報を比較対象にする。実行時間、所有ID、採用記録IDなどは従来の`辞書化()`に保持する。出力データ中の「計算量」「時刻」を名前だけで除外しない。意味比較は監査記録全体の一致や真正性の代替ではない。

実際の有限命題能力で、同一入力の二回実行、キャッシュ再利用、原実行回数、意味全体の一致を検査する。問い、根拠、参照、文脈、能力版の差を捨てない。標準全能力factoryとWindows上流失敗testの全面動的試験は未実施。

## 受入コマンド

Python 3.11以降を想定するが、この成果物の実測環境は受入JSONを参照する。新しい外部依存はない。

```text
python tools/部分検証.py
python tools/監査改善チャット.py --契約
python tools/監査改善チャット.py --発話 "命題資料「例」を登録：P。PならばQ。" --発話 "資料「例」から「Q」を判定して"
```

分割して実行・記録する場合：

```text
python tools/第24受入.py --組 既存回帰 --結果 検証/既存回帰.json
python tools/第24受入.py --組 ファイル公開 --結果 検証/ファイル公開.json
python tools/第24受入.py --組 標準入出力 --結果 検証/標準入出力.json
python tools/第24受入.py --組 符号化行列 --結果 検証/符号化行列.json
python tools/第24受入.py --組 意味と計測 --結果 検証/意味と計測.json
```

Windows実機では上記と元リポジトリの全回帰・CLI smokeを実施する必要がある。この部分受入をWindows PASSへ読み替えない。
