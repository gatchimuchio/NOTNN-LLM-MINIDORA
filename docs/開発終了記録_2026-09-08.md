# 2026-09-08 開発終了記録

ユーザー指示により、GPQA Diamond 40%到達に向けた今回の改善探索を終了する。目標の80/198は未達。完成・測定済みの英語質問境界修正と述語探索の短絡、Windows開発環境、手動検証workflowをmainへ還元する。

## 採用した変更

- 英語質問の焦点・本体・条件・質問表示を共通の境界解析で扱う。引用、関係節、条件節を単語の有無だけで質問へ昇格させず、境界を確定できないwhen句は未確定として保持する。
- 英語の29関係構文は、必要な述語が不在の場合に限り全文正規表現探索を省略する。構文、matchの位置・順序・group、独自構文との互換性を回帰試験で確認する。
- 射影監査は問いと匿名化した全4候補を入力とし、正解ラベル・正解解説をCompilerへ渡さない。人工射影契約の失敗は非ゼロ終了にする。
- Windows用仮想環境、準備・検証用PowerShell、VS Code設定を追加する。手順は [Windows開発環境](Windows開発環境.md) にまとめた。
- [.github/workflows/manual-validation.yml](../.github/workflows/manual-validation.yml) を追加する。Ubuntu / Python 3.13で既存の監査・構文確認・全単体試験・規模測定回帰・CLI確認を手動実行する。

## ローカルとActionsの併用

編集と日常の動作確認はWindowsで行い、全テスト・監査を外部CPUで実行したいときに手動workflowを使う。GitHub上の [Actions](https://github.com/gatchimuchio/NOTNN-LLM-MINIDORA/actions/workflows/manual-validation.yml) で **MINIDORA 手動検証 → Run workflow → main → Run workflow** を選ぶ。

手動workflowはGitHub上の選択したrefを検証する。未pushのローカル差分は検証対象にならない。権限は `contents: read`、checkoutの認証情報は保持しない。ソース・テスト・既存toolsを読み取り専用にし、導入・bytecodeはrunnerの一時領域を使う。終了時に追跡ファイルの差分がないことを確認する。コード生成、修正、commit、push、PR作成、リポジトリへの書き戻しを行わず、成否とログを返す。
