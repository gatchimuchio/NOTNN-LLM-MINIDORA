# MINIDORA 汎用Capability開発進捗

更新: 2026-09-11
目的: GUIの体裁より先に、内部の汎用能力とその合成を開発する。
GPT-4世代の汎用テキスト能力との同等性は開発目標であり、本記録は到達認定ではない。

## 第1バッチ

②の**明示計画の依存解決・合成実行 v0.1**を追加した。
新設2ファイルは `src/minidora/能力合成.py` と `src/minidora/能力合成_局所接続.py`。
既存の抽出要約・情報抽出・文脈変換を連鎖させるAdapterを含む。

①の自由文解釈を先に作ったことにはしない。HDS Compilerが保持する意味構造と実行計画の境界を確認し、先に後段の受け口を実装した。

## 第2バッチ

①の**文書操作に限定した要求解釈・タスク分解 v0.1**を追加した。
HDSIRの原文を全文解釈し、上流の座標・関係・残差を保持・照合したうえで、第1バッチの合成計画へ接続する。

対応は抽出要約、数値／URL／キーワード抽出、箇条書き変換。対象資料の名前指定、同一要求内の前工程参照、元資料への復帰、独立複数出力、行数条件を扱う。未知の条件や尾部は捨てず全体を保留する。

①全体の完成ではない。有限文法の局所解釈を汎用日本語理解と呼ばない。③の過去turn照応、②の動的再計画、標準チャット接続は未実装のまま。

任意の照応理解、文章内の箇条書き項目選択、自然言語による訂正・話題転換、長期記憶は未完了。標準チャットへは未接続。

## 第4バッチ

④の**必要語に基づく検索・公開HTTPS本文取得・抜粋 v0.1**を追加した。

検索語と必要語は上位から明示して渡す。要求全体からの汎用的な検索目的の推定、意味的な資料十分性判定、公開日・版の自動判定は未実装。語の一致を事実確認完了にしない。

同時に⑮のうち静的本文の取得部分を実装。公開IPへ接続先を固定し、転送先も検査する。JS描画、PDF、表構造、ログイン、ブラウザ操作は対象外。

## 第5バッチ

⑤の**数値主張の証拠統合・矛盾処理 v0.1**を追加した。
対象・属性・値・単位・否定・不等号・条件・時点を原文位置へ結び付け、同じ適用群の制約共通域を調べる。
別条件・別時点、同一URL/本文の重複、未解釈片を保持する。

分析報告と値採用を別Moduleに分けた。報告は競合でも成立し、記載値採用の関門で未解釈・競合・範囲未選択等を保留する。第4バッチの取得資料→証拠統合→記載値採用→既存数値抽出を接続した。

局所数値文法であり、任意の文章の意味理解・事実性・出典独立性の認定ではない。未解釈片があると値採用を保留する。⑤全体の完成や、通常のWeb文書全体の意味処理が成立したとは主張しない。

## 第6バッチ

⑥の**数値証拠報告からの応答構成 v0.1**を追加した。
第5バッチの報告を元資料から再比較し、結論・理由・適用群・記載・残差・出典・限界を回答計画へ分け、日本語の段落／箇条書きへ構成する。要点／詳細を選べ、詳細では原文引用も表示する。

同じ意味の数値記載だけを束ね、反対値・否定・不等号・条件・時点・未解釈の存在を短文化で落とさない。最大8報告を依頼順にまとめ、各項目の値採用可否は分離する。回答構成の成功を、全記載の採用や事実認定と同一視しない。

回答の各単位と元報告・参照本文位置を対応づける。文字数が足りなければ途中切断せず保留する。元報告の再比較と回答の再構成により、hashを書き直した値変更・否定削除・引用位置改変も検査する。ただし真正性の証明ではない。

今回の入力は数値証拠報告に限定する。自由作文、任意の説明、翻訳、対話的な言い換え、一般的な文章生成は未実装。標準チャットへの自動接続も行っていない。

## 第7バッチ

⑦の**差分関係・比較・制約処理 v0.1**を追加した。
同一尺度の明示関係から推移・差の加算・等値・厳密比較を導き、問いの導出／反証／未確定、前提矛盾、上流未解釈の保留を分ける。根拠制約と原文位置を保持する。

既存数値証拠を同一属性・単位・条件・時点の関係へ接続。一意の値が採用できない範囲情報からも大小比較を導ける。関係判定と採用を分離し、未確定・矛盾では後段を呼ばない。

実数差分制約の連言に限定する。整数・一般的論理和・集合包含・因果・自然言語の一般関係抽出・動的再計画は未実装。標準チャットにも未接続。

## 第8バッチ

⑧の**目的分解・多段解決 v0.1**を追加した。
明示された最終目的から解法と下位目的を選び、既存能力を実行して目的別検証を行う。下位目的が一度成立していても、親・後続目的が不成立なら子の別解へ戻る。複数最終目的の全件成立を要求し、失敗枝の成果を採用経路へ混ぜない。

「原文の全数値を抽出」という局所例では、要約経由の数値欠落を検査で退け、原文を保持する解法へ戻って完了する。第7バッチの関係判定も処理と目的検証へ接続し、未確定・条件不一致を前提追加で埋めない。

宣言済みの有限解法と純粋な処理能力に限定する。自由文からの目的・解法の発見、外部作用を含む再計画、最適計画、一般的な自律問題解決は未完成。標準チャットへは未接続。

## 第9バッチ

⑨の**限定Pythonコード能力 v0.1**を追加した。
単一関数の構造読解、構造化アルゴリズムからのPython生成、独自AST評価、有限入出力試験を4つのCapabilityとして接続する。分岐・反復・整数演算・比較・添字・限定した組込操作を扱う。生成コードの定数実値は別Dataに保持する。

第8バッチの多段解決器を使い、生成できても境界値の試験で失敗する候補を退け、別の明示アルゴリズム候補へ戻る経路を接続。候補が尽きれば検証条件を緩めず保留する。

ユーザー入力をexec/evalに渡さず、許可した構文を独自評価する。一般的なPython互換やOS隔離実行ではない。自由文からのアルゴリズム抽出、未知バグの修正案作成、外部ライブラリ・他言語・標準チャット接続は未完了。

既存能力合成へ原文選択→数値抽出を接続し、実HDS・既存短期会話への素材渡しも試験する。依存・条件・改訂の自由文抽出、意味的十分性、要約、巨大文書分割、永続ストレージ、標準チャット自動接続は未完了。既存短期セッションの上限は変更しない。
