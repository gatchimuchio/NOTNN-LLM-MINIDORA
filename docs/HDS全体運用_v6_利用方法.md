# HDS全体運用v6：必要条件と例外を区別して説明する

2026-09-18 / 実装契約：[設計68](../設計/68_HDS_MINIDORA_必要条件と例外_v6.md)

## 必要条件

```python
from minidora.HDS運用 import HDS運用セッション

会話 = HDS運用セッション("必要条件")
会話.資料を登録(
    "条件",
    "装置Aが稼働するためには装置Aが有効であることが必要。装置Aは有効である。",
)
回答 = 会話.応答("資料「条件」をもとに、装置Aが稼働するかどうか説明して")
print(回答.本文)
```

`有効`は`稼働`の必要条件なので、有効であることだけから稼働を導かない。

一方、次は`稼働 → 有効`として扱う。

```text
装置Aが稼働するためには装置Aが有効であることが必要
装置Aが有効であることは装置Aが稼働するための必要条件
装置Aが有効な場合に限り装置Aは稼働する
装置Aが有効な場合のみ装置Aは稼働する
```

「必要十分条件」は本増分では未対応で、片方向へ勝手に縮退しない。

## 例外付き規則

```python
会話 = HDS運用セッション("例外")
会話.資料を登録(
    "手順",
    "装置Aは有効であるならば装置Aは稼働する。"
    "ただし装置Aは故障である場合を除く。"
    "装置Aは有効である。"
)
回答 = 会話.応答("資料「手順」をもとに、装置Aが稼働するかどうか説明して")
print(回答.本文)
```

この状態では、故障でないことが不明なので本則を適用しない。`装置Aは故障ではない`が明示されれば本則を適用できる。

例外時の帰結も明示できる。

```text
装置Aは有効であるならば装置Aは稼働する。
ただし装置Aは故障である場合は装置Aは稼働しない。
```

内部上は、本則と例外規則を分離する。故障が成立したというだけで、本則の逆を自動生成しない。

## 未対応例外

```text
装置Aは有効である。
ただし故障時は除く。
```

のように作用域や条件を一意に解釈できない場合、直前の記載は推論へ採用せず、原文と未解釈理由を残す。無関係な他の記載まで資料全体として捨てない。

## v5保存からの移行

```python
from pathlib import Path
from minidora.HDS運用 import HDS運用セッション, 旧保存を移行

原本 = Path("旧v5.json").read_text(encoding="utf-8")
会話 = 旧保存を移行(原本)
会話.応答("再計算して")
Path("新v6.json").write_text(会話.保存(), encoding="utf-8")
HDS運用セッション.復元(会話.保存())
```

通常復元はv6だけを受理する。標準v1〜v5は`旧保存を移行`で明示移行する。

v5関係回答は意味契約が変わるため、そのまま現行回答として再採用しない。旧原本内には完全に保持し、再計算用の目的だけ現行要求版へ移した上で、現行資料から再計算する。

## 適用範囲

v6は順序2の部分増分である。必要条件と有限な直前例外を安全側に扱えるようにしたが、一般動詞、任意修飾、複数例外の優先、対象同一性、一般内容生成、翻訳、未知課題の一般解法は残る。
