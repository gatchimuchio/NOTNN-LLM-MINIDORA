## 資料から導出して説明する

既存のHDS入口を使います。ニューラル模型や別の制御主体は必要ありません。

```python
from minidora.HDS運用 import HDS運用セッション

会話 = HDS運用セッション("手順確認", 手順形成=False)
資料 = (
    "担当Aは書類を読みます。"
    "装置Aは停止しない。"
    "担当Aが書類を読むなら担当Aは担当Bに書類を送る"
    "（ただし、装置Aが停止する場合を除く）。"
)
登録 = 会話.資料を登録("手順", 資料)
if not 登録.成立:
    raise RuntimeError(登録.本文)
回答 = 会話.応答("資料「手順」から担当Aが書類を担当Bに送るかどうか説明して")
print(回答.状態)
print(回答.本文)
```

この例は、書類を読む記載、停止しない記載、例外付き規則から送ることを支持します。語順が違っても「を」「に」の役割は同じです。送信そのものを実行する例ではありません。

「装置Aは停止しない」を削除すると非例外の根拠が不足するため、規則を採用せず未確定を説明します。「装置Aは停止する」も追記すると例外の根拠が矛盾するため、同じ規則を採用しません。ただし別の独立した根拠が後件を支持していれば、その根拠は別途説明します。

## 必要条件と十分条件

```text
資料：
装置Aが稼働するためには、装置Aは有効であることが必要です。
装置Aは有効である。

依頼：資料「手順」から装置Aが稼働するかどうか説明して
```

有効であることが必要でも、それだけでは稼働を導けません。明示された「十分条件」「必要十分条件」は別方向として扱います。

## 更新・再表現・保存

```python
# 回答を作った後、意味・原文を変えず表示を切り替える。
文章 = 会話.応答("文章にして")
保存文字列 = 会話.保存()
復元 = HDS運用セッション.復元(保存文字列)

# 更新すると旧回答は失効する。新資料による結果は明示再計算で得る。
復元.資料を登録("手順", "担当Bは書類を担当Aに送ります。", 更新=True)
再回答 = 復元.応答("再計算して")
print(再回答.本文)
```

主体と宛先が交換された別の事実から、元の送信関係を導くことはありません。保存・再表現では外部通信を再実行しません。

## v5保存物からの明示移行

```python
from pathlib import Path
from minidora.HDS運用 import 旧保存を移行

旧文字列 = Path("旧保存.json").read_text(encoding="utf-8")
会話 = 旧保存を移行(旧文字列)
Path("移行後.json").write_text(会話.保存(), encoding="utf-8")
# 旧原本・履歴・依存を保持したまま、旧成果は未採用にする。
回答 = 会話.応答("再計算して")
```

標準v1〜v5が対象です。独自能力を追加した未知の目録は自動移行しません。外部読取許可を保存から獲得せず、呼出側の明示設定との一致が必要です。再計算前の旧関係回答は旧意味契約で検査し、明示再作用から現行の意味構成を使います。

CLIの既存`--移行元`も同じ移行処理に接続します。詳しいオプションは`python -m minidora.HDS運用 --help`で確認できます。

## 公開資料の不足調査と境界

既存の知識取得器を設定したセッションで、外部読取を全体設定と当該依頼の両方で許可し、「不足は公開資料で調べて」を付けた場合だけ取得へ進みます。検索語は問いであり、内部資料の全文や例外を勝手に送信しません。問いに機密情報が含まれる場合は、公開調査の許可前に取り除いてください。

取得本文にも新しい格役割の読解を使います。語の一致や取得成功だけでは支持になりません。ローカルと公開資料の同名対象を無条件に結合する機能はありません。認証付きサービス・投稿・送信は本増分の対象外です。

新しい格役割は単純名詞と対応する動詞・活用に限ります。任意の修飾・受動・使役・一般の長文脈を読めるわけではありません。対応表現、例外の採否、容量、旧版境界、残件の正本は[設計68](../設計/68_HDS_MINIDORA_格役割と明示例外_v6.md)です。
