# 開放並列場

この文書は、もっともらしい一説へ早期収束しないための並列保持台帳である。

## 1. 状態・文脈系

### M1 KDA能力源モデル
K3の長文脈・推論能力の主要因はKDAそのものにある。

支持:
- K3は69 KDA層を採用。
- Kimi LinearはKDAがfull MLAより良い結果を示したと報告。

反証・弱化:
- full attention系LLMも成立し高性能。
- Kimi Linear自身がKDAをfull attentionのdrop-in replacementとして比較している。

未解残差:
- K3規模でKDAをfull attentionへ置換した同条件結果は未観測。

### M2 状態作用モデル【M1の反対】
KDAは原理ではなく、**文脈に応じて過去情報を保持・更新・参照可能にする状態作用**の一実装である。

予測:
- KDAを別の状態保持/参照方式へ置換しても同責任を満たせばLLMは成立する。
- 性能・効率は変わり得る。

## 2. 深度系

### M3 AttnRes能力源モデル
Attention Residualsによるdepth選択がK3高性能の中核である。

支持:
- AttnRes論文は内容依存のdepth-wise selectionによる改善を報告。

反証・弱化:
- standard residualのLLMも成立する。
- AttnResは既存residualのdrop-in replacementとして提案されている。

### M4 深度利用効率モデル【M3の反対】
AttnResはLLM成立原理ではなく、**過去の変換結果を入力依存で再利用する深度利用政策**である。

予測:
- 固定残差でもLLMは成立する。
- 大規模・深層化では選択的再利用が性能/安定性を改善し得る。

## 3. 幅・専門化系

### M5 MoE能力源モデル
多数expertから一部を選ぶこと自体が高能力の原理である。

支持:
- K3、DeepSeek、Qwen、MiniMaxの大規模系でMoEが反復出現。

反証:
- Llama 3.1 405BはDenseで高性能LLMとして成立。

### M6 条件付き変換モデル【M5の反対】
MoEは、**入力・状態に応じて適切な変換作用を使い分ける**責任の効率的な実装であり、sparse expert自体は原理ではない。

予測:
- Denseでも条件依存変換を十分表現できればLLMは成立する。
- MoEは容量/計算効率の配分方法として有利になり得る。

## 4. 規模・weight系

### M7 巨大weight本体モデル
K3の能力は2.8T weight自体にあり、非ニューラル再構成にはscalar意味復元が必要である。

支持:
- K3は大規模学習済みparameterを持ち、能力はtraining後のweightへ反映される。

反証・弱化:
- scalar単位と概念単位の一対一対応は公開観測されていない。
- 異なるarchitecture/parameter規模でも類似能力が成立する。
- `weightが能力を実現する媒体`と`各scalar意味の完全復元が必要`は別命題。

### M8 能力構造媒体モデル【M7の反対】
weightはCapability / Knowledge / Relation / Transformation等を混成保持する媒体であり、再構成で必要なのはscalarの同型復元ではなく**観測作用を成立させる実行可能構造の復元**である。

未解残差:
- CapabilityとKnowledgeをどこまで機能損失なく分離できるかは未検証。

## 5. Knowledge配置系

### M9 内部Knowledge不可分モデル
K3級LLMの能力には、世界知識をweight内部へ保持することが不可欠である。

### M10 外部Knowledge分離モデル【M9の反対】
計算Capabilityを命令形Pへ、内容Knowledgeを外部参照Rへ分離しても、適切な参照・変換・合成があれば同等機能へ近づける。

現状:
- MINIDORAの設計仮説。
- K3公開情報だけからは原理として閉じられない。
- benchmark / perturbationで検証するまで`原理候補へ昇格禁止`。

## 6. training / post-training / agent系

### M11 architecture主因モデル
K3のfrontier性能は主としてKDA / AttnRes / Stable LatentMoEによって成立する。

### M12 複合生成モデル【M11の反対】
観測されるK3能力は、architecture、pretraining data、training objective、post-training、RL、reasoning budget、agent environmentが相互作用した結果である。

支持:
- K3 Technical Report自身がarchitecture以外のdata recipe、general/agentic/coding RL、reasoning effort、persistent rollout/sandboxを性能要因として記載。
- MiniMax-M2もagentic data / RL / scaffold分離を主要要因として公開。

## 7. 長文脈系

### M13 全履歴直接アクセスモデル
1M context能力には広範な直接attentionが本質的に必要。

### M14 状態保持 + 選択参照 + 再照合モデル【M13の反対】
長文脈では、全情報を同じ形で保持するのではなく、限定状態保持と必要情報参照、必要時のglobal reconciliationを組み合わせても成立する。

支持候補:
- Kimi Linearの有限状態KDA + MLA hybrid。
- K3の69 KDA + 24 Gated MLA。

未解:
- これが1M contextの必要原理か、K3の効率的実装かは未閉包。

## 8. multimodal系

### M15 言語核変質モデル
native vision追加により言語LLMのLayer-0自体が別原理になる。

### M16 追加入力Projectionモデル【M15の反対】
visionは異なる入力を言語/内部状態へ接続する追加Projectionであり、言語結果形成の最小責任は維持される。

現状:
- K3のvision ablationを本Runでは実行していないため保留。

## 9. 不可能性・未観測

保持する不可能性候補:
- 公開資料だけで、全能力の因果寄与率を一意に分解すること。
- scalarごとに概念を一意対応させること。
- K3 Native全体を公開Projectionだけで完全表現すること。

未観測:
- K3全内部activation介入
- 全training data
- architecture置換ablation at 2.8T
- Knowledge外部化ablation

これらが残るため、本Runでは`完全解析`を宣言しない。
