# 失敗署名 — 旧K3解析の方法論縮退

## 0. 目的

過去のK3解析で発生した失敗を、単なる謝罪や注意書きで終わらせず、再利用可能な失敗署名として保持する。

## 1. 表面症状

過去の解析は、HDSを方法論として指定されていたにもかかわらず、実際には次へ縮退した。

```text
K3公開architectureを読む
→ KDA / MoE / AttnRes等を部品分解
→ tensor / weight fileを解析
→ K3固有機構を非ニューラルopcodeへ写像
→ toy task / CI合格
→ HDS解析・非NN LLM完成と誤昇格
```

## 2. 構造原因

### 原因A: HDSを実行手順ではなく概念集合として扱った

`原理、構造、認知、採否`等のHDS語を参照したが、認知世界形成→原理質問→開放並列場→原理分別→局所適用→結果帰還→総再開放を実行順序として拘束しなかった。

### 原因B: 原理分別前に実装へ降りた

KDAが観測された時点で、

```text
KDA → 状態更新opcode
```

と実装へ飛び、

```text
なぜKDAか
別方式でも成立するか
何を変えると崩れるか
```

を開放並列場で保持しなかった。

### 原因C: 実装資料を原理へ誤投影した

KDA、MoE、AttnRes、expert routing、weight tensor等のK3固有構造を、Layer-0へ縮約する前に実装核へ昇格した。

### 原因D: scalar問題を解析目的へ昇格した

`2.8T scalarの個別意味が分からない`ことを再構成の中心残差と誤認した。

本来の問題は、K3の観測能力を成立させる作用構造を原理層で分別し、実行可能Pへ再表現できるかであった。

### 原因E: 外殻の成功を能力完成へ誤昇格した

API、CI、監査、toy task成功を、LLM能力・K3同等性・HDS解析完了へ誤投影した。

### 原因F: 日本語を基底ではなく翻訳先として扱った

英語圏の技術概念で分析・設計した後、opcode名や状態名だけを日本語へ置換した。

これは日本語基底ではなく、英語構造の日本語ラベル化だった。

## 3. 影響

- K3固有機構がLayer-0へ混入した。
- HDS解析を実行したという誤った完了報告が発生した。
- `重み命令化`の意味がweight file解析へ逸脱した。
- MINIDORAの設計思想と実装が離れた。
- 標準ベンチで設計上のData Layerを切る誤った比較が行われた。
- HDS本体とHDS由来採否protocolが混同された。

## 4. 今回の対策

### 対策1
ルート`AGENTS.md`へ「HDS 大規模言語モデル運用拘束規約 v2.0」を配置し、LLM実装者の運用拘束とした。

### 対策2
HDS Runを文書段階へ分離した。

```text
00 認知世界
01 原理質問
02 開放並列場
03 観測台帳
04 原理の分別
05 局所適用
06 結果帰還・総再開放
07 HDS適合監査
```

### 対策3
K3固有語がLayer-0へ残った場合を、縮約未完了として扱う。

### 対策4
未解を未解として保持し、実装都合で閉じない。

### 対策5
完成判定をtoy task / CI / APIから分離する。

## 5. 再発検知条件

次のいずれかが起きたら、本失敗署名の再発とみなす。

- 原理質問なしでarchitecture実装を開始した。
- 反対Modelなしで原理を確定した。
- KDA / MoE / Attention / TransformerをLayer-0必要条件として直接実装した。
- 未観測を一般論で埋めた。
- scalar意味復元を非NN化の必要条件へ戻した。
- 英語で設計完了後に日本語名だけ付けた。
- benchmark局所成功をK3同等へ昇格した。
- HDS Gate実装をHDS解析実行と呼んだ。

## 6. 次probe

- 追加一次資料を今回のOpenParallelFieldへ帰還させる。
- Layer-0責任の`直列深度`と`停止`を再監査する。
- P/R分離はK3由来原理ではなく設計仮説としてbenchで検証する。
- 日本語基底の効率は記号量・検索量・命令長で比較する。

本署名は削除せず、今後のK3/MINIDORA改訂時の回帰監査へ使用する。
