# 局所適用 — Layer-0と日本語命令形P

## 0. 適用条件

ここでは前段の暫定原理候補を、MINIDORAの現行目的へ**局所適用**する。

これはK3 Nativeの完全説明でも、普遍LLM定理の更新でもない。

目的:
- K3固有実装を持ち込まずに、非ニューラル計算主体へ残す責任を選ぶ。
- 現行`設計/02_Layer0責任契約.md`と照合し、支持・再開放・非適用を分ける。

## 1. 現行Layer-0責任との照合

### 1. 言語アドレス化

判定: **維持。ただし本K3 Run単独由来ではない。**

K3は160K vocabularyを持つため言語単位をアドレス可能にする実装を持つ。しかし、この責任の普遍性はK3分析だけではなく既存Layer-0仕様側の論点である。

K3固有tokenizerは残さない。

### 2. 状態保持

判定: **強く支持。**

P1「文脈状態継続」と整合する。

ただし命令名はKDA状態等にしない。

日本語命令候補:

```text
保持
更新
参照
忘却
```

### 3. 内容依存参照

判定: **支持。ただし明示的Top-k選択を必須とはしない。**

K3ではKDA / MLA / AttnRes等に内容依存の情報利用が現れる。

Layer-0へ残すのは、

```text
現在の入力と状態によって利用情報が変わる
```

という責任であり、attention、routing、top-kは残さない。

日本語命令候補:

```text
参照
選別
照合
```

### 4. 条件付き変換

判定: **強く支持。**

P2と整合する。Dense/MoE差を除いても残る。

日本語命令候補:

```text
条件
変換
適用
分岐
```

### 5. 関係合成

判定: **支持候補。**

K3の多段処理・推論能力と整合するが、本Runだけで普遍必要条件までは証明しない。

日本語命令候補:

```text
結合
連鎖
合成
比較
```

### 6. 直列深度

判定: **維持するが再開放対象。**

P4は「反復合成」を支持するが、物理的multi-layerを必要条件とはしない。

したがって責任名を`直列深度`へ固定するより、

```text
必要な中間状態遷移を反復できる
```

という意味へ寄せる余地がある。

将来候補名:
- 反復
- 継続
- 多段

### 7. 結果形成

判定: **維持。**

内部状態を外部言語結果へ接続する責任はK3でも観測される。

日本語命令候補:

```text
形成
選択
出力
```

### 8. 停止

判定: **Layer-0 LLM原理として再開放。**

計算終了自体は運用上必要だが、`成立/未解/矛盾/境界違反`による明示停止はHDS判断主体・製品Runtime責任が混入している。

K3解析から、HDS型の`保留/失敗`をLLM計算核へ帰属させる根拠はない。

したがって、

```text
計算終了条件
```

と

```text
HDS採否停止
```

を分離する必要がある。

## 2. K3からLayer-0へ残さないもの

次は本RunではLayer-0へ昇格しない。

```text
KDA
Gated MLA
Attention Residuals
Stable LatentMoE
expert
Top-k
shared expert
93 layer
MXFP4 / MXFP8
MoonViT-V2
```

これらは実装・性能機構・入力拡張として別層へ残す。

## 3. K3から命令形Pへ持ち込み得るもの

命令PはK3の部品名を記述する場所ではない。

現時点の暫定語彙候補:

```text
保持
更新
参照
忘却
条件
変換
適用
分岐
結合
連鎖
合成
比較
反復
継続
形成
選択
照合
```

これらを、単なる動詞一覧ではなく、

```text
対象
条件
入力状態
作用
出力状態
参照範囲
停止/継続条件
根拠
```

を持つ実行構文へ落とす。

## 4. `選択的情報流`の扱い

K3では時間・文脈・深度・幅・予算の複数軸に選択が反復する。

しかし、これは現時点では

```text
frontier規模の性能/効率を成立させる局所原理候補
```

であり、

```text
LLM Layer-0普遍必要条件
```

ではない。

MINIDORAでは、最初から複雑な多軸routingを模倣せず、必要になった時点でP側の政策として追加検証する。

## 5. Capability / Knowledge分離の局所適用

MINIDORA設計では、

```text
Capability → P
Knowledge/Data → R
```

と分離する。

ただし本HDS Runでは、この分離がK3同等能力を維持することは**未閉包**である。

よって実装方針として採用してよいが、K3から発見済みの原理として扱わない。

検証責任:
- 同一問題Dataを外部Rへ置いた場合の性能
- P側に保持すべき手続き/関係とR側へ置ける内容資源の境界
- Reference latency / cost / retrieval errorによる能力変化
- Knowledge不足時にCapabilityそのものが崩れるか

## 6. 日本語基底の局所適用

日本語基底はK3から抽出された原理ではなく、MINIDORAの内部表現設計である。

したがって、

- K3英語技術語を日本語へ翻訳して満足しない。
- 原理候補の意味構造を最初から日本語で保持する。
- 漢字による情報密度優位は仮説として、記号量・検索量・命令長・監査量で実測する。

## 7. 局所適用結果

現時点でMINIDORAの次実装へ直接許可できるのは、

```text
文脈状態の保持・更新・参照
条件付き変換
関係/結果の合成
必要な反復処理
結果形成
```

まで。

K3固有routing、scalar意味復元、MoE模倣、AttnRes模倣は実装許可しない。

また、現行Layer-0契約の`停止`責任は、計算終了とHDS採否を分離する方向で再開放する。
