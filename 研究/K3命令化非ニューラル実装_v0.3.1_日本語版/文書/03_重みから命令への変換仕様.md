# 重みから命令への変換仕様

## 目的

公開K3 checkpointを巨大binaryのまま同一視せず、処理責任、命令、operand、学習済み意味、未解決残差へ分ける。

## 四段階

### A：構造役割変換

```text
config／report／reference code
→ KDA／MLA／AttnRes／MoE／vision／result role
→ 明示命令順
```

実装済み。

### B：テンソル役割変換

```text
tensor name／shape／dtype／shard
→ 命令語／軸／層／専門器
```

実装済み。HF index又はsafetensors headerを使う。

### C：重みbyte結合

```text
safetensors data_offsets
→ absolute byte range
→ role opcode operand reference
→ optional streaming SHA-256
```

実装済み。巨大tensorをRAMへ全展開しない。

### D：重み値意味変換

```text
individual learned scalars
→ concepts／relations／rules／procedures／knowledge
```

未成立。

## 挙動変換器

重みroleだけで回収できない学習済み作用は、K3のI/O probe、摂動、反実仮想から命令雛形へ変換する。

```text
input
K3 output
status
source
perturbation
counterexample
    ↓
command template
    ↓
held-out validation
    ↓
promote／reopen／falsify／residual
```

compilerは実装済み。実K3 probe corpusは未投入。

## 誤変換禁止

- `W @ x`をMUL/ADD列へ展開しても、同じnetwork作用なら非ニューラル意味変換とは呼ばない。
- weight bytesをopcode operandへ結び付けても、scalarが何の知識を表すかは確定しない。
- `q_proj.weight`の処理責任は分かっても、そのscalarが保持する概念はtensor名だけでは分からない。
