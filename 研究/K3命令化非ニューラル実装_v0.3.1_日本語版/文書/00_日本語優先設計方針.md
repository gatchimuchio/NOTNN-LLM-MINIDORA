# 日本語優先設計方針

## 目的

本実装では、LLM・命令列・監査履歴・参照台帳の内部表現を、可能な限り日本語、とくに漢字中心の短い表意記号へ統一する。

本プロジェクトでは、次を**設計仮説**として採用する。

> 英語のような表音文字中心の記述より、漢字を含む日本語の表意記述を用いる方が、同じ概念を短い記号列へ圧縮しやすく、命令保持・検索・比較・監査における情報密度を高められる。

これは普遍的優位を証明済みとする主張ではない。ミニドラ内部の語彙長、検索照合、履歴量、監査可読性を改善するための工学的仮説であり、今後は英語命令版との実測比較によって検証する。

## 日本語を正本とする範囲

- 命令語
- 問題系統名
- 状態名
- 採否理由
- 実行履歴
- 参照台帳
- 変換台帳
- 文書名・操作名
- CLI説明・誤り文
- Python公開APIの日本語別名

```text
RETAIN                   → 保持
DELTA_WRITE              → 差分書込
SELECT_REFERENCES        → 参照選択
GLOBAL_RECONCILE         → 全体照合
DEPTH_TOPK_READ          → 深度上位読出
EMISSION_AUTHORIZED      → 出力許可
UNRESOLVED_CONTRADICTION → 未解消矛盾
```

## 英字を残す境界

- Python予約語・標準ライブラリ名
- HTTP、JSON、SHA-256、safetensors等の標準名
- K3公式tensor名、config key、shard名
- URL・commit SHA・license原文
- 第三者APIのfield名
- 外部互換用のPython API

公式tensor名を翻訳すると公開checkpointのbyte位置へ再接続できなくなる。したがってtensor名は原文を番地として保持し、日本語の役割命令を別層で結合する。
