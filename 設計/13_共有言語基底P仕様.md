# 共有言語基底P仕様 v0.1

## 1. 目的

MINIDORAは日本語を内部意味正本とし、英語を主要な外部接続言語として扱う。
そのため、文字・基本文法・基底概念を毎回Rへ問い合わせる構造にはしない。

本仕様では、HDS CompilerとMINIDORA計算主体Cが共通参照する最小の常在言語資産を**共有言語基底P**として定める。

```text
共有言語基底P
    ├─ HDS Compiler
    │    └─ 入力の文字体系・言語・文法・意味候補を射影
    └─ MINIDORA / C
         └─ HDS-IR・語・記号を意味計算へ利用
```

同じ辞書を二重管理せず、一つの版付き正本を両側が参照する。

## 2. P / M / Rとの境界

共有言語基底Pへ入れるのは、世界についての個別事実ではなく、言語を成立させるための常在能力である。

```text
共有言語基底P
= 文字体系
+ 表音対応
+ 基本文法機能
+ HDS/Pの基底概念
+ 外部言語との最低限の接続

M
= 実行経験・根拠・仮説・状態

R
= 世界について必要時に取得する外部Data / Knowledge
```

例:

- `猫`が漢字である、`ね`と`ネ`が同じ音へ接続する、`if`が条件を表す → 言語基底P
- 現在の猫の個体数、特定地域の人口、ニュース、人物情報 → RまたはM

正しい事実であることだけを理由にPへ昇格させない。

## 3. v0.1の実装範囲

`src/minidora/言語基底.py` を正本実装とし、次を保持する。

### 3.1 文字体系

- ひらがな
- カタカナ
- 漢字
- ラテン文字
- 数字
- 補助記号

かなはローマ字表記へ接続する。
漢字は表意文字として認識するが、v0.1ではJIS漢字集合・全読み・全語義の完全収録を主張しない。

### 3.2 日本語基底

- HDS/Pで常用する基底概念
- 基本的な助詞・否定・丁寧表現の文法機能
- 日本語を内部基底とする入力言語判定

漢字だけの短い入力を自動的に中国語へ落とさない。
中国語固有性が明示される場合だけ`zh`へ分別する。

### 3.3 英語基底

英語は内部正本ではなく主要外部接続言語として、最低限の機能語を保持する。

- 冠詞
- 並列・選択
- 否定
- 条件
- 時間順序
- 疑問
- be動詞
- 基本助動機能

英語世界知識を常在Pへ大量格納することは本仕様の目的ではない。

## 4. HDS Compiler側の責務

現行公開HDS Compiler v1.2は共有言語基底Pを保持し、入力言語判定を同資産へ委譲する。

Compilerは言語基底を使って入力をHDS-IRへ射影するが、世界知識の真偽判定や最終採否は行わない。

## 5. MINIDORA / C側の責務

MINIDORAの意味照合は共有言語基底Pを参照する。

特に、日本語の漢字は表意文字であるため、英字と同じ「一文字だから雑音」という規則で捨てない。

```text
猫
→ 一文字
→ 漢字 / 表意文字
→ 意味記号として保持
```

一方、助詞等の文法機能は意味証拠へ無差別に混入させず、Compiler側の構造責務へ分離する。

## 6. 漢字資産の拡張条件

漢字の読み・基本義・語形成を拡張するときは、次を必須とする。

1. 採用集合の範囲を明示する
2. 出所・ライセンス・版を固定する
3. 文字、読み、基本義、語形成を分離して保持する
4. 世界知識を漢字基底へ混入させない
5. CompilerとMINIDORAの双方が同じ版を参照する
6. 追加前後の回帰試験を行う
7. 不要知識率・重複・意味衝突を監査する

JIS水準、常用漢字、教育漢字、辞書資産等を採用する場合も、名称だけで範囲を推測せず、実際のsource lockを別途固定する。

## 7. 不変条件

```text
言語基底Pの正本は一つ
CompilerとCは同じ版を参照
日本語が内部意味正本
英語は主要外部接続言語
世界知識は原則R/Mへ分離
未検証推論を言語基底Pへ昇格しない
```

## 8. 次段

v0.1以後は、次を段階的に追加する。

- 採用漢字集合のsource lock
- 漢字の読み・基本義
- 熟語形成
- 日本語活用・助動表現
- 英語基本語彙・屈折・構文関係
- 言語基底PからP-IRへの正式コンパイル
- 言語基底版を実行同一性・成果物監査へ含める

追加は量ではなく、MINIDORAのC能力へ必要な最小性・再利用性・境界明瞭性で採否する。
