# 共有言語基底P仕様 v0.2

## 1. 目的

MINIDORAは日本語を内部意味正本とし、英語を主要な外部接続言語として扱う。
そのため、文字・基本文法・基底概念を毎回Rへ問い合わせる構造にはしない。

本仕様では、HDS CompilerとMINIDORA計算主体Cが共通参照する最小の常在言語資産を**共有言語基底P**として定める。

```text
共有言語基底P
    ├─ HDS Compiler
    │    └─ 入力の文字体系・言語・文法・意味候補・明示関係を射影
    └─ MINIDORA / C
         └─ HDS-IR・語・記号・一般関係を意味計算へ利用
```

同じ辞書を二重管理せず、一つの版付き正本を両側が参照する。

## 2. P / M / Rとの境界

共有言語基底Pへ入れるのは、世界についての個別事実ではなく、言語を成立させるための常在能力である。

```text
共有言語基底P
= 文字体系
+ 表音対応
+ 基本文法機能
+ HDS/Pの基底概念
+ 外部言語との最低限の接続
+ 屈折・派生語の正規化
+ 一般関係語の意味接続
+ 高確度な明示構文

M
= 実行経験・根拠・仮説・状態

R
= 世界について必要時に取得する外部Data / Knowledge
```

例:

- `猫`が漢字である、`ね`と`ネ`が同じ音へ接続する、`if`が条件を表す → 言語基底P
- `generated` / `generation` が `generate` へ接続し、`generate`と`produce`が一般関係として「生成」へ接続する → 言語基底P
- `inhibited` / `inhibition` / `inhibitory` が `inhibit` へ接続する → 言語基底P
- 現在の猫の個体数、特定地域の人口、ニュース、人物情報、科学分野の個別事実 → RまたはM

正しい事実であることだけを理由にPへ昇格させない。

## 3. v0.2の実装範囲

`src/minidora/言語基底.py` を共有正本の入口とし、日本語基底と英語基底の実装を版付きで保持する。

### 3.1 文字体系

- ひらがな
- カタカナ
- 漢字
- ラテン文字
- 数字
- 補助記号

かなはローマ字表記へ接続する。
漢字は表意文字として認識するが、v0.2でもJIS漢字集合・全読み・全語義の完全収録を主張しない。

### 3.2 日本語基底

- HDS/Pで常用する基底概念
- 基本的な助詞・否定・丁寧表現の文法機能
- 日本語を内部基底とする入力言語判定

漢字だけの短い入力を自動的に中国語へ落とさない。
中国語固有性が明示される場合だけ`zh`へ分別する。

### 3.3 英語基底

英語は内部正本ではなく主要外部接続言語として、次の言語能力を保持する。

#### 基本文法機能

- 冠詞
- 並列・選択
- 否定
- 条件
- 時間順序
- 疑問
- be動詞
- 基本助動機能

#### 屈折・派生語正規化

一般関係を表す英語語について、現在形・過去形・過去分詞・進行形、および保守的に同一概念へ戻せる名詞形・形容詞形を基本形へ接続する。

例:

```text
produces / produced / producing / production → produce
generates / generated / generating / generation → generate
inhibits / inhibited / inhibiting / inhibition / inhibitory → inhibit
activates / activated / activation → activate
depends / depended / dependence / dependency / dependent → depend
correlates / correlated / correlation → correlate
uses / used / using / usage → use
leads / led / leading → lead
```

派生名詞・形容詞を、それだけで有向HDS関係へ昇格させない。
派生語接続は、語の基本概念と意味照合anchorを共有するために用いる。

この正規化は「語が何を意味する言語要素か」を保持するためのものであり、外界事実を追加する処理ではない。

#### 一般関係同義語

表面語が異なっても、言語上同じ一般関係を表す語は日本語正本概念へ接続する。

```text
cause / lead / result          → 因果
increase / raise / enhance     → 増加
decrease / reduce / lower      → 減少
inhibit / suppress / block     → 阻害
activate / stimulate           → 活性化
produce / generate             → 生成
require / need / depend        → 要求
contain / include / comprise   → 包含
use / utilize / employ         → 使用
prevent / protect              → 防止
associate / correlate / relate → 相関
```

これは語義・関係の基底知識であり、特定分野の事実知識ではない。

#### 明示関係構文

過去形・進行形・受動態を含め、関係が文面に明示されている高確度構文だけをHDS関係へ射影できる。

例:

```text
Protein A generated B
→ A --生成→ B

Protein A was inhibited by Protein B
→ Protein B --阻害→ Protein A
```

ただし`Protein A`や`Protein B`についての世界知識をPに持つという意味ではない。ここでPが知っているのは`generated`や`was inhibited by`という**言語構造**だけである。

## 4. HDS Compiler側の責務

現行公開HDS Compiler v1.2は共有言語基底Pを保持し、入力言語判定およびv0.2の英語明示関係構文を同資産へ委譲する。

Compilerは言語基底を使って入力をHDS-IRへ射影するが、世界知識の真偽判定や最終採否は行わない。

### 4.1 関係射影の安全境界

言語基底Pによる関係補完は次を満たす場合だけ行う。

- 関係動詞・構文が文面に明示される
- 始点・終点が意味語として成立する
- 疑問文の未知端点を勝手に確定しない
- 既存Compilerが既に保持する同一関係を二重追加しない
- 名詞の共起・近接だけを理由に関係を作らない
- 派生名詞・形容詞だけから有向関係を作らない
- 分野知識から暗黙関係を推定しない

したがって、過去に不採用となった広い「科学・技術文の関係補完」とは責任範囲を分ける。
v0.2は**言語上明示された関係の語形差を回収する層**であり、意味上の未知関係を推測する層ではない。

## 5. MINIDORA / C側の責務

MINIDORAの意味照合は共有言語基底Pを参照する。

特に、日本語の漢字は表意文字であるため、英字と同じ「一文字だから雑音」という規則で捨てない。

```text
猫
→ 一文字
→ 漢字 / 表意文字
→ 意味記号として保持
```

一方、助詞等の文法機能は意味証拠へ無差別に混入させず、Compiler側の構造責務へ分離する。

英語関係語については、表面形・派生形を基本形へ戻しつつ、同義語間で共有できる日本語関係anchorを意味照合へ追加する。

```text
produced / production  → produce  + rel:生成
generated / generation → generate + rel:生成
inhibited / inhibition → inhibit  + rel:阻害
suppressed / suppression → suppress + rel:阻害
```

基本形を保持し、一般関係anchorだけへ潰さない。

## 6. 漢字資産の拡張条件

漢字の読み・基本義・語形成を拡張するときは、次を必須とする。

1. 採用集合の範囲を明示する
2. 出所・ライセンス・版を固定する
3. 文字、読み、基本義、語形成を分離して保持する
4. 世界知識を漢字基底へ混入させない
5. CompilerとMINIDORAの双方が同じ版を参照する
6. 追加前後の回帰試験を行う
7. 不要知識率・重複・意味衝突を監査する

JIS水準、常用漢字、教育漢字、辞書資産等を採用する場合も、名称だけで範囲を推測せず、実際のsource lockを別途固定する。

## 7. 不変条件

```text
言語基底Pの正本は一つ
CompilerとCは同じ版を参照
日本語が内部意味正本
英語は主要外部接続言語
世界知識は原則R/Mへ分離
屈折・派生語差は言語基底で吸収する
派生語だけから有向関係を捏造しない
明示されない関係を言語基底だけで捏造しない
未検証推論を言語基底Pへ昇格しない
```

## 8. 検証

v0.2では少なくとも次を回帰試験する。

- かな・カタカナの音接続
- 一文字漢字の意味保持
- 日本語優先の言語判定
- 英語関係動詞の屈折正規化
- 英語関係語の派生語正規化
- 一般関係同義語の日本語概念接続
- 英語過去形の明示関係射影
- 英語受動態の意味方向正規化
- 現在形既存関係の重複防止
- 疑問文への確定関係捏造防止
- 単なる共起の関係化防止
- 世界知識の非混入

性能ベンチマークはR取得揺れと分離して解釈し、スコアだけをP採否の唯一条件にはしない。ただし既存能力を明確に退行させる変更は、その原因を切り分けるまで正本化しない。

## 9. 次段

v0.2以後は、次を段階的に追加する。

- 採用漢字集合のsource lock
- 漢字の読み・基本義
- 熟語形成
- 日本語活用・助動表現
- より複雑な英語節構造・係り受け
- 言語基底PからP-IRへの正式コンパイル
- 言語基底版を実行同一性・成果物監査へ含める

追加は量ではなく、MINIDORAのC能力へ必要な最小性・再利用性・境界明瞭性で採否する。
