# HDS-MINIDORA 共通通常運用 v1

日付: 2026-09-17。基点: `4067f2ee32efb5d4f3f091095e1fa61412ea0792`。第27バッチ。

## 目的と責任

HDSを実行主体とし、既存の構文化器、能力群、意味計画、資料、会話、回答、採否を通常の製品入口へ接続する。MINIDORA30の高得点化、互換実行系の後段に付ける監督、既存能力の再実装ではない。

新しい `HDS運用セッション` は案件資料と採用履歴を保持する入口であり、別の判断主体ではない。要求構成、計画修復、個々の能力実行、回答構成はすべて `HDS実行主体.実行()` の同じ通常循環が選ぶ作用である。合成計画はデータであり、旧 `能力合成器.実行()` や旧会話監督の実行ループを呼ばない。

```text
通常依頼／同じ会話の訂正／明示意味目的
  → HDS通常循環
      ├ 要求構成作用：原文・構文化・意味目的・実行計画
      ├ 能力実行作用：選ばれた一工程の既存能力
      ├ 計画修復作用：明示回復契約による新しい計画版
      └ 回答構成・原要求成果照合
  → HDS COMMIT / SUSPEND / FAIL
  → 採用時だけ案件資料・会話焦点へ反映
```

構文化器の意味構成、能力の局所成功、回答形式の成立、HDSの最終採用を区別する。目的ごとの内容保証は既存の能力契約・検証作用に依存する。全世界の真実性や独立した形式証明を共通入口が保証するわけではない。

## 実装

| ファイル | 責任 |
|---|---|
| `HDS運用/セッション.py` | 依頼、資料、採用成果、確認待ち、訂正、保存復元と既存HDS起動 |
| `HDS運用/能力目録.py` | 既存能力の共通登録と意味契約。登録名・版・権限を固定 |
| `HDS運用/要求構成.py` | 既存構文化・有限日本語解釈から目的と計画を構成 |
| `HDS運用/資料要求.py` | 本文・命題・仮説・介入の要求と再表現 |
| `HDS運用/作用.py` | 一工程ごとの能力起動、計画修復、回答照合、作用境界の停止 |
| `HDS運用/契約.py` | 原資料、計画、結果、輸送・保存の境界 |

| `HDS運用/__main__.py` | 対話CLI、JSONL、明示ファイル、保存復元、ローカルHTTP |

## 能力目録と意味供給

既存統合29能力、会話・数量集合・命題・帰属文脈・監査改善能力、および科学候補報告の合計48登録を同じ目録へ接続する。登録数は自由文の理解範囲や能力総数の絶対指標ではない。

有限の自然文から使えるもの、明示意味目的から使えるもの、明示計画と型付きデータが必要なものを区別する。48能力のすべてを任意の自由文から自動起動できるとは主張しない。長文脈選択の既存部品は登録されるが、その原記録庫へこの会話資料を自動同期する処理はまだない。

追加能力は `登録能力` と、必要なら `役割作用` をセッション構築時に渡す。意味作用は成果種別・必要役割・設定・適用条件・費用・権限・回復規則を持つ。新しい組合せは既存の意味計画器で構成し、その各工程をHDSが直接実行する。実行中に目録を差し替えない。

既定構文化器は既存の有限な目的射影と整合する `HDS構文化器.公開HDSコンパイラ`。高度な構文化器を注入する境界はあるが、v1拡張構文化器の全意味を消費する接続まで完成したものではない。原文と構文化結果は保持し、意味射影が未対応の尾部・条件を捨てて成功にしない。

## 状態と依存

入力原文・資料・依頼文脈を `運用入力` に保持し、計画は `運用計画:版`、各能力の実成果は `運用工程:版:工程`、失敗は `運用試行:版:工程:能力` へ分ける。計画の版を不変な成果キーで分離し、旧成果の同時上書きによる自己依存を作らない。

元資料の名称・内容印、計画印、能力名・版、実入力印と中間成果を照合する。全最終出力とその依存工程が成立するまで途中結果を会話の成功成果にしない。明示計画の検証器は呼出側・能力契約が定めるものであり、共通入口が任意目的の検証条件を発明したとは扱わない。

資料の更新は明示する。参照済み資料の内容印が変わると旧成果の再表現を止め、依頼を再実行する。無関係な資料追加で既存成果を失効させない。条件の訂正は既存意味要求へ反映して再計画する。短文化・詳細化では利用可能な採用成果から再構成し、不要な再計算・再取得をしない。

各ターンのHDS実行状態は新しく作り、案件資料と採用成果等を明示的に受け渡す。ターンをまたぐ任意の未完HDS作用列そのものの再開ではない。会話記録上限は128件、資料32件・合計2MB、依頼8192文字。個々の既存能力の制限も維持する。

## 再計画と停止

入れ子資料等の既存回復契約を、専用の別監督ではなくHDS作用へ接続する。旧失敗・旧計画を保持したまま、新計画の要求被覆を照合する。同じ失敗は禁止へ追加し、対象外の目的を無言変更しない。回復は最大8版。外部読取を含む計画全体の自動再実行はこの初版の対象外。

能力不適用と能力故障を区別する。不適用のときだけ宣言済みの次候補を使う。例外・入力改変・非有限な判定・結果型破損を回答成功へ変換しない。権限不足を迂回しない。

Python入口の `停止確認` は作用境界と最終検証で確認する。停止後は途中成果を採用しない。すでに実行した外部作用の取消や、処理中のブロッキング呼出しを強制中断する仕組みではない。

## 保存・外部作用・監査

保存は原資料、前回採用成果、最後の要求、確認待ち、履歴連鎖、能力契約、版をJSONで持つ。旧能力が要求するtupleは、検査した型位置情報でのみ復元する。コード・関数・権限は読み込まない。外部読取は復元時も呼出側が明示する。

保存上限8MB。CLIは同ディレクトリの一時ファイルをflush/fsyncした後、置換する。保存失敗を成功と報告しない。長大な会話記録で保存上限を超える場合の自動圧縮は未実装。整合印とhash連鎖は真正性の認証でも改変不能な保管でもない。

HTTPは127.0.0.1へ限定し、HostとOriginを検査する。利用者認証・インターネット公開・OS実行隔離の代替ではない。既存監査台帳へHDS作用履歴・計装を記録する。監査保存失敗時に既に完了した作用を未実行扱いにしない。

## 既存正本との境界

MINIDORA30、MINIDORA80、厳密言語模型核、科学解決器本体、HDS通常循環本体、GPQA正本は変更しない。この新入口はMINIDORA30の回答を先に作る経路や承認固定包絡を呼ばない。旧比較・性能経路の非退行契約は保存するが、その数値下限をこの新しい通常運用へ転記しない。旧製品の既定挙動を無言置換せず、HDS製品は `--HDS` 又は `minidora.HDS運用` から起動する。既存画面は現在の日本語通信鍵と旧鍵の両方を読み、HDS起動時に適切な利用例を表示する。

本版は全体運用の実行側をつなぐ初版であり、広域知識の形成供給、自由文の一般化、自由作文、一般的な立式・コード生成、経験形成の全体運用は未完了。HDS自動形成は、この適合器の純粋性を実証していないため既定で無効。GPT-4同等性能の完成や再学習を主張しない。
