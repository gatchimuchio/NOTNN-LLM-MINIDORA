# MINIDORA 能力状態差循環 v1

## 1. 位置づけ

本書は、MINIDORA v0.5能力模型核が、構成定義v8およびHDS Compiler Architecture v1.3 / Pipeline v1.4で構文化された「状態差」を、実際の後続作用選択へ接続する局所設計正本である。

基底・規定・内部意味正本は日本語とする。

本書は厳密言語模型成立条件を変更しない。厳密言語模型核と能力模型核は引き続き分離する。

## 2. 問題

旧能力模型核にはcheckpointと再照合経路が存在したが、再活性条件は主として「上位候補集合をまだ処理していないこと」であり、直前作用によって状態が実際に変化したことを必要条件としていなかった。

そのため、次を区別できなかった。

```text
状態を記録した
≠ 状態が変化した
≠ 状態差が次作用を成立可能にした
≠ 次作用を実行した
≠ 新しい状態差が生じた
```

## 3. 現行循環

現行能力模型核は次の順に処理する。

```text
現在状態
↓
一般関係作用
↓
形成済み関係作用
↓
一次能力作用
↓
候補状態の前後差を生成
↓
状態差なし ─────────→ 終了
↓ 状態差あり
差が生じた候補を起点に次作用集合を選ぶ
↓
再照合可能な作用を実行
↓
新しい寄与が生じたかを比較
↓
新状態差あり ───────→ 次の循環
↓ なし
終了
```

「候補集合が未訪問だから」ではなく、**直前作用によって候補状態が実際に変わったこと**を再作用の入口とする。

## 4. 能力状態差

能力状態差は少なくとも次を保持する。

- 差分ID
- 前段
- 後段
- 変化した候補ID
- 各候補の前得点 / 後得点

実装では得点だけでなく、寄与の意味同一性も状態署名へ含める。同点のまま証拠構造だけ変化した場合も状態差として観測できる。

## 5. 次作用選択

再作用候補は、直前の能力状態差で変化した候補を優先する。

1候補しか変化していない場合は、現状態で最も強い別候補を競合対象として一つ加える。

これは全候補を無条件に再実行することとは異なる。

同一の状態差、同一候補集合、同一作用集合の組を再び実行しない。これにより同一循環の無限反復を止める。

## 6. 同一証拠の別名再加点禁止

旧経路では、同じ参照証拠が

- `候補共同参照`
- `候補共同再照合:N`

のように段階名だけ変わることで別寄与として追加される余地があった。

現行では寄与名を意味的に正規化し、候補共同参照については少なくとも参照識別子集合を同一性へ含める。

```text
同じ証拠
+ 段階名だけ変更
→ 新規寄与ではない
```

再作用によって本当に新しい参照差が成立した場合だけ新規寄与とする。

## 7. HDS Compiler作用差分との接続

HDS Compiler固有型を能力模型核へ直接依存させない。

```text
HDS作用差分構造
↓ HDS能力作用構造射影
能力作用構造
↓
MINIDORA能力模型核
```

能力側の日本語内部型は次である。

- 能力作用記録
- 能力状態差記録
- 能力後続利用記録
- 能力作用構造

## 8. Compiler作用差分を能力証拠へ使う条件

参照Data中の作用差分を能力証拠へ使う場合、少なくとも次を満たす。

1. 質問や候補ではなく外部参照Data由来である。
2. 状態差が存在する。
3. 状態差の後状態が別作用の入力状態へ接続する。
4. `状態条件充足=True` である。
5. 後続作用の `追加条件` が空である。
6. 連結終端状態が一候補だけを識別する。

追加条件が残る場合、Compilerが確認していない条件を能力側が補完してはならない。

```text
状態条件が満たされた
≠ 追加条件も満たされた
≠ 後続作用が発火した
```

## 9. 専門作用起動数

`専門作用起動数` は数値を増やすための計数器ではない。

現行では、Compiler作用差分連結が上記条件を満たし、実際に候補寄与として消費された証拠件数だけを計上する。

単なるcheckpoint再活性、一般参照再照合、候補得点変更は専門作用起動数へ加算しない。

## 10. ベンチ統計

正式能力経路では、以下を0固定せず模型結果から取得する。

- checkpoint数
- checkpoint再活性数
- 大域再照合数
- 候補横断更新数
- 専門作用起動数

ただし非ゼロであること自体を成功条件としない。

- 状態差がなければ0が正しい。
- 状態差があっても次作用が成立しなければ0が正しい。
- 実作用が成立した場合だけ非ゼロになる。

## 11. 受入条件

最低限次を満たす。

1. 状態差がない人工入力ではcheckpoint再活性が0。
2. 一次作用が候補状態を変え、その差で次作用が開く人工入力では再活性が1以上。
3. 再作用によって新しい候補寄与が実際に生成される。
4. 同一参照証拠を段階名だけ変えて再加点しない。
5. `S0→S1→S2` のCompiler作用差分を能力系が消費できる。
6. 後続作用に未確認追加条件があれば発火させない。
7. 厳密言語模型核へ候補得点・作用差分を混入しない。
8. 旧能力模型核を必要とする互換呼出は明示注入で維持できる。
9. Linux / Windows × Python 3.11–3.14 CIを通す。
