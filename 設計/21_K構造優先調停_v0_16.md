# K構造優先調停 v0.16

## 1. 目的

v0.15でCompiler→Runtimeの責務別射影を確立した後、K内部の証拠選択を構造優先へ整える。

Data IR自体は問いを知らないため、Data Projectionで安全な情報を先に削らない。

優先制御は、問い・候補・証拠が同時に見えるK評価時に行う。

## 2. 現行構造上の問題

Kは同一sourceから、

- 個別Fact証拠
- 文書単位に再結合したdocument証拠

を作り、候補横断調停で同一sourceにつき最強の一経路へ潰している。

二重加点自体は防げているが、得点が高ければdocument bagが、問い・候補と有向関係で直接一致したFactより優先され得る。

これは情報量の多い表層再結合が、より精密な構造表現を上書きする倒錯である。

## 3. 正本方針

同一候補・同一sourceでは証拠の意味精度を次で優先する。

```text
直接完全一致
  > 問い/候補と有向関係一致した構造Fact
  > 通常Fact
  > document bag
```

有向関係一致が存在する時、そのsourceについてdocument bagの絶対得点が大きくても構造Factを採用する。

構造一致が無い時だけ、従来のfact/document比較へ縮退する。

## 4. なぜData Projectionで削らないか

一つの取得文書には複数の独立事実が存在し得る。

問いを知らない段階で、

```text
関係がある
→ その関係以外を捨てる
```

とすると、別の値・属性・事実を不当に失う。

従ってCompiler/K Data Projectionはv0.15の安全Fact保持を維持し、どのFactを候補評価に使うかだけを問い条件付きで選ぶ。

## 5. 実装境界

- v0.15 `HDSKData射影` は変更しない
- `k3_hds_native` が証拠Factと問い/候補の有向辺一致を判定する
- 有向一致したFactを `structural_fact` 経路として調停へ渡す
- `hds_candidate_reconcile` は同一sourceで `structural_fact` をdocument bagより優先する
- source dedupは維持する
- graph証拠の独立source補正は維持する
- 世界知識追加なし
- benchmark固有分岐なし

## 6. 受入条件

固定回帰で次を確認する。

1. 同一sourceに高得点document bagと低めの有向一致Factがある場合、有向一致Factを選ぶ。
2. 有向一致Factが無い場合、従来の高得点fact/document選択を維持する。
3. 別sourceは独立証拠として維持する。
4. 有向関係の向きが逆なら `structural_fact` に昇格しない。
5. CI全通過後にのみ外部benchmarkを受入確認する。
