# K関係修飾保持契約 v0.18

## 1. 目的

HDS Compilerは関係に対して、極性だけでなく様相・条件scope・量化等を保持できる。

例:

```text
Compound A may inhibit Enzyme X.
```

```text
関係 = 阻害
始点 = Compound A
終点 = Enzyme X
様相 = 可能
```

v0.17まではKがこれらを忠実に表現できないため、Data K射影で関係自体を落としていた。

これは誤肯定化を防ぐには正しいが、Compilerが取得した意味をK側で失う。

v0.18では、**関係修飾をHDS専用の証拠identityとしてKへ保存し、既存の無条件推論へは流さない**。

## 2. なぜ汎用Factを直接拡張しないか

既存K3能力核の `Fact` / `KnowledgeBase` は無条件事実を前提としており、`find()` / `infer()` 等が広く利用している。

汎用Factへ修飾を追加して既存canonical Kへそのまま投入すると、

- K3公開構造の互換性
- 既存rule inference
- contradiction処理
- 一般KnowledgeBase検索

へ不要な影響が広がる。

したがってv0.18では、HDS境界に

```text
HDS修飾Fact(Fact)
```

を置く。

修飾FactはKに付属するHDS証拠台帳へ保存するが、無条件canonical KnowledgeBaseへは投入しない。

## 3. HDS修飾Fact

意味identityは、

```text
predicate
args
polarity
qualifiers
provenance
```

から作る。

`qualifiers` は日本語正本の関係修飾をkey/valueで保持する。

例:

```python
(("様相", "可能"),)
```

```python
(("条件scope", "If condition X"),)
```

修飾の順序差でidentityが変わらないよう正規化・sortする。

## 4. 保持する関係修飾

v0.18でFact identityへ写す対象は次とする。

- `様相`
- `条件scope`
- `量化`
- `scope`
- `条件作用`

次は意味identityではなくCompiler/R/監査メタなので修飾Factのkeyには入れない。

- `検索述語`
- `scope結合`
- `様相表層`
- `英日意味射影`
- `受動態`

外部表層は完全HDS-IR側に残る。

## 5. canonical Kとの境界

### 5.1 無修飾関係

```text
A inhibits B
```

は従来通り、

```text
canonical KnowledgeBase
+
HDS証拠台帳
```

へ入る。

### 5.2 修飾関係

```text
A may inhibit B
```

は、

```text
HDS証拠台帳: 保存
canonical KnowledgeBase: 入れない
```

とする。

これにより、

```text
may inhibit
↓ 禁止
inhibit
```

という無条件化を防ぐ。

## 6. 極性との直交

v0.17の `polarity` とv0.18の `qualifiers` は直交する。

したがって、

```text
A may not inhibit B
```

は、

```text
polarity = False
qualifiers = (("様相", "可能"),)
```

として保持できる。

## 7. HDS証拠view

`HDS証拠事実` は、極性と修飾を独立に選択できる。

```python
HDS証拠事実(core)
# positive + 無修飾

HDS証拠事実(core, 極性=False)
# negative + 無修飾

HDS証拠事実(core, 修飾=(("様相", "可能"),))
# positive + 様相=可能

HDS証拠事実(core, 極性=None, 修飾=None)
# 全証拠
```

既存K候補比較・Graph・direct verifierは引数なしのviewを使うため、修飾Factは無条件支持へ混入しない。

## 8. Data射影

v0.18では `HDSKData射影` に限り、

- 明示否定
- 様相
- 条件scope
- 量化等

を保持する。

質問/候補のscopeはJの選択意味と接続するため、現段階では従来の強いK関係へ通さない。

## 9. 非変更

v0.18では次を行わない。

- modal Factを無条件Factとして推論に使用しない
- 条件付きFactを条件なしGraphへ流さない
- qualifier matchingによる回答採否を追加しない
- R queryを変更しない
- 検索予算を変更しない
- 世界知識を追加しない
- benchmark固有分岐を追加しない

**保存と利用を分ける。v0.18は保存契約まで。**

## 10. 不変条件

1. Compilerが得た様相・条件・量化をK境界で消さない。
2. 修飾Factを無条件canonical Kへ入れない。
3. 無条件Factと修飾Factを同一identityへ潰さない。
4. `may` と `must` を同一identityへ潰さない。
5. 条件Xと条件Yを同一identityへ潰さない。
6. 極性と修飾を独立に保持する。
7. 既定positive/unqualified evidence viewへ修飾Factを混ぜない。
8. 既存KnowledgeBase rule inferenceへ修飾Factを流さない。
9. 完全HDS-IRは保持する。
10. benchmarkを開発勾配にしない。

## 11. 次段

v0.19以降で初めて、質問/候補側のscopeとData修飾Factを照合する。

そこで必要なのは、

```text
問いscope
候補scope
Data qualifiers
```

の一致・含意規則であり、v0.18では先取りしない。
