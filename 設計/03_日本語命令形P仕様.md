# 日本語命令形P仕様

## 1. 目的

命令形Pは、MINIDORAの**計算実行器**が直接実行可能な日本語構文として、手続き的な計算作用を保持する。

PはLLM模型中核そのものではない。K3等のweight fileの代用品でもない。

```text
言語模型性     = 模型側関係が文脈から成立差を生じさせる責任
日本語命令形P = どう計算・操作するかを明示する運用命令
```

を分離する。

## 3. 命令の基本形

命令は次の形を正本とする。

```text
命令:
  名称:
  対象:
  条件:
  参照:
  作用:
  更新:
  境界:
  停止:
  根拠:
```

例:

```text
命令:
  名称: 条件付関係結合
  対象: 現在状態
  条件: 関係Aと関係Bが接続可能
  参照: 関係A, 関係B
  作用: 結合
  更新: 合成関係を状態へ追加
  境界: 矛盾があれば確定しない
  停止: 新規関係が生じない
  根拠: 参照元関係
```

## 4. PとDataを混同しない

```text
命令P:
  どう処理するか

Data R:
  何について処理するか
```

例:

```text
命令P = 比較して大きい側を選ぶ
Data R = A=10, B=7
```

`A=10`を命令Pへ埋め込まない。

## 5. Pと模型関係を混同しない

模型関係は、文脈付き言語状態から成立差を生じさせる再利用可能な関係である。

Pは、明示された状態・Dataへ作用する計算命令である。

```text
模型関係
→ 成立差

P
→ 計算実行器
→ 状態更新 / 計算結果
```

同じ処理で両方を実現できる場合があっても、意味責任を同一視しない。

## 6. 日本語を基底にする理由

目的は翻訳ではない。

- 同じ概念を短い表意記号で保持する
- 命令語と状態語の意味境界を短く固定する
- 検索・比較・照合・監査で扱う記号量を減らす
- 観測から実装まで同一概念語彙を維持する

英語等は外部互換境界に限定し、内部正本へ昇格させない。

## 7. 外部互換

Python、HTTP、JSON、既存API、公式config名等との接続には変換境界を置く。

```text
外部英字
↔ 互換変換
↔ 日本語正本命令
```

互換名から内部構造を決めない。

## 8. Pの一般化関門

命令Pは次を満たす必要がある。

1. 参照モデル固有名なしで表現できる
2. 別Dataでも実行できる
3. 外部Data差替えで同じ手続きが保持される
4. held-out入力で再利用できる
5. 摂動で境界が説明できる
6. 命令追加が既存命令の意味を壊さない

これらを満たしても、それだけでLLM模型性・大規模性が成立したとは扱わない。
