# 日本語命令形P仕様

## 1. 目的

命令形Pは、上流解析で抽出しLayer-0へ縮約したCapabilityを、Layer-0が直接実行可能な日本語構文として保持する。

PはK3のweight fileの代用品ではない。参照モデルが実現している能力構造を、実装非依存の明示命令へ外在化したものである。

## 3. 命令の基本形

命令は次の形を正本とする。

```text
命令:
  名称:
  対象:
  条件:
  参照:
  作用:
  更新:
  境界:
  停止:
  根拠:
```

例：

```text
命令:
  名称: 条件付関係結合
  対象: 現在状態
  条件: 関係Aと関係Bが接続可能
  参照: 関係A, 関係B
  作用: 結合
  更新: 合成関係を状態へ追加
  境界: 矛盾があれば確定しない
  停止: 新規関係が生じない
  根拠: 参照元関係
```

## 4. 命令とDataを混同しない

```text
命令P:
  どう処理するか

Data R:
  何について処理するか
```

例えば、

```text
命令P = 比較して大きい側を選ぶ
Data R = A=10, B=7
```

であり、`A=10`を命令Pへ埋め込まない。

## 5. 日本語を基底にする理由

目的は翻訳ではない。

- 同じ概念を短い表意記号で保持する
- 命令語と状態語の意味境界を短く固定する
- 検索・比較・照合・監査で扱う記号量を減らす
- 上流解析から実装まで同一概念語彙を維持する

英語は外部互換境界に限定し、内部正本へ昇格させない。

## 6. 外部互換

Python、HTTP、JSON、既存API、公式tensor/config名等との接続には変換表を置く。

```text
外部英字
↔ 互換変換
↔ 日本語正本命令
```

互換名から内部構造を決めない。

## 7. Pの一般化関門

命令Pは次を満たす必要がある。

1. 参照モデル固有名なしで表現できる
2. 別モデル由来Dataでも実行できる
3. 外部Data差替えで同じ能力が保持される
4. held-out入力で再利用できる
5. 摂動で境界が説明できる
6. 命令追加が既存命令の意味を壊さない
