# HDS-MINIDORA 全体運用 v1

基点: `4067f2ee32efb5d4f3f091095e1fa61412ea0792`。サンドボックスでの追加実装。
既存のMINIDORA30/80性能正本・HDS受入値を置換しない。GPT-4同等性能の認定ではない。

## 1. 開発対象

HDS実行主体が、通常の依頼を構文化し、意味目的から既存能力を組み合わせ、その中間成果と失敗を同じ状態へ帰還し、要求に対応する回答を採用する運用系を追加する。

旧製品の選択器、旧監督、旧合成実行器へ依頼全体を渡した後に、HDSで承認する方式ではない。既存の目的計画器・役割計画器は計画候補を構成する部品として利用する。合成器の構造検査を再利用するが、通常の新経路ではその合成実行を呼ばない。宣言済みの「多段解決」能力を明示的に利用した場合の、部品内部の局所探索まで禁止するものではない。

HDSそのものを本実装の有限な型・状態・作用列へ還元しない。

## 2. 実行主体と動的供給

既存HDSに `HDS作用供給器` を追加する。供給器は現在状態の複製から実行可能な作用候補を返す。返却型・重複ID・予約名前空間・生成件数・状態の直接変更を検査する。状態の変更、作用の選択・実行、停止とCOMMITは従来と同じHDS通常循環が行う。

新しい引数を指定しない呼出の挙動は維持する。供給器の型追加を既存の観測器・仮説・計画器の別主体化には使わない。

運用系では、依頼構文化→目的計画が成果として合成計画を形成し、各工程が動的なHDS作用として現れる。工程の入力状態、読取成果、能力版、外部権限を宣言し、その工程の成功によってだけ次の工程が利用可能になる。複数候補は実不成立を受けて次候補へ進む。最終出力に必要な全工程が成立するまでは、途中成果を利用者向けの最終回答へ採用しない。

## 3. 現行構文化器との責任接続

`HDS構文化器_v1.py` の現行公開構文化器を使う。全IRをHDS成果内に保持する。

既存の局所目的射影器は、構文化器が自動追加する `監査.構造`、座標未固定の観測マーカー、最終採否委譲などを利用者の未処理条件と同じ扱いにすると、単純な算術依頼も実行できない。`構文化接続.py` は、由来・ID・種別・内容・値状態の組が明示的な生成契約に一致するメタデータだけを、局所能力用の別ビューへ渡す際に分離する。

これは未観測の世界座標を確定する操作ではない。責任対応には「解消済み認定=False」を残す。構文化器が自ら最終採否を行わないという既知の委譲記録は、実際にHDSが採否する責任へ接続する。それ以外の意味損失、未解参照、否定、条件、意味関係は免除しない。追加座標を使う意味関係は局所接続を拒否する。未知の監査種別を一括して除去しない。

原IR・局所ビュー・責任対応を同じ解釈成果に保存する。この限定接続を、公開構文化器の全拡張座標を汎用的に実行へ降下できたという主張にしない。

## 4. 能力目録と合成

48個の能力を同じ目録に登録する。内訳は既存基礎29、会話7、数量集合1、命題2、文脈命題2、改善6、科学接続1である。科学接続は既存科学解決器群を呼ぶ一つの橋であり、48という数を科学解決器の総数と混同しない。

自然文から利用できる範囲は既存の局所文法と今回の接続範囲である。「48登録」を「48能力へ任意の自然文で自動到達」とは扱わない。数学・コード・文書等は自然文、型付き目的、明示役割目的、明示合成計画の入口を持ち、いずれも同じHDS循環で実行する。

追加能力は `登録能力`、必要なら `役割作用` を構築時に渡す。読込済みの信頼する実装だけを登録する。利用者文や提供資料からコードを評価して登録しない。能力版・外部読取区分・意味契約に変化があれば、既存計画や保存記録をそのまま利用しない。契約内の隠れた挙動変更を検出する認証機構ではないので、実装変更には版更新が必要である。

専門部品の成果は既存の専用表現のまま保持する。数式・命題・文書等の内部型を一つの平坦な文章へ潰さない。交換表現ではtuple/listの位置情報を保持し、復元後も専用結果の比較・検証を成立させる。

## 5. 失敗と再計画

既存の回復契約が対応する失敗について、実際の工程失敗から回復対象を特定する。自己又は名前付き直接入力役割の回復に限定する。同じ失敗入力を闇雲に反復しない。

回復では新しい計画世代を追加し、以前の計画・失敗成果を残す。利用者目的、資料、能力目録と回復対象外の役割被覆を保持し、対象部分だけを再構成する。入れ子資料の代替読取、取得不足後の焦点化した再取得を接続する。既定の回復上限は4回。任意失敗の自己修正・任意の新しい解法発明は含まない。

権限制約、契約違反、安全性が未定義の外部副作用は一般的な代替経路へ流さない。外部ネットワーク自体の取消や書込み補償は本実装範囲外である。

## 6. 共有状態・資料・知識・訂正

セッションが保持する提供資料には、種類、原文、データ、版、参照識別子を付ける。資料と知識は同じ原資料境界から能力へ供給できる。知識登録の成功を内容の事実認定へ読み替えない。

前回目的、確認中の目的、採用結果、資料への依存、未解釈、会話履歴を保持する。数値比較・集合等の単位確認、属性・年の訂正に対応する。目的の差替えは利用者の明示操作による。未対応の訂正を推測で埋めない。

資料更新で、その資料に依存する採用成果を現行利用から外す。依存は最終出力の祖先工程が読んだ原資料から収集し、能力が参照を返し忘れても消さない。関係しない資料の追加・変更で採用結果を無意味に失効しない。再表現は前回の目的・資料依存を保持する。

「再計算して」は現在資料から同じ目的を再構成する。「詳しく説明して」等は保存した実成果から表現を構成する。説明の変更のためだけに算術や外部取得を再実行しない。

旧長文脈庫の選択能力は登録するが、新セッションの全資料を旧庫へ自動同期する接続は未完了。今回の共有状態は有界な運用資料・成果の保持であり、巨大文書の意味的選択・無制限長文脈の完成ではない。

## 7. 再利用と形成

既存契約上の純粋な部品だけを、能力名・版・全実入力・目録を鍵に再利用する。外部取得・可変な長文脈選択・探索全体・追加能力は既定では再利用しない。後段が失敗した計画の純粋な中間成果は、同一入力で成立していれば再利用できるが、計画全体を成功としない。

完遂した作用列・契約・資料版を経験記録へ保存する。これは実行記録であり、一般化した能力の学習ではない。既存v3の自動経験形成は変更しないが、本運用入口の動的作用群には再実行の純粋性契約をまだ与えず `自動形成=False` とする。

事前知識の大量構文化、経験から新しい意味契約を自動形成・審査・登録する循環、新実行器の自動合成は、今回の実装範囲に含めない。

## 8. 採用・説明・保存

最終検証は原依頼、現行計画、目録、実出力、資料依存、再構成した回答を照合する。能力が返した主張の世界での真実性を、この整合確認だけで証明しない。科学・数学・命題・文書の既存専門検証契約と限界を継承する。

セッションへの資料変更・焦点更新はHDS採用後に反映する。取消・保留・失敗時はそのターンの更新候補を採用しない。取消と期限は作用間で確認する協調的な停止であり、実行中の任意関数を強制終了するOS隔離ではない。

保存は有限JSON、SHA256整合、参照・本文・版・回答の再照合を用いる。実行コード・秘密・キャッシュは保存しない。権限を保存物から昇格させず、呼出側の設定と一致させる。保存先は一時ファイルから置換する。SHA256は真正性の証明や改ざん不能化ではない。旧形式の無言移行は行わない。

既定上限は資料32個・2MB、単体資料10万文字、入力8192文字、履歴128発話、作用128回、結果2MB、保存16MB。これらは宣言した表現の上限であり、OSメモリ量の強制制限ではない。

## 9. 製品入口

```bash
python -m minidora.HDS運用
python -m minidora.製品版 --HDS
python -m minidora.製品版 --HDS --serve
```

新HDSサーバは127.0.0.1限定と同一生成元制限を使い、既存UI/APIと監査台帳へ接続する。認証付きのインターネット公開サーバではない。

既存の無指定製品、`--汎用`、GPQA、厳密言語模型核、科学部品本体は変更しない。`--HDS`と`--汎用`は併用しない。

## 10. 次の実装境界

通常運用を維持して、自然文の意味被覆、目的からの内容・アルゴリズム・立式の構成、言語生成、知識資産の形成と更新、長文脈の自動同期へ拡張する。検査項目数・能力登録数・単体試験成功をGPT-4水準の汎用性能へ読み替えない。
