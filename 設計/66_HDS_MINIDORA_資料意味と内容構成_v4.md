## 1. 目的と継承

一般依頼への能力拡張を始める。v1〜v3で成立した案件・知識資産・原記録・工程実行・数量・手順形成を再実装しない。HDSを唯一の実行主体とし、意味選択、内容構成、既存文章生成、照合を作用として供給する。数量・従来会話の解釈を先に残し、今回対応した資料文章依頼を追加する。

MINIDORA30/80系、厳密言語模型核、GPQA正本と既存能力のアルゴリズムは変更しない。内部の独自意味名・要求・計画・説明は日本語。今回追加した有限の文法・分類はHDS総体でも、対象の完全な意味構造でもない。

## 3. 要求と意味選択の契約

`一般要求を検査` は版、対象、主題、操作、形式、範囲、文字予算だけを受ける。未消費の操作節・追加条件・競合形式は捨てず保留する。引用された主題を勝手に分割しない。主題未指定の資料全体要約も扱う。対照には2資料以上と明示観点が必要。

例：

```text
資料「A」の保守について要点を整理して
保守について資料「A」をもとに要点をまとめて
資料「A」と「B」を保守と寿命の観点で比較し、確認事項を提案して
資料「A」を根拠付きで要約して
登録資料から保守について説明して
公開資料で保守について調べて、根拠付きで説明して
```

NFKCと大小文字正規化は検索候補の照合だけに使い、原文と原文位置を変更しない。明示別名は同一資料内だけで展開し、別資料の同一対象性へ転用しない。別名宣言や語の一致は記載された関係であり、世界事実の確定ではない。

選択単位は見出し節全体とする。文書の前文、選択節の親前文、明示的な条件・例外・時点等の検出節、使用した別名宣言を同伴させる。適用対象が違う可能性を残すため見出し経路と区間を表示する。未選択の節も原文・構造として保存する。主題が一つも対応しない資料集合は保留する。

引用・コード領域内の偽見出しで文章を切断しない。局所の引用・囲いが閉じない場合は保留する。未知の言い回しによる条件の全検出、Markdown仕様全体、曖昧な照応の全解決は保証しない。

## 4. 同じHDSによる工程

登録資料では次の4工程を既存HDSの工程依存として構成する。

```text
資料意味選択 → 資料内容構成 → 既存文章作成 → 資料文章照合
```

公開調査では既存 `知識取得` が先行し、`取得資料意味選択` に接続する5工程となる。資料名とシステム素材住所は分離し、同名で内部指示を上書きできない。

追加能力は5個。従来56個に対し計61個の登録となるが、個数を能力水準の証拠にしない。新しい制御主体や万能ルータは追加していない。未知一般工程の発明・動的再計画の完成ではない。

内容構成は要求操作と記載対応から既存の `文章仕様` を作る。原文は必須・保護断片として入れる。説明量の上限を満たすために条件を削って成功扱いしない。生成器が不成立を返した場合は照合器も成功にしない。

最終照合では原文から意味選択、内容仕様、文章生成を再構成して照合する。さらに運用の採用前に、現行要求、現行資料、対象集合と照合する。同じアルゴリズムでの再構成なので、独立した語義理解や現実対応の証明とは呼ばない。

## 5. 公開取得と権限

セッション設定と今回の依頼の外部読取許可が両方必要。取得済み本文、最終URL、取得要求、本文SHA256、参照ID、記録SHA256を対応検査する。全文を後段へ渡し、抜粋・検索スニペットだけでは回答しない。

保存された公開回答の再表現は保存時の資料に基づく表示変更であり、Web再取得や最新性の再確認ではない。この境界を回答本文にも示す。再調査の依頼は改めて取得工程を通す。時点ごとの十分性・資料間同一性・一般知識の真偽検証は別の未完了能力である。

ネットワーク境界は既存の公開HTTPS取得器に委ね、認証、メール、投稿、任意URL実行や任意コード実行を追加しない。

## 6. 原記録・失効・再表現・手順形成

元の要求と表示形式を別欄に保持する。再表現では既存の要求を別の要求へ無言変更しない。単一の再表現作用をHDSが起動するが、内部の原文照合と再生成は行うため「計算なし」ではない。

指定資料の回答は使用した資料の更新で失効する。登録全資料を対象にした回答は、**新しい資料の追加でも対象集合が変わるため失効**する。原記録にあるその成果も失効させる。無関係な資料追加で指定資料の回答を失効させる必要はない。

資料4工程は既存の純粋手順形成を使う。キャッシュなしの再実行が一致した手順だけを形成する。値の変更後は新原文で再計算し、回答値を暗記しない。現行計画照合は残るため、広い課題転用や高速化の完成とはしない。外部取得と再表現は形成対象外。

## 7. 保存形式v4と旧保存の明示移行

通常の復元はv4だけを受理する。`旧保存を移行` / CLI `--移行元` を明示した場合に限り、実際の旧実装が出力した標準目録のv1〜v3を変換する。独自追加能力のある未確認目録は拒否する。

旧版・目録・由来commitは `tests/資料/HDS旧保存/由来.json` に記録した。GitHub Actions run `35285161012` が各固定commitを起動し、人工資料の登録・更新・`2+3`・保存・同版復元を実行して採取した。現行コードで旧版らしいJSONを捏造したものではない。

移行では元のJSON文字列をそのまま履歴へ封入する。現行資料、残存旧資料、発話、経験、前回要求・結果・依存を保持する。v1にない原記録庫は残存資料から作り、失われた履歴や時刻は補完しない。

能力契約が変わるため、旧成果は失効させ、旧形成手順は原本の中に保持して実行対象から外す。再評価・再計算後の成果だけを現行で採用する。移行中に能力・旧コード・通信を実行しない。保存データから権限を獲得しない。CLIは未作成の別出力先を必須にし、旧ファイルを上書きしない。

SHA256と構造照合は内部整合性の検査であり、保存ファイルの署名認証や悪意のある作成者の真実性の証明ではない。
