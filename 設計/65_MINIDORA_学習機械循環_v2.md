# MINIDORA 学習機械循環 v2

## 目的

MINIDORAの学習を独立した「学習器」や結果後処理として実装せず、HDS通常循環そのものへ接続する。

本実装での学習対象期間は、明示初期化されるまでの同一 `HDS駆動コア` 寿命とする。同一実行内と実行間を別機能にはせず、同じ状態更新の時間幅として扱う。

外向き回答、正解ラベル、ベンチマーク採点結果は学習開始条件ではない。

## 通常循環

```text
入力・観測
→ 後続利用可能な記憶へ保持
→ 保持状態と現在入力から関係・仮説を導出
→ 導出を観測方法・計画・判断前提へ反映
→ 更新状態で次の内部作用を実行
→ …
→ 必要条件が閉じた場合だけ外向き回答
```

外向き回答の有無とは独立に、通常循環で成立した状態更新は同一Coreの後続処理へ継承する。

## 継続状態

同一Coreでは次を継続する。

- HDS記憶
- 形成関係
- 作用実測から得た適応記憶
- 実際に観測した参照記録

前問の `hds_query_*` / `hds_observation_*` は検索経路情報であり経験内容ではないため、継続参照記憶へ昇格する際に除去する。資料自身の意味条件は保持する。

選択問題では、過去の実観測参照を現在の問いで再検索し、関連するものだけを現在処理へ戻す。前問の回答ラベルや採点結果を参照記憶として保存しない。

新しい `HDS駆動コア` には継続状態を引き継がない。明示的な `継続状態を初期化()` でも破棄できる。

## 選択問題の処理順

候補関係の不足観測は模型評価結果から生成しない。

1. Compiler Kernelから現在の問い・候補関係を得る。
2. 現在保持している参照を構文化する。
3. 候補代入関係と保持参照を照合する。
4. 未観測・矛盾関係を導出する。
5. 必要な追加観測要求へ適応する。
6. 新しい観測を参照記憶へ保持する。
7. 更新された参照状態で模型評価する。
8. 閉包しなければ通常の残差帰還・追加観測を続ける。

したがって、`評価結果 → 学習経験形成 → 学習観測` という旧経路は使用しない。

## 反証と再開放

適応済み状態は最終固定しない。

- 同一定義・同一意味入力で失敗または反証が観測された場合、過去の成功期待をそのまま再利用しない。
- 資料更新・依存変更・反例で古い認識や形成関係を失効・再評価へ戻す。
- 新しい証拠で既存回答を変更する場合は、従来の非退行・証拠優越境界を維持する。

## 禁止

- gold、正解ラベル、採点結果の学習状態への取り込み
- ベンチマーク固有情報の実装
- 外部からのコード改修を機械内部の学習へ算入
- 保存量の増加だけを学習成立と扱うこと
- 結果後にだけ発火する独立Learnerをactive pathへ置くこと
- 同一Core境界を越える無言共有

## GPQA評価

GPQA 198問の連続評価では、1問ごとにCoreを作り直さず、同一 `HDS駆動コア` を198問で継続使用する。

各問について少なくとも次を記録する。

- 処理前継続状態署名
- 処理後継続状態署名
- 処理前継続参照件数
- 処理後継続参照件数
- 初回評価参照件数

正答率の上昇だけを学習成立の証明にはしない。学習成立の受入は、経験保持、導出、後続処理への反映、次経験への継承をコードと回帰試験で確認する。

## 受入

- 模型評価結果より前に、現在状態から候補関係の不足観測を導出できる。
- 実観測参照が同一Coreの次処理へ継承される。
- HDS記憶が次実行の処理前提として実際に利用される。
- 実行経験から形成された適応が同一Coreの次実行へ継承される。
- 別Coreへ継続状態が漏れない。
- 明示初期化で継続状態を破棄できる。
- 旧結果後学習モジュールをactive pathにもdefault treeにも残さない。
- 日本語基底、公開境界、全単体試験、再構築CIを通す。
