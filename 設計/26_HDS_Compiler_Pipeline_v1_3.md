# HDS Compiler Pipeline v1.3

## 1. 目的

公開HDS Compilerの意味・監査能力を維持したまま、意味表現と計算実行表現を分離する。

Meaning/Audit Architectureは `v1.2` を維持し、Pipelineを `v1.3` とする。

```text
Architecture v1.2 = 意味・監査機能
Pipeline v1.3     = 意味IR / 計算計画 / 計算降下の責任分離
```

## 2. 正本経路

```text
自然言語
  ↓
意味コンパイル
  ↓
意味HDS-IR
  ├─ R / K / J / 監査
  └─ 計算計画
       ↓
     計算降下
       ↓
     計算中間表現 v1
       ↓
     計算実行境界 v1
```

## 3. 意味正本

`公開HDSコンパイラ.意味コンパイル()` を意味正本入口とする。

意味HDS-IRは次を満たす。

- `手順 is None`
- `初期状態 == {}`
- 対象・関係・条件・状態・目的・残差・監査構造を保持する
- `参照必須` と用途種別は意味・運用メタとして保持してよい
- 計算Pを内包しない
- 閉包状態は `CLOSED_FOR_SEMANTIC_TRANSFER`

## 4. コンパイル束

`コンパイル束()` は次を別フィールドで保持する。

- `意味IR`
- `計算計画`

同じobjectへ混在させない。

## 5. 計算降下

`計算降下()` は形成済みコンパイル束だけを受け、自然言語を再解析しない。

```text
計算計画
↓
命令計算降下
↓
計算中間表現 v1
```

計算中間表現には意味HDS-IRの由来参照を残すが、HDS意味語彙そのものを計算実行境界へ解釈させない。

## 6. 互換境界

旧 `コンパイル()` は既存Runtimeとの互換窓口として残す。

ここだけで、意味IRへP・計算初期状態を最外周再付与できる。

この互換IRを意味正本として再利用してはならない。

## 7. 独立Data / 候補

検索取得Data、選択肢、独立文書は意味入口を優先する。

- 会話の現在焦点を無断注入しない
- 計算Pを混入しない
- K/Jへ意味構造だけを渡す

## 8. 非責任

Pipeline v1.3は以下を行わない。

- HDS本体理論の追加
- 意味解析能力そのもののv1.3化
- 計算実行境界による自然言語再解析
- Pと意味HDS-IRの再統合
- Legacy互換を正本化

## 9. 受入条件

最低限次を通す。

1. Architecture版 `v1.2` 維持。
2. Pipeline版 `v1.3`。
3. 意味IRへP・初期状態を内包しない。
4. コンパイル束で意味IRと計算計画を分離。
5. 計算降下で自然言語再解析なし。
6. 旧 `コンパイル()` の互換挙動を維持。
7. 独立DataコンパイルへPを混入しない。
8. 既存HDS/K3/Runtime回帰を壊さない。
9. Ubuntu / Windows × Python 3.11–3.14 CIを通す。
