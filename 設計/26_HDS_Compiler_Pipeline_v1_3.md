# HDS Compiler Pipeline v1.3 — 意味/計算責任分離

## 1. 状態

- Meaning / Audit Architecture: `v1.2` 維持
- Compiler Pipeline: **`v1.3`**
- 基底・規定言語: 日本語

v1.3はv1.2のFailure Signature、暗黙知、状態遷移、認知世界差分等を置き換えない。

変更対象は **意味形成と計算実行準備の責任境界** である。

## 2. 旧構造の問題

v1.2以前の基礎Compilerは、意味座標・関係・残差を作った後にLegacy自然言語計画器を呼び、同じHDS-IRへ次を直接格納していた。

```text
実行核
初期状態
参照必須
種別
手順P
```

このため、

```text
意味IR
+
運用メタ
+
計算P
```

が一つのRecordへ再結合されていた。

Compute IR / ABI導入後はこの構造を正本にできない。

## 3. v1.3正本構造

```text
自然言語
  ├──────────────┐
  ↓              ↓
意味フロントエンド   計算意図形成
  ↓              ↓
HDS意味IR           日本語命令形P
  └──────┬────────┘
         ↓
      コンパイル束
         ↓
   計算降下バックエンド
         ↓
     計算中間表現
         ↓
     計算実行境界
```

重要:

- HDS意味IRにPを格納しない。
- 計算降下は形成済みコンパイル束を受け、自然言語を再解析しない。
- Pと計算中間表現は別物である。
- 意味フロントエンドと計算意図形成は並列責任であり、一方を他方へ誤投影しない。

## 4. 正本API

### `意味コンパイル()`

意味正本入口。

返却HDS-IR:

- 座標: 保持
- 関係: 保持
- 残差: 保持
- 意味作用履歴: 保持
- 認知世界/監査情報: 保持
- `手順`: `None`
- `初期状態`: `{}`
- 閉包状態: `CLOSED_FOR_SEMANTIC_TRANSFER`

### `コンパイル束()`

```text
意味IR
+
計算計画P
```

を**別フィールド**で保持する。

これは意味IRにPを戻すことではない。

### `計算降下()`

既に形成済みのコンパイル束を計算中間表現へ降下する。

自然言語入力を受けない。

### `計算コンパイル()`

一括入口:

```text
入力
→ 意味コンパイル
→ 計算意図形成
→ 計算降下
```

返却:

- 意味IR
- 計算中間表現
- 計算初期状態
- 参照必須
- 種別

### `コンパイル()`

Legacy互換入口。

旧Runtimeが `HDSIR.手順` を必要とするため、**最外周だけ**でPを再付与する。

```text
意味IR
+
計算P
↓ compatibility bridge
Legacy HDSIR
```

この返却形を意味正本とはしない。

## 5. 基礎Compilerからの計算責任隔離

旧基礎Compilerは歴史的に `self._legacy.計画()` 呼出を含む。

v1.3では意味フロントエンド専用の基礎Compilerへ `HDS意味専用計画器` を注入する。

この計画器は空の無作用Pだけを返し、意味抽出中に実計算計画を生成しない。

実計算Pは公開v1.3層の `計算意図形成` で別に生成する。

したがって基礎意味抽出と計算計画形成の状態を共有しない。

## 6. 独立Data / 候補

`HDS独立コンパイル()` は、Compilerが `意味コンパイル()` を持つ場合はそちらを優先する。

結果:

```text
choice / Data
→ HDS意味IR
→ K / J / R
```

へPを混入しない。

旧外部Compilerは従来の `コンパイル()` へ自動フォールバックする。

## 7. 計算降下

計算降下バックエンドはPを `計算中間表現 v1` へ変換する。

```text
Pの "$入力0"
↓
状態値("入力0")
```

ABIは `$` を解釈しない。

計算IRへHDS認知世界ID・座標IDの一部を `由来参照` として残すが、その意味をABIへ解釈させない。

## 8. 互換境界

維持するもの:

- `HDSコンパイラProtocol.コンパイル()`
- 旧外部Compiler
- v0.3 Runtime
- `HDSIR.手順` フィールド自体
- 過去Replay/保存物

変更する意味:

```text
HDSIR.手順
= Legacy compatibility field
!= HDS意味IRの必須責任
```

フィールドの即時物理削除は行わない。過去Recordの読み込み互換を壊さないためである。

## 9. 非責任

Pipeline v1.3は以下を行わない。

- HDS本体の非公開導出規則の公開
- Failure Signature Architecture v1.2の意味変更
- LLM模型核への計算責任再混入
- Compute IRへの自然言語解析追加
- ABIへのHDS解釈追加
- 旧Replay資産の書換え

## 11. 受入条件

- `Architecture版 == v1.2` を維持する。
- `Pipeline版 == v1.3` を持つ。
- `意味コンパイル().手順 is None`。
- `意味コンパイル().初期状態 == {}`。
- 意味IRと互換IRで座標・関係・残差が一致する。
- `コンパイル束`で意味IRとPが別フィールドになる。
- 形成済み束の計算降下で自然言語Plannerを再実行しない。
- `計算コンパイル`結果を計算実行境界v1で実行できる。
- `コンパイル()` Legacy互換だけは従来どおり実行可能HDSIRを返す。
- 選択問題IR・詳細意味成果にPが混入しない。
- 独立Data/候補コンパイルで意味入口を優先する。
- Linux / Windows全CI行列を通過する。
