## 1. 目的と責任

第20バッチの命題構造・導出・採用を維持し、発言や信念の帰属、資料中の局所照応、資料側の解釈候補、場合分けの導出、取得全文からの検討を同じ汎用会話へ接続する。文書や利用者の記載を実世界の事実へ昇格させない。

今回の表現は対応構文の有限な射影であり、HDS全体や人の認知を固定形式へ還元するものではない。Core、公開HDS Compiler、科学Capability、GPQA正本、元の29能力本体、必須依存、既定製品モード、CIは変更しない。既存の命題追加層・汎用会話入口を拡張する。GitHubへの書込みは今回行わない。

## 2. 接続

```text
利用者要求 → 実公開HDSの原文・作用域・残差照合
    → 問い候補（複数なら確認）
    → 選択資料の文脈解析又は明示許可された本文取得
    → 資料候補を別々の解釈場合へ構成
    → 各場合の支持・反証を独立導出
    → 同じ判定なら読みは未確定のまま報告
      異なる判定なら確認又は条件付きの別報告
    → 役割計画・能力実行・回答意味IR・採用
    → 原成果からの根拠説明、問い訂正、資料更新による失効
```

利用者提供資料の解釈を事前検討しても、その段階では統合セッションの成果採用を進めない。既存の採用境界を通った回答だけを後続成果として保持する。

| ファイル | 責任 |
|---|---|
| `命題句.py` | 括弧・引用の対応を保つ区切りと原文位置。 |
| `命題構造.py` / `命題解釈.py` | 帰属の構造と局所構文。引用内外の変数・時点・否定を分離。 |
| `文脈命題.py` | 隣接主題への照応、直接引用の一人称、資料側候補、候補間依存、場合別判定。 |
| `命題推論.py` | 支持と反証の有限導出に、全場合を閉じる選言除去を追加。 |
| `文脈命題接続.py` | 文脈判定・取得全文の2能力と5作用、既存取得記録の照合。 |
| `導出談話.py` / `命題回答.py` | 実根拠グラフから記載・仮定・具体化・条件・場合統合の説明節を構成。 |
| `文脈命題回答.py` | 未確定の読み・選択条件・照応・取得由来を回答に保持。 |
| `命題会話解釈.py` / `汎用会話.py` | HDS照合、要求と資料の候補を区別、確認継続、製品入口への接続。 |

## 3. 帰属・引用の扱い

帰属命題は主体、種類、内容命題、任意の明示時点を持つ。種類は発言・過去発言・信念・過去信念・伝聞。推論器にとって帰属は独立した照合単位であり、内容だけを外へ取り出す規則は持たない。

| 入力 | 保持する意味 |
|---|---|
| `太郎は「P」と述べている` / `述べた` | 太郎の発言。Pの成立とは別。 |
| `太郎は「P」と考えている` / `信じている` | 太郎の信念。Pの成立とは別。 |
| `太郎は「P」と考えていた` / `信じていた` | 過去信念。現在信念に昇格しない。 |
| `資料甲によると「P」` | 伝聞元の帰属。直接引用話者とは扱わない。 |
| `太郎は「花子は『P』と述べた」と考えている` | 太郎の信念と花子の発言を入れ子で保持。 |
| `2025年では(太郎は「2024年では(P)」と述べた)` | 発言時点と内容時点を別々に保持。 |

引用中の句点・接続詞を、外側の文や規則の区切りにしない。直接引用の複数記載は引用内の連言へ構成する。外側の量化は引用の主体に適用できるが、引用内容の同字変数を捕捉しない。引用内で束縛されていない関数形の`x`は、従来の明示構文規約どおり定数であり、外側の変数とは別。

帰属は論理的に同値な内容を自動同一視しない。引用内部の論理閉包、信念の整合性、話者の誠実性、発言の真実性は認定しない。「述べた」という過去形を具体的な日時へ補完しない。

## 4. 局所照応と資料候補

`太郎は猫である。彼は鳥である。`では、直前記載の明示主題を「彼」の候補にする。対応指示語は彼・彼女・同者・それ。「彼女」から性別を推測しない。同じ直前記載に複数主題があれば全候補を保持する。任意述語の第一引数や引用内部の人物を、外側の談話主題と推定しない。別資料や任意の過去ターンまで探索しない。

直接引用内の`私は…`又は`わたしは…`は、その引用の明示話者へ束縛する。入れ子引用では最も近い明示話者へ切り替える。伝聞の情報源を一人称の話者とみなさない。話者自身が未解決の指示語なら停止する。複雑な修飾・括弧内・省略主語一般への照応は未実装。

原文・原文範囲・射影文・解消理由・束縛先・前提となった記載候補番号を保持する。例えば一つ前の照応が「太郎」か「花子」かで分かれた場合、次の照応もその選択に依存させ、互いに成立しない組合せを作らない。局所照応規約に基づく束縛であり、話者の実際の意図が保証されたとはしない。

接続・否定の資料内曖昧さも候補として保持する。既存の厳格API `命題資料を読む` の一意性要求は維持し、新しい会話経路で `文脈資料を読む` を使用する。

全ての保持した解釈を別の記載集合として検討する。異なる解釈の証拠を混合しない。判定が共通なら読みを一つ選ばずに共通判定を報告する。違う判定なら、提供資料では`資料解釈は2です`等で確認を継続する。その選択は「この読みの下で」の条件であり、原文の客観的な一意性ではない。

問い側の`解釈は2です`と資料側の選択は分離する。資料更新後の古い番号指定は拒否する。問い訂正後は資料解釈の選択も再開放する。結論に都合のよい読み、矛盾しない読み、もっともらしい読みだけを自動採用しない。

## 5. 選言の場合分けと説明

`PまたはQ`、`PならばR`、`QならばR`から、全ての場合でRを導出してRを報告できる。各場合の仮定は独立させ、他の枝・次の問い・持続知識へ漏らさない。矛盾した枝を除外して結論を作らない。P又はQのどちらが実際に成立したかは確定しない。

根拠グラフに選言、各場合の仮定、枝の導出、全場合を閉じる作用を残す。支持・反証は引き続き別々に計算する。一階論理全体の完全性、一般対偶、等号、一般因果、仮説形成や常識の自動補完は主張しない。

説明は実導出の依存順から節を作る。記載、仮定、具体化、条件適用、場合統合を区別し、原文位置・利用した根拠・採用条件を保持する。これは汎用の自由作文ではなく、導出内容からの説明生成である。未登録の作用は文章で補完しない。

## 6. 外部取得の接続

```text
公開資料から「太郎は哺乳類である」を検討して
```

問いの述語・定数から有限の検索目的を構成し、既存`知識取得`を使用する。セッション構築時と当該実行の両方の外部読取許可を必要とする。自然文中の「許可します」、取得資料内の命令、検索スニペットから権限を得ない。CLIでは`--汎用 --外部読取`による運用者の明示設定を使う。新しい送信APIや任意コード実行は追加しない。

取得記録と全文参照の対応、版、要求、件数、本文hash、参照ID、URL・取得経路、時差付き取得時刻、抜粋位置、必須語・根拠を照合し、全文を命題解析へ渡す。全文中の未知記載を抜粋外だからと無視しない。検索スニペットは資料として使わない。取得時刻を記事公開時刻へ読み替えない。再構成検査はネットワークを再実行せず、保存した取得事実を再検査する。

取得器は既存の停止条件（必要語と最低資料数の充足）を維持するため、検索結果全件を必ず読むものではない。複数の本文を採用したときは別資料として照合できるが、出典数や検索範囲の網羅性・独立性・最新性は保証しない。取得に失敗した場合、旧Coreや定型回答で埋めない。

取得資料の読みで結論が異なる場合は、各読みの条件と判定を併記する報告を採用する。今回、取得資料の候補番号を選択して再開する会話は実装しない。提供資料の確認待ちと、取得資料の条件付き報告を混同しない。

説明の再表示は保持した原成果を使い、再取得しない。問いの訂正で再取得が必要なら、新たな実行許可を必要とする。資料の真実性や署名真正性は自己整合hashでは証明しない。

## 7. 上限と未完成範囲

問い4096文字、要求8192文字、命題256節点・深さ24。資料は8件・全体256記載、各資料32000文字・128記載、記載自体は既存命題解析の4096文字上限。記載ごとの候補8、整合する解釈場合16まで。候補上限を超えた場合は一部だけを使わず停止する。

引用対応の深さ32、引用内照応の深さ8、直接引用内の記載8。推論は既存の操作数・根拠数・項数・仮定深さ上限に加え、選言分岐は8、資料候補全体の操作予算100000を持つ。個々の導出は最大50000操作。資料候補の事前検討と能力実行・整合再構成では同じ導出を再計算する。これは全会話の総計算量上限や結果キャッシュの実装ではない。

検索目的は最大8語、最大2検索・4本文取得・4資料。必要な語が検出できない問いは検索前に停止する。外部全文は対応構文を必要とするため、一般Web記事の自由文理解・任意調査QAを完成させた扱いにしない。

任意語義・省略・長距離照応、因果候補の評価、アブダクション、時刻順序からの因果推定、自由作文、一般数学・コード・翻訳の被覆拡張は次工程。今回の拡張をGPT-4同等性の認定に読み替えない。

## 8. 利用

```bash
python tools/文脈命題デモ.py
python tools/文脈命題デモ.py --json
python -m minidora.製品版 --汎用
```

デモは人工資料・人工検索・人工本文を使うが、実公開HDS、実取得器、既存計画・合成・採用・回答を通す。公開Webへ通信しない。実取得を運用者が許可する場合は`python -m minidora.製品版 --汎用 --外部読取`。今回の検証記録は人工供給を使ったものと区別する。
