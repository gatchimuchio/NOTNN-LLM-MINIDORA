# HDS Compiler Runtime射影契約 v0.15

## 1. 目的

HDS Compilerの責務は、自然言語から得た情報を一つの平坦な語集合としてミニドラへ渡すことではない。

Compilerは完全なHDS-IRを保持し、そのIRからRuntime各主体・境界が実際に消費する最小十分なProjectionを渡す。

```text
自然言語
  ↓
HDS Compiler
  ↓
完全HDS-IR
  ├─ R核: 検索表層 / 検索述語 / 既知端点 / 条件 / 候補
  ├─ K核: 主題語 / 関係種別 / 有向端点 / 候補意味 / Data事実
  ├─ J核: 選択意図 / 値状態 / 残差 / 境界
  └─ M核: 完全IR / 由来 / 履歴 / 再開放情報
```

完全IRを削るのではなく、用途別に読む範囲を限定する。

## 2. 構造から逆算したK入力

現行K3/HDS native評価は主に次を消費する。

- 問いの意味語
- 候補の意味語
- 候補固有語
- 関係種別
- 始点→終点の有向関係
- 独立出典
- Fact confidence / 値状態 / 残差阻害

したがってKへ検索語、選択制御、監査要求、目的メタを混入させる理由はない。

Kへ渡すのは以下だけとする。

```text
対象 / 実体 / 主題語 / 状態 / 属性 / 値 / 条件 / 文脈上の意味
Kが表現可能な関係種別
Kが表現可能な関係の意味端点
残差と値状態
```

次はK世界事実へ入れない。

```text
検索.*
制御.*
目的.*
監査.*
保持.*
暫定性.*
帰還.*
原文保持 / language surface
R query経路そのもの
```

## 3. 質問IRのK射影

### 3.1 未知スロット関係がある場合

例:

```text
Which molecule inhibits Enzyme X?
```

Compilerが既に

```text
未知始点 = molecule
関係 = 阻害
既知終点 = Enzyme X
```

を持つなら、Kへ必要なのは次だけである。

```text
関係種別 = 阻害
既知端点 = Enzyme X
未知位置 = 始点（端点は未観測のまま）
choice集合
```

重要なのは、未知なのは端点であって `阻害` という関係種別ではないことである。

従来は関係全体が `未観測` のためK側で関係種別まで落ちた。v0.15ではK質問射影上だけ関係種別を既知として扱う。

これは世界事実の確定ではなく、**問いが要求する作用素の確定**である。

### 3.2 関係質問でない場合

公開Compilerは、役割座標へ使われなかった意味語を `対象.主題語` として保持している。

一般質問ではKはこの `対象.主題語` だけを問いの照合核として使う。

```text
Which of the following statements best describes cellular respiration?
```

なら、Kに必要なのは例えば

```text
対象.主題語 = cellular
対象.主題語 = respiration
choice集合
```

である。

`検索.英語正規化` はR専用でありKへ逆流させない。専門語・固有名の表層が英語で残っていても、それは外部検索queryではなく「対象ラベル」であり、内部の役割・関係正本とは分離する。

## 4. R質問射影

Rは「問題を理解する主体」ではなく、Compilerが確定した検索要求を外部参照へ運ぶ境界である。

### 4.1 関係質問

Rへ渡すのは次だけとする。

```text
choice集合
検索述語付き関係
既知端点
未知端点の位置
検索条件 / 時間 / 範囲
```

例:

```text
Which molecule inhibits Enzyme X?
```

で候補Aなら、Rは完全質問文を再解釈せず、

```text
Compound A inhibit Enzyme X
```

を生成するための構造だけを見る。

R Projectionの `原文/正規化文` も検索核から再生成し、検索器のfallbackが完全質問文を裏口から読み直さないようにする。

`least likely` 等の `条件.検索極性` はJの選択制御であり、外部世界の検索条件ではないためR Projectionから除外する。

### 4.2 一般質問

関係スロットが作れない場合は、Compilerが既に生成した `検索.*` 座標を最優先する。

```text
Which of the following statements best describes cellular respiration?
```

なら、R射影は選択制御や監査要求を落とし、例えば

```text
検索.英語正規化 = cellular respiration
```

だけを検索焦点として残す。

`検索.*` が存在しない場合のみ、対象・実体・状態・属性・値・条件へ縮退する。

## 5. 候補IRのK射影

候補は他候補との差を識別するために使う。

したがって候補K射影は、

- 候補の意味対象
- 候補自身が明示する事実関係

だけを保持する。

検索語、目的、選択制御、監査情報は候補識別へ混ぜない。

baseline候補比較と直接関係検証は、どちらも同じ `HDSK候補射影` を使う。直接検証だけraw候補IRへ戻る経路を作らない。

## 6. Data IRのK射影

Rから取得したDataは世界証拠候補である。

Kへ投入してよいのは、

- 意味座標
- Kが表現可能な明示関係
- 値状態
- 残差
- provenance / source confidence

である。

### 6.1 未対応scopeを強いFactへ潰さない

Kがまだ否定・様相・条件scopeを関係演算として表現できない場合、次を禁止する。

```text
A does not inhibit B
        ↓ 禁止
A --阻害→ B
```

```text
A may inhibit B
        ↓ 禁止
A --阻害→ B
```

この場合、端点や述語の語情報はKへ残してよいが、有向関係Factは生成しない。

対象となるのは、

- `極性=否定` 等の明示scope
- modal/否定を吸収した偽端点
- `不確実性.明示`
- `前提.明示`
- `射程.明示`
- `動態.分岐`

など、Kが現在の関係形式で忠実に保持できない意味である。

### 6.2 query routeはK証拠ではない

検索queryや「どの候補queryで取得したか」は世界事実ではない。

従来の `HDS参照検索経路` 型の擬似IRをKへ低信頼Factとして加える経路はv0.15で使用しない。

query kind / query choice はprovenance・監査情報として保持してよいが、候補真偽の意味Factへ昇格させない。

Kが評価するのは、**取得された本文をCompilerした結果**である。

## 7. J/M/R/Kの非干渉

v0.15は元HDS-IRを変更しない。

- R検索器には `HDSR質問射影` を渡す
- K3 baseline候補比較には `HDSK質問射影` / `HDSK候補射影` を渡す
- 直接関係検証にも同じK質問・候補射影から候補代入仮説を作る
- KへのR取得Data投入前に `HDSKData射影` を通す
- Jは元質問IRと選択意図・残差・境界を見る
- Mは完全IRを保持する
- query routeはR provenanceへ残し、KのFactへ入れない

従って検索・比較の効率化によって、J/Mの監査情報を不可逆に失わない。

## 8. 不変条件

1. 完全HDS-IRを破壊しない。
2. Rへ選択制御・監査・保持・帰還メタを検索対象として渡さない。
3. `条件.検索極性` をRの世界検索条件へ混ぜない。
4. Kへ検索・制御・目的・監査メタを世界事実として渡さない。
5. 非関係質問のK焦点にR検索表層を流用しない。
6. 未知端点と既知関係種別を同一の未観測状態へ潰さない。
7. K Data射影で片端しか残らない関係を生成しない。
8. K未対応scopeを無条件の肯定関係へ縮退させない。
9. R query経路をKの意味証拠へ昇格させない。
10. baseline照合と直接検証で別の候補意味契約を使わない。
11. R/J/M/Kの責務を混線させない。
12. benchmark固有分岐を入れない。
13. 世界知識を追加しない。

## 9. 検証順序

採否は次の順とする。

1. Runtime消費構造との整合
2. 単体回帰
3. Windows / Ubuntu CI
4. 既存機能非退行
5. 最後に外部benchmarkを受入確認として一度だけ実行

benchmark値を局所探索の勾配として使用しない。
