# 英語検索焦点直結仕様 v0.13

## 1. 目的

v0.3の英日意味Compilerは、最終質問文から外部Rへ戻すための英語正規化語を既に生成している。

従来はこの座標を `検索.英語正規化` として保持していたが、R query生成器では専用の検索焦点として扱われず、一般の「その他」語群へ混入していた。

v0.13では、新しい意味推論を追加せず、既存の英語正規化表層を `目的.検索焦点` としてR queryの焦点群へ直結する。

```text
英語質問
  ↓
英日意味フレーム
  ↓
外部検索語
  ↓
lang-sem:search / 目的.検索焦点
  ↓
HDS参照queryの焦点群
  ↓
R
```

## 2. 変更しないもの

- 世界知識
- 共有言語基底Pの語彙
- K
- J
- 候補採否規則
- 関係質問の不足スロットquery
- benchmark固有分岐

## 3. 検索焦点の共存

`目的.検索焦点` は一意な単一座標ではない。

基礎Compilerが生成する検索焦点と、英日意味Projectionが生成する `lang-sem:search` は、それぞれ異なる情報経路を保持したまま共存できる。

```text
基礎Compiler焦点
        ┐
        ├─ 目的.検索焦点 ─→ R query順位付け
        │
lang-sem:search
        ┘
```

v0.13は既存焦点を上書き・削除・統合しない。
英日意味由来の検索焦点は `座標ID=lang-sem:search*`、`由来=共有言語基底P` で識別する。

複数焦点の内容が異なる場合も、どちらかを真の焦点として勝手に採用するのではなく、R query生成器へ複数候補として渡す。

## 4. 一般質問

例:

```text
Which of the following statements best describes cellular respiration?
```

英日意味側で制御語を除いた外部検索語が

```text
cellular respiration
```

なら、その表層を `lang-sem:search / 目的.検索焦点` として保持する。

R query生成器は `目的.*` を焦点群へ置くため、全文やCompiler内部語より前段で検索目的へ利用できる。

## 5. 関係質問

関係質問で既に

```text
未知始点 + 関係 + 既知終点
```

が成立する場合は、既存の不足スロットqueryを維持する。

例:

```text
Which molecule inhibits Enzyme X?
```

候補Aについては

```text
Compound A inhibit Enzyme X
```

のような関係方向付きqueryを優先する。

v0.13はこの経路を置換しない。

## 6. 不変条件

- 英日意味フレームが生成した外部検索語の内容を勝手に増やさない
- 既存検索焦点を削除・上書きしない
- 日本語正本の意味と外部英語検索表層を混同しない
- control語を世界知識として扱わない
- 関係質問の方向を変えない
- 候補内容を捏造・補完しない
- R検索のためにK/Jの責務を移さない

## 7. 受入条件

- `lang-sem:search` を機械取得できる
- `lang-sem:search` の種別が `目的.検索焦点` である
- 内容が英日意味フレームの外部検索語と一致する
- 基礎Compilerの既存検索焦点と共存できる
- 一般質問のprimary queryへ正規化検索焦点が入る
- 関係質問の不足スロットqueryが維持される
- 通常CIが全通過する
- 現mainのGPQA Diamond 198問に対して明確な退行を起こさない

## 8. 評価上の位置づけ

この変更は言語能力そのものを増やすものではない。

対象は、Compilerが既に得た意味・検索情報をR境界へ渡す際の**配線損失**である。

したがって採否は、追加知識量ではなく、

```text
意味保持
× 検索焦点純度
× 既存焦点共存
× 既存関係query非退行
```

で判断する。
