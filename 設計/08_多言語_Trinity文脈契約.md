# 多言語 / Trinity文脈契約 v0.4

## 1. 言語原則

MINIDORAの**基底・規定言語は日本語**とする。

設計、内部意味役割、状態、関係、制御語、監査語彙は日本語を正本とする。他言語は外部API・規格・Data・ベンチマーク・互換性・原文照合など、実務上やむを得ない境界でのみ使用する。

```text
外部表層入力
  ↓
必要時: HDS意味Projection / 多言語対応
  ↓
日本語規定の運用文脈
  ├─ MINIDORA模型核 → 成立差
  └─ 日本語命令形P → 計算実行器
  ↓
主体整合 / 採否
  ↓
必要な表層言語へ出力
```

HDS Compilerを通ること自体をLLM模型性の成立条件にしない。

## 2. 多言語境界

HDS-IRは既存運用上、

- `入力言語`
- `出力言語`
- `文脈引用`

等を保持できる。

外部表層が英語・中国語等でも、内部の役割・状態・関係名をその言語へ複製しない。検索や出典照合に必要な語句は原言語Dataとして保持する。

v0.4模型核では `言語状態.言語体系` を明示する。自然言語だけでなくプログラム言語等も対象にできるが、異なる体系を同一文脈へ無言混在させない。

## 3. Trinity文脈の位置

既存運用ではTrinityを次の責任へ分ける。

- J: HDS判断主体。必要な記憶を引用し、意味Projectionや採否に利用する。
- C: 運用計算主体。日本語命令形Pと計算実行器等を扱う。
- M: 記憶主体。焦点、直前結果、HDS-IR、未解残差、履歴をturn間で保持する。

```text
M_t --context--> J
J --compile / decision context--> HDS外周
HDS-IR / P --> C
C --operational result--> J
J --accepted update--> M_{t+1}
```

### 重要な分離

```text
C != LLM模型中核
Trinity != LLM成立条件
HDS-IR != LLM内部形式の普遍条件
```

MINIDORA v0.4のLLM模型中核は `src/minidora/模型.py` に独立して存在する。

## 4. HDS文脈

Compiler契約へ渡す `HDS文脈` は最低限次を持つ。

- 記憶版
- 現在焦点
- 直前結果
- 直前IR
- 未解残差
- 記憶引用アドレス

Compilerは必要な項目だけを引用し、使用した記憶アドレスをHDS-IRへ残せる。

## 5. 更新規則

- HDS-IRは実行成否にかかわらず現在turnの監査記録としてMへ保持できる。
- `合格` かつ値ありの場合だけ、直前結果と現在焦点を更新する。
- `保留` かつ残差ありの場合、未解残差を保持する。
- 未確定の指示語や参照先をRuntime側で捏造しない。
- 記憶更新はJの採否後に行い、CがMを直接確定更新しない。
- 模型核の成立差を主体状態やHDS状態へ自動同一視しない。

## 6. 後方互換

既存Compilerが `文脈` 引数を実装していない場合、Runtimeは従来の `前回結果` と `HDS履歴` を渡す互換経路を維持する。

外部互換のために英語識別子・プロトコル名を保持しても、MINIDORA内部の規定言語を英語へ戻したとは扱わない。

## 7. 受入条件

- 日本語入力で公開HDS Compilerの既存機能が成立する。
- 実務上必要な外部言語入力をHDS-IRへ射影できる。
- 内部役割名・状態名・関係名が日本語正本である。
- 結果を必要な表層言語へ表面化できる。
- 指示語がMの現在焦点をJ経由で引用できる。
- 文脈が存在しない指示語入力は残差または保留へ送る。
- 模型核がTrinity/HDSなしでも単体構築できる。
- 旧C/Layer0経路をLLM模型中核として再昇格させない。
