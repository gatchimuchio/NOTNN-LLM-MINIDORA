# MINIDORA 知識取得 v0.1

日付: 2026-09-10
基点commit: `a24cff7f81d30c2dfe42a1aed95664912534a298`
対象: 開発一覧④「汎用知識取得v2」の最初の実装と、⑮の静的本文取得。

## 1. 今回の作用

```text
上位が明示した検索語・必要語・資料数・予算
→ 既存検索供給器でURL候補を取得
→ 公開HTTPS本文を実取得
→ 本文の必要語照合・段落抜粋
→ 不足語があれば検索語を更新して再検索
→ 必要語と最低資料数を充足した取得結果
→ 既存Capability合成器 → 要約・抽出等の後続能力
```

検索スニペットを取得本文の代わりに使わない。取得本文中の語不足を検索結果の見出しや要約で補わない。能力実行のたびに取得し、以前のrunの本文を自動再利用しない。

**取得成立は、指定した必要語・資料数・取得契約の充足であり、回答の事実性や証拠十分性の認定ではない。** 知識量を増やす取得と、取得知識を適切に解釈・利用する能力を分ける。

## 2. ファイルと接続境界

| ファイル | 責任 |
|---|---|
| `公開本文取得.py` | URL・公開IP検査、通常の証明書検証を使うHTTPS取得、転送先再検査、サイズ制限、文字コード復号、静的HTML本文抽出。 |
| `知識取得.py` | 明示要求の検査、必要語不足による再検索、本文選別・段落抜粋、来歴と診断記録。 |
| `知識取得接続.py` | 既存`能力Module`・`能力文脈`・`能力結果`への接続。検索語等は`合成設定`Dataから受け取る。 |
| `tools/知識取得デモ.py` | 利用者の明示URL、または既存SearXNGからLIVE本文を取得するCLI。 |

Core、HDS Compiler、既存SearXNG供給器、従来の要約・抽出・変換、合成器、文脈セッション、科学Module、GPQA正本、標準チャット、GUI-Shellは変更しない。新しい依存パッケージや外部LLMは追加しない。

今回のModuleは合成器へ明示登録する。③の純粋な文書操作セッションへ外部読取を無言で追加しない。①の有限文法に「検索して」を追加して汎用要求理解と見なすこともしない。

## 3. 取得要求と再検索

`知識取得要求`は検索語と1〜16個の必要語を必須とする。

| 設定 | 既定値 |
|---|---|
| 最低資料数 | 1 |
| 最大検索回数 | 3 |
| 一回の最大候補数 | 5 |
| 最大本文取得数 | 8 |
| 最大採用資料数 | 4 |
| 最大抜粋文字数 | 12000 |
| 優先ホスト | 空。指定時は完全なホスト名で照合。 |

初回は明示検索語を使う。次回は`元検索語 + まだ本文抜粋で充足していない必要語`に変える。必要語が揃っても最低資料数が不足する場合は全必要語を追加する。既に試した同一検索語を反復しない。予算上限で不足が残れば保留し、架空の本文を補わない。

必要語はNFKC/casefold後の部分一致。概念同義性・含意・否定・因果を判定する意味理解器ではない。日本語の形態素解析や検索クエリの汎用的生成は未実装。上位が不適切な必要語を選んだ場合、その不足を本器だけでは補償できない。

優先ホストは上位が指定する取得順序であり、ドメイン名だけで一次資料・権威・正しさを自動判定しない。同順位は検索供給器の順序を維持する。

## 4. 本文取得の責任

公開HTTPS・443番ポートに限定する。認証情報付きURL、制御文字、非公開IP、非HTTPS、異常なホスト名を拒否する。

DNS結果の全アドレスを検査し、混在した非公開アドレスも拒否する。接続先は検査したIPへ固定し、TLSのSNI・証明書照合には元のホスト名を使う。環境プロキシやCookieを本文取得へ自動継承しない。HTTPへ降格しない。

301/302/303/307/308は最大3回、転送先ごとにURLと接続先を再検査する。任意の許可ホスト集合を指定した場合、転送先にも完全一致を要求する。転送循環を拒否する。

本文は既定500000バイトまで。Content-Length上限、実読取上限、受信長の不一致を検査する。本文の途中切断を成功扱いしない。タイムアウトは既定8秒。本文読取の経過時間も制限するが、OSのDNS解決待ちを強制中断する総時間上限ではない。

認める内容種別は`text/html`、`text/plain`、`text/markdown`。文字コードはUTF-8系、ASCII、Shift_JIS/CP932、EUC-JP、ISO-8859-1の明示範囲。復号不能なバイトを置換文字で隠さない。圧縮転送は未対応として拒否する。

HTMLはタグから静的テキストを抽出する。script/style/head/noscript/template/svg/canvas/tableを除外し、除外種別を記録する。題名は本文と分ける。CSSによる表示判定、JS描画、ログイン、PDF、図・表の構造理解は実装していない。表を平坦化して関係が保たれた本文であるかのように渡さない。HTMLのブラウザ表示と等価な本文取得を保証しない。

検索供給器は既存SearXNG実装を再利用する。管理者指定のローカル接続先は、任意の検索結果URLとは別の信頼境界である。既存検索供給器自体のHTTP実装や運用設定は今回変更・完全監査していない。

## 5. 抜粋・来歴・未充足

本文中で必要語に一致する段落をそのまま選ぶ。原文位置はHTMLバイト位置ではなく、**抽出後の本文に対するPython文字位置**である。NFKCは照合だけに用い、返却抜粋を無言で正規化しない。

段落が残りの抜粋予算を超える場合は途中で切らず、非採用とする。この選択は先頭からの限定方式であり、重要度最適化・関連文脈の十分性は未保証。

採用資料には要求URL、最終URL、転送経路、取得時刻、転送byte数、転送SHA256、抽出本文SHA256、抜粋の参照ID・開始・終了・一致語を保持する。取得時刻を記事公開時刻にしない。公開時刻は未確認のまま`None`とする。最新性・版・公開日を必要とする上位要求を本器だけで充足したと扱わない。

同一URL、同じ最終URL、同一本文hashの重複は資料数の水増しに使わない。ただし異なる本文が別資料として得られたことも、出典の独立性の証明ではない。異なる資料の相反する値を一つへ確定しない。⑤の証拠統合・矛盾処理へ渡す。

不足時は`成立=False`、最終本文は空。取得済みの部分資料と抜粋・不足語・試行は診断記録に残すが、合成器は後段を実行しない。記録と参照本文の合計は1000000バイトまで。超過は保留とし、完全記録を保持できたと主張しない。

記録SHA256は返却記録の内部整合用であり、署名、認証、改ざん不能性を提供しない。供給器差替えは信頼するPython実装のための境界であり、悪意あるコードの隔離ではない。

## 6. 許可と停止

取得器の直接呼出には`外部読取許可=True`が必要。Moduleには構築時の明示許可と`登録能力.外部読取=True`を設定し、合成器側でも外部読取を許可する。

直接取得器に渡した停止要求は検索・取得の前後で検査する。返却時に停止を観測した本文を採用しない。実行中のネットワーク処理を強制終了する機能はない。Module内部への合成器の停止コールバック伝播は未実装であり、合成器はModule呼出の前後で停止を検査する。

## 7. 利用例

SearXNG検索（JSON形式の有効化が必要）:

```bash
python tools/知識取得デモ.py --検索語 "Python JSON documentation" --必要語 JSON --外部読取許可
```

明示URLのLIVE本文取得（検索結果や保存済み本文ではない）:

```bash
python tools/知識取得デモ.py --検索語 "Python JSON documentation" --必要語 JSON --url "https://docs.python.org/3/library/json.html" --外部読取許可
```

`MINIDORA_SEARXNG_URL`または`--searxng`で管理する検索接続先を指定する。`--url`との同時指定は拒否する。

合成器では`知識取得Module(..., 外部読取許可=True).登録()`を登録し、工程の設定Dataへ`検索語`・`必要語`を渡す。後段の要約・抽出へ工程参照で接続する。具体例は`tests/test_知識取得_合成.py`。
