## 1. 起点

P0全数測定ではWorking Relation Store自体は形成されたが、実GPQAでは次だった。

```text
working_relations_created = 114,443
working_relations_reused = 0
checkpoint_reactivations = 0
global_reconciliations = 0
temporary_working_evidence = 0
blocked_evidence_facts = 0
```

従って、実データの主要欠落は「HDS投入時点で阻害された同一関係を二独立出典から救済すること」ではなかった。

候補診断では正解候補が候補得点1位になったのは44/198に留まり、候補識別そのものが主要不足候補となった。

## 2. 作用構文化との接続

K3 / OLMo / Qwen / DeepSeekで共通して見えたのは、全文を一段で処理して終えるのではなく、局所更新と広域再接続を別作用として持つこと。

MINIDORAではneural architectureをコピーせず、次へ射影する。

```text
外部参照全文
↓
全文HDS化（既存）
↓
初回候補共同状態
↓
問題語 + 候補差分語が同じ局所窓にある箇所を選択
↓
局所窓を同じ公開HDS Compilerで再構文化
↓
request-local cloneへ統合
↓
大域候補共同状態を再計算
↓
初回結果と再照合結果を保守的に比較
```

## 3. 局所Window選択

局所Window選択は真偽を決めない。

利用するのは、

- 問題の意味語
- 全候補を対称に比較して得た候補差分意味語
- 原資料内で両方が同じsentence / adjacent-sentence windowに存在するか
- source confidence

だけ。

gold label、benchmark domain、正解パターンは利用しない。

### 3.1 候補対称性

候補ごとの識別語は、

```text
candidate terms - union(other candidate terms)
```

を基本にする。差分が空なら候補自身の意味語へ戻す。

### 3.2 source identity

局所windowは新しい独立sourceではない。

局所再構文化したHDS-IRを投入するときも、元 `参照記録` の provider / origin / identifier / query provenance をそのまま使用する。

同じ論文を複数windowへ分けても独立出典数を水増ししない。

### 3.3 全文と同一windowを除外

原資料全文と同一のwindowは再解析しない。

## 4. request-local境界

局所windowから得た関係はpersistent canonical Kへ追加しない。

```text
persistent base core
↓ clone
全文Dataをrequest-local workingへ投入
↓ clone
局所window再解析を追加
↓
二巡目候補判断
↓
request終了で破棄
```

P1は同一request内の再解析作用であり、長期学習ではない。

## 5. 再照合結果採用

P0の保守規則を維持する。

- 初回direct relation verifiedを局所再解析で上書きしない。
- 二巡目SUSPENDで初回APPROVEを消さない。
- 初回SUSPEND→二巡目APPROVEは採用可能。
- 回答変更は二巡目の独立出典・識別一致出典・margin・根拠数・得点が明確に強い場合だけ採用する。

## 6. 新規内部指標

- `local_windows`
- `local_windows_compiled`
- `local_windows_compile_failed`
- `local_window_facts_added`
- `local_reconciliations`

P0指標も併記する。

## 7. Controlled A/B

外部Rは時点により取得資料が変動するため、異なるrunのスコア差だけでは改善を帰属しない。

標準GPQA runでは同じ問題について一度だけR取得し、その同一 `参照記録` を、

```text
baseline: 作業再作用=False, 局所再照合=False
current : 作業再作用=True,  局所再照合=True
```

の双方へ渡す。

記録項目:

- baseline score
- current score
- correct delta
- answer-rate delta
- answered-accuracy delta
- changed answers
- improved cases
- regressed cases

これを性能変更の第一根拠とする。

## 8. 不変条件

1. gold labelを推論前に使用しない。
2. 局所window共起だけで事実を確定しない。
3. 局所windowは同じHDS Compilerで再解析する。
4. persistent canonical Kを変更しない。
5. source identityをwindow数で増やさない。
6. negative / conditional / modal scopeを無条件肯定へ変換しない。
7. 模型核へHDS依存を逆流させない。
8. 3:1 schedule / KDA / attention等を必須化しない。

## 9. 受入条件

1. 局所window選択が問い・候補差分の両方を要求する。
2. 全文一括で失った一般有向関係を局所再解析fixtureで回収できる。
3. P0全試験を維持する。
4. 既存全単体試験を維持する。
5. Linux / Windows × Python 3.11–3.14をPASSする。
6. controlled A/B GPQA Diamond 198問を完走する。
7. persistent canonical Kへの作業関係自動昇格は0を維持する。

## 10. P1後も候補識別が偶然水準なら

次は局所window数を増やすのではなく、HDS Compilerの一般関係抽出域を再監査する。

現行は高信頼な有限一般関係族を中心にしているため、科学文の一般述語関係がHDS有向関係にならずbag-of-termsへ落ちている可能性がある。

その場合はdomain knowledgeではなく、一般的なSVO / copular / passive / scopeを保つ**開放述語関係層**を追加候補とする。
