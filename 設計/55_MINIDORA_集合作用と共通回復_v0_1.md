## 1. 機構と責任

```text
日本語の入力
→ 引用を壊さない句分割
→ 対象群・属性・操作・単位・時点・選別・表示要求
→ 実公開HDSの原文・座標・関係・残差との照合
→ 名前付き対象役割の数量集合目的
→ 既存役割計画器
→ 資料からの数量取得、又は許可された主題別の外部取得
→ 元資料に再接続できる数量群
→ 選別・比較・集約
→ 回答意味IR（記載命題・演算の依存・条件・留保・由来）
→ 文章・表・算術手順
→ 既存統合セッションの採用
→ 確認返答・訂正・再表現・資料更新による失効
```

処理失敗は、作用契約の回復規則へ戻る。監督器にはJSONや検索の特定作用名を置かない。契約の追加は開発時に限り、利用者の本文・取得資料から回復権限を登録しない。

## 2. 回復契約

`役割作用.回復` は `回復規則` の列で、失敗種別ごとに一つの規則だけを認める。

- `対象=自己`: 発生した下位目的と当該作用の組を禁止して、その下位目的の別経路を探索する。
- `対象=入力役割`: 指定した名前の直接入力工程だけを対象にし、許可した作用IDである場合だけ再開放する。任意の祖先や兄弟へは広げない。

失敗は情報不足、入力不足、意味未確定、前提矛盾、能力非対応、検証失敗、入力不正、実行環境、停止、権限不足へ整理する。未知は未分類のまま残す。分類を付けただけでは回復しない。

入力不足、意味未確定、前提矛盾、入力不正、停止、権限不足は、この初版では自動回復契約を許可しない。利用者の明示修正等を受けて新たに処理することとは別である。特に、矛盾した証拠を都合のよい再取得で消さない。

既存の直下数量選択には構造未到達時の自己回復、取得成立採用には取得不足時の報告入力役割の回復を宣言する。別名の能力でも同じ監督器を使えるが、元の29能力すべてに回復経路を追加したわけではない。

監督器は呼出時の目的と資料を複製し、全試行で同じ指紋を確認する。起点、登録能力、作用契約の変更があれば中止する。発生目的・作用・入力・失敗種別の同一反復を止める。経路が尽きた際も、直前の実行失敗と計画保留の記録を残す。試行上限は既定12、設定上限16。

**計画の再開放範囲と、実行の再利用範囲は異なる。** 禁止する経路は該当下位目的だけだが、既存統合器へは修復した全計画を再投入する。純粋処理は既存の再利用機構が利用し得る。外部取得を巻き戻したことにはせず、再試行で同じ主題のGETが再度実行される場合がある。このバッチは外部取得のexactly-onceや再開可能な外部トランザクションを実装しない。

## 3. 数量集合の意味契約

1〜8対象を順序付きの別役割として渡す。同一資料の明示した二〜八時点も別役割にでき、原資料の読取等の同じ下位目的は共有する。

対応操作は一覧、比較、合計、平均、最大、最小、件数。同じ属性・単位次元・条件の数量のみを処理し、異時点は明示した時点差要求が必要。数量は既存の原文対応付き記録から再構成する。JSON数値文字列、真偽値、曖昧な行、未解釈注記を無言で数値化しない。

選別は指定属性の単一閾値に対する以上・以下・未満・超・一致・不一致。閾値も対応単位で換算する。別属性を条件にする意味結合、論理和、一般的な集合演算は未対応であり、未解釈のまま実行しない。対象資料の名前による除外は、元の対象群に存在するものだけを除外し、除外条件を回答に残す。

比較の同値は同順位とし、最大・最小の同値対象をすべて残す。合計・平均は `Fraction` で計算し、循環小数は `230/3` のような分数表記を保持する。値がなくなった集合の件数・一覧は返せるが、平均等を0で捏造しない。比較対象が二つ未満になった場合も保留する。

集約は指定記載値に対する算術であり、データの独立性、対象の重複がないこと、事業上の加算可能性、母集団の代表性を認定しない。同じ資料の同じ位置を二重に数える要求は拒否するが、異なる資料の記載対象が現実にも別物であるとは推定しない。

## 4. 解釈と会話の拡張

対応する句を独立させ、語順を変えても同じ役割へ構成する。例:

```text
この3つの売上の合計と平均を円で教えて。表で
円で、全資料の売上を比較して
資料「表」の2024年と2025年と2026年の売上の平均は？表で
この3つの売上の合計を円で教えて。値が70円以上だけ
この3つの売上の合計を円で教えて。資料「B」を除いて
全資料の売上の平均は？2025年だけ。条件「国内」で。単位は円です
```

資料の名前、数量条件、年、条件の宣言を目的と分離する。引用中の疑問符・句点等は句の区切りとして扱わない。未解釈の付加要求、競合する条件、対応していない否定・因果要求は、既知の前半だけ実行せず保留する。

確認返答と訂正は同じ目的に戻る。集合要求でも単位、属性、共通年を変更できる。明示した複数時点の要求に共通年を付け替える訂正は、複数時点から共通年の要求へ変更する。外部主題の年訂正は今回未対応として拒否する。一般的な言い換え・省略解決・談話理解の完成ではない。

## 5. 回答と由来

数量ごとの記載命題に原結果番号、原資料位置、原文範囲を対応づける。集約命題には採用した数量命題の依存を付ける。回答IRでは記載一覧、選別条件、比較・演算、限界、由来を分離する。

文章表示と表表示は同じ原結果を再構成する。「計算過程も説明して」は算術式と実行済みの操作を生成し、隠れた思考や存在しない因果説明を作らない。選別で外れた数値と、明示除外した資料名も表示に残す。

今回発見した既存不具合も修正する。第18バッチの回答・二資料比較の整合検査は、外側の参照や根拠を削っても本文と内部Dataの一致だけで通る場合があった。再構成した必須参照の包含・内容一致、根拠、保留理由、外側の型を検査する。合成器が追加する参照は許容し、由来そのものの欠落は許容しない。

これは記録の自己整合検査であり、秘密鍵による認証や悪意ある全記録再生成への耐性、外部資料の真実性の証明ではない。

## 6. 複数主題の外部取得

```text
主題「機器A」と主題「機器B」と主題「機器C」の電圧をVで調べて比較して
主題「機器A」と主題「機器B」の電圧の平均をVで調べて。表で
```

主題・属性・単位を各取得数量目的へ分け、既存の検索・本文取得・数量の記載採用を再利用する。資料名を外部検索主題へ勝手に読み替えない。

セッション側と要求側の二重許可を必要とし、外部禁止を優先する。数量の対応単位がない場合は取得前に確認待ちにする。取得後の説明は採用済み原成果へ戻り、再取得せず再表現する。主題群の時点・条件・除外指定は今回未対応。

実装確認では実取得器へ人工検索供給器・人工本文供給器を渡す。実際の検索目的生成、本文利用、失敗帰還、採用は実コードだが、公開サイトのLIVE品質評価ではない。

## 7. 起動

```bash
python tools/集合会話デモ.py
python tools/集合会話デモ.py --json
python -m minidora.製品版 --汎用
python -m minidora.製品版 --汎用 --serve
```

製品の標準入口・既存HTTPへ接続しており、デモ専用の疑似処理器は使用しない。旧モードは既定のまま。汎用モードの未解決要求をCoreへ透過して埋めない。HTTPのローカル・同一生成元境界を変更しない。

## 8. 残る実装

上記は有限な数量・表・取得記載領域の拡張である。任意自由文理解、一般命題の照合、因果・類推・論証、自由作文、未知アルゴリズム生成、任意サイトの探索、無制限N資料、複雑なJOINや集約、永続的な会話改訂グラフは未完成。

次は、数量に閉じない命題と根拠の型、文中の否定・条件・量化の作用域、複数解釈の保持と解消を、今回の共通計画・回復・回答境界へ接続する。名前だけの「一般推論」Moduleを追加して能力が成立した扱いにはしない。
