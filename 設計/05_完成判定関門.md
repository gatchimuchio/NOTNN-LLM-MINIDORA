# 完成判定関門

## 1. 基本原則

APIが動く、CIが通る、toy taskが解ける、監査ログが出る、という事実だけではLLM完成と判定しない。

完成判定は能力・方法論・縮約・Data・実装・評価を分離する。

## 2. HDS関門

- 観測台帳がある
- 原理質問がある
- 複数Model / Mechanismがある
- 反対Modelがある
- 摂動又は反実仮想がある
- 水平引き算がある
- 暫定原理がある
- Whole-Field Returnがある

一つでも欠ければHDS解析完了としない。

## 3. Layer-0関門

- K3固有語がLayer-0責任から除去されている
- 実装非依存責任だけで説明できる
- P差替え可能
- R差替え可能
- 状態依存参照・変換・合成・停止が成立

## 4. 命令形P関門

- 日本語正本
- Capabilityを実行可能構文として保持
- Dataを命令へ混入しない
- held-out入力で再利用可能
- 摂動結果を説明可能
- K3固有エミュレータになっていない

## 5. 外部参照R関門

- 検索API又は固定Corpus等で標準Data Layerが成立
- 取得Dataが内部計算へ戻る
- 文書丸写しを回答としない
- 複数Dataの矛盾保持
- 出典追跡
- Provider差替え

## 6. 能力評価関門

最低限、同一harnessで次を分けて測る。

```text
推論能力
知識能力
命令追従
長文脈
コード
agentic長期実行
未知時停止
矛盾時停止
```

K3等と比較する際は、prompt・dataset・judge・tool条件を固定する。

## 7. 効率評価関門

- p50 / p95 latency
- CPU / RAM
- GPU要否
- 外部参照費用
- 1問当たりI/O量
- 内部命令数
- 日本語命令と英語互換表現の記号量比較

## 8. 禁止される昇格

```text
局所task PASS
≠ 汎用LLM完成

構造解析
≠ HDS原理抽出

K3部品の命令化
≠ Layer-0縮約

weight file解析
≠ Capability命令化

製品外殻完成
≠ LLM能力完成

Reference OFF失敗
≠ MINIDORA標準能力失敗
```

## 9. 状態語

各関門は次だけを使う。

- 合格: 定義された証拠が揃った
- 保留: 未試験、未解、証拠不足、競合
- 失敗: 明示条件に違反
- 非適用: 宣言範囲外

## 10. 最終完成

以下がすべて合格するまで「完成」と呼ばない。

1. HDS解析
2. Layer-0縮約
3. 日本語命令形P
4. 標準外部参照R
5. Runtime閉路
6. held-out一般化
7. 同一harness比較
8. 効率評価
9. 監査・再現性
10. 未成立主張の隔離
