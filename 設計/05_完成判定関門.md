# 完成判定関門

## 1. この文書が扱う完成

MINIDORAには少なくとも次の二つの完成状態を区別する。

| 状態 | 意味 | 現在 |
|---|---|---|
| `PROTOTYPE COMPLETE` | 正規アーキテクチャ経路が閉じ、外部未知問題で測定可能な非ゼロ能力を発生させた | **成立 — 2026-08-22** |
| 製品・最終完成 | 能力・一般化・効率・監査等を含む本書の全関門を満たす | 本書だけからは宣言しない |

2026-08-22のプロトタイプ完成正本は `../評価/PROTOTYPE_COMPLETION_2026-08-22.md` とする。

したがって、本書で以下「完成」と記す箇所は、特記しない限り**製品・最終完成側の関門**を意味する。プロトタイプ完成記録を否定・上書きするものではない。

## 2. 基本原則

APIが動く、CIが通る、toy taskが解ける、監査ログが出る、という事実だけでは製品・最終完成と判定しない。

完成判定は能力・Data・実装・評価を分離する。

## 3. Layer-0 v4関門

論理上位正本は [gatchimuchio/LLM-Layer-0-Functional-Compliance-Specification](https://github.com/gatchimuchio/LLM-Layer-0-Functional-Compliance-Specification) `v4.0-provisional`。
MINIDORA局所写像は [`02_Layer0責任契約.md`](02_Layer0責任契約.md) を参照する。

必須責任:

1. 言語アドレス化
2. 文脈束縛状態
3. 変換・合成中核
4. 文脈依存結果形成
5. 結果表面

責任数と実装機構数を同一視しない。

必須negative control:

- context除去/固定
- transformation bypass/canned response
- source material破損
- result surface遮断
- unknown input fallback
- contradictory context resolution
- exact retrieval と composition の区別
- merged-role implementation の許容確認

## 4. 命令形P関門

- 日本語正本
- Capabilityを実行可能構文として保持
- Dataを命令へ混入しない
- held-out入力で再利用可能
- 摂動結果を説明可能
- 特定モデル専用エミュレータになっていない

## 5. 外部参照R関門

- 検索API又は固定Corpus等で標準Data Layerが成立
- 取得Dataが内部計算へ戻る
- 文書丸写しを回答としない
- 複数Dataの矛盾保持
- 出典追跡
- Provider差替え

## 6. 主体主幹関門

Llama 3由来の自己一貫性をK3基盤へ内包するため、次を独立評価する。

- turn間で同じ主体状態を必須参照する
- 理由なし主体反転を保留する
- 理由付き自己訂正を許可する
- 旧版/新版/差分/理由/根拠を監査できる
- Layer-0/P/専門処理が主体状態を直接書き換えられない
- 主体整合に失敗した候補を結果表面へ昇格させない

この関門はLayer-0の第6責任ではなく、MINIDORA製品・能力要件である。

## 7. 能力評価関門

最低限、同一harnessで次を分けて測る。

```text
推論能力
知識能力
命令追従
長文脈
コード
agentic長期実行
未知時停止
矛盾時停止
主体的一貫性
理由付き自己訂正
```

他モデルと比較する際は、prompt・dataset・judge・tool条件を固定する。

K3を主基盤、Llama 3を自己一貫性の対抗基準、その他LLMを差分観測点として扱う。

## 8. 効率評価関門

- p50 / p95 latency
- CPU / RAM
- GPU要否
- 外部参照費用
- 1問当たりI/O量
- 内部命令数
- 主体状態読取/更新コスト
- 日本語命令と英語互換表現の記号量比較

## 9. 禁止される昇格

```text
局所task PASS
≠ 汎用LLM完成

特定モデル部品の命令化
≠ Layer-0縮約

weight file解析
≠ Capability命令化

主体主幹の単体PASS
≠ Llama 3と同等の自己一貫性

PROTOTYPE COMPLETE
≠ 製品・最終完成

製品外殻完成
≠ LLM能力完成

Reference OFF失敗
≠ MINIDORA標準能力失敗
```

## 10. 状態語

各関門は次だけを使う。

- 合格: 定義された証拠が揃った
- 保留: 未試験、未解、証拠不足、競合
- 失敗: 明示条件に違反
- 非適用: 宣言範囲外

## 11. 製品・最終完成

以下がすべて合格するまで、`PROTOTYPE COMPLETE` を越えた**製品・最終完成**とは呼ばない。

1. Layer-0 v4機能適合
2. 日本語命令形P
3. 標準外部参照R
4. Runtime閉路
5. 主体主幹
6. held-out一般化
7. 同一harness比較
8. 効率評価
9. 監査・再現性
10. 未成立主張の隔離
