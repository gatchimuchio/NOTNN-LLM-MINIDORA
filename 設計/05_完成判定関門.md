# 完成判定関門

## 1. この文書が扱う完成

MINIDORAには少なくとも次を区別する。

| 状態 | 意味 | 現在 |
|---|---|---|
| `PROTOTYPE COMPLETE` | v0.3系正規経路が閉じ、外部未知問題で非ゼロ能力を実測 | **成立 — 2026-08-22 / 履歴固定** |
| v0.4模型核成立 | 上流LLM成立規定へ整合した模型核・計算実行器分離が機械試験で閉じる | 現行開発関門 |
| 製品・最終完成 | 能力・大規模性・一般化・効率・監査・運用を含む全関門を満たす | 本書だけから宣言しない |

v0.3プロトタイプ完成正本は `../評価/PROTOTYPE_COMPLETION_2026-08-22.md` とする。v0.4再構成によって履歴値を上書きしない。

## 2. 基本原則

APIが動く、CIが通る、toy taskが解ける、監査ログが出る、という事実だけでは製品・最終完成と判定しない。

能力・模型性・大規模性・Data・実行系・評価を分離する。

## 3. 大規模言語模型成立関門

論理上位正本:
[gatchimuchio/LLM-Constitutive-Specification](https://github.com/gatchimuchio/LLM-Constitutive-Specification)

- 版: `2026-08-26-成立規定-2`
- MINIDORA参照commit: `e94a13ba32208aabd9dc88b6de320872963725be`
- 局所写像: [`02_大規模言語模型成立契約.md`](02_大規模言語模型成立契約.md)

### 言語模型性

最低限次を確認する。

1. 対象言語体系・対象言語関係が候補模型から独立して定められる。
2. 文脈付き内部状態の差が成立差へ到達する。
3. 同じ模型側関係を複数状態・文脈へ再利用できる。
4. 対象言語側と模型内部側を追跡できる言語対応がある。
5. 差分追従・複数対照再利用・再現性による局所対応証拠がある。

これらを物理5部品として扱わない。

### 大規模性

v0.4経路で次を再測定する。

- 状態域規模
- 関係域規模
- 共有適用規模

v0.3 GPQA等をv0.4大規模性へ自動転用しない。

## 4. 模型核 / 計算実行器分離関門

- `src/minidora/模型.py` がHDS Compiler・旧Layer0命令器へ依存せず単体成立する。
- `成立差` を確率分布・samplingへ固定しない。
- 根拠差なし・同率で一候補へ勝手に確定しない。
- 旧 `Layer0` は計算実行器互換aliasに限る。
- 算術・比較・状態更新等をLLM模型性の成立条件へ混入させない。

## 5. 命令形P / 計算実行関門

- 日本語正本
- Capabilityを実行可能構文として保持
- Dataを命令へ混入しない
- held-out入力で再利用可能
- 特定モデル専用エミュレータになっていない
- `計算実行器`の故障を模型核の不成立へ自動帰属しない

## 6. 外部参照R関門

- 標準Data Layerが成立
- 取得Dataが必要な運用経路へ戻る
- 文書丸写しを回答としない
- 複数Dataの矛盾保持
- 出典追跡
- Provider差替え
- 取得結果と模型内部関係を同一視しない

## 7. HDS / Compute IR関門

HDS-IRは意味Projection・運用入力・監査履歴として扱う。

```text
HDS-IR != LLM模型中核
HDS-IR != Compute IR
```

v0.4模型核後にCompute IR / ABIを確定し、その後にHDS Compiler loweringを更新する。

この段階を飛ばしてHDS Compilerを模型核へ直接固定しない。

## 8. 主体主幹関門

- turn間で同じ主体状態を必須参照する
- 理由なし主体反転を保留する
- 理由付き自己訂正を許可する
- 旧版/新版/差分/理由/根拠を監査できる
- 模型核・計算実行器・専門処理が主体状態を直接書き換えられない
- 主体整合に失敗した候補を結果表面へ昇格させない

主体主幹をLLM模型中核の追加構成要素とはしない。

## 9. 能力評価関門

最低限、同一harnessで次を分けて測る。

```text
推論能力
知識能力
命令追従
長文脈
コード
agentic長期実行
未知時停止
矛盾時停止
主体的一貫性
理由付き自己訂正
```

他モデルと比較する際はprompt・dataset・judge・tool条件を固定する。

## 10. 効率評価関門

- p50 / p95 latency
- CPU / RAM
- GPU要否
- 外部参照費用
- 1問当たりI/O量
- 模型関係評価数
- 計算命令数
- 主体状態読取/更新コスト
- 日本語内部表現と外部互換表現の記号量比較

## 11. 禁止される昇格

```text
模型核単体PASS
≠ 大規模性成立

局所task PASS
≠ 汎用LLM完成

計算実行器PASS
≠ LLM模型性成立

weight解析
≠ MINIDORA模型関係成立

主体主幹PASS
≠ LLM模型核成立

PROTOTYPE COMPLETE(v0.3)
≠ v0.4大規模性

PROTOTYPE COMPLETE
≠ 製品・最終完成

Reference OFF失敗
≠ MINIDORA標準能力失敗
```

## 12. 状態語

- 合格: 定義された証拠が揃った
- 保留: 未試験、未解、証拠不足、競合
- 失敗: 明示条件に違反
- 非適用: 宣言範囲外

## 13. 製品・最終完成

3. 模型核 / 計算実行器分離
4. Compute IR / ABI閉包
5. HDS semantic IR lowering
6. 日本語命令形P
7. 標準外部参照R
8. Runtime閉路
9. 主体主幹
10. held-out一般化
11. 同一harness比較
12. 効率評価
