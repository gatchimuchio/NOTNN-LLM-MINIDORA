# HDS Compiler 作用差分構文化 — Architecture v1.3 / Pipeline v1.4

## 1. 目的

構成定義v8とK3除外横断構文化v3で分離した、

```text
状態担体
→ 作用
→ 状態差
→ 後続利用
```

を、公開HDS Compilerが判断せずに保持・受け渡せる契約へ落とす。

本変更は推論器・再作用器・HDS判断主体をCompilerへ追加するものではない。

## 2. 現行欠落

v1.2/v1.3は状態遷移図と認知世界差分を別々に生成できる。一方、

```text
作用Aによって状態X→Yが生じた
Yが別作用Bの入力状態条件である
```

という接続を一級のCompiler成果として保持していなかった。

そのため、状態を記録しても、その差が後続作用へどう接続し得るかを下流が再構成する必要があった。

## 3. 新しい並列成果

`HDS作用差分構造` は次を別々に保持する。

- `HDS作用記録` — 作用種別、入力状態、出力状態、条件、可逆性、巻戻し先、由来。
- `HDS状態差記録` — 原因作用、前状態、後状態、変化有無。
- `HDS後続利用記録` — 状態差の後状態が、別作用の入力状態条件を満たす構造的接続。
- `未閉包` — 前後状態を確定できない作用等。

## 4. 後続利用の意味

後続利用は「作用が実際に発火した」という意味ではない。

```text
状態差Δの後状態 = Y
次作用Bの入力状態 = Y
```

が一致したとき、`Y` がBの状態条件を満たしたことだけを記録する。

Bに追加条件がある場合、その条件は `追加条件` として残す。Compilerは追加条件の充足、Bの採用、Bの実行、最終結果を確定しない。

## 5. 無変化

前状態と後状態が同一なら、現行Projectionでは `変化有無=False` とする。

未知の内部属性変化を補完しない。また、無変化記録だけを根拠に新規後続利用を生成しない。

## 6. Pipeline v1.4

```text
自然言語
↓
意味コンパイル
↓
意味HDS-IR ─────────────┐
                       ├→ コンパイル束
計算計画 ───────────────┤
                       │
作用差分構造 ────────────┘
```

三者は別フィールドで保持する。

作用差分構造を計算Pへ自動変換しない。能力実行系がこの構造を再利用する場合は、別の実装・採否・検証契約を要求する。

## 7. 日本語基底

内部正本は日本語とする。

```text
規定言語 = 日本語
基底言語 = 日本語
基底言語コード = ja
```

外部入力に `transition`、`rollback` 等が現れても、内部作用種別は `遷移`、`巻戻し` 等へ射影する。原語は原文・出典・外部互換境界で保持する。

## 8. 非責任

公開Compilerは次を行わない。

- 状態差を真実へ昇格する
- 後続作用を自動実行する
- checkpointを再活性する
- 候補を採否する
- HDS判断主体の代わりに最終状態を決める
- 能力得点を上げるために後続利用を捏造する

## 9. 受入条件

1. 日本語の連続状態遷移から作用・状態差・後続利用を生成できる。
2. 無関係な遷移間へ後続利用を生成しない。
3. 同一状態への無変化を新規差として利用しない。
4. 外国語入力でも内部作用種別は日本語正本になる。
5. 未閉包端点を推測で埋めない。
6. 意味IR・計算計画・作用差分構造を別保持する。
7. 計算降下で作用差分構造を自動実行命令へ変えない。
8. 既存Compiler/Runtime回帰を壊さない。
9. Ubuntu / Windows × Python 3.11–3.14で通常CIを通す。

## 10. 次段

本版は「差によって次作用が変わり得る構造をCompilerが渡せる」までを責任とする。

次段の能力系では、この構造を実際の作業状態へ接続し、差が生じた場合だけ後続作用の候補集合・参照・評価・再結合が変化するかを独立に検証する。
