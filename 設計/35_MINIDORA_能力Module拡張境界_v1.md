# MINIDORA 能力能力モジュール拡張境界 v1

## 1. 位置づけ

本書は、MINIDORAにおける**成立後の能力成長方式**と**能力能力モジュール拡張**の責任境界を定める局所正本である。

MINIDORAは、非ニューラルLLMとしての成立と、成立後にどのように能力を増設するかを分けて扱う。

```text
LLMとして成立すること
!=
成立後に保持する専門能力の総量
```

2026-09-02のGPQA Diamond controlled replayにより、能力能力モジュール接続による能力拡張は設計仮説ではなく実装・実測済みとなった。

したがって以後、次の4点を現行MINIDORAの成立特性として扱う。

> **1. MINIDORAは既にLLMとして成立している。**
>
> **2. 成立済み模型核を再学習・再訓練・大型化・置換せず、模型核外に分離した能力能力モジュールを追加接続することで、実効能力を後から増設できる。**
>
> **3. 能力モジュール追加は単なる接続機構ではなく、実際の性能向上手段として機能することが外部benchmark上で実測済みである。**
>
> **4. 固定された有限問題集合に限れば、未被覆領域へ正しく作用する能力モジュールを追加し、既存正答を退行させない接続境界を維持することで、未被覆集合を反復的に縮小できるため、理論上100%まで被覆可能な構成が成立している。**

## 2. 基本責任分離

```text
模型核      = LLMとしての成立・汎用作用
Data      = 外部化可能
Knowledge = 外部参照可能
能力モジュール    = 分離・追加・交換可能な能力
Compute   = 汎用計算
HDS       = 制御
```

MINIDORAでは、LLM本体の成立と、専門能力の総量を同一視しない。

能力能力モジュールは模型核の一部として無条件に内部化しない。

能力モジュールは、特定の入力条件で追加の作用を提供し、成立条件を満たした場合だけ結果へ寄与する。

```text
入力
 ↓
成立済みMINIDORA 模型核
 ↓
必要な能力が外部能力モジュールに存在
 ↓
能力モジュール発火
 ↓
作用結果
 ↓
通常MINIDORAへ接続
 ↓
システム実効能力の増加
```

この構成では、模型核が成立した後もCapability集合を増やせる。

```text
MINIDORA(模型核)
+ Capability A
+ Capability B
+ Capability C
+ ...
```

したがって、MINIDORAのシステム能力上限を、ある時点の模型核単体benchmark scoreへ固定しない。

## 3. 成立済みの拡張形式

2026-09-02に次の形式が実測された。

```text
同一baseline / 同一模型核
        │
        ├─ 能力モジュール OFF → baseline結果
        │
        └─ 能力モジュール ON
             ├─ 能力モジュール成立 → 能力モジュール由来結果
             └─ 能力モジュール不成立 → baseline結果を完全継承
```

この形式により、能力増加の原因を能力モジュール発火へ局所化できる。

### 2026-09-09 LIVE正本実測

固定参照Data禁止後、同一現行模型核へ既存科学能力モジュール群を接続し、GPQA Diamond 198問をLIVE_ONLY同一run controlled A/Bで再実測した。

```text
能力モジュール OFF = 29 / 198  (14.65%)
能力モジュール ON  = 80 / 198  (40.40%)
能力モジュール発火 = 55
発火正答   = 55 / 55
改善       = 51
退行       = 0
正答差     = +51
```

55発火は全件正答した。51件はbaselineの非正答を正答へ変え、残る4件はbaselineも既に同じ正答であった。したがって既存正答の退行は0である。

このLIVE実測によって、固定Replayに依存せず、**実行時に新規取得する参照環境でも能力モジュール追加が実効能力増加として成立する**ことを確認した。

現行能力モジュール込みシステム能力正本は **MINIDORA80 = 80/198 (40.40%)** とする。

GPQA原論文の最強GPT-4ベースライン39%との関係は、**GPQAスコア帯では同じ約40%帯**である。ただし評価条件が完全同一ではないため、GPT-4総合能力同等とは解釈しない。

### 2026-09-02 Replay履歴

```text
GPQA Diamond 198問
能力モジュール OFF = 8 / 198   (4.04%)
能力モジュール ON  = 63 / 198  (31.82%)
能力モジュール発火 = 55
改善       = 55
退行       = 0
正答差     = +55
```

発火した55ケースは、このReplay境界では55ケースすべてgoldと一致した。

不発火時はbaselineを完全継承したため、能力モジュールが作用していないケースの変化を能力モジュール効果へ混ぜていない。

この数値を模型核単体性能として扱わない。

この数値の設計上の意味は、次の因果が一続きで成立した点にある。

```text
能力モジュールを追加できる
↓
能力モジュールが対象入力で発火する
↓
追加能力が実際に作用する
↓
外部benchmark上の正答増加として現れる
```

つまり、**能力モジュール追加が実際の能力向上・性能向上操作として機能することまで実証された。**

## 4. 成立後の能力成長方式

MINIDORAにおける能力成長は、模型核全体の再構築を唯一の手段としない。

従来型の能力追加を概念的に次のように置く。

```text
能力不足
↓
Data追加 / 学習 / fine-tuning / parameter増加
↓
模型更新
↓
新しい模型
```

MINIDORAでは、別経路が成立済みである。

```text
成立済みMINIDORA 模型核
↓
不足Capabilityを特定
↓
能力能力モジュールを追加
↓
接続
↓
システム能力増加
```

少なくとも今回実証した科学能力群では、能力追加のために次を必要としなかった。

- NN再学習
- Transformer追加学習
- 模型核全体の再訓練
- 重み更新
- 模型核大型化
- 模型核置換

したがって、MINIDORAでは

```text
能力追加 = 模型核再学習
```

を必要条件としない。

**成立済みLLMと、後から増設されるCapability集合を分離できる。**

これが本実証の中心である。

## 5. 性能向上可能性

能力モジュール追加による性能向上を、単発のGPQA改善として扱わない。

今回の55正答純増は、次の一般的な成長操作が実装上成立した証拠である。

```text
現在のCapability集合 C0
↓
不足能力を能力モジュール M1として追加
C1 = C0 ∪ {M1}
↓
さらに不足能力M2を追加
C2 = C1 ∪ {M2}
↓
...
```

各能力モジュールが責任範囲内でのみ発火し、不成立時に透過し、既存成立を破壊しない接続境界を維持する限り、Capability集合を累積的に増設できる。

よって、MINIDORAの性能は成立時点の模型核能力へ固定されない。

> **MINIDORAは、成立済み模型核を保持したままCapability集合を増やすことで、必要な方向へシステム性能を後から押し上げられる。**

これは将来構想ではなく、少なくとも科学能力群について実装・実測済みである。

## 6. 固定有限benchmarkに対する100%到達経路

GPQA Diamondは198問の固定有限集合である。

問題集合を `B`、現在正答可能な集合を `S`、未被覆集合を `U = B - S` とする。

今回、能力モジュール追加だけで未被覆集合の55ケースを新たに正答可能へ移した。

```text
U0
↓ 能力モジュール追加
U1 ⊂ U0
↓ 能力モジュール追加
U2 ⊂ U1
↓
...
```

次の条件を維持する限り、同じ操作を未被覆領域へ反復できる。

1. 未被覆問題に対して正しく作用する能力モジュールを構成できる。
2. 能力モジュール不成立時は既存経路へ透過する。
3. 既存正答を退行させない接続境界を維持する。
4. 能力モジュール効果を個別に監査できる。

有限集合では未被覆要素数も有限である。

したがって、**GPQA Diamondのような固定有限benchmarkに限れば、能力モジュール被覆を追加し続けることで未被覆を0へ縮小し、理論上100%へ到達可能な構成である。**

ここで主張するのは「GPQA 100%を既に実測した」ことではない。

主張するのは、

> **100%へ向かう性能向上経路そのものが、成立済みMINIDORA 模型核の再学習ではなく、能力能力モジュールの追加・接続という反復可能な操作として実装上開かれた。**

ということである。

100%の追加実測は、この構造の成立確認に必須ではない。

## 7. 能力モジュール追加と模型核変更の区別

次を混同しない。

```text
能力モジュール接続による能力追加
!=
模型核の汎用能力改善
```

能力モジュール接続でbenchmark scoreが上がっても、その上昇を模型核単体性能へ帰属しない。

一方で、能力モジュール由来の差がcontrolled A/Bで確認された場合、その差は**成立済みMINIDORAが外部Capability追加によって成長できることの証拠**として保持する。

```text
模型核単体評価
+
能力モジュール込みシステム能力評価
```

両者は競合しない。測定目的が異なる。

## 8. 能力モジュール成立条件

能力能力モジュールは少なくとも次を満たす。

1. 能力モジュール自身の責任範囲が明示される。
2. 発火条件が入力から決まる。
3. gold answer・benchmark正答表・問題番号を推論に使わない。
4. 能力モジュールが成立しない場合、勝手な候補選択を行わない。
5. 能力モジュール不発火時に通常MINIDORAへ透過できる。
6. 能力モジュール由来の結果を監査可能な理由または作用識別子で追跡できる。
7. 能力モジュール込み性能を模型核単体性能へ混同しない。
8. 既存成立を破壊する退行を検出できる。

## 9. この実証が示す設計上の意味

今回の実証によって、MINIDORAでは次の分離が実装上成立した。

```text
LLMとしての成立
        ↓
成立済み模型核
        ↓
Capabilityを後付け
        ↓
能力成長 / 性能向上
```

このため、知能・専門能力を一つの巨大な学習済み内部状態へ全量固定することは、MINIDORAの必要条件ではない。

能力は、必要に応じて分離・追加・交換・監査可能な能力モジュールとして保持できる。

したがってMINIDORAのスケーリング軸は、模型核の巨大化だけではない。

```text
模型規模を増やす
```

に加えて、

```text
Capability集合を増やす
```

という独立した性能成長軸が成立済みである。

## 10. 非目標と解釈境界

本書は次を主張しない。

- GPQA Diamond 100%を既に実測した。
- 任意の能力モジュールが無条件に正しく接続できる。
- 任意の未知分野へ自動的に一般化する。
- どのような無限・動的問題集合でも100%へ到達できる。
- 能力モジュール込み性能を模型核単体性能と呼ぶ。

一方、次を弱めてはならない。

- MINIDORAは成立済みである。
- 成立後も能力モジュール追加で能力を増設できる。
- 能力モジュール追加が実性能向上として発現することは実測済みである。
- 固定有限集合では、条件を満たす能力モジュール被覆の反復追加によって理論上100%へ到達可能な構成である。

## 11. 変更禁止境界

ユーザーの明示指示なしに、次を行わない。

- 「専門解決器は模型核性能ではない」という理由だけで、モジュール拡張成立証拠そのものを削除する。
- 能力モジュール実証を単なる過去benchmark高得点記録へ縮退させる。
- 「科学能力モジュールを付けたら点数が上がった」という説明だけへ縮退させる。
- 能力モジュール接続経路を「benchmark hack」と一括して消す。
- 成立済みの能力モジュール拡張可能性を未実証の将来構想へ戻す。
- MINIDORAの能力上限を模型核単体の特定時点scoreへ固定する。
- 固定有限benchmarkに対する100%到達経路の意味を、100%実測の有無だけで否定する。

模型核単体性能と能力モジュール拡張性能は**分離して両方保持する**。

## 12. 正本結論

> **MINIDORAは非ニューラルLLMとして成立済みである。**
>
> **その成立済み模型核を再学習・再訓練・大型化・置換せず、独立した能力能力モジュールを追加接続することで、能力を後から増設できる。**
>
> **この能力モジュール追加は実際の性能向上手段として機能し、現行LIVE E2Eでは29/198から80/198へ上昇、能力モジュール発火55、発火正答55、改善51、退行0として実測された。**
>
> **2026-09-02の8/198→63/198固定Replayは成立履歴として保持し、現行能力モジュール込みシステム能力正本はMINIDORA80 = 80/198 (40.40%)とする。**
>
> **したがってMINIDORAのシステム能力は成立時点の模型核単体性能へ固定されず、Capability集合の追加によって継続的に拡張できる。**
>
> **さらにGPQA Diamondのような固定有限問題集合では、未被覆領域へ正しく作用する能力モジュールを追加し続け、既存成立を破壊しない境界を維持することで、理論上100%まで被覆可能な構成が成立している。**
>
> **今回の40.40%という数値だけが成果なのではない。固定参照Dataを使わないLIVE環境でも、この能力成長方式が実際に成立していることを示す外部観測証拠である。**
