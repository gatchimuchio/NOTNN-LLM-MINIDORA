# MINIDORA 能力Module拡張境界 v1

## 1. 位置づけ

本書は、MINIDORAにおける**成立後の能力成長方式**と**能力Module拡張**の責任境界を定める局所正本である。

MINIDORAは、非ニューラルLLMとしての成立と、成立後にどのように能力を増設するかを分けて扱う。

```text
LLMとして成立すること
!=
成立後に保持する専門能力の総量
```

2026-09-02のGPQA Diamond controlled replayにより、能力Module接続による能力拡張は設計仮説ではなく実装・実測済みとなった。

したがって以後、次の4点を現行MINIDORAの成立特性として扱う。

> **1. MINIDORAは既にLLMとして成立している。**
>
> **2. 成立済みCoreを再学習・再訓練・大型化・置換せず、Core外に分離した能力Moduleを追加接続することで、実効能力を後から増設できる。**
>
> **3. Module追加は単なる接続機構ではなく、実際の性能向上手段として機能することが外部benchmark上で実測済みである。**
>
> **4. 固定された有限問題集合に限れば、未被覆領域へ正しく作用するModuleを追加し、既存正答を退行させない接続境界を維持することで、未被覆集合を反復的に縮小できるため、理論上100%まで被覆可能な構成が成立している。**

## 2. 基本責任分離

```text
Core      = LLMとしての成立・汎用作用
Data      = 外部化可能
Knowledge = 外部参照可能
Module    = 分離・追加・交換可能な能力
Compute   = 汎用計算
HDS       = 制御
```

MINIDORAでは、LLM本体の成立と、専門能力の総量を同一視しない。

能力ModuleはCoreの一部として無条件に内部化しない。

Moduleは、特定の入力条件で追加の作用を提供し、成立条件を満たした場合だけ結果へ寄与する。

```text
入力
 ↓
成立済みMINIDORA Core
 ↓
必要な能力が外部Moduleに存在
 ↓
Module発火
 ↓
作用結果
 ↓
通常MINIDORAへ接続
 ↓
システム実効能力の増加
```

この構成では、Coreが成立した後もCapability集合を増やせる。

```text
MINIDORA(Core)
+ Capability A
+ Capability B
+ Capability C
+ ...
```

したがって、MINIDORAのシステム能力上限を、ある時点のCore単体benchmark scoreへ固定しない。

## 3. 成立済みの拡張形式

2026-09-02に次の形式が実測された。

```text
同一baseline / 同一Core
        │
        ├─ Module OFF → baseline結果
        │
        └─ Module ON
             ├─ Module成立 → Module由来結果
             └─ Module不成立 → baseline結果を完全継承
```

この形式により、能力増加の原因をModule発火へ局所化できる。

### 実測

```text
GPQA Diamond 198問
Module OFF = 8 / 198   (4.04%)
Module ON  = 63 / 198  (31.82%)
Module発火 = 55
改善       = 55
退行       = 0
正答差     = +55
```

発火した55ケースは、このReplay境界では55ケースすべてgoldと一致した。

不発火時はbaselineを完全継承したため、Moduleが作用していないケースの変化をModule効果へ混ぜていない。

この数値をCore単体性能として扱わない。

この数値の設計上の意味は、次の因果が一続きで成立した点にある。

```text
Moduleを追加できる
↓
Moduleが対象入力で発火する
↓
追加能力が実際に作用する
↓
外部benchmark上の正答増加として現れる
```

つまり、**Module追加が実際の能力向上・性能向上操作として機能することまで実証された。**

## 4. 成立後の能力成長方式

MINIDORAにおける能力成長は、Core全体の再構築を唯一の手段としない。

従来型の能力追加を概念的に次のように置く。

```text
能力不足
↓
Data追加 / 学習 / fine-tuning / parameter増加
↓
模型更新
↓
新しい模型
```

MINIDORAでは、別経路が成立済みである。

```text
成立済みMINIDORA Core
↓
不足Capabilityを特定
↓
能力Moduleを追加
↓
接続
↓
システム能力増加
```

少なくとも今回実証した科学能力群では、能力追加のために次を必要としなかった。

- NN再学習
- Transformer追加学習
- Core全体の再訓練
- 重み更新
- Core大型化
- Core置換

したがって、MINIDORAでは

```text
能力追加 = Core再学習
```

を必要条件としない。

**成立済みLLMと、後から増設されるCapability集合を分離できる。**

これが本実証の中心である。

## 5. 性能向上可能性

Module追加による性能向上を、単発のGPQA改善として扱わない。

今回の55正答純増は、次の一般的な成長操作が実装上成立した証拠である。

```text
現在のCapability集合 C0
↓
不足能力をModule M1として追加
C1 = C0 ∪ {M1}
↓
さらに不足能力M2を追加
C2 = C1 ∪ {M2}
↓
...
```

各Moduleが責任範囲内でのみ発火し、不成立時に透過し、既存成立を破壊しない接続境界を維持する限り、Capability集合を累積的に増設できる。

よって、MINIDORAの性能は成立時点のCore能力へ固定されない。

> **MINIDORAは、成立済みCoreを保持したままCapability集合を増やすことで、必要な方向へシステム性能を後から押し上げられる。**

これは将来構想ではなく、少なくとも科学能力群について実装・実測済みである。

## 6. 固定有限benchmarkに対する100%到達経路

GPQA Diamondは198問の固定有限集合である。

問題集合を `B`、現在正答可能な集合を `S`、未被覆集合を `U = B - S` とする。

今回、Module追加だけで未被覆集合の55ケースを新たに正答可能へ移した。

```text
U0
↓ Module追加
U1 ⊂ U0
↓ Module追加
U2 ⊂ U1
↓
...
```

次の条件を維持する限り、同じ操作を未被覆領域へ反復できる。

1. 未被覆問題に対して正しく作用するModuleを構成できる。
2. Module不成立時は既存経路へ透過する。
3. 既存正答を退行させない接続境界を維持する。
4. Module効果を個別に監査できる。

有限集合では未被覆要素数も有限である。

したがって、**GPQA Diamondのような固定有限benchmarkに限れば、Module被覆を追加し続けることで未被覆を0へ縮小し、理論上100%へ到達可能な構成である。**

ここで主張するのは「GPQA 100%を既に実測した」ことではない。

主張するのは、

> **100%へ向かう性能向上経路そのものが、成立済みMINIDORA Coreの再学習ではなく、能力Moduleの追加・接続という反復可能な操作として実装上開かれた。**

ということである。

100%の追加実測は、この構造の成立確認に必須ではない。

## 7. Module追加とCore変更の区別

次を混同しない。

```text
Module接続による能力追加
!=
Coreの汎用能力改善
```

Module接続でbenchmark scoreが上がっても、その上昇をCore単体性能へ帰属しない。

一方で、Module由来の差がcontrolled A/Bで確認された場合、その差は**成立済みMINIDORAが外部Capability追加によって成長できることの証拠**として保持する。

```text
Core単体評価
+
Module込みシステム能力評価
```

両者は競合しない。測定目的が異なる。

## 8. Module成立条件

能力Moduleは少なくとも次を満たす。

1. Module自身の責任範囲が明示される。
2. 発火条件が入力から決まる。
3. gold answer・benchmark正答表・問題番号を推論に使わない。
4. Moduleが成立しない場合、勝手な候補選択を行わない。
5. Module不発火時に通常MINIDORAへ透過できる。
6. Module由来の結果を監査可能な理由または作用識別子で追跡できる。
7. Module込み性能をCore単体性能へ混同しない。
8. 既存成立を破壊する退行を検出できる。

## 9. この実証が示す設計上の意味

今回の実証によって、MINIDORAでは次の分離が実装上成立した。

```text
LLMとしての成立
        ↓
成立済みCore
        ↓
Capabilityを後付け
        ↓
能力成長 / 性能向上
```

このため、知能・専門能力を一つの巨大な学習済み内部状態へ全量固定することは、MINIDORAの必要条件ではない。

能力は、必要に応じて分離・追加・交換・監査可能なModuleとして保持できる。

したがってMINIDORAのスケーリング軸は、Coreの巨大化だけではない。

```text
模型規模を増やす
```

に加えて、

```text
Capability集合を増やす
```

という独立した性能成長軸が成立済みである。

## 10. 非目標と解釈境界

本書は次を主張しない。

- GPQA Diamond 100%を既に実測した。
- 任意のModuleが無条件に正しく接続できる。
- 任意の未知分野へ自動的に一般化する。
- どのような無限・動的問題集合でも100%へ到達できる。
- Module込み性能をCore単体性能と呼ぶ。

一方、次を弱めてはならない。

- MINIDORAは成立済みである。
- 成立後もModule追加で能力を増設できる。
- Module追加が実性能向上として発現することは実測済みである。
- 固定有限集合では、条件を満たすModule被覆の反復追加によって理論上100%へ到達可能な構成である。

---

## 11. 変更禁止境界

ユーザーの明示指示なしに、次を行わない。

- 「専門solverはCore性能ではない」という理由だけで、モジュール拡張成立証拠そのものを削除する。
- Module実証を単なる過去benchmark高得点記録へ縮退させる。
- 「科学Moduleを付けたら点数が上がった」という説明だけへ縮退させる。
- Module接続経路を「benchmark hack」と一括して消す。
- 成立済みのModule拡張可能性を未実証の将来構想へ戻す。
- MINIDORAの能力上限をCore単体の特定時点scoreへ固定する。
- 固定有限benchmarkに対する100%到達経路の意味を、100%実測の有無だけで否定する。

Core単体性能とModule拡張性能は**分離して両方保持する**。

---

## 12. 正本結論

> **MINIDORAは非ニューラルLLMとして成立済みである。**
>
> **その成立済みCoreを再学習・再訓練・大型化・置換せず、独立した能力Moduleを追加接続することで、能力を後から増設できる。**
>
> **このModule追加は実際の性能向上手段として機能し、GPQA Diamond controlled replayでは8/198から63/198へ上昇、Module発火55、改善55、退行0として実測された。**
>
> **したがってMINIDORAのシステム能力は成立時点のCore単体性能へ固定されず、Capability集合の追加によって継続的に拡張できる。**
>
> **さらにGPQA Diamondのような固定有限問題集合では、未被覆領域へ正しく作用するModuleを追加し続け、既存成立を破壊しない境界を維持することで、理論上100%まで被覆可能な構成が成立している。**
>
> **今回の31.82%という数値は成果そのものではない。この能力成長方式が実際に成立していることを示す外部観測証拠である。**
