# HDS-MINIDORA：必要条件・例外の意味境界 v6

日付：2026-09-18（日本時間）
基点main：`49949048d6c20d991caf81025f97b9204505907c`
基点tree：`38caf0aed103d51a567707fdd0bf64eead8a4691`

## 1. 目的

全能力開発ロードマップ順序2を継続し、v5で残した一般条件・例外のうち、意味方向を誤ると結論が反転する範囲を先に実装する。

本増分は既存HDS通常循環、関係4工程、不足調査6工程、命題推論器、保存・失効・再計算をそのまま使う。新しい制御主体や別オーケストレータは作らない。

対象は次の有限範囲である。

- 必要条件と十分条件の向きの区別
- 「場合に限り」「場合のみ」の必要条件化
- 直前の明示条件規則に対する有限な例外節
- 例外条件が不明な場合の保留
- v5関係成果を現行意味へ無言昇格しない保存移行

任意の日本語条件、一般的な法令例外、優先規則、デフォルト論理、確率的例外を完成したものとはしない。

## 2. 必要条件

通常の十分条件はv5と同じく、

```text
AならばB
=> A → B
```

として扱う。

必要条件は向きを反転する。

```text
BするためにはAが必要
AであることはBするための必要条件
Aな場合に限りB
Aな場合のみB

=> B → A
```

したがって、Aだけを観測してBを導出しない。後件肯定、前件否定と同様に、必要条件の充足から目的成立を逆算しない。

「必要十分」は双方向契約を別途定義していないため、本増分では必要条件だけへ縮退させず保留する。

## 3. 例外付き規則

次のような直前規則と例外節を対象とする。

```text
AならばB。ただしEの場合を除く。
```

内部では、例外が存在しないことを勝手に仮定せず、

```text
(A ∧ ¬E) → B
```

へ変換する。

このため、AだけではBを導かない。Aと`¬E`が明示された場合だけ本則を適用する。

```text
AならばB。ただしEの場合はC。
```

は、

```text
(A ∧ ¬E) → B
E → C
```

として保持する。

Eが成立しただけで`¬B`を作らない。例外時の逆結果が必要なら、Cとして明示されなければならない。

## 4. 作用域

例外節は直前一件の条件規則だけへ接続する。別句でも同一構成句でも、直前の本則が一意に確定できる場合だけ採用する。

次は採用しない。

- 直前に条件規則がない「ただし」
- 条件または帰結が解釈できない例外節
- 複数の候補規則へ係り得る例外
- 「例外がある」だけで条件が不明な記載
- 未束縛照応を含む例外条件

未対応例外が後置された場合、直前の記載を先に事実化しない。直前記載の原文・読解構造は保持するが推論採用を局所的に保留し、無関係な前後の記載まで一括隔離しない。

## 5. 原文・導出・検査

v5と同じく、原文区間、変換履歴、採用命題、残差、実導出を保存する。

例外付き本則は、保存された構造から再構成して照合する。`¬E`ガードを保存後に除去した構造は検査不一致となる。これは内部構造の再構成一致であり、資料内容の現実的真偽を保証するものではない。

## 6. v5保存物の移行

現行保存版は`HDS-MINIDORA-全体運用-v6`。

標準v1〜v5を明示移行対象とする。v5で保存された関係回答は、必要条件・例外の意味契約がv6で変わるため現行成果へ自動昇格しない。

- v5原本、旧回答、旧目的、履歴、依存、旧形成手順は移行原本内にそのまま保持する。
- 現行の`前回結果`は失効する。
- 「再計算して」で利用できるよう、関係目的の要求構造が同型であることを検査した上で、再計算用の要求版だけv2へ移す。
- 旧形成手順は検査するが再採用しない。
- v4/v5原本内の過去移行履歴は、その当時存在した移行記録版v1だけを許容する。未来版を旧原本へ後付けしない。
- 保存データから外部読取権限を獲得しない。

## 7. 非対象

本増分では次を未実装として残す。

- 一般動詞・修飾の網羅
- 「〜しない限り」等の複合否定条件の一般化
- 複数例外の優先順位、例外の例外
- 規則間の優先度、法的な特則優先・新法優先等
- 資料間対象同一性の自動確定
- 暗黙の常識による例外不存在の補完
- 任意自然言語からの一般論理式生成

これらを補完して成功率を上げず、残差として次の開発へ渡す。
