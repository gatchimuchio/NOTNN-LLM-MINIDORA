# MINIDORA 文脈・照応解決 v0.1

日付: 2026-09-10
基点commit: `6f2479c2963883f1782bb452db7141b518b9f39b`
対象: 開発一覧③の、採用済み会話成果を後続の文書操作へ束縛する局所実装。

## 1. 作用と責任

```text
既存局所解釈キャッシュ S_t + 採用済み成果
→ 所有者・世代・状態版付きスナップショット
→ HDS文脈として既存公開Compilerへ引用
→ 要求解釈 v0.2：会話参照／依頼内参照を区別
→ 初期Dataへ参照先の実値を束縛
→ 既存能力合成器・既存Module
→ 明示出力条件を検査
→ 採用結果だけを記憶へ追加、S_t+1へ更新
```

状態の存在だけではなく、過去成果の差が後続の処理結果へ到達することを検査する。本文を命令や計画へ埋め込まない。Core、HDS Compiler、既存局所解釈キャッシュ、科学Module、GPQA正本、標準チャット入口、GUI-Shellは変更しない。

## 2. 実装

| ファイル | 責任 |
|---|---|
| `文脈照応.py` | 会話成果、スナップショット、所有境界、参照解決、状態確定。既存`局所解釈キャッシュ`を再利用。 |
| `文脈要求.py` | 同期セッション。実HDS Compiler→要求解釈→実行→状態更新を接続。既存の副作用のない3能力だけを登録。 |
| `要求解釈.py` | v0.2。任意指定の文脈を受け取り、参照をDataへ束縛。文脈未指定時の既存経路も維持。 |
| `要求解釈実行.py` | 文脈を使用した計画には一致する起点を要求し、実行セッションの不一致を拒否。 |

標準チャットへ自動接続していない。`文脈付き要求セッション`を明示的に作成して呼ぶ、ライブラリ段階の能力である。

## 3. 対応する参照

| 表層 | 今回の限定された解決規則 |
|---|---|
| 依頼先頭の`それ` | 現在の採用済み焦点。新規資料もある場合は対象競合として保留。 |
| `さっきの`・`前の結果`・`前の回答`・`直前の応答`等 | 最も新しい採用済みの成果集合。失敗・保留メッセージは参照対象にしない。 |
| `さっきの2番`・`前の2番` | 最新の採用済み成果集合の2番目の出力。 |
| `第1応答`・`第1応答の2番` | この世代の明示応答番号と出力番号。全角数字にも対応。 |
| 同じ依頼の2工程目以降の`その結果`・`それ` | 第2バッチ同様、この依頼内の前工程。過去の会話とは別の参照。 |
| 2工程目以降の`さっきの結果`等 | 明示された過去会話への参照。前工程へすり替えない。 |

応答番号は状態更新ごとに増える。保留・失敗・中止も番号を占めるが、成果として参照できない。`前の`等を直前のエラーメッセージ一般に適用する意味解析ではなく、採用成果に限定した契約である。

**出力番号と、回答文内の箇条書き項目番号は別である。** 本版の`3番`は構造化された第3出力のみを選ぶ。文章中の第3項目は未対応。出力が複数なのに`それ`だけの場合、一つへ勝手に確定せず保留する。

「それから数字を抽出して」は`それ`＋格助詞`から`として対象を読む。接続詞を明示する「それから、数字を抽出して」は別の解析になる。文法は有限であり、任意の語用・省略・言い換えへ一般化したとは主張しない。

## 4. HDS接続

実HDS Compilerへ、現在のスナップショットを識別する引用、状態版、直前IR、未解残差、入力・採否を渡す。焦点の本文をCompiler入力へ注入せず、参照集合の識別子を渡し、実値は計画の初期Dataに分離する。

Compilerの推定共参照を無条件に確定しない。次が揃う場合だけ局所解消記録を追加する。

- 引用と参照先が、今回使用するスナップショットの識別子に一致する。
- 共参照関係の始点・終点・種別・推定状態が適合し、追加条件がない。
- 原文中の指示語の全出現が、解決済みの対象範囲へ収まる。
- 対象・操作・条件を既存の全文消費契約で解釈できる。

元のHDSIR、推定座標、関係、残差、損失履歴は削除・書換えしない。無関係な共参照、未知条件、semantic_lossは保留する。重複した関係ID・残差IDで検査を迂回できないよう入力検査も追加した。

## 5. 状態と実行の境界

`準備(依頼, 資料)`は状態を進めず、スナップショットと解釈を返す。`実行(計画)`は所有者・世代・状態版・指紋が現在と一致した場合だけ実行する。`応答`は両者を同期的に行う。

- 同名セッションでも異なるインスタンスは別の所有境界を持つ。
- 初期化で世代が進み、旧世代の計画は再利用できない。
- 一度実行した計画、別turnの更新前に作った計画、改変された計画は実行しない。
- 合成成功でも行数等の要求制約が未達なら、最終出力を採用成果へ追加しない。
- 保留・失敗・中止は採否を記録するが、既存の採用済み焦点を未採用値で上書きしない。
- 返却値・スナップショット・入力Dataを複製し、外部の可変値変更を所有状態へ反映させない。
- 同一セッションの再入・同時処理は待機せず保留。処理中の初期化を拒否する。

状態確定は候補状態を別に構築し、検査後にだけ反映する。サイズ超過等で確定できなければ、最終出力を公開せず状態を維持する。純粋な文書操作に限定しており、外部への送信・書込みのロールバックを提供するものではない。

低水準の`要求計画を実行`だけでは、渡されたスナップショットが現在も現行かは判定できない。現在の所有状態との比較と世代検査は`文脈付き要求セッション.実行`が担う。通常はこの所有境界を経由する。

## 6. 記録・上限・非保証

`照応束縛`に原文範囲、表層、文脈識別子、応答番号、出力番号、出力ID、Dataキー、結果指紋を残す。来歴は事実性や資料の含意を保証しない。

既定は64応答、会話記録2,000,000バイト、依頼8192文字。上限で履歴を黙って剪定しない。明示初期化が必要。これは長文脈管理Moduleの代替ではない。

所有IDはインスタンス生成時のUUID。識別用メタデータであり、能力の選択や回答を乱数で決めない。同じスナップショットと入力に対する解釈は同じだが、異なるインスタンス間の記録ハッシュ同一性は主張しない。

指紋は信頼する同一プロセス内の整合検査。電子署名、認証、悪意あるPythonコードからの隔離を提供しない。外部LLM、永続記憶、端末間同期は追加しない。

## 7. 実行

```python
from minidora.文脈要求 import 文脈付き要求セッション
from minidora.製品版.型 import 能力結果

会話 = 文脈付き要求セッション("demo")
会話.応答("本文を1行で要約して", {
    "本文": 能力結果(True, "売上は120です。費用は75です。利益は45です。")
})
会話.応答("それから数字を抽出して")
結果 = 会話.応答("さっきの結果を箇条書きにして")
assert 結果.出力[0][1].本文 == "- 120"
会話.初期化()
assert 会話.応答("それを要約して").状態 == "保留"
```
