# MINIDORA 局所解釈起点契約 v1

日付: 2026-09-09
状態: active

## 1. 目的

MINIDORAの意思決定を、各turnで独立したその場処理として開始せず、同一Runtime内で直前までに更新された現在解釈を起点として開始する。

これはLLM内部に永続人格や長期記憶を持たせる規定ではない。

```text
局所解釈 S_t
+ 現在入力 O_t
→ 解釈 / 判断 / 実行
→ 採否・結果・残差
→ 局所解釈 S_t+1
```

次turnは必ず更新後の `S_t+1` を起点として開始する。

## 2. 責任境界

局所解釈はMINIDORA Runtimeの一時作業状態である。

- Runtime / スレッド / セクション等の局所範囲だけで保持してよい。
- Runtimeを作り直せば初期状態へ戻ってよい。
- 明示初期化で境界を切ってよい。
- ファイル永続化、端末間同期、日を跨ぐ自己同一性、長期目標の維持を要求しない。
- 上記の長期保持はAgent / AGI等の上位主体の責任であり、LLM成立条件へ混入させない。

したがって、局所解釈連続性と永続主体性を同一視しない。

## 3. 局所解釈状態

最低限、次を局所状態として保持する。

```text
版
直前入力
現在焦点
直前結果
直前HDS-IR
直前採否
未解残差
HDS-IR履歴
```

状態の存在だけでは成立としない。次turnの計算入口へ `局所解釈起点` として実際に渡されることを要求する。

## 4. 更新規則

### 合格かつ値あり

- 直前入力と直前採否を更新する。
- 直前結果を採用値へ更新する。
- 現在焦点を採用値へ更新する。
- 未解残差を解消する。

### 保留

- 直前入力と直前採否を更新する。
- HDS-IRが残差を持つ場合は未解残差を更新する。
- 既に採用済みの現在焦点・直前結果を、値なし保留によって無言上書きしない。

### 失敗

- 失敗したturn自体は局所状態へ記録する。
- 既に採用済みの現在焦点・直前結果を失敗結果で無言上書きしない。

HDS-IRが生成された場合は採否にかかわらず局所履歴へ保持できる。

## 5. 意思決定起点

各top-level turnの開始時に更新前スナップショットを固定し、そのturnの `局所解釈起点` とする。

- HDS Compiler接続時は、その起点から生成した `HDS文脈` をtop-level入力解釈へ渡す。
- 計算実行時は `局所解釈起点` を実行状態へ渡す。
- turn完了前に次状態へ更新しない。
- turn完了後にだけ `S_t → S_t+1` を確定する。

これにより、現在入力だけを起源として毎回ゼロから判断する経路を標準Runtimeから除く。

## 6. 独立資料境界

選択肢、検索取得Data、独立文書等の意味コンパイルは会話局所状態から独立させる。

`HDS独立コンパイル` は空の `HDS文脈` を使用し、現在焦点・直前結果・局所履歴を独立Dataへ注入しない。

局所状態を意思決定起点にすることと、外部資料へ会話文脈を混入させることを同一視しない。

## 7. 受入条件

1. 同一Runtimeの第2turnが第1turn後の局所状態を `局所解釈起点` として受け取る。
2. HDS未接続turnでも局所状態が更新される。
3. 保留・失敗が採用済み焦点を無言上書きしない。
4. 別Runtime間で局所状態を共有しない。
5. 明示初期化で局所状態を初期状態へ戻せる。
6. 永続化機構をMINIDORA Runtimeへ追加しない。
7. 既存の厳密言語模型確率・能力得点へ局所状態を混入しない。
