# 大規模言語模型成立契約 — MINIDORA v0.5 / 上位v7射影

## 1. 上位正本

- Repository: https://github.com/gatchimuchio/LLM-Constitutive-Specification
- 版: `2026-08-28-成立規定-7`
- 参照commit: `debb83e091a705a5eac09ef4fb97a5b36305db6d`
- 正本: `規定/02_大規模言語模型成立.md`

MINIDORAは成立条件を独自再定義しない。本書はv7をMINIDORAへ写像する局所契約である。

## 2. v0.5の二核

```text
[厳密LM核]
完全言語状態空間
+ 持続模型状態
→ 正規化済み条件分布
→ chain rule + EOS
→ 完全系列確率

[能力核]
Question / Candidate / Data
→ 関係・証拠・候補差
→ knowledge choice
```

両者を同一視しない。

## 3. 厳密LM実装

正本実装は `src/minidora/言語確率法則.py`。

現行成立形は有限n-gram / finite-state型である。

- NFKC正規化後のUnicode文字を記号として扱う。
- 形成資料で観測されない文字は `UNK` へ写像する。
- `BOS` は文脈記号、`EOS` は終端記号。
- 全条件分布はadditive smoothingにより `Fraction` で厳密正規化する。
- 系列確率は各次記号条件確率とEOS確率の積で求める。
- 全文脈でEOS確率に正の下限を持たせ、無限長へ確率質量を漏らさない。
- samplingは行わない。最尤選択を行う場合も決定論的にtie-breakする。

この成立形をLLM一般の唯一方式へ昇格しない。

## 4. 最小基底模型

`最小厳密言語模型()` は形成資料0でも `UNK/EOS` 上のadditive priorを持つ。

これは**厳密LM法則の最小成立証人**であり、言語能力・知識・Large・現代LLM呼称の証拠ではない。

有用な言語確率は `MINIDORA厳密言語模型.形成(文書群, ...)` で持続模型状態を形成して得る。

## 5. 能力模型

旧 `MINIDORA模型核` はv0.5では能力模型核として再分類する。

- 意味連続
- 順序連続
- 有向関係整合
- 肯否整合
- 履歴近接
- 条件結合
- 参照寄与
- 候補共同再照合

は推論・候補評価の能力作用であり、それ自体を厳密LMの確率法則としない。

Runtimeでは:

```text
言語模型核 = MINIDORA厳密言語模型
能力模型核 = MINIDORA模型核(v0.4互換)
模型核       = 能力模型核 の互換alias
```

とする。

## 6. HDS境界

HDS Compiler / Data / 後段HDSは能力経路へ接続する。HDSの候補score・寄与を実行時にLM確率へ変換しない。

## 7. Large境界

旧v0.4の状態域/関係域/共有適用規模測定は履歴として保持する。

v7ではLargeを別監査するため、v0.5の厳密LM成立から旧三面測定を使ってLargeを自動継承しない。

現行v0.5:

```text
厳密LM成立 = 受入対象
推論能力    = 別評価
Large       = 再監査要
現代LLM呼称 = 再監査要
```

## 8. 受入条件

- 各条件分布の和がexact `1`。
- `系列確率()` が正の`Fraction`を返す。
- EOS確率下限が正。
- 形成文書順を変えても同じ模型状態hash。
- JSON辞書化→復元で同じhash・同じ系列確率。
- 最小模型でも厳密正規化が成立。
- sampling依存なし。
- Runtimeが厳密LM核と能力核を別保持。
- 候補scoreをLM確率へ流用しない。
- 既存knowledge choice回帰を壊さない。
