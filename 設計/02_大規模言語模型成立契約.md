# 大規模言語模型成立契約 — MINIDORA v0.4

## 1. 論理上位正本

MINIDORAは大規模言語模型の成立条件を独自定義しない。

上位正本:

- Repository: [gatchimuchio/LLM-Constitutive-Specification](https://github.com/gatchimuchio/LLM-Constitutive-Specification)
- 版: `2026-08-26-成立規定-2`
- 参照commit: `e94a13ba32208aabd9dc88b6de320872963725be`
- 正本: `規定/02_大規模言語模型成立.md`

本書は上位規定をMINIDORA v0.4へ写像する局所契約であり、代替正本ではない。

旧Layer-0 v4契約は [`旧/02_Layer0責任契約_v4.md`](旧/02_Layer0責任契約_v4.md) に履歴として保持する。

## 2. v0.4で解消する旧混線

v0.3までは `src/minidora/layer0.py` の汎用命令インタプリタを、LLM機能責任の実装中心として扱っていた。

しかし実体は、算術・比較・取得・状態更新等を実行する**計算実行器**である。これは有用な運用部品だが、言語状態と成立差の関係そのものではない。

v0.4では次を分ける。

```text
LLM模型中核        != 汎用計算実行
LLM模型中核        != HDS意味Projection
LLM模型中核        != 外部参照
LLM模型中核        != 主体整合Gate
LLM模型中核        != 表面化
```

## 3. MINIDORA v0.4模型中核

現行写像は次である。

```text
対象言語状態
    ↓ 言語対応
文脈付き内部状態
    ↓ 再利用可能な模型側関係
成立差
```

実装正本: `src/minidora/模型.py`

### 言語状態

`言語状態` は、対象範囲で明示した言語体系上の状態を保持する。

既定は `自然言語:ja` だが、上位規定に従いプログラム言語等の明示体系も扱える。任意ID列を名称だけで言語へ昇格させない。

### 言語対応

`言語対応` は外部状態を模型内部で比較可能な `内部言語状態` へ写す。

現行v0.4では既存 `semantic_tokens.意味語` を内部住所として再利用する。特定tokenizer名を上位必須条件へしない。

### 文脈付き内部状態

`文脈付き言語状態` は現在状態、履歴、条件を保持する。

文脈を単なる長文履歴へ限定しない。

### 再利用可能な模型側関係

`模型関係` は、同じ関係を複数の言語状態・文脈へ適用できる実装境界である。

現行実装は、

- `関係規則` — 明示条件に基づく決定論的関係。
- `意味連続関係` — 明示文脈と候補の共有意味差だけを読む最小汎用関係。

を持つ。

候補ID、正解ラベル、benchmark名を関係条件へ埋め込まない。

### 成立差

`成立差` は候補ごとの整数差と、その寄与・根拠を保持する。

確率分布・softmax・samplingを必要としない。根拠差が0または同率の場合は、一候補へ勝手に確定しない。

## 4. 運用外周

次は模型中核の外側へ置く。

| 現行機構 | v0.4での位置 |
|---|---|
| `計算実行器` | P等の計算作用を実行する運用部品 |
| `HDS Compiler / HDS-IR` | 意味Projection・運用入力・監査履歴 |
| `参照R` | 外部Data取得 |
| `K3相当能力核` | 能力補助・観測再構成資産 |
| `主体主幹` | turn間主体状態・整合Gate |
| `採否` | 実行結果の採否境界 |
| `multilingual_surface` / `自然言語器.表面化` | 生成運用・外部表面 |

外周であることは「不要」を意味しない。LLM成立条件と責任を混ぜないための分離である。

## 5. 計算実行器

旧 `Layer0` 命令器は `src/minidora/計算実行器.py` へ再分類する。

```text
日本語命令形P
↓
計算実行器
↓
状態更新・計算結果
```

旧公開名 `Layer0` は `src/minidora/layer0.py` の互換aliasとしてのみ残す。

## 6. Runtime

`src/minidora/runtime.py` はv0.4統合入口である。

- `ミニドラ.模型核` — LLM模型中核。
- `ミニドラ.計算実行器` — 旧命令実行経路。
- `ミニドラ.言語評価(...)` — 文脈と候補から成立差を直接得る模型核API。
- 既存 `実行 / 応答` — v0.3運用経路を互換継承。

旧運用経路を残すことを、新模型核の成立証拠へしない。

## 7. HDS-IRとの暫定境界

v0.4ではHDS Compiler本体を先回り改造しない。

HDS-IRは現在、意味Projection・選択問題・命令実行等の運用外周で利用する。HDS-IRをそのままLLM内部表現またはCompute IRと同一視しない。

次段で、

```text
HDS semantic IR
→ Compute IR / 模型関係lowering
→ MINIDORA模型核 / 計算実行器
```

の境界を別途確定する。

## 8. 大規模性

v0.3のプロトタイプ性能・GPQA値を、v0.4模型核の大規模性へ自動継承しない。

上位正本に従い、

- 状態域規模
- 関係域規模
- 共有適用規模

をv0.4経路で再測定する。

したがってv0.4移行直後の大規模性状態は **再測定要** とする。これは模型性の否定ではなく、旧評価経路と新模型核を混同しないための評価境界である。

## 9. 受入条件

- 新模型核が旧Layer0命令器へ依存せず単体成立する。
- 文脈差が成立差へ到達する試験がある。
- 同じ模型関係を複数文脈へ再利用できる試験がある。
- 根拠差なし・同率で一候補へ勝手に確定しない。
- 明示したプログラム言語体系も扱える。
- `Layer0`旧名は計算実行器互換aliasに限定される。
- 既存CLI / HDS / K3 / 主体 / 参照回帰を壊さない。
- 上位正本URL・版・commitが機械監査で固定される。
