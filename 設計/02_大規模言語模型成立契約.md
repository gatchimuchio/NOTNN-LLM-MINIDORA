## 2. v0.5の二核

```text
[厳密言語模型核]
完全言語状態空間
+ 持続模型状態
→ 整合した言語確率法則

[能力模型核]
質問 / 候補 / 資料
→ 関係・証拠・状態差
→ 候補選択
```

両者を同一視しない。

## 3. 厳密言語模型実装

正本実装は `src/minidora/言語確率法則.py`。

現行成立形は有限n-gram / finite-state型である。

- NFKC正規化後のUnicode文字を記号として扱う。
- 未観測文字は `UNK` へ写像する。
- `BOS` は文脈記号、`EOS` は終端記号。
- 条件分布は加算平滑化により `Fraction` で厳密正規化する。
- 系列確率は連鎖則と終端確率の積で求める。
- 全文脈で終端確率に正の下限を持たせる。
- 模型状態を保存・復元できる。
- 無作為抽出を成立条件にしない。

この成立形を言語模型一般の唯一方式へ昇格しない。

## 4. 最小基底模型

`最小厳密言語模型()` は厳密言語確率法則の最小成立確認だけを担う。能力・知識・Large・現代LLM呼称の証拠ではない。

## 5. 能力作用構成

成立規定v8では能力を厳密言語模型性と分離した上で、観測単位を次へ開く。

```text
状態担体
作用
状態差
後続利用
参照変更
経路変更
計算量変更
再参照
再結合
循環尺度
```

これらを厳密言語模型成立条件へ混入しない。

MINIDORAでは現行HDS Compiler Architecture v1.3が `作用→状態差→後続利用` を構文化する。ただし、それは後続作用の実発火・能力改善を意味しない。

## 6. HDS境界

HDS Compiler / Data / 後段HDSは能力経路へ接続する。HDS候補得点・寄与を言語模型確率へ変換しない。

## 7. Large境界

旧v0.4規模測定は履歴として保持する。厳密言語模型成立からLargeを自動継承しない。

## 8. 受入条件

- 各条件分布の和が厳密に1。
- 系列確率が正の`Fraction`を返す。
- 終端確率下限が正。
- 形成文書順を変えても同じ模型状態hash。
- 保存・復元で同じhash・系列確率。
- 実行系が厳密言語模型核と能力核を別保持。
- 候補得点を言語模型確率へ流用しない。
- 能力作用構成を厳密言語模型性へ混入しない。
