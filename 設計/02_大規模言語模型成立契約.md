# 大規模言語模型成立契約 — MINIDORA v0.4

## 1. 論理上位正本

MINIDORAは大規模言語模型の成立条件を独自定義しない。

上位正本:

- Repository: [gatchimuchio/LLM-Constitutive-Specification](https://github.com/gatchimuchio/LLM-Constitutive-Specification)
- 版: `2026-08-26-成立規定-2`
- 参照commit: `e94a13ba32208aabd9dc88b6de320872963725be`
- 正本: `規定/02_大規模言語模型成立.md`

本書は上位規定をMINIDORA v0.4へ写像する局所契約であり、代替正本ではない。

旧Layer-0 v4契約は [`旧/02_Layer0責任契約_v4.md`](旧/02_Layer0責任契約_v4.md) に履歴として保持する。

## 2. 解消した旧混線

v0.3までLLM機能責任の実装中心として扱っていた旧Layer0命令器は、実体が算術・比較・取得・状態更新等の汎用命令インタプリタであるため、v0.4で **計算実行器** へ再分類した。

```text
LLM模型中核 != 汎用計算実行
LLM模型中核 != HDS意味Projection
LLM模型中核 != 外部参照
LLM模型中核 != 主体整合Gate
LLM模型中核 != 表面化
```

## 3. MINIDORA v0.4模型中核

```text
対象言語状態
    ↓ 言語対応
文脈付き内部状態
    ↓ 再利用可能な模型側関係
成立差
```

実装正本:

- `src/minidora/模型.py`
- `src/minidora/言語構造.py`

### 言語状態

`言語状態` は、対象範囲で明示した言語体系上の状態を保持する。

既定は `自然言語:ja` だが、上位規定に従いプログラム言語等の明示体系も扱える。任意ID列を名称だけで言語へ昇格させない。

### 言語対応

`言語対応` は外部状態を模型内部で比較可能な `内部言語状態` へ写す。

内部状態は現在、

- 意味語集合
- 意味語列
- 有向関係構造
- 肯否
- 条件結合

を保持する。

特定tokenizer名を上位必須条件へしない。

### 文脈付き内部状態

`文脈付き言語状態` は現在状態、履歴、条件を保持する。

履歴順序を集合和へ潰さず、近接位置の差を模型関係へ到達させる。

### 再利用可能な模型側関係

標準模型核は次の一般関係作用を持つ。

1. `意味連続関係`
2. `順序連続関係`
3. `有向関係整合`
4. `肯否整合関係`
5. `履歴近接関係`
6. `条件結合関係`

固定端点やbenchmark正答を個別規則へ埋め込まず、同じ関係作用を異なる言語状態・端点・文脈へ再利用する。

模型核はHDS-IR / HDS Compilerへ依存しない。

### 成立差

`成立差` は候補ごとの整数差と、その寄与・根拠を保持する。

確率分布・softmax・samplingを必要としない。

**正の成立差が一意に生じた場合だけ一候補へ確定する。** 同率、0、負値のみでは勝手に確定しない。

## 4. 運用外周

| 現行機構 | v0.4での位置 |
|---|---|
| `計算実行器` | P等の計算作用を実行する運用部品 |
| `HDS Compiler / HDS-IR` | 意味Projection・運用入力・監査履歴 |
| `参照R` | 外部Data取得 |
| `K3相当能力核` | 能力補助・観測再構成資産 |
| `主体主幹` | turn間主体状態・整合Gate |
| `採否` | 実行結果の採否境界 |
| 表面化 | 生成運用・外部表面 |

外周であることは不要を意味しない。LLM成立条件と責任を混ぜないための分離である。

## 5. 計算実行境界

```text
日本語命令形P
↓
命令計算降下
↓
計算中間表現 v1
↓
計算実行境界 v1
↓
計算実行器
```

旧公開名 `Layer0` は `src/minidora/layer0.py` の互換aliasとしてのみ残す。

## 6. HDS Compiler境界

Meaning/Audit Architectureは `v1.2`、Pipelineは `v1.3`。

```text
自然言語
↓
意味コンパイル
↓
意味HDS-IR
├─ R / K / J / 監査
└─ 計算計画
   ↓
 計算降下
   ↓
 計算中間表現 v1
```

- 意味正本IRへPと計算初期状態を内包しない。
- 計算降下で自然言語を再解析しない。
- 旧 `コンパイル()` は互換窓口に限定する。

## 7. Runtime

`src/minidora/runtime.py` はv0.4統合入口。

- `ミニドラ.模型核` — LLM模型中核
- `ミニドラ.計算実行器` — 計算実行経路
- `ミニドラ.言語評価(...)` — 文脈と候補から成立差を得る模型核API
- `実行 / 応答` — 既存運用経路の互換統合

運用経路全体を模型核の成立証拠へしない。

## 8. 大規模性

v0.3のGPQA等の性能値をv0.4模型核の大規模性へ自動継承しない。

上位正本に従い、

- 状態域規模
- 関係域規模
- 共有適用規模

をv0.4模型核単体で再測定した。

初回v1は関係域不足のため `未成立`。関係構造修正後のv2は、明示した比較集合・対象範囲で **`局所成立候補`** と判定した。

v2主要値:

- 状態域: 384 / 384内部状態識別
- 3言語体系
- 10,000文字状態、履歴深さ256を受理
- 一般関係族: 17 / 17
- 関係構造: 544 / 544識別
- 方向 / 肯否 / 履歴順序 / 条件結合: すべて成立差へ到達
- 共有適用: 256 / 256
- 模型関係実体: 6

正本記録: [`../評価/MINIDORA_v0_4_規模測定_v2_2026-08-26.md`](../評価/MINIDORA_v0_4_規模測定_v2_2026-08-26.md)

この判定は現代ニューラルLLMとのparameter数・計算量・benchmark性能の同等を意味しない。

## 9. 受入条件

- 模型核が旧Layer0命令器へ依存せず単体成立する。
- 文脈差が成立差へ到達する。
- 同じ模型関係を複数状態・文脈へ再利用できる。
- 方向・肯否・履歴順序・条件結合を無言で潰さない。
- 正の成立差が一意でない場合、一候補へ勝手に確定しない。
- 明示したプログラム言語体系も扱える。
- `Layer0`旧名は計算実行器互換aliasに限定する。
- HDS意味IRと計算表現を再統合しない。
- 既存CLI / HDS / K3 / 主体 / 参照回帰を壊さない。
- 上位正本URL・版・commitが機械監査で固定される。
- 大規模性は一点閾値でなく三面＋物理値を併記する。
