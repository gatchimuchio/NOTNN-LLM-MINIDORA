# MINIDORA 会話合成・再計画 v0.1

日付: 2026-09-11。第18バッチ。
基点: `7eb3eeefe07fcbb033d232d27b9e14f553a02b3f`（第17バッチ）。

## 1. 目的と今回の到達範囲

能力の名前を増やすのではなく、二つの資料の数値比較・記載照会を、要求解釈・複数入力の合成・不足時の再計画・回答構成・確認会話まで実際に閉じる。既存の数学・文書・限定コードの目的実行も同じ採用状態へ接続する。

```text
発話と明示した資料
→ 実公開HDS
→ 対象・属性・単位・条件・時点、依頼／質問／補充／訂正
→ 複数素材の役割付き目的
→ 登録作用の後方計画
→ 既存合成器と能力
→ 資料不足なら対象を保った経路変更、又は利用者へ確認
→ 比較結論・記載値・差分・適用範囲・根拠・残差の回答意味
→ 文章化
→ 全体成立後の採用
→ 同じ会話から補充・訂正・再参照
```

これは有限の日本語数値照会・比較を中心とする初版である。自由な会話全般、一般的な因果推論、未知アルゴリズム発見、任意文書の意味理解や自由作文を完成したものではない。GPT-4同等性は認定しない。

## 3. 意味射影と会話行為

引用で示した一つ又は二つの対象、属性、単位、明示した条件・ISO日付を再利用可能な欄へ分離する。述語は「比較」「照会」という成果目的を表し、Module名や工程列を返さない。

```text
「装置A」と「装置B」の電圧をVで比較して
「装置A」と「装置B」の電圧はどちらが大きい？
条件「通常」で、2026-09-11時点、「装置A」の電圧をVで調べて
```

単位がないときは未指定のまま保持し、「単位はVです」という補充を受けて元の要求へ戻る。「訂正：単位はmVです」は前の比較条件を改訂し、元の資料から再計算する。未対応の否定・但し書き・後半命令は捨てず、全体を保留する。

公開HDSの導出規則は変更しない。原文・未確定座標・関係・残差を照合し、対応していない意味を分類名だけで解消しない。任意の言い換え、語義選択、長い談話の解釈はまだ対象外。

## 4. 複数入力の計画

`役割状態`は成果種別と具体的対象の組を持つ。`結合作用`は入出力の役割、設定構成、外部読取、費用、回復可能な失敗を宣言する。

```text
左の証拠 ─┐
          ├→ 二対象関係化 → 比較導出 ─┐
右の証拠 ─┘                         ├→ 回答意味 → 文章化
左の証拠・右の証拠 ─────────────────┘
```

この工程列を入力文ごとの固定配列として返さない。必要状態から登録作用を逆引きし、各入力役割に対応した対象の経路を求める。同じ中間成果は共有し、左右を入れ替えると束縛も変わる。別対象の同型素材で欠落を埋めない。

探索は外部読取数、宣言費用、実行工程数の順に最小化する。異なる同順位計画は未確定として停止する。循環、深さ・展開数・候補数、64工程の既存上限を守る。最適性はこの有限登録・予算内の候補に限る。

今回の具体的作用は局所記載、取得、取得記載、関係化、関係導出、比較又は照会の回答意味、文章化の9宣言。計画器そのものは複数入力の役割構成を扱うが、実装されていない一般推論を出力型だけで生成しない。

## 5. 実行監督と再計画

各試行の目的・条件のhash、計画hash、実行履歴、理由を保持する。新しい候補でも対象・属性・単位・条件・時点・出力予算を緩めない。

回復できるのは、登録された`会話記載解釈`が返す`資料不足`であり、その作用が回復を宣言し、外部読取が許可されている場合だけである。失敗した対象の局所経路だけを除外し、その対象の取得経路を再探索する。

例えば両方の資料がない場合、局所A不足→A取得後にB不足→A取得結果を同一要求内で再参照してB取得→比較・回答という経路になる。外部取得済み本文は同一ターン・同一条件・同一所有状態だけで再参照し、次の利用者要求では再取得する。GETは取り消せない。

矛盾、条件不一致、未解釈を資料不足と扱ってWebの都合のよい値で置き換えない。任意の例外文や資料中の署名風文字列を回復指示にしない。失敗理由は試行ごとにリセットし、前試行の理由で新しい環境失敗を説明しない。反復回数上限、同一計画の反復禁止、停止要求、状態世代変更を検査する。

## 6. 知識取得と境界

検索目的は発話中で明示した対象・属性・条件・時点・単位から構成する。資料全文・過去会話・自動抽出した秘密を検索語へ送らない。

既存`知識取得器`、SearXNG供給器、検査済みHTTPS本文取得を利用する。セッション作成時と当該実行時の二重許可が必要で、確認返答や資料中の命令から権限を引き継がない。CLIの`--外部読取`は両方への明示指定である。

検索語の構成と、取得本文が一般的なWeb情報として十分・正しい・最新であるという判断は別。今回の取得接続試験では実取得器と実本文復号器を使い、検索応答・HTTP供給だけを人工化した。実Web品質や実運用検索サービスの可用性は未実測。GPQA正本の参照や性能値は変更しない。

## 7. 回答意味と文章化

数値証拠と関係結果を再照合し、結論、記載値、差分、適用範囲、留保、根拠引用、未解釈、出典を別節にする。比較・照会ではModule本文を貼り合わせず、報告の意味Dataから節を組み立てる。否定、不等号、競合する値、別条件の記載、未解釈の原文範囲を保持する。

差分を数値で出せるのは両側の一意な記載値が採用可能な場合だけ。範囲から大小を導けても一点や差は捏造しない。単位をVからmVへ訂正すれば、同じ資料から表示値と差分を再計算する。

文章化前に元成果から回答意味を再構成する。hashを書き直して節を改変しても、再構成との差で拒否する。ただし内部整合検査であって、出典の真正性や世界の事実性を保証するものではない。回答予算が足りなければ必須内容を切断せず、最終成果を採用しない。

数学・文書・コード等の旧目的経路は、まず「既存成果」として原結果と由来を保持する回答意味へ接続する。この経路の本文は元Moduleの出力であり、任意の説明や自由作文へ一般化したとは扱わない。

## 8. 会話状態・訂正・採用

発話の保存は事実採用と別。確認待ちには目的・資料・適用範囲・元要求・出力仕様を保存し、補充・資料追加後に同じ要求を再開する。別目的で確認待ちを無言上書きせず、取消を要求する。

明示訂正は改訂後の条件で再実行し、過去の採用履歴を消さない。任意の誤記訂正や長期依存全体の失効伝播までは未実装。保留中又は改訂対象の世代が変わっていれば古い要求を実行しない。

旧数学結果の「それ」は、文章化した文字列ではなく保持した元成果へ戻す。複数成果の曖昧な照応を一つに潰さない。新旧の処理は同じ統合セッションの準備・実行・採用を通す。回答が不成立なら途中結果で成功焦点を上書きしない。

発話記録と確認待ち状態はメモリ内。永続化・自由な話題転換・一般的な定義や主張の会話状態は未実装。既存長文脈庫への採用接続は維持する。

## 9. 起動方法

```powershell
python tools/汎用チャット.py
python tools/汎用チャット.py '「x**3」をxで微分して'
python -m minidora.製品版 --汎用 '「2+3」を計算して'
```

比較資料を明示する場合:

```powershell
python tools/汎用チャット.py --資料 装置A=a.txt --資料 装置B=b.txt
```

`a.txt`を`装置Aの電圧は5Vです。`、`b.txt`を`装置Bの電圧は3Vです。`とした人工例:

```text
利用者: 「装置A」と「装置B」の電圧はどちらが大きい？
応答: 比較・照会に使う単位を指定してください。
利用者: 単位はVです
応答: Aの方が大きい。記載値は5Vと3V、差は2V。（本文には条件・留保・出典も付く）
利用者: 訂正：単位はmVです
応答: 記載値は5000mVと3000mV、差は2000mV。
```

`/資料 名前=パス`で資料を追加・置換し、`再開して`で確認待ちへ戻れる。`/初期化`は資料と会話を消去、`/終了`は終了する。`--json`で目的と試行履歴、`--形式 箇条書き`で出力形式を指定する。資料はUTF-8又はUTF-8 BOM、本文合計1MB以内。外部取得を有効にする場合は既存検索サービス設定も必要。

標準製品CLIの`--汎用`は選択入口であり、既定の製品API・HTTP・GUIを置換しない。

## 10. 残る開発

非数値の命題・因果・一般文書理解、任意言い換え、一般的な計画失敗の原因分解と修復、未知の解法生成、全能力の意味付き接続、汎用説明・作文は残る。今回の9作用・4接続部品・107件の新規確認を、それらの完成へ読み替えない。実装で観測した不足を後続の設計と能力拡張へ戻す。
