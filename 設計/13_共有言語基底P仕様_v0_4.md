# 共有言語基底P仕様 v0.4

## 1. 目的

共有言語基底Pは、HDS CompilerとMINIDORA計算主体が共通参照する常在言語資産である。

v0.4では言語責任を次のように固定する。

```text
日本語
= 唯一の基底言語
= 唯一の規定言語
= 内部意味正本

外国語
= 実務上必要な外部互換表層
= 必要時だけ日本語正本へ射影
```

英語を第二基底または主要基底として扱わない。現状英語処理が多いのは外部資料・API・評価集合の実務上の比率によるものであり、内部理論上の特権ではない。

## 2. P / M / Rの境界

```text
共有言語基底P
= 日本語文字・語・文法・基底概念
+ 外部言語を日本語意味へ接続する最小互換資産

M
= 実行経験・根拠・仮説・作業状態

R
= 世界について必要時に取得する外部資料
```

世界事実を正しいという理由だけでPへ入れない。

## 3. 日本語正本

Pで内部正本として保持するもの:

- ひらがな
- カタカナ
- 漢字
- 数字・補助記号
- 日本語の基本文法機能
- HDS/Pで使用する基底概念
- 状態・関係・作用・境界・採否の日本語語彙
- 日本語の活用・意味関係の必要部分

漢字は一文字であっても表意記号として保持し、英字一文字と同じ雑音規則で捨てない。

## 4. 外部言語互換

外国語処理はPの外部互換機能として保持する。

現在実装では英語の語形・文法・一般関係を主に扱うが、名称上も意味上も「英語基底」としない。

```text
外部英語表層
→ 語形・文法認識
→ 日本語関係概念
→ 日本語意味正本
```

例:

```text
generated / generation
→ generate
→ 生成

inhibited / inhibition
→ inhibit
→ 阻害
```

`generate` や `inhibit` は外部互換用の基本形であり、内部関係正本は `生成`、`阻害` である。

## 5. 外部言語識別コード

`ja`、`en`、`zh` 等は入力・API・成果物互換のための識別コードとして使用できる。

ただし、

```text
基底言語 = 日本語
基底言語コード = ja
```

を分離する。

識別コードから内部意味構造を決めない。

## 6. 外部原語の保存

外部語を失うと再検索・出典照合・互換処理ができなくなるため、対応語として保持してよい。

ただし、内部概念と外部原語を同じ欄へ潰さない。

```text
内部正本: 生成
外部対応: generate / produce
```

外部語同士の差が日本語概念上一つへ潰せない場合は、無理に統合せず日本語側の概念分別を再監査する。

## 7. Compiler側責務

HDS Compilerは共有言語基底Pを使って、入力表層を日本語意味構造へ射影する。

Compilerは世界知識の真偽や最終採否を行わない。

外国語入力でも、内部IRへ持ち込む関係・作用・状態名は日本語正本を優先する。

## 8. MINIDORA側責務

MINIDORAは日本語正本の意味語・関係語で照合する。

外国語表層は必要な外部参照や互換境界でだけ再利用する。

```text
内部: 何を意味するか
外部: 何という表層で接続するか
```

を分ける。

## 9. 不変条件

```text
規定言語は日本語
基底言語は日本語
内部意味正本は日本語
外国語は例外的外部互換
外部識別コードと基底言語を同一視しない
世界知識を言語基底へ混入させない
外部原語から未観測関係を捏造しない
意味衝突時は日本語正本を再監査する
```

## 10. 受入条件

- `規定言語 == 日本語`
- `基底言語 == 日本語`
- `基底言語コード == ja`
- 日本語入力を日本語として保持する
- 外国語入力を識別できる
- 外国語関係語が日本語関係概念へ射影される
- 外国語表層が内部正本へ昇格しない
- 一文字漢字を意味記号として保持する
- 既存の外部英語評価経路を壊さない
- Linux / Windows CIを通過する
