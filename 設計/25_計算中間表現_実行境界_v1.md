# 計算中間表現 / 計算実行境界 v1

## 1. 目的

MINIDORAの意味処理と計算実行を分離する。

外部で一般に `Compute IR / ABI` と呼ばれる境界を、本リポジトリでは次の日本語を正本名とする。

- **計算中間表現** — 実行直前の計算専用中間表現
- **計算実行境界** — 計算中間表現を消費する実行契約

`IR` / `ABI` は外部技術語との接続ラベルとしてのみ使う。

## 2. 非同一性

次を固定する。

```text
HDS-IR != 計算中間表現
日本語命令形P != 計算中間表現
LLM模型中核 != 計算中間表現
計算実行器 != LLM模型中核
HDS Compiler != 計算実行境界
```

HDS-IRは意味・関係・残差・由来を保持する。
日本語命令形Pは人間および上流設計が読める運用命令である。
計算中間表現は、意味解釈後に実行器が必要とする情報だけを保持する。

## 3. 現行経路

```text
日本語命令形P
      ↓ 命令計算降下
計算中間表現 v1
      ↓
計算実行境界 v1
      ↓
計算実行結果
```

現行HDS互換経路:

```text
HDS semantic IR
      ↓ HDS計算降下
計算中間表現 v1
```

ただし現行HDS-IRはv0.3由来の `手順` を内部に保持しているため、`HDS計算降下` v1はその閉包済み手順を利用する**移行用降下境界**である。

次段のHDS Compiler再設計ではsemantic frontendとcompute lowering backendを分離し、`HDSIR.手順`を意味IRの正本責任から外す。

## 4. 計算値

文字列規約で値と状態参照を混同しない。

v1は次の3種を型で分ける。

| 種別 | 意味 |
|---|---|
| `即値` | その値自体を入力に使う |
| `状態値` | 指定住所に現在保持されている値を読む |
| `状態住所` | 値ではなく住所自体を操作対象にする |

旧Pの `$a` は計算中間表現では `状態値("a")` へ降下する。

```text
"$a"
  ↓
状態値("a")
```

計算実行境界は `$` 文字列を解釈しない。

## 5. 計算命令

計算命令は最低限次を持つ。

```text
命令ID
名称
計算作用
入力
対象住所
出力住所
根拠
境界
```

命令IDは一つの計算中間表現内で一意とする。

v1で受理する作用:

```text
設定
取得
抽出
加算
減算
乗算
除算
比較
計数
結合
交換
反転
停止
```

これはLLMの普遍能力一覧ではない。現行MINIDORA計算実行器のABI v1が受理する作用集合である。

## 6. 計算中間表現

計算中間表現は次を持つ。

```text
名称
命令列
出力住所
由来
由来参照
境界
検証
版
```

`由来参照`は監査用の不透明な参照であり、計算実行境界はその意味を解釈しない。

HDS座標名、文書ID、上流手順名等を由来参照へ残してよいが、それらを実行条件へ暗黙変換してはならない。

## 7. 計算実行境界

計算実行境界v1は次だけを行う。

1. 計算中間表現の構造検証
2. 型付き値参照の解決
3. 指定計算作用の実行
4. 状態更新
5. 計算履歴の記録
6. 指定出力住所から結果を取得

行わないこと:

- 自然言語解析
- HDS関係解釈
- LLM候補生成
- 外部検索
- 正解ラベル推定
- 主体更新
- 採否判断
- 表面化
- 未記載作用の類推実行

## 8. 作用別の型境界

### 通常値

算術・比較・抽出・計数・結合・反転は `即値` または `状態値` を取る。

`状態住所`を通常値として使用しない。

### 取得

`取得`は `対象住所` を明示する。

### 交換

`交換`だけは2個の `状態住所` を取る。

これにより、

```text
状態の値
```

と

```text
状態を置く住所
```

を同じ文字列として扱わない。

## 9. 互換P降下

既存の日本語命令形Pは削除しない。

`計算実行器.実行(手順)` は内部で必ず次へ変換する。

```text
手順
 ↓
命令計算降下
 ↓
計算中間表現
 ↓
計算実行境界
```

したがって旧API互換を維持しても、v1以降の実計算経路は計算中間表現を迂回しない。

## 10. HDS降下

現行 `HDS計算降下` は次を条件とする。

- HDS-IRが実行可能
- 実行入力座標が欠落していない
- 実行入力が未確定・未観測・矛盾・留保ではない
- semantic_loss残差がない
- 閉包済み互換手順が存在する

自然言語原文は再解析しない。

HDS実行核の入力座標・出力座標・境界・検証は、計算中間表現の由来参照・境界・検証へ保持する。

## 11. 失敗境界

計算実行境界は未対応作用や型不整合を推測で補わない。

例:

```text
加算へ状態住所を入力
→ FAIL

交換へ即値を入力
→ FAIL

比較演算子が未対応
→ FAIL

0除算
→ FAIL
```

HDS意味側の未確定は計算中間表現へ昇格する前に止める。

## 12. 決定論

同一の、

```text
計算中間表現
+
初期状態
```

に対して、計算実行境界v1は同一の状態・履歴・出力を返す。

外部時刻、乱数、ネットワーク、モデルAPIをABI内部から参照しない。

## 13. 実装正本

- `src/minidora/計算中間表現.py`
- `src/minidora/計算実行境界.py`
- `src/minidora/命令計算降下.py`
- `src/minidora/HDS計算降下.py`
- `src/minidora/計算実行器.py`

受入試験:

- `tests/test_計算IR_ABI.py`

## 14. 次段

Compute IR / ABI v1確定後の次工程はHDS Compiler再設計とする。

目標:

```text
自然言語
 ↓
HDS semantic frontend
 ↓
意味HDS-IR
 ↓
compute lowering backend
 ↓
計算中間表現
 ↓
計算実行境界
```

この時、semantic HDS-IRへ計算命令列を直接抱え込ませない。

LLM模型核への言語状態・文脈・候補形成入力と、計算実行器への計算作用も同じIRへ混ぜない。

## 15. 受入条件

- `$`文字列をABIが解釈しない。
- 即値・状態値・状態住所が型で分かれる。
- 旧P経路も計算中間表現を経由する。
- HDS未閉包入力をCompute IRへ昇格しない。
- ABIが自然言語/HDS/模型核/外部Rへ依存しない。
- 同一IR+初期状態で同一結果を返す。
- 既存Runtime回帰を維持する。
- Linux / Windows CIを通過する。
