# MINIDORA 能力合成 v0.1

日付: 2026-09-10
状態: 明示計画の合成実行を実装。自由文からの計画生成は未実装。
基点commit: `72797083b88d4e3614324065ecd7bc775980f748`

## 1. 目的と完成範囲

汎用Capability開発一覧の②「Capability合成・実行計画」のうち、**明示された計画を依存関係に従って複数Moduleへ実行し、中間結果を後続入力へ接続する局所機構**を実装する。

初回差分はUIではない。モデル核の置換、HDSの再定義、GPT-4同等性の認定でもない。

```text
上位の要求解釈・判断（本差分で代替しない）
    ↓ 明示計画 + 指示・設定・素材Data
能力合成器
    ↓ 依存解決 / 明示候補の試行
既存Capability Module
    ↓ 中間結果を後続工程へ束縛
全指定出力の完了、または保留・失敗・中止
    ↓
上位の採否・会話状態更新（本差分で代替しない）
```

合格は「登録された能力が成立を返し、指定工程の実行契約が閉じた」を意味する。意味解釈の正しさ、根拠十分性、回答の事実性は別責任である。

## 2. 既存境界との関係

- [Module拡張境界](35_MINIDORA_能力Module拡張境界_v1.md) を維持する。
- [局所解釈起点](36_MINIDORA_局所解釈起点_v1.md) の状態を本合成器から直接更新しない。
- [計算中間表現と実行境界](25_計算中間表現_実行境界_v1.md) を置換しない。本計画はCapability呼出の依存関係であり、既存の算術命令ABIではない。
- HDS-IRの関係や作用差分を、勝手に本計画へ変換しない。
- HDS Compiler、模型核、科学Module、GPQA経路、GUI-Shell、既存の標準チャット入口は変更しない。
- 原文・設定値・参照本文は初期Dataへ分離する。合成工程に埋め込むのは識別子と参照先だけとする。

## 3. 公開型

| 型 | 責任 |
|---|---|
| `素材参照(領域, 識別子)` | `入力`または`工程`のどちらを読むかを型で指定する。本文中の文字列は参照命令にしない。 |
| `合成工程(識別子, 能力候補, 指示参照, 入力, 設定参照)` | 能力候補は明示順の代替候補。指示・設定は初期Dataのキーを指定する。 |
| `合成計画(工程, 出力工程)` | 依存グラフと、すべて完了すべき終端集合。 |
| `登録能力(Module, 外部読取=False)` | 既存`能力Module`契約の実体と、呼出者が管理する効果宣言。 |
| `合成結果` | 全指定出力、中間結果、実行記録、終了理由、ハッシュ。 |

`能力結果`・`能力文脈`・`参照資料`は既存の型を再利用する。新たな「第二のCore」は作らない。

## 4. 事前検証

全工程の構造を確認してから最初の能力を呼ぶ。

未登録能力、必要Dataの欠落・未成立、未許可の外部読取では保留する。工程ID重複、参照先不正、依存循環、出力指定不正、出力に寄与しない工程、型不正、Dataサイズ超過では失敗する。

出力に寄与しない工程を黙って実行しない。複数の独立した成果が必要なら、それぞれを出力工程に指定する。

依存解決は標準ライブラリ`graphlib.TopologicalSorter`を使用する。独立工程の順序は工程IDを整列して決定する。並列実行はこの版には含まない。

## 5. Data束縛と後続利用

各工程の能力文脈は次のように構成する。

```text
初期Data[指示参照].本文 → 能力文脈.入力文
指定した素材の本文     → 能力文脈.直前応答
指定素材の参照来歴     → 能力文脈.直前参照
素材ごとの参照先・結果 → 能力文脈.補助["合成入力"]
初期Data[設定参照].データ → 能力文脈.補助["合成設定"]
```

複数本文の結合は互換入力であり、各素材の区別は`合成入力`に残る。上位会話の直前本文・参照を素材未指定時に勝手に使用しない。

指示参照と設定参照は初期Dataだけを指す。資料本文や前段回答から新しい指示を自動生成・実行しない。上位が作った計画と元要求の意味的な一致を検証する①は、別の未完了課題として残す。

Dataは文字列キーを持つJSON互換値に限定し、非有限数・循環構造・過深な入れ子を拒否する。任意のHDSオブジェクトを文字列化して受理することはしない。

原入力、呼出時文脈、中間結果、最終出力の可変部分を複製して分離する。判定処理が入力を書き換えても、その変異を実行処理に渡さない。

## 6. 候補・失敗・採否

候補順序は計画が明示した順序を用いる。`判定`の数値は適用可否の契約値であり、回答正答率には読み替えない。

非該当、不成立、能力例外の後は、同じ工程に明記された次候補だけを試す。未指定のCore、外部LLM、他の登録能力へ暗黙委譲しない。

すべての指定出力が揃った場合だけ`合格`とする。途中失敗で得られた部分値は`中間結果`に残すが、`出力`を空にし、全体成功に昇格させない。

能力呼出例外の本文は監査記録へそのまま転記せず、例外型を記録する。

## 7. 参照来歴と監査

入力素材の参照と能力の返却参照を終端まで保持する。同じ識別子で異なる内容を持つ参照を黙って上書きしない。異なる識別子を持つ相反する資料は、そのまま別資料として残る。

**これは消費した資料の来歴であり、各文章を資料が含意するという証明ではない。** 根拠十分性・主張ごとの対応・資料矛盾の意味的解消は⑤の課題として残す。

記録には工程、能力名と版、呼出有無、状態、理由、入力・出力ハッシュ、前記録ハッシュを含める。開始時には計画、Data、基点文脈、能力版、効果宣言、許可、上限を固定する。終端ハッシュには終了状態と成果を含める。

`監査整合()`は記録の内部整合だけを検査する。署名、WORM、出典の真正性、改ざん不能性を提供しない。事前検証不成立の場合は準備前の識別ハッシュと理由を記録し、不正入力全量の保存を保証しない。

## 8. 効果・予算・中止

既定上限は64工程、128候補試行、宣言または各入出力資料2,000,000バイト。上限を超えた結果は採用しない。

外部読取は既定で不許可とする。効果宣言は信頼する登録コードの契約であり、悪意あるPythonコードや虚偽申告を隔離するセキュリティサンドボックスではない。書込み・送信・任意OS操作は今回の登録対象外とする。

停止要求を能力の判定前後・実行前後・完了前に確認する。処理中の停止要求が戻り時に観測された場合、その結果を採用しない。停止判定器の故障から代替能力実行へ進まない。

実行中のPython処理やネットワークを強制終了する機能はない。外部読取能力側でタイムアウトを設定する必要がある。

## 9. 既存Moduleへの接続

`能力合成_局所接続.py`は次の薄いAdapterだけを追加する。

| 合成能力名 | 呼ぶ既存実装 | 設定 |
|---|---|---|
| 抽出要約 | `製品版/要約.py` | 行数1〜8。未指定は3。範囲外を黙って丸めない。 |
| 情報抽出 | `製品版/抽出.py` | 種別を`数字 / URL / キーワード`から明示。不明種別を既定キーワード抽出にしない。 |
| 文脈変換 | `製品版/変換.py` | 形式を`箇条書き / 短く`から明示。 |

未知の設定を無視しない。要約・抽出・短文化の品質は既存実装の限界を継承する。これらのAdapterを、新規の汎用言語理解・生成能力として計数しない。
