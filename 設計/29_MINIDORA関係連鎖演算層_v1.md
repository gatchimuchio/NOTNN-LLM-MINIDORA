# MINIDORA 関係連鎖演算層 v1

日付: 2026-08-28
状態: サンドボックス受入中
基底言語: 日本語

## 1. 根拠

GPQA Diamond実測と既存LLM横断構文化の再監査から、現行MINIDORAの数値は主として候補への寄与順序を表す序数であり、関係状態そのものを次段へ渡して変換する推論状態としては不足していた。

既存LLM構文化で共通して観測したのは、特定のAttention/MoE等ではなく、

```text
内部状態
↓ 作用
更新状態
↓ 別作用
再更新状態
↓
…
```

という、変換後状態が後段作用の入力になる連鎖である。

最初のサンドボックス試行では、これを `因果 / 増加 / 阻害...` という文法上の因果族だけへ限定した。その版は単体試験では成立したが、GPQA 198問で `CAUSAL_DERIVATION_APPLIED=0` となり、実入力へ作用しなかった。よって因果動詞の推移律としてではなく、より上位の **関係連鎖・連想演算** として再構成する。

## 2. 責任位置

```text
自然言語 / 外部Data
  ↓
HDS Compiler
  ↓
正式MINIDORA入力
  ├─ 問い関係
  ├─ 問題文中の確定事実関係
  └─ 外部Data関係
  ↓
MINIDORA
  ├─ 既存直接関係照合
  ├─ 関係連鎖演算
  └─ 候補成立差形成
  ↓
MINIDORA出力
  ↓
後段HDS
  ├─ APPROVE → OUTPUT
  ├─ HOLD    → SILENT
  └─ REJECT  → SILENT
```

後段HDSへ元Question / Data / Referenceを渡さない。再検索・再計算・差し戻しもMINIDORA単体へ持たせない。

## 3. 前段入力射影

旧 `HDSK質問射影()` は旧K/helper候補比較用であり、問い関係へ縮約する。

正式MINIDORAでは別に `HDS模型質問射影()` を持ち、

- 問い関係
- 問題文中の確定済み背景関係

を同時に保持する。

推定・未確定・未観測・矛盾・留保の背景関係を推論前提へ昇格しない。候補・検索制御メタも世界事実へ昇格しない。

## 4. 関係の数値状態

17一般関係族には安定した数値IDを与える。

```text
因果=1 / 増加=2 / 減少=3 / ... / 由来=17
```

未知・開放述語は安定hashから既知番号と衝突しないIDへ写す。

この番号は意味の大小や信頼度ではない。関係identityを計算状態へ保持するための座標である。

各一段は、

```text
(関係ID, 方向, 極性)
```

を持つ。

したがって、

```text
A -所属-> B -使用-> C
```

は、例えば

```text
[(所属ID,+1,+1), (使用ID,+1,+1)]
```

という順序付き数値状態として保持する。

## 5. 世界事実への誤縮約禁止

`A -R1-> B -R2-> C` が存在しても、一般に `A R? C` という単一の新世界事実が成立するとは限らない。

よって本層は、関係列を勝手な推移律で一関係へ潰さない。

形成するのは、

```text
始点
終点
関係数値列
関係種別列
深さ
出典列
条件
訪問節点
```

を持つ **関係連鎖状態そのもの** である。

候補評価はこの形成後に行う。

## 6. 連鎖規則

- 深さ1は既存直接照合へ任せ、本層は深さ2以上だけを推論状態とする。
- 前段状態の終点と次関係の始点が意味同一なら接続する。
- 同一経路で同じ辺を再利用しない。
- 同一経路で同じ節点へ戻らない。
- 最大深さは既定4。
- 最大状態数は既定4096。
- 条件が衝突する関係は接続しない。
- 否定関係を反対の正関係へ読み替えず、連鎖支持には使わない。
- 相関・結合・相互作用は観測上対称関係として逆向きアクセスを許す。
- 他関係は無言で逆向きへしない。

## 7. 候補との接続

関係連鎖は候補を見て生成しない。

```text
問題文前提 + Data
↓
候補非依存の関係連鎖状態形成
↓
候補代入済み問い関係 / 候補命題との端点照合
↓
多段到達があれば候補へ +1
```

経路数・深さ・source数を候補点へ水増ししない。一候補に複数経路があっても、本作用が返す差は一回の `+1` のみ。

複数候補へ同じように到達すれば、それぞれ同じ差を受けるため、本作用だけで一意化しない。

反転/except型では「経路がない」を反証とみなせないため、本作用を採否差へ使わない。

## 8. 旧因果限定試行との境界

旧サンドボックス試行は、

```text
因果 / 増加 / 活性化 / 生成
減少 / 阻害 / 防止
```

だけを符号積で連鎖した。

これは局所演算として成立したが、GPQA実測で候補差へ一度も到達しなかったため正本化しない。最終成果物へ旧因果モジュール・試験・仕様は残さない。

## 9. 監査指標

正式実測では少なくとも次を記録する。

- `RELATION_CHAIN_STATE_FORMED`
- `RELATION_CHAIN_STATE_NOT_FORMED`
- `RELATION_CHAIN_STATES:n`
- `RELATION_CHAIN_MAX_DEPTH:n`
- `RELATION_CHAIN_TRUNCATED:0/1`
- `RELATION_CHAIN_APPLIED`
- `RELATION_CHAIN_NOT_APPLIED`
- `RELATION_CHAIN_CONTRIBUTIONS:n`
- `RELATION_CHAIN_CANDIDATES:n`

また、正式模型の `checkpoint再活性数 / 大域再照合数 / 候補横断更新数` をRuntimeで0固定せず、模型統計の実値から返す。

## 10. 受入条件

- 異種関係 `A-R1-B-R2-C` を順序付き数値列として保持できる。
- 関係列を単一の世界事実へ誤縮約しない。
- 問題文中の確定前提と外部Dataを跨いで連鎖できる。
- 旧K/helperへ正式模型用の背景前提を逆流させない。
- 推定背景関係を推論前提へ昇格しない。
- 相関等の対称関係だけ逆向きアクセスできる。
- 否定を逆作用へ変換しない。
- 循環で経路を自己増幅しない。
- 経路数で候補差を水増ししない。
- 反転問題で不存在を反証扱いしない。
- 後段HDS output-only / SILENT / NO_FEEDBACK_LOOPを壊さない。
- Linux / Windows × Python 3.11–3.14を全通過する。
- GPQA実測で関係連鎖の形成・適用が観測できる。

GPQAの点数上昇だけを成立条件にしない。ただし現行正本に対する明確な性能退行が生じる場合はmainへ還元しない。
