# 三層射影忠実度契約 v1

- 日付: 2026-08-26
- 対象: MINIDORA v0.4
- 状態: 実装契約
- ライセンス: CC-BY-4.0

## 1. 対象

```text
実LLM
↓ ① 構文化
能力保存作用則
↓ ② HDS Compiler
意味HDS-IR
↓ ③ MINIDORA射影
正式MINIDORA模型核
```

MINIDORA独自の能力設計を追加する契約ではない。三段の意味・作用保存精度を一致させる契約である。

## 2. ① 構文化

K3 D4と10モデル第二巡の高位作用を、実行可能な部品非依存作用則へ落とす。

必須:
- 状態分離
- 意味同一性
- 寄与Gate
- checkpoint / 累積状態保持
- 再結合
- 終端遅延
- 形成分離

未観測のweight内部意味・training全因果は推測しない。

## 3. ② HDS Compiler

### 質問

知識選択質問は、正常状態のままtopic-onlyへ落としてはならない。

保持対象:
- 未知位置
- 既知端点
- 要求型
- 関係種別
- finite vocabulary外の明示述語identity
- 否定極性
- modality / quantifier / condition scope
- selection reversal

finite relationへ分類できない明示述語は `開放述語` として保持する。
命題真偽・説明選択は世界事実へ捏造せず `命題適合` / `説明適合` として問い関係化する。

### 候補 / Data

有限関係語彙外でも、明示SVO・受動・copular predicateは世界知識を付加せず開放関係として保持する。

### semantic_loss

質問意味を関係として保持できない場合、主題語抽出だけで成功扱いせず `semantic_loss` を明示する。

## 4. ③ MINIDORA射影

HDSは模型核の外側Adapterに限定する。

```text
HDS-IR
↓ hds_model_projection
言語状態 / 言語関係構造
↓
MINIDORA模型核
```

正式模型核は、
- 標準6模型関係
- 能力保存作用群
- 参照状態
- 候補共同差
- checkpoint
- unique positive difference終端

を持つ。

外部Dataは `参照状態` とし、会話履歴へ混ぜない。
旧`K3相当能力核`は互換・診断資産として残すが、正式性能経路の最終回答主体にしない。

## 5. ベンチ経路

正式GPQA経路:

```text
R
→ 公開HDS Compiler
→ 意味HDS-IR
→ HDS→模型Adapter
→ MINIDORA正式模型核
→ 成立差
→ 終端採否
```

標準workflowは `tools/benchmark_formal.py` を入口にする。
controlled A/Bでは同一question IR・同一取得Dataを固定し、baseline=旧v0.3 helper経路、current=正式MINIDORA模型核経路として**実行経路差そのもの**を比較する。これは旧経路との移行差確認であり、同一模型核のablationとは呼ばない。

## 6. 不変条件

1. goldを推論へ使用しない。
2. benchmark固有規則を模型核/Compilerへ入れない。
3. HDS型を模型核へ入れない。
4. 外部Dataを会話履歴へ混ぜない。
5. 反証・逆向・scope差を即時廃棄しない。
6. 根拠差がなければ確定しない。
7. K3 helperの診断結果で正式模型核結果を上書きしない。
8. v0.3互換直呼びは維持する。

## 7. 受入

- `Which ... stabilizes ...?` 等の有限語彙外述語を質問関係化できる。
- 宣言文 `A stabilizes B` を同じ述語identityへ戻せる。
- `statement correct / best describes` をtopic-onlyにしない。
- polarity / condition scopeを候補代入まで保持する。
- 正式模型核が参照状態から候補差を形成する。
- 正式ベンチprotocolに `formal_model_core=true` を記録する。
- 既存全テスト、Linux/Windows × Python 3.11–3.14を維持する。
- GPQA全数は正式模型核経路で完走させる。
