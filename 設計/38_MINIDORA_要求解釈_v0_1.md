# MINIDORA 要求解釈・局所タスク分解 v0.1

日付: 2026-09-10
基点: `2b764ab4bac2c155f028726a8eacb9914b2d923a`
対象: 汎用Capability一覧①の最初の局所実装と、②への接続。
状態: 文書操作の限定文法を実装。任意の自然言語理解の完成ではない。

## 1. 今回の作用

```text
利用者の依頼 → 既存の公開HDS Compiler → HDSIR
                                           ↓
                    原文保持・局所要求解釈・上流構造照合
                                           ↓
                             要求工程 + 合成計画 + Data
                                           ↓
                       第1バッチの能力合成器 → 既存Module
                                           ↓
                          明示出力制約の検査 → 結果／保留
```

依頼と資料本文は別入力である。資料内の命令文を依頼へ昇格させない。

既存HDSIRには、今回の文書操作をそのまま実行するタスク列がない。そこでHDSIRの原文を起点に**有限の文法による局所解釈**を追加し、元の座標・関係・残差・意味作用履歴と照合する。元HDSIRを改変したり、既存Compilerが汎用タスク計画を既に生成したと主張したりしない。

HDS-IR、今回の要求工程、Capability呼出計画、既存Compute IRは別の責任である。既存の`HDSIR.実行可能`は旧計算手順の閉包判定であり、それを今回のCapability実行可否に流用しない。代わりに本書の局所契約で判断する。HDSの上流残差を無条件に無視しない。

## 2. 実装ファイル

- `src/minidora/要求解釈.py`: 原文全体の構文消費、資料・前工程への束縛、要求工程、計画生成、残差、整合指紋。
- `src/minidora/要求解釈実行.py`: 成立済み・未改変の計画だけを合成器へ渡し、明示した出力条件を検査する。
- `tools/要求解釈デモ.py`: 本物の公開HDS Compilerから既存Module実行までを呼ぶ。

Core、HDS Compiler、前回の能力合成器、既存の要約・抽出・変換、科学Module、標準チャット入口、GUI-Shellは変更しない。追加依存パッケージ・外部LLM・検索呼出はない。

## 3. 対応する要求

| 要求 | 降下先 | 保持する指定 |
|---|---|---|
| `本文を1行で要約して` | 抽出要約 | 行数一致1。1〜8、全角数字と一〜八も受理。 |
| `3行以内で要約してください` | 抽出要約 | 上限3。指定なしは既定上限3を記録。 |
| `その結果から数字を抽出して` | 情報抽出 | 数字／数値を数値抽出へ対応づける。 |
| `資料「A」からURLを抽出して` | 情報抽出 | URL／url／ＵＲＬ／リンクをURL抽出へ対応づける。 |
| `キーワードを抽出して` | 情報抽出 | 既存の頻度ベース抽出。 |
| `箇条書きにして` | 文脈変換 | 箇条書き／リスト指定。 |

基本の接続は句読点・改行、または`してから`。`まず・次に・続けて・最後に・その後・それから`も接続用の表層として扱う。終止形は実装の有限文法で明示する。連用形`し`は後続がある場合に限定する。

例:

```text
本文を1行で要約して、その結果から数字を抽出して、箇条書きにして
```

複数の提供資料を選ぶ場合:

```text
資料「A」から数字を抽出して、資料「B」から数字を抽出して
```

これは独立した2つの出力を作る。すべての操作を一つの直列パイプへ押し込まない。

### 対象の解決

- 初回の対象省略・`本文`・`提供文`: 提供資料が一つの場合だけ一意に束縛する。
- `資料「名前」`: 完全一致する資料名を使う。近似一致で補わない。
- 2工程目以降の対象省略: 直前工程の結果を使う。
- `その結果`・`それ`: この依頼内の直前工程だけを指す。
- `元の本文`・`元の資料`: この依頼の最初に使用した提供資料へ戻る。
- 初回の`それ`、資料欠落、複数資料からの曖昧選択: 保留する。

過去turnの参照解決や長期記憶の実装ではない。上流が前turnへ推定束縛した照応を、無言で今回の前工程へ置き換えない。

## 4. 全文消費と残差

能力名を含むだけで処理しない。対象・引数・述語・接続詞を読んだ後、原文が終端まで消費された場合だけ実行計画を返す。

```text
要約しないで                              → 保留、実行なし
要約して、英訳して                        → 保留、要約だけの先行実行もしない
もし数字があるなら、要約して              → 保留、条件を捨てない
3行で要約して、初心者向けに説明して        → 保留、未対応指定を残す
```

残差は原文の文字位置 `[開始, 終了)`、該当原文、理由、解消条件を持つ。位置はNFKC後の位置ではなく、保持した原文のPython文字インデックスである。

未完了時は診断用の部分要求を保持してよいが、`計画=None`、`初期Data={}`として実行可能な部分計画を出さない。

## 5. HDSの保持・照合

HDSIRを複製してそのまま保持する。入力の`source_text`座標が原文と一致し、確定していることを要求する。

v0.1は次の範囲の上流注記だけを扱う。

```text
source_text / language.normalized / 文脈.言語
制御.選択意図（通常のみ）
値.数量 / 属性.単位 / 対象.主題語 / 目的.検索焦点
文脈.参照先 / 文脈.指示語（確定済みだけ）
数量単位関係（確定、追加条件なし、参照先あり）
```

未知の座標種別、未確定座標、その他の関係・条件は保留する。上位Compilerが追加する構造を万能に解釈するとは主張しない。多言語出力指定もv0.1では保留する。

`未解共参照`の残差は、原文の`その`または`それ`の全出現が、この依頼内で前工程へ束縛済みの対象範囲に収まり、追加の影響座標がない場合に限り、局所解消記録を追加する。資料名などの別位置に同じ語がある場合は解消したことにしない。

解消しても元HDSIRから残差や損失履歴を削除しない。未知残差・semantic_loss・解消対応がない意味作用の損失は保留する。

照合は今回の限定構造に対する境界検査であり、HDS全体の意味的一貫性の完全検証ではない。

## 6. 要求・計画・Dataの分離

`要求工程`は能力、束縛先、引数、原文範囲、対象範囲、解決理由、行数条件、既定適用を保持する。

`合成計画`には工程ID・能力名・参照先だけを入れる。指示原文・行数・資料本文は別の初期Dataへ格納する。使用資料名と内部Dataキーを分離し、利用者の資料名による指示・設定キーの上書きを防ぐ。

依存先として消費されていない工程を要求された最終出力とする。連鎖の場合は最後の結果、明示的な独立要求の場合は複数結果になる。

## 7. 実行と出力条件

`要求計画を実行`は解釈指紋を検査し、合格した未改変の計画だけを第1バッチ合成器へ渡す。外部読取は許可しない。停止要求は合成器へ渡す。

合成が成功しても、明示出力条件が未達なら要求全体は保留する。

- `3行で`: 実際の要約が3行であること。1行しか生成できなければ不足を返し、水増ししない。
- `3行以内で`: 非空かつ3行以下であること。
- 箇条書き変換: 入力から分割された全項目を保持すること。既存実装の12項目切捨てを成功扱いしない。

この版の出力条件検査は、純粋な文書操作の合成終了後に各中間結果を検査する。条件未達の中間結果に対する後続計算をその場で止める仕組みは未実装。最終出力は隔離する。送信・書込み等の副作用を持つ能力をこの経路へ追加してはならない。

指紋と実行ハッシュは入力・解釈・計画・Data・結果を追跡するためのもので、電子署名でも事実性の証明でもない。入力の偽造に対する認証境界ではない。

## 8. 上限

既定で32要求、依頼8192文字、HDS記録または提供資料集合1,000,000バイト。非JSON互換の資料Data、非有限数、循環値、不正Unicode等は失敗にする。上限違反で入力を黙って短縮しない。

## 9. 未実装と次段

任意の自然言語理解、未知の言い換え、条件付き実行、動的再計画、比較・推論、翻訳、コード、検索、過去turnの照応、長文生成、標準チャットへの自動接続は今回の完成範囲外。

今回の新規能力は**限定された依頼から要求・依存・資料・制約を分離し、実行可能な合成計画へ接続すること**である。既存の要約・抽出・整形の品質そのものは改善していない。
