# MINIDORA 目的駆動計画 v0.1

日付: 2026-09-11。第17バッチ。
基点: `fedc9e5a9cf7035ac07b219bab592bec24b98ad9`（第16バッチ）。

## 1. 目的

利用者に能力名や工程列を指定させず、要求の対象・必要成果・引数から既存能力の経路を組み立てる。成立済みCore、公開HDS Compiler、既存29能力の本体を置換しない。これは汎用チャットの実装を進める一差分であり、GPT-4同等性の完成宣言ではない。

```text
日本語の依頼・別入力の資料
→ 実公開HDS Compiler
→ 対象・作用・引数・依存の局所射影
→ 汎用要求IR（目的とDataを能力名から分離）
→ 能力意味カタログの作用契約を後方探索
→ 既存の合成計画・合成工程・素材参照
→ 既存統合セッションの準備・実行・採用
→ 次の依頼で同じ採用成果を利用
```

## 2. 実装と責任

| ファイル | 責任 |
|---|---|
| `能力意味カタログ.py` | 既存29能力の入力・作用・出力・制限・版・外部読取境界と照合。20の計画作用を宣言する。 |
| `汎用要求IR.py` | 名前付き素材、素材型宣言、目的、対象依存、引数Data、原文範囲、出力、残差。 |
| `目的計画.py` | 単一素材の型付き経路を必要成果から逆引きし、多目的の依存順で既存計画へ降下する。 |
| `HDS目的射影.py` | 日本語の局所構文を全文消費し、実HDSの原文・残差・関係と照合する。 |
| `目的会話.py` | 実HDS、計画生成、既存統合実行器、採用履歴を接続する追加入口。 |
| `tools/目的チャット.py` | 単発又は継続会話の日本語CLI。明示パスのUTF-8資料を取り込む。 |
| 既存`統合実行.py`の追加メソッド | ロック下で同じ起点と採用履歴の複製を返す。既存応答処理は変更しない。 |

29は能力記述の数であり、自然文から29能力全てを起動できるという意味ではない。今回の20作用は、数学・構造文書・本文処理・限定コードの既存12能力へ接続する。証拠統合、原因説明、一般翻訳、外部検索を型名だけで完成扱いにしない。

## 3. 意味記述と作用契約

能力名・版・外部読取属性が現行登録一覧と一致しない場合は利用しない。意味記述は責任と限界の説明であり、その記述自体が能力実装や正しさの証拠にはならない。

計画作用は入力状態の候補、出力状態、既存能力名、固定設定、引数から設定への写像を持つ。固定設定は作用の宣言、式・値・JSON位置・変数名等はDataである。自由文の語彙表は「どの成果を求めるか」を返し、Module名や工程列は返さない。

初版の例:

```text
数式 → 正規化結果 → 定数値
JSON原文 → JSON文書 → JSON選択文書 → 文書単一値
CSV原文 → CSV文書 → JSON変換文書
コード仕様 → コード本文 → コード評価結果
```

計画器に上の特定工程列を直接実装しない。必要成果から、登録された個別作用の入出力が接続する経路を求める。入力素材の識別子を維持し、別資料の同じ型で目的を代用しない。

## 4. 計画化の境界

単一素材を入力に取る作用経路と、複数目的間の依存を扱う。任意の複数素材の意味的結合、原因候補の生成、目的の発明、実行失敗後の自動再計画は今回の対象外。

最短の型付き経路を選び、同順位の異なる経路が残れば保留する。未解消引数、未知引数、未接続目的、参照欠落、循環、探索上限は停止条件である。上限で探索を打ち切った候補を完成結果へ読み替えない。

出力型は計画段階では「予定」。型宣言だけでは素材の意味的妥当性を確定しない。実行時には既存Moduleの入力判定・処理結果と統合器の採用境界を通す。計画化中に能力・外部取得・会話更新は実行しない。

積分の代表元を正規化して確定値へ昇格する経路は作らない。「一意解を求める」は数学結果採用へ接続し、自由解を一意解として回答しない。「解く」は一意解・自由解・解なしの診断を区別して報告する。

## 5. 自然言語とHDS

日本語の引用対象、資料名、数学の対象変数、JSON位置と値型、作用述語、前工程参照、前回単一成果の「それ」を扱う局所構文。未知の語尾・条件・修飾が残る依頼は、既知の前半だけを実行しない。

式は計算せずAST構文を調べ、必要な変数宣言と左右辺Dataへ分離する。計算は既存数学Moduleが行う。任意Python式の呼出や属性参照を数式として実行しない。

実HDSの原文と座標、未確定状態、残差、意味損失を保持・照合する。引用された形式等式に対応するHDS等価関係だけを局所的な形式数式へ射影する。一般文の等価関係や未知残差は免除しない。既存公開HDSの導出規則は変更しない。

これは日本語理解全般の完成ではない。文章題、任意の言い換え、因果・常識推論、長い談話の意味解析は残作業である。正規表現等はこの局所表層文法の実装に使うが、能力名への直接振分けや工程列のハードコードにはしない。

## 6. 会話状態と外部作用

`目的会話セッション`は既存`統合セッション`を所有するか、明示的に共有できる。計画の前後で同じ起点を確認し、他の入口からの更新・初期化で古くなった解釈を実行しない。

過去成果の参照は既存の採用履歴に限る。失敗した要求や途中成果を最後の成功成果へ上書きしない。複数出力の「それ」を勝手に一つへ確定しない。別セッションとの混線、停止要求、計画の改変は既存境界も利用して拒否する。

今回の自動経路には外部読取を登録しない。知識取得・ブラウザは意味記述と実装境界の把握までであり、取得目的の生成や外部許可を推定する入口は追加していない。

## 7. 使い方

```bash
python tools/目的チャット.py '「(x+1)**3」をxで微分して、その結果を箇条書きにして'
python tools/目的チャット.py '「x+y=3;x-y=1」の一意解を求めて'
python tools/目的チャット.py --資料 設定=settings.json 'JSON資料「設定」の位置「/税率」の数値を取り出して'
python tools/目的チャット.py --資料 売上=sales.csv 'CSV資料「売上」をJSONに変換して'
python tools/目的チャット.py --一覧
python tools/目的チャット.py
```

最後の入口は同じセッションで1行ずつ日本語を処理する。`/終了`で終了、`/初期化`で履歴を消去する。`--json`でHDS原文・計画経路・実行記録を表示する。資料ファイルは明示したものだけ、各1MB以内のUTF-8/UTF-8 BOMを読む。

出力は現在も既存能力の本文である。汎用的な回答意味IR・談話生成・自由作文はまだ追加していない。標準チャット・GUI・既存APIをこの入口へ自動置換しない。
