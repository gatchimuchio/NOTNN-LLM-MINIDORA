# HDS Compiler Pipeline v1.4

## 1. 目的

意味・監査・計算責任を混ぜず、Architecture v1.3で追加した作用差分構造を並列成果として運ぶ。

```text
Architecture v1.3 = 意味・監査 + 作用差分構文化
Pipeline v1.4     = 意味IR / 計算計画 / 作用差分構造 / 計算降下の責任分離
```

## 2. 正本経路

```text
自然言語
  ↓
意味コンパイル
  ↓
意味HDS-IR ─────────────┐
                        ├→ HDSコンパイル束
計算計画 ────────────────┤
                        │
作用差分構造 ─────────────┘
       │
       └─ 判断・採否・実行はしない

計算計画
  ↓
計算降下
  ↓
計算中間表現 v1
  ↓
計算実行境界 v1
```

## 3. 三成果の分離

- 意味IR: 対象・関係・条件・状態・目的・残差・監査構造。
- 計算計画: 計算Pへ降下する手順と初期状態。
- 作用差分構造: 作用・状態差・後続利用・未閉包。

同一フィールドへ潰さない。

## 4. 作用差分構造の非実行性

作用差分構造は意味上の構造Recordである。

`計算降下()` はこの構造を保持して返せるが、作用差分を計算命令へ自動変換しない。後続能力系が使用する場合は別契約で発火条件・採否・資源・停止を定める。

## 5. 互換境界

旧 `コンパイル()` は既存実行系向け互換窓口として残す。ここだけで計算Pを最外周再付与できる。

互換IRへ作用差分構造を埋め込んで意味正本化しない。

## 6. 日本語基底

```text
規定言語 = 日本語
基底言語 = 日本語
基底言語コード = ja
```

`ja` は外部互換コードであり、基底意味そのものではない。

## 7. 受入条件

1. Architecture v1.3。
2. Pipeline v1.4。
3. 意味IRへ計算Pを内包しない。
4. 三成果を別フィールドで保持する。
5. 計算降下で自然言語再解析なし。
6. 作用差分構造を自動実行命令化しない。
7. 旧 `コンパイル()` 互換を維持する。
8. 既存HDS/K3/実行系回帰を壊さない。
9. Ubuntu / Windows × Python 3.11–3.14 CIを通す。

作用差分の意味契約は [`29_HDS_Compiler_作用差分構文化_v1_3.md`](29_HDS_Compiler_作用差分構文化_v1_3.md) を参照する。
