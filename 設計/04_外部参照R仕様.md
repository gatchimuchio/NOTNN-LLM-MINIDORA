# 外部参照R仕様

## 1. 定義

外部参照RはMINIDORAの**外部Data運用層**である。

Rは取得・参照・由来保持を担う。大規模言語模型成立規定が定める模型側関係そのものではなく、LLM模型中核の普遍必須条件でもない。

MINIDORAでは、ニューラルLLMがweight内部へ保持しがちなKnowledge/Dataを可能な範囲で外部へ分離する設計を採用する。

## 2. 供給器

Rは交換可能である。

- 検索API
- 固定Corpus
- DB
- 文書庫
- 知識API
- ローカルファイル
- 任意の外部LLM API

外部LLM APIを参照供給器として使う場合も、その出力をMINIDORA自身の模型側関係へ自動帰属しない。

## 3. 標準運用経路

```text
要求
↓
参照要求生成
↓
供給器選択
↓
Data取得
↓
正規化
↓
由来結合
↓
運用文脈へ投入
├─ 必要なら模型核の言語状態・文脈へ写す
└─ 必要なら命令P / 計算実行器へ渡す
↓
候補 / 結果
```

取得文をそのまま最終回答へ昇格させない。

## 4. 模型核との境界

```text
外部参照R
!= 模型側関係
!= 言語対応
!= 成立差
```

Rから得たDataを模型核で利用する場合は、対象言語体系・言語状態・文脈条件等へ明示変換する。

検索で得た完成個体をそのまま返す処理と、文脈付き言語状態から再利用可能な模型関係により成立差を生じさせる処理を区別する。

## 5. 参照記録

各参照Dataは最低限次を持つ。

```text
識別子
供給器
取得時刻
対象
内容
由来
信頼境界
改変有無
```

## 6. Data正規化

外部Dataは必要に応じて次へ落とす。

- 実体
- 属性
- 値
- 関係
- 状態
- 時刻
- 条件
- 出典
- 不確実性

取得文から解釈できない項目を推測で埋めない。

## 7. 複数参照

Top-1だけで確定しない。

同一主題・同一属性に複数Dataがある場合、並列保持し、矛盾・差異・更新時刻を採否層へ渡す。

## 8. Provider選択

選択規則はData責任として明示する。

例:

```text
最安
一次資料優先
新鮮度優先
複数照合
局所固定Corpus優先
```

Providerの性能をMINIDORA模型核の能力と混同しない。

## 9. 評価上の位置

MINIDORA製品の標準運用ではRを有効にできる。一方、LLM模型性そのものの監査ではRを切った模型核単体試験も必要である。

したがって、

```text
Reference Layer OFF
```

は製品標準能力のablationになり得るが、模型核単体性を確認する試験としては正当である。評価目的を明示して混同しない。

## 10. 完了関門

- Providerを差替えても模型核の意味契約が変わらない
- 取得Dataを必要な運用経路へ再投入できる
- 外部文をそのまま回答しない
- 複数Dataの矛盾を保持できる
- 出典追跡可能
- Provider停止時に保留又は代替経路へ移れる
- Rなしでも `MINIDORA模型核` を単体構築・監査できる
