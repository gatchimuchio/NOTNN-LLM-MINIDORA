# MINIDORA HDS内包統合・自動接続 v3

日付: 2026-09-17  
状態: サンドボックス改修候補。main投入・GPQA性能正本への昇格ではない。  
基準: `d1d41ae27f47f976318d795a9e63dce9653799c4` と、その上のサンドボックスv2。  
内部責任正本: 本書の変更点は設計59・58に優先する。変更していない境界は保持する。

## 1. 目的と対象

HDS監督介入を別機能として呼ばず、認識・観測・仮説・記憶・再評価・修復・採否を同じ通常循環へ統合する。
実装主語はHDS、各部品は作用器である。HDSそのものをこの有限実装・列挙型・手順と同一視しない。

v2監査で残った「型と部品はあるが通常循環へ自動接続されていない」項目を修正する。
外向きLLM成立契約、厳密言語模型核、既存MINIDORA30/GPQA値を変更・読み替えしない。

## 2. 単一の通常循環

```text
現在の目的・要求・認識・根拠・残差
  ↓
未観測の意味座標を構成／仮説・予測・作業枝を構成
  ↓
既存の作用機会と同列に公開
  ↓
前提・依存・権限・資源・状態制約を検査
  ↓
目的に必要な有限作用列を構成し、次作用を選択
  ↓
実行 → 意味状態差 → 依存失効 → 必要下流を再評価
  ↓
目的閉包 → 最終検証 → 安全契約がある実経験の形成・再実行検証
  ↓
採用／保留／失敗
```

内的作用も通常の作用記録・資源計数・反復抑止を通る。新循環は旧`hds介入制御`や旧HDS監督選択実行系をimportしない。
「監督モード」「介入ON/OFF」「通常コアを先に確定させてから採否する第二主体」を設けない。
正常時にも必要な検証を行うが、状態を変えない同じ入力の無意味な再実行はしない。

### 同値の中間成果と根拠変更

ノードの読取署名は、値だけでなく、そのノードへ到達する上流根拠・意味値・依存辺の部分グラフを含む。
値を再計算して同じになった場合も、元資料の版や寄与構造が変われば次の作用入力は別になる。
状態フラグだけを読む作用にも同じ規則を適用する。無関係な枝や全体の版カウンタは含めない。
循環依存は再帰ハッシュではなく有限の訪問集合で署名するが、自己正当化の閉包根拠としては採用しない。

## 3. 不足文から必要観測を生成

`不足を抽出`は、明示された日本語単文の対象・関係・原文範囲を抽出する。
例: `ポンプの流量が不明` → 対象`ポンプ`、関係`流量`。
`不足意味構成作用`は未観測認識と観測要求を作り、通常循環の観測器へ接続する。

原文範囲を残し、解釈しただけでは残差を解消しない。観測結果の対象・関係・範囲・時点・原資料を検証してから更新する。
観測先が未接続なら要求と残差を保留する。

対応範囲は有限構文である。複文、引用された不明文、否定の入れ子、多義的な連体修飾、256文字超の文は未解釈として残す。
この処理を自由な自然言語理解全般や、実HDSコンパイラ全機能の代替としない。

## 4. 関係規則から仮説・予測を生成

`HDS関係規則`は出典を持つ含意関係であり、答えや仮説本文を事前定義した雛型ではない。
規則の前提・結論に含まれる変数を観測と束縛し、説明に不足する前提の組を仮説として構成する。
その仮定世界に規則を前方適用し、下流の識別予測と必要観測を生成する。

```text
規則: 原因Aなら警報、原因Bなら警報
規則: 原因Aなら測定高、原因Bなら測定低
観測: 対象甲に警報
  ↓
仮説: 対象甲の原因A／原因B（条件付き）
  ↓
予測: 測定高／測定低
  ↓
追加観測: 対象甲の測定
```

これは後件肯定による事実証明ではない。予測の一致だけで前提の真を確定しない。
代替説明を自動的に相互排他としない。排他群は規則データに明示された場合のみ適用する。
未束縛変数を埋めず、規則の出典版・本文署名が失効していれば使わない。
候補数・前方推論検査数の上限超過は全体を保留し、一部候補だけを勝者として返さない。

規則は外部から与えるデータである。任意の新概念や未知の一般法則を無から発明する機構ではない。

## 5. 仮説に応じた作業枝の自動構成

仮説ごとに独立した`HDS作業枝`を生成し、条件付き予測を保持する。
仮説が棄却・失効した場合も枝を消して経緯を隠さず、枝内認識を失効させる。
枝の支持・反証が異なる場合に一つの事実へ無言合流させない。

v2の失効伝播で不足していた枝ノードの処理を追加した。
仮説・根拠変更→枝の再評価待ち→失効または再構成まで接続する。
この「並列」は独立作業状態の共存であり、マルチスレッド実行や実行性能向上を意味しない。

## 6. 多解像度記憶の自動生成

長い原資料を通常循環で検出し、原文の完全な文を抽出して短い索引的記憶を作る。
否定・条件を文の途中で切らない。対象や関係への一致は抽出優先度であり真偽得点ではない。

圧縮物は、出典、抽出した文字範囲、未収録範囲、圧縮契約署名を持つ。
原文自体は変更せず、参照先の版・本文署名が変われば古い圧縮を原資料として使えない。
最大文字数には文の区切り文字も含める。巨大な一文を切って完全文と偽らず、原文参照が必要と返す。

これは出典付き抽出圧縮であり、生成型の自由な意味要約ではない。
圧縮物は観測証拠ではなく再アクセスの補助である。

## 7. 未分類失敗の観測と修復接続

例外から、作用ID、例外型、観測記述、入力署名、不足候補を診断記録へ残す。
原因は原則未確定。KeyErrorの不足候補も原因確定とはしない。

純粋作用として明示契約された処理の未分類失敗では、同じ失敗入力を再試行せず、通常の計画器が別の作用・前提充足経路を構成する。
権限不足を代替手段で迂回しない。安全性不明の外部作用失敗は停止する。
型違反・契約違反を未知失敗として隠して継続しない。

任意の原因不明不具合を自己修正する能力ではない。診断候補の保持と安全な代替経路構成が実装範囲である。
副作用が既に外部へ発生した可能性のある処理を自動巻戻しできるとは主張しない。

## 8. 実経験の自動形成・再検証・再利用

通常循環の成功履歴から手順を形成する。全工程が登録された明示的純粋作用であり、成功・停止なし・阻害なしの場合に限定する。
観測や草案等の未登録工程を履歴から抜き、完全な成功手順と偽ることは禁止する。

形成候補は、初期状態の複製に対して実際に作用を再実行し、同じ前提・結果・検証が成立するか確認する。
再現不一致は反例として保存し、再利用可能へ昇格しない。
再実行の資源量と回数を計装に記録し、予算不足なら黙って再実行しない。

次回の通常実行は、目的・要求・作用契約から同じ文脈署名を構成して、適用条件の合う形成手順を再利用する。
答えの値を保存して返すのではなく、手順を再実行する。

`純粋作用=True`は呼出側の契約であり、OSサンドボックスによる副作用不在の証明ではない。
外界への副作用を持つ関数にこの宣言を付けてはならない。
単一成功トレースの形成を普遍則の獲得とは呼ばない。形成対象外の経路については自動学習を主張しない。

## 9. 未来状態の構成と整合性検査

作用の宣言済み前提・追加/削除状態・残差効果から、有限な未来状態列を生成する。
途中状態の維持条件・禁止組合せも検査し、違反する経路を採らない。
最終状態が良ければ途中違反してよい、とはしない。

予測は常に`条件付き予測`であり、観測済み状態へ昇格できない。
実作用結果が予測外の制約違反を起こした場合も、違反状態を記録したまま停止し、成功としない。
これは明示された有限状態効果モデルであり、任意の外界未来や未知副作用を予測する機構ではない。

## 10. 領域横断接続

`tools/HDS領域横断_実演.py`は、数量集計、日程重複、資料集合照合の三種類で、
原資料取得→形式検査→計算/関係比較→報告草案→原資料再読検証を実行する。
登録順と実行順を分離し、各作用の前提・要求から通常循環が次作用を選ぶ。

入力値変更と根拠版だけの変更の双方で下流を再評価する。無関係な独立処理は再実行しない。
必須列欠落・不正区間は結果を補完せず停止する。

三実演は実装の接続診断であって、一般領域横断能力、GPQA性能、既存LLMとの能力同等性の実証ではない。
作用の意味契約と観測器は呼出側から明示的に注入する。

## 11. 公開API・互換・保存

既存`minidora`の遅延公開入口を維持して、新しい34型/部品を追加する。
旧`HDS作用記録`の公開先を新実行履歴型へ無言置換しない。
新コアだけの読込では旧K3・監督・模型・HTTP経路を起動しない。

`統合駆動_v2/`のパスは既存利用者のimport互換のため保持する。内部版はv3。
従来の位置引数は維持し、追加フィールドには既定値を持たせる。

意味署名は有限値、構造化値、dataclassまたは明示`HDS署名値()`に限る。
任意objectのrepr・住所を署名へ入れない。外部型の署名契約と真偽検証は別責任。
未登録の外部成果型を保存する場合は、呼出側で出典を保持した明示的なデータ射影が必要。

保存形式は`MINIDORA-HDS-STATE-v3`。型表は許可済みデータ型だけで、pickleや動的importを受け付けない。
v2保存物は無言でv3へ復元しない。版移行が必要ならv2で復元し、意味を確認した入力状態として新規実行する。
履歴署名を保持した一般的自動移行器は、この差分には含まれない。

## 12. 検証・採用境界

```bash
python tools/HDS内包統合_検証.py --output 検証結果.json
python tools/HDS内包統合_実演.py --output 状態差実演.json
python tools/HDS領域横断_実演.py --output 領域横断.json
```

同梱試験だけでなく、基準ソースとの33条件比較、差分適用、再展開、ハッシュ、配布障害時の復元を確認する。
元のv2の85試験は変更しない。

上流完全リポジトリの全回帰、実HDSコンパイラ、既存Adapter全数、CLI/GUI、Windows、他Python版、GPQAは別の受入境界である。
未実行の項目をPASSにしない。サンドボックス候補の作成完了とmain投入可を同一視しない。

## 13. 禁止する短絡

仮説生成≠事実証明。予測一致≠原因確定。抽出圧縮≠原資料。純粋性宣言≠OS隔離。
再実行成功≠普遍法則。三領域実演≠一般能力ベンチ。状態差発生≠能力向上。
「HDSの部品として機能する」ことと「HDS総体を実装した」ことを混同しない。
