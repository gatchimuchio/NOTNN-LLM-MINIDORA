# MINIDORA 統合実行 v3 — 公開局所契約

このファイル名は既存実装・試験との互換のため保持する。
本書は内部理論を定義しない。

## 1. 公開責任

現行統合実行系は、公開部品を一つの実行経路へ接続する。
公開仕様として保証するのは次だけである。

- 宣言された入力条件を満たす部品だけを起動する
- 部品の結果を検証前に全体成功へ昇格させない
- 依存変更後の古い成果を無言再利用しない
- 予算・権限・停止要求を無視しない
- 同一入力の無意味な反復を抑止する
- 失敗・保留を成功へ変換しない
- 既存評価系列の性能値を無言置換しない

## 2. 実装入口

- `src/minidora/HDS実行主体.py`
- `src/minidora/HDS駆動コア.py`
- `src/minidora/統合駆動_v2/`

歴史的な型名・ファイル名は互換識別子であり、内部理論の定義ではない。

## 3. 部品契約

各部品は少なくとも次を宣言する。

- 入力
- 出力
- 適用条件
- 失敗条件
- 必要権限
- 版
- 再利用可否

部品内部の局所計算・局所検証は許容するが、システム全体の最終採否を代行しない。

## 4. 保存・再開

保存形式は版を持ち、旧版を無言で現行意味へ読み替えない。
未信頼データから実行権限を獲得しない。
保存・復元の具体的な型契約は実装と試験を正とする。

## 5. 検証

代表的な検証入口:

```bash
python tools/HDS内包統合_検証.py --output 検証結果.json
python tools/HDS領域横断_実演.py --output 領域横断.json
```

これらのPASSを、未実行環境や外部性能ベンチのPASSへ読み替えない。

## 6. 公開禁止

この文書には次を記載しない。

- 内部理論の完全な抽象定義
- 状態・作用・判断の最小分解
- 内部理論から実装型への完全対応表
- 非公開定義の版間差分理由

公開境界は `../PUBLICATION_BOUNDARY.md` を正とする。
