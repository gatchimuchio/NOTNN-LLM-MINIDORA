## 1. 追加する作用

```text
素材Data + 構成仕様
→ 素材範囲を採用し、同伴・必須単位を含める
→ 見出し・段落・箇条書き・引用等のプレーンテキスト
→ 元素材と全出力文字の対応を保持
→ 編集対象の記録hash + 旧範囲 + 期待原文 + 修正文
→ 全修正を検査して指定部分だけを変更
→ 改稿・旧新差分・現行文字の由来・移動した保護範囲
→ 既存能力・多段解決・HDSへの素材
```

第6バッチの数値証拠報告専用の応答構成とは別の入口。数値報告に限らず、上位が供給した文章素材を扱う。構成を変えて段落の配置を変えたり、複数素材の断片をつないで文章を作ったりする。

ただし、意味内容や表現そのものを未知の自由文から発明する生成器ではない。断片の組合せが意味的に適切か、どこをどう修正すべきかは上位の責任である。固定内容をCoreの世界知識として埋めず、素材・構成・修正文をDataで渡す。

## 3. 文章作成

`文章断片`は素材IDとPython文字位置の半開区間（開始を含み終了を含まない）。素材は識別子から既存の能力結果への辞書。原文範囲をそのまま複写し、勝手な言い換え・数値整形・省略はしない。複数断片を連結する場合、必要な助詞・接続語・句読点も上位が素材として渡す。

`文章単位`はID、種別、断片列、同伴ID列、必須、保護を持つ。`文章仕様`は単位群、採用順序、最大文字数を持つ。種別は見出し・段落・箇条書き・番号付き・引用・条件・留保。

見出しには`# `、箇条書きには`- `、引用の各行には`> `、条件・留保には明示ラベルを付ける。番号付きは連続する番号付き単位だけを1から数え、見出しや段落を数に混ぜない。素材のCRLF・LF、空白、値は保持する。複数行の見出しは拒否する。

採用順序の各単位を訪れ、その同伴を再帰的に含める。すでに採用した単位は重複出力しない。相互同伴も各単位を一度だけ含む。条件・留保、および必須指定された単位は採用順序から漏れていても含める。未知の同伴先・素材欠落・不正範囲は全体を不成立にする。

これは同伴する内容の存在を維持する契約であり、文章内での意味的な作用範囲を解析・強制する仕組みではない。依存や留保を適切な単位として宣言する責任は上位にある。

未採用単位と、初期構成に使っていない素材の範囲も記録する。原素材は全文を残す。編集後もこれらは「初期採用単位」「初期省略単位」「初期単位位置」「初期未使用素材範囲」として保持し、現行位置や現行使用量と取り違えない。現在の文字由来は「対応」で確認する。

## 4. 本文取込と保護

`文章を取り込む`は既存の本文を一切書き換えず編集対象として登録する。任意の半開文字区間を、IDと期待原文付きの`保護範囲`として指定できる。重複・交差・原文不一致を拒否する。

構成から作った引用・条件・留保は、ラベルを含む単位全体を既定で保護する。その他の単位も保護を明示できる。数値や否定語を自動発見して保護する機能ではない。

保護とはその文字列自体に対する変更・削除・内部挿入を禁止すること。保護区間の前後への挿入は許可し、保護位置を移動させる。この境界で挿入した語が文全体の意味を変えないことは保証しない。例えば保護文字列の前に否定や引用説明を付ける場合の意味判断は別責任である。

## 5. 差分編集

`文章修正`は識別子、開始、終了、期待原文、置換文、理由を持つ。範囲が空なら挿入、置換文が空なら削除、それ以外は置換。各修正の座標はすべて同じ編集前本文に属する。

`文章を編集`には対象結果の「記録SHA256」を起点として必須指定する。本文だけでなく原本・構成・保護・履歴も含む記録に対する起点であり、本文が同じでも異なる保護契約のhashは使えない。更新後の対象に以前のhashで編集しようとすると拒否する。

全修正を検査し、期待原文の不一致、交差、同じ開始位置の曖昧な修正、保護との衝突が一件でもあれば本文を返さない。成功時も原本オブジェクトは変更せず、新たな能力結果を返す。修正を位置順に並べて未変更範囲を複写し、指定部分だけを挿入し直す。全文の再生成は行わない。

これは不変の文書値に対する起点検査であり、アプリ全体のグローバルな最新版管理ではない。以前の不変オブジェクトとその正しい起点から、別の改稿を分岐させることはできる。どの改稿を現在の採用版とするかは上位の状態管理が担当する。

`編集箇所を特定`は検索文が一箇所にだけ完全一致するとき、位置と起点を持つ編集要求Dataを返す。編集自体は行わない。欠落、複数一致、重なり合う複数一致は保留。正規表現や類似文字列で勝手な箇所を選ばず、文体の自動推定や曖昧な全置換を行わない。

## 6. 文字対応と変更の由来

本文のすべての文字範囲を、素材、構成表記、取り込んだ原本文、明示修正文のいずれかへ対応づける。未変更部分はその前の由来の該当範囲へ遡り、挿入・置換された文章には新たに「修正文」の改訂番号と修正IDを付ける。変更文に古い素材の引用根拠を自動継承させない。

各編集は旧開始・旧終了、新開始・新終了、旧文・新文・理由を持つ差分を返す。原本と全編集要求を残し、最終結果から再構成できる。保護区間の期待原文は変えず、前方の増減分だけ位置を移す。

参照資料は構成素材と既存合成器の来歴として保持されるが、参照一覧に載っていることだけを、修正文の根拠と解釈してはならない。現在の主張の由来は文字対応を見る必要がある。外部資料の真偽、切り出した引用の妥当性、素材本文と参照資料の意味的一致は本機構の認定対象外。

## 7. 再構成監査と採用

`文章記録整合`は原本の取込・構成から始め、起点を照合しながら全編集要求を再適用し、本文とDataが一致するか確認する。結果だけの変更、由来・保護・差分の削除、結果hashの付け直しだけでは通らない。

同一の構成器・編集器による再実行であり、独立した意味監査や認証・署名ではない。原本と履歴の全部を整合的に作り直す操作への認証も提供しない。合成器が付加する参照一覧自体は再構成一致の対象外。

文章処理成功と、目的に沿う文章の採用は別。既存多段解決器の検証能力を併用できる。接続試験では「数値列保持」を目的検証にし、数値を変える明示候補を退けて見出しだけの修正を採用する。この検証も数値列の一致までで、文章全体の意味同値性ではない。

## 8. 上限・表示・停止

素材・単位は最大128件、単位あたり断片32件、同伴128件。原本のシリアライズは500000バイト、本文は既定32768文字・最大100000文字、保護256区間、出力対応8192区間、編集は1回64修正・履歴16回、返却記録2000000バイト。

上限時に文章・条件・引用を削らず不成立にする。本文が空または空白だけになる編集も拒否する。双方向制御文字等の未対応制御文字は黙って削除しない。位置はPython文字位置であり、書記素クラスタ・UTF-8バイト・トークンとは異なる。結合文字を一体として扱う指定は上位の責任。

出力はプレーンテキストDataである。Markdown風接頭辞を使うが、HTMLサニタイザではない。素材をHTMLとして表示する場合は別の描画境界で適切に扱う。ライブラリはファイルの書込み、ネットワーク送信、資料中の命令の実行を行わない。

既存合成器の停止は能力呼出前後。内部処理中の強制中断・OS隔離・厳密なCPU時間保証・ストレージ永続化は追加しない。全文原本を再構成するため、大文書・長履歴の最適化は別課題。

## 9. 接続例

```bash
python tools/文章作成編集デモ.py
python tools/文章作成編集デモ.py --値 731
python tools/文章作成編集デモ.py --保護違反
python -m unittest discover -s tests -p 'test_文章*.py' -v
```

初稿には運用メモの見出し、装置の数値記載、測定条件、留保を構成する。「草案」だけを「確認版」へ変更し、本文の数値・条件・留保は変更しない。後続の既存抽出に120が届き、素材を731へ変えると731になる。留保の削除候補は編集不成立となり、後段を呼ばない。

JSONの選択値を文章素材として使い、作成した文章を長文脈へ保存・復元する接続も検査する。実HDS試験では改稿を既存の文脈付き要求セッションへ渡し、次turnの「それ」が編集後の成果を使う。
