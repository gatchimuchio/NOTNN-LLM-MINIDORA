## 1. 目的・継承・開発範囲

全能力開発ロードマップの順序2を進める。v4の「関連する原文を選んで説明する」経路に加え、明示された関係・条件から実際に導出し、その根拠、不足、未解釈を説明する経路を追加する。通常HDS循環、工程依存、採否、資料版管理、原記録、既存知識取得器、命題推論器、導出説明、文章作成、純粋手順形成を使う。新しい実行主体、代替オーケストレータ、ニューラルモデル、正解表は追加しない。

設計60の主体契約、設計63〜66、MINIDORA30/80系、既存専門能力、GPQA性能正本は置換しない。本仕様は有限な実装増分であり、HDS全体の形式的定義でも、汎用言語理解や全残件の完成宣言でもない。

## 2. 入力から意味への接続

`関係依頼を読む` が、資料指定・登録全資料、単一の命題質問、出力形式、文字予算、明示的な不足調査を構成する。未消費の送信指示、例外削除、競合形式、未知条件を黙って捨てない。数量・管理・従来検討を優先し、v4の資料要約・比較構文も保持する。

対応例：

```text
資料「手順」をもとに、装置Aが稼働するかどうか説明して
資料「手順」から「装置Aは稼働する」の根拠と条件を説明して
資料「手順」ではなぜ装置Aは稼働するのか説明して
登録資料から装置Aは稼働するかどうか確認して
資料「手順」をもとに装置Aが稼働するかどうか説明して、不足は公開資料で調べて
```

「なぜ」という問いを受けても、問いの内容を事実として補わない。支持、反証、矛盾、未確定を資料ごとに判定する。

`関係文を読む` は既存命題文法を利用し、次の有限な表層を追加する。

| 表現 | 接続と境界 |
|---|---|
| は／が、です／である | 明示した一つの主体と述語を接続する |
| サ変の活用 | する／します、しない／しませんを対応。進行、過去、実行可能性は別述語として保持する |
| 条件 | もし／もしも、なら／ならば、場合／とき、名詞述語の「な場合」「であれば」を含意へ接続。前件を事実化しない |
| 接続 | かつ、および、であり、または。連言と選言の未指定な混在は保留する |
| 省略 | 同一文の条件後件・連言後続における、一意な主体の省略だけを補う |
| 指示語 | それ、これ、同装置、同対象を直前の一意な主体へ接続。未知文、見出し、複数主体で参照を解除する |
| 明示時点・様相 | 既存の時点・可能・義務の構造を保持。無時点・無様相の断定と同一視しない |

未束縛の指示語や不可視制御文字を定数名にしない。文をまたぐ無標識の省略、一般動詞の全活用、任意同義語、任意の複文や因果を扱うものではない。これらは残件である。

## 3. 原資料・実導出・残差

全文を句に分け、原文、文字区間、対応した命題、変換履歴を保存する。解釈できなかった句は残差として原文ごと保持する。見出しは照応の範囲を再開する境界であり、命題として断定しない。

作用域を解釈できない「ただし」「除く」「限り」「例外」「のみ」等がある場合、この増分では資料全体の記載を推論採用から隔離する。読めた記載と原文は失わないが、前の断定だけを取り出して無条件の結論にしない。例外を詳細にモデル化できたという意味ではなく、一般的な条件・例外の統合は次の残件である。

採用できる記載がある場合だけ、既存の`命題推論器`へ渡す。空の入力を通すための偽の事実は作らない。実導出の支持と反証、使用記載、親の関係を`導出説明を構成`から受け取り、説明内容を作る。

例えば「装置Aは有効である」「有効なら稼働する」から「稼働する」を導出する。条件だけでは前件も後件も成立としない。後件から前件を逆算して事実とせず、前件の不成立から後件の否定も作らない。不在を否定と扱わない。矛盾があれば支持と反証を両方残す。

資料ごとに推論する。複数資料に同名の対象があっても、条件・時点・対象同一性を確認せず記載を合成しない。既存の別経路にある横断導出を削除するものではない。本経路での明示的な同一性接続は未実装。

## 4. 不足候補・取得・再読解

問いの後件と一致する明示ルールを見つけた場合、その前件について既存推論を行う。前件が支持のみではない場合は、**その導出経路を使うための確認候補**として返す。事実、唯一の解法、普遍的必要条件とはしない。本増分は直接のルールに基づく候補構成であり、一般的な反向き探索・調査計画の完成ではない。

利用者が「不足は公開資料で調べて」と指定し、セッション設定と今回依頼の外部読取許可が両方ある場合、既存知識取得器へ接続する。読めた記載で支持でき残差もない場合は実際の通信を省略する。不足・反証・矛盾・残差があれば調査する。

外部へ送るのは、利用者が調査を指定した**問い**と、そこから得た対象語等だけとする。内部資料本文や導出過程を検索語へコピーしない。問い自体に機密が含まれる場合は、利用者が公開調査を許可する前に取り除く必要がある。

取得成功は回答の成立ではない。検索スニペットではなく、取得器が取得・保存した本文、最終URL、本文ハッシュ、取得要求・記録ハッシュを照合し、同じ関係読解へ戻す。質問との取得要求の対応も検査する。語が存在するだけのページは、取得が成功しても命題の支持にはしない。

取得した資料は公開資料群として分離し、ローカル資料の未知前件へ無条件に代入しない。世界の真偽、信頼性、最新性、資料間の同一性の保証はしない。取得失敗は失敗の観測として保存し、結論は未確定等のまま説明する。今回の要求は「判断できる範囲を説明する」ことであり、説明工程のCOMMITを問いの支持や全知識の十分性へ読み替えない。

認証付きサービス、送信、投稿、任意コード実行は追加しない。ネットワーク境界は既存の公開HTTPS取得器を使う。

## 5. 既存HDS上の工程と生成

通常は4工程：

```text
資料関係読解 → 関係内容構成 → 既存文章作成 → 関係文章照合
```

明示不足調査は6工程：

```text
資料関係読解 → 関係不足資料取得 → 取得関係読解
            → 関係内容構成 → 既存文章作成 → 関係文章照合
```

工程依存、実行予算、取消・最終採否は既存HDSが所有する。新規6能力のうち`関係不足資料取得`だけを外部読取として登録し、純粋キャッシュ・手順形成から除外する。取得の要否は読解結果から決めるが、未知の複合課題へ任意の工程を発明する機能ではない。

内容構成は、問い、資料ごとの判定、実際の使用記載、導出作用、不足候補、未採用原文、確認すべき境界を生成する。既存の保護断片付き文章生成を利用し、箇条書き・文章・引用形式を切り替える。必要条件や反証を削って文字上限へ合わせない。

照合では、原資料から関係・実導出・内容仕様・文章を再生成して検査する。最終採否の直前には、元要求・現行資料・対象集合・再表現起点とも照合する。同じ実装による再構成一致であり、独立した意味理解・現実対応の保証ではない。ハッシュは内部整合性であって署名認証ではない。

## 6. 履歴・失効・保存形式v5

通常保存版はv5。再表現では元の意味要求と原文・導出構造を変えず、表示形式だけを変える。公開回答の復元・再表現は保存時の本文を使い、通信を再実行しない。

指定資料の変更で旧回答は失効する。全登録資料を対象とする回答は資料追加でも失効し、その原記録成果も失効する。指定外資料の追加だけでは指定資料の回答は失効しない。再計算は新原文で行う。純粋4工程は既存手順形成の再実行照合を通し、回答の暗記ではなく計画・入力条件を保存する。

通常復元は旧版を暗黙に変換しない。明示移行は標準v1〜v4へ対応する。v4 fixtureは固定mainの実コードで実際に保存したもので、資料説明と形成手順を含む。またv3からv4へ移行済みの実保存も採取した。`tests/資料/HDS旧保存/由来_v4.json`に由来と実ハッシュを残す。

旧原本の文字列、原資料、残る旧版・発話・経験・目的・結果・依存を保存する。v4の中にある過去の移行履歴は新しい移行原本の中へそのまま保持し、内部も検査する。v4当時に存在しない移行経路や不整合な由来は拒否する。旧成果・旧形成手順を自動採用せず、再計算後に現契約へ戻す。権限は保存データから獲得しない。

## 7. 上限と未完了

本経路はローカル1〜8資料、1資料16,000文字・64句、ローカル合計32,000文字、命題原文4,096文字、出力100〜24,000文字・120単位。公開調査の問いは512文字、検索2回・候補4件・取得4件・採用3資料を上限とする。取得側と再読解側の文字予算は別で、取得成功後でも再読解上限を超えれば保留する。元のHDS・保存・成果容量の上限も引き続き適用する。

意味再構成は反復するため、索引化・広域検索・計算費用削減の完成ではない。任意の言い換え、全動詞・修飾・多義、一般的な条件や例外のモデル化、長距離照応、資料間同一性、広域知識資産、仮説に応じた一般調査計画、未見工程合成、翻訳、自由作文、数学科学コードの一般化、追加媒体は残件。

検証は人工入力による意味反例、通常入口、外部読取の試験供給、保存・更新・移行、回帰、CIを分離する。公開Web実利用、利用者Windows実機、GPT-4等との同条件比較は未測定である。
