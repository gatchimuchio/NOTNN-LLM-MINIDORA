# 構文化統一状態循環 v1

- 日付: 2026-09-02
- 対象: MINIDORA v0.5 標準選択Runtime
- 根拠: K3 / GLM-5.3系 / Llama 3 / 言語模型横断構文化
- 状態: 標準実行経路へ還元

## 1. 目的

既に構文化済みの作用を「部品が存在する」状態から、標準MINIDORA実行で実際に状態差を生む循環へ統合する。

## 2. 統一する寿命

```text
主体状態              turn横断
認知世界 / task状態    request/task
作業状態 / candidate   request-local
参照計画              有限lease
粗い索引              archive探索専用
正本Data               非圧縮・証拠正本
```

これらを同一視しない。

## 3. 標準選択経路

```text
HDS Compiler
→ 参照取得
→ HDS統一状態Session
→ HDS能力経路V3
   ├ archive/index/plan分離
   ├ plan lease / invalidation
   ├ progressive widening
   ├ V2の局所再照合/checkpoint/状態差
   └ candidate pass lane保持
→ HDS適応候補調停
→ HDS統一選択評価
→ J/HDS
→ APPROVE / SUSPEND
```

追加参照・計算後の再評価も同じ統一入口へ戻す。初回だけV3、その後旧経路へ戻る二重構造を禁止する。

## 4. K3からの還元

- 確定前状態を保持する。
- checkpoint再作用を許す。
- 局所更新と大域再照合を分離する。
- 共通作用と専門作用を分離する。
- 最終確定をJ/HDSまで遅延する。

## 5. GLMからの還元

- `M_ARCHIVE != M_INDEX != M_RETRIEVAL_PLAN != M_WORKING`
- 索引だけを圧縮し、証拠本文は正本から再読する。
- 参照計画を有限leaseで再利用する。
- archive / candidate / subject差分でplanを失効する。
- 複数評価passを意味固定しないlaneとして保持する。

## 6. Llama 3からの還元

- 主体を不可変な内在実体とは扱わず、同一主体住所と版付き状態を毎判断へ接続する。
- 専門作用は主体を直接上書きせず差分を返す。
- 主体状態変化を参照計画の再開放条件へする。

## 7. 横断構文化からの還元

状態保存と後続利用を分離する。

```text
存在した
!=
後続へ使われた
!=
参照集合が変わった
!=
経路が変わった
!=
計算量が変わった
```

`hds作用実効監査.py` で removed / fixed / replaced 等の変種を比較し、実効差を測る。

## 8. 形成循環

実行履歴から `残差 → 既存作用 → 実進展` を形成候補化する。

- 反復成功だけで自動推論規則へ昇格しない。
- `ELIGIBLE` と `APPROVED` を分離する。
- 明示承認された作用だけ推奨可能にする。
- 世界知識そのものを形成規則へ埋め込まない。

## 9. 不変条件

1. canonical Kを作業状態で水増ししない。
2. 索引内容を証拠としてJへ渡さない。
3. 同一状態・同一Dataの無意味な決定論的再実行をしない。
4. 候補生成系にCOMMIT権限を与えない。
5. 形成候補を自動で推論へ接続しない。
6. 模型固有の3:1、4 lane等を成立条件へ固定しない。

## 10. 受入条件

- リポ整合性監査 PASS
- 日本語基底監査 PASS
- compileall PASS
- 全unittest PASS
- Linux / Windows × Python 3.11–3.14 CI PASS
- CLI smoke PASS
