# K否定極性保持契約 v0.17

## 1. 目的

HDS Compilerは宣言文の否定を `relation.条件` の `極性=否定` として保持できる。

一方、v0.15まではKが否定関係を安全に扱えない前提で、Dataの否定関係をK射影時に落としていた。

しかしKの既存 `Fact` は既に、

```python
polarity: bool
```

を持ち、KnowledgeBaseも `(predicate, args, polarity)` を別Factとして保持できる。

したがって否定情報を捨てる必要はない。

v0.17では、**HDSの否定極性を既存K Factの極性へそのまま写し、positive候補評価へは混ぜない**。

## 2. 射影

```text
HDS関係
  種別 = 阻害
  始点 = Compound A
  終点 = Enzyme X
  条件 = 極性=否定

        ↓ HDSKData射影

HDS関係を保持

        ↓ HDSIR知識Adapter

Fact(
  predicate = hds_relation_阻害,
  args = (Compound A, →, Enzyme X),
  polarity = False,
)
```

肯定は従来通り `polarity=True` とする。

## 3. Dataだけで否定関係を通す

現段階では、

- Data IR: 明示否定をKへ保持する
- 候補 IR: 従来のJ補集合/選択制御を維持する
- 質問 IR: 従来のJ補集合/選択制御を維持する

とする。

理由は、Dataの否定は外界から得た事実情報であり保存価値がある一方、否定質問・否定候補の採否規則はJの選択意味と接続しているためである。

## 4. positive証拠viewと全証拠viewを分ける

既存のK候補比較、HDS Graph、direct verifierは肯定関係の支持経路として実装されている。

否定Factをそこへそのまま混ぜると、

```text
A does not inhibit B
↓ 誤り
A --阻害→ B の支持
```

になり得る。

したがって `HDS証拠事実` は既定でpositiveだけを返す。

```python
HDS証拠事実(core)              # positive
HDS証拠事実(core, 極性=False)  # negative
HDS証拠事実(core, 極性=None)   # all
```

否定Fact自体はKと証拠台帳から消さない。

## 5. 正負共存

同じpredicate/argsに対して、

```text
positive Fact
negative Fact
```

は別Factとして共存する。

これにより既存KnowledgeBaseの `contradictions_for` で正負衝突を観測できる。

## 6. 未対応scope

v0.17で新たに通すのは**明示否定だけ**である。

次はまだK辺へ昇格しない。

- may / might / could 等の様相
- 条件scope
- 量化scope
- その他、Fact.polarityだけでは忠実に表現できない意味

これらを肯定Factへ縮退させないv0.15の境界は維持する。

## 7. 不変条件

1. HDSの `極性=否定` を消さない。
2. 否定関係を肯定Factへ変換しない。
3. 正負Factを同一keyへ潰さない。
4. positive候補評価へnegative Factを混ぜない。
5. negative FactをKから削除しない。
6. modal/条件scopeを無条件Factへ昇格しない。
7. R query・検索予算を変更しない。
8. Jの否定選択意味をKへ勝手に移さない。
9. benchmark固有分岐を入れない。
10. 世界知識を追加しない。

## 8. 検証

- Data否定関係がK射影で残る。
- Adapter後に `Fact.polarity=False` となる。
- 同一predicate/argsのpositive/negativeが共存する。
- `contradictions_for` が正負衝突を検出できる。
- `HDS証拠事実()` の既定viewにnegativeが混ざらない。
- negative view / all viewでは否定Factを取得できる。
- modal関係は引き続きK辺へ昇格しない。
