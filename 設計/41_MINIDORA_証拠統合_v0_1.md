# MINIDORA 証拠統合・矛盾処理 v0.1

日付: 2026-09-10
基点commit: `644af240d18d90c95d4beec26cab1b744149c61b`

## 1. 完成した作用

```text
第4バッチの取得資料、または利用者が明示した参照資料
→ 証拠統合: 対象・属性・値・比較・単位・条件・時点・原文位置
→ 条件と時点ごとの制約共通域、競合、未解釈部分を保持した報告
→ 記載値採用: 一意・非競合・未解釈なし・資料数条件を検査
→ 既存Capability合成器の後続処理へ値を渡す、または保留
```

**分析報告の成立と、記載値を採用できることは別である。** `証拠統合器.実行`は矛盾のある資料も分析報告として返す。`能力結果.成立=True`を「資料が正しい」と読むことを禁止する。`記載値を採用`が別途関門を担い、未解決なら最終値を返さない。

既存の外部参照R仕様が求める同一主題・同一属性の差異の並列保持を、数値の限定領域で実装する。HDSやCoreの最終採否を置き換えない。資料が外付けされていることと、内容の制約差が後段の実行を変えることを区別して検査する。

## 3. 局所文法

```text
装置Aの電圧は120 Vです。
装置Aの電圧は0.12 kVである。
装置Aの電圧は120 Vではない。
装置Aの電圧は100 V以上です。
装置Aの電圧は200 V未満です。
2026-09-01時点、条件「通常」では、装置Aの電圧は120 Vです。
```

対象・属性・必要な出力単位は`証拠照合要求`で明示する。任意の自然言語質問からの抽出は未実装。名前は完全一致であり、同義語や別名を自動同一視しない。

日付と条件は各記載自身が明示したものだけを採る。条件は`条件「…」では、`、時点はISO日付の`…時点、`。公開日時・取得日時・依頼文を、主張が適用される時点へ昇格させない。未記載は`None`のまま保持する。

否定は数値比較の否定として扱う。「以上ではない」は「未満」、等値の否定は除外値となる。約・推定・引用・質問・複合否定・未知の但し書きは、肯定の数値へ削って変換しない。

改行と句点で局所単位を分離し、全体一致する単位だけを読む。小数点で文を分割しない。原文位置は渡された参照本文のPython文字位置であり、HTMLバイト位置ではない。

## 4. 単位と数値制約

標準ライブラリ`Fraction`へ数値文字列から変換し、二進浮動小数点の許容誤差で異なる値を同じにしない。出力も丸めない。数値は128文字以内、指数の絶対値100以内。

対応単位: V/mV/kV、A/mA、W/kW、m/cm/mm/km、s/ms、kg/g、Pa/kPa、Hz/kHz、%、個、人、円。大文字小文字を区別する。温度オフセット、複合単位、通貨換算、暗黙の整数性や物理制約は扱わない。未対応単位・次元違いは残差にする。

一致、不一致、以上、超、以下、未満を有理数上の制約として統合する。

- `120 V`と`0.12 kV`: 同じ記載値。
- `120 V`と`240 V`: 同じ対象・属性・条件・時点の群では記載競合。
- `100 V以上`と`200 V以下`: 非空な範囲だが一意値ではない。
- `120 V以上`と`120 V以下`: 共通一点120。
- 上記2条件と`120 Vではない`: 3主張を同時に満たせず競合。

競合集合には全主張IDを保持する。最小反証集合を求めたとは主張しない。別時点・別条件は異なる群として保存する。新しい資料を理由なく優先せず、多数決で反対記載を消さない。

## 5. 原文・文脈・未解釈部分

比較するのは`参照資料.本文`である。前段の生成文や検索スニペットを証拠本文へ取り替えない。第4バッチの抜粋に入らなかった留保も、保持された参照本文を走査して残差にする。

未対応の本文片は原文位置・原文・理由を残す。明確に別対象・別属性の局所数値文は対象外として別記録に残す。**その他の未解釈片が一つでも残れば記載値の採用を保留する。** 見出しや無関係な案内も解釈できなければ保留になるため、普通の長いWebページをそのまま渡すと採用できない場合が多い。これは未完の意味処理を隠さないための初版の制約である。

上流がHTMLから既に削除した表・図・脚注などを本Moduleが復元することはできない。渡された本文の内部比較に限る。未記載の条件同士を一群にして比較しても、現実に同じ測定条件だったとは認定しない。報告にその境界を明記する。

## 6. 重複と系統

同一URL（fragmentを除く）または同一本文hashでつながる資料を同じ系統として数える。間接的なつながりも結合する。同じURLの異なる本文は削除せず、競合として残し得る。

資料IDが同じで内容が異なる入力は契約違反として拒否する。異なる系統数を出典独立性の証明や投票数へ昇格させない。同一サイトの転載等の追跡は未実装で、独立性は未確認のままである。

## 7. 報告と採用

報告のDataに要求、主張、条件・時点別の群、共通域、原文対応、残差、対象外記載、資料原本、採用可否、理由、記録hashを保持する。

値採用は次を満たすときだけ成立する。

1. 報告が成立し、記録・本文・根拠・資料の整合が取れる。
2. 指定した条件・時点に対応する群が一つである。指定なしで複数群があれば保留する。
3. 競合も未解釈片もなく、適用条件不明の群を捨てていない。
4. 共通域が一点で、必要な資料系統数を満たす。

採用値には資料側の条件・時点と記録hashを付ける。これは資料記載値であって、実世界の事実認定ではない。値だけを無条件の主張に変換しない。

報告だけを読む経路は競合でも動く。数値処理へ流す経路は`証拠統合→記載値採用→後続Module`とし、採用保留で後段を呼ばない。既存合成器はこの違いを自動推測しない。

ハッシュは同一プロセスの整合検査であり、署名、出典の真正性、悪意あるPythonコードの隔離ではない。既存合成器が参照順を維持するため、証拠照合は資料順序だけの変更を改変扱いしない。


デモは人工資料を使う局所対照。ネットワーク取得や汎用能力ベンチではない。接続試験では既存の知識取得・HTML復号・合成器・数値抽出を実際に呼ぶが、検索・HTTP本文の供給は人工である。
