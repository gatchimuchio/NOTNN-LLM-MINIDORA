## 1. 目的

数量以外の命題を保持し、提供された複数資料から問いの支持・反証を別々に導出し、意味候補の確認と根拠説明を同じ会話へ接続する。名称だけの一般命題IRではなく、原文解析・条件適用・量化・説明までの実行経路を追加する。

このIRは実装範囲を表す暫定的な射影であり、HDS全体や世界そのものの完全な表現ではない。能力模型核・厳密言語模型核の定義を変更しない。世界知識や正解表を追加せず、入力の記載を世界の事実へ昇格しない。

## 2. 接続と責任

```text
利用者の命題検討要求
→ 会話行為・選択資料・問い・表現条件
→ 実公開HDSの原文・座標・残差の保持と局所照合
→ 問いの構成解析・意味候補
→ 複数候補なら実行前に確認
→ 役割計画器
   → 各原資料の命題化
   → 記載集合から支持と反証を別々に導出
   → 既存の回答意味IRへ接続
→ 既存統合セッションの採用境界
→ 原成果・依存資料・問いを会話へ保持
→ 説明・表への再構成、問い訂正、資料更新による失効
```

| ファイル | 責任 |
|---|---|
| `命題構造.py` | 原子・項・否定・接続・量化・時点・様相の型、復元、置換、上限。 |
| `命題解釈.py` | 括弧と節の構成解析、局所日本語、候補保持、資料内原文範囲。 |
| `命題推論.py` | 有限具体化、前向き条件適用、仮定導入、量化の支持/反証、根拠グラフ。 |
| `命題能力接続.py` | 原資料の再構成検査、命題報告、2能力・3作用の登録。 |
| `命題会話解釈.py` | 命題検討、候補番号、問い訂正、実HDSとの照合。 |
| `命題回答.py` | 判定・根拠依存から説明、表、導出手順を構成。 |
| 既存会話・製品接続 | 旧数量系を維持し、追加作用を同じ汎用モードへ接続。 |

元の29能力本体、Core、公開HDS Compiler、GPQA正本、既存CI、依存パッケージ、既定製品モードは変更しない。追加能力は`命題資料解釈`と`命題関係判定`。新たな外部通信・任意コード実行は行わない。

## 3. 表現と解析

原子命題は任意の述語名と0〜4項を持つ。項は定数・束縛変数・内部の存在証人・内部の任意個体を区別する。文字列が同じだけで定数と変数を同一視しない。利用者は内部個体を復元入力として持ち込めない。

接続は否定、連言、選言、前向き含意、全称、存在。時点と様相（記載・可能・義務）は原子の照合軸として保持する。異なる時点の入れ子は上書きせず、様相の入れ子を単層へ潰さない。

| 入力例 | 作用 |
|---|---|
| `太郎は猫である` / `太郎は猫ではない` | 所属記載・明示否定。 |
| `親(太郎,花子)` | 任意述語の項を順序付きで保持。 |
| `PかつQ` / `PまたはQ` / `PならばQ` | 節から接続式を構成。 |
| `否定(PまたはQ)` | 否定の作用域を括弧で指定。 |
| `すべての猫は哺乳類である` | 全称条件として保持。 |
| `一部の猫は鳥である` | 同じ匿名個体についての存在記載。 |
| `すべてのxについて(親(x,花子)ならば保護者(x,花子))` | 束縛変数を持つ関係規則。 |
| `2025年では(P)` | 指定年の記載。未指定年へ自動昇格しない。 |
| `可能性として(P)` / `義務として(P)` | 実際の成立とは別の命題。 |

資料は句点・改行・セミコロンで区切る。括弧内は区切らず、文全体を消費できない断片が一つでもあれば採用しない。任意の自由文を文字列原子に丸めない。原資料の未知構造Dataを本文だけへ読み替えない。

語彙と工程列は分離する。`猫`等は例の資料内容であり、推論器内に動物や人物の知識を登録しない。述語の類義性・常識・因果は自動補完しない。

## 4. 意味候補

`PまたはQかつR`では係り先の異なる候補を残す。`すべての猫は鳥ではない`では全称否定と全否定の作用域候補を残す。候補番号は意味の正しさの順位ではない。

問いが複数解釈を持つ場合、実行器へ渡す前に確認する。`解釈は1です`等の返答で同じ問いを再開する。確認中の選択資料版を保持し、資料が変わっていれば古い候補への番号回答だけで進めない。

資料本文自身の曖昧さは、この版では原資料の括弧・否定範囲の明示を要求して停止する。資料の候補組合せを自動探索して都合のよい解釈を採用しない。文脈による候補の自動消去は未実装。

## 5. 導出規約

支持と反証の各経路を独立して求める。

| 支持 | 反証 | 報告 |
|---|---|---|
| あり | なし | 支持 |
| なし | あり | 反証 |
| あり | あり | 矛盾 |
| なし | なし | 未確定 |

報告生成の`合格`は「この判定報告を構成できた」という意味であり、「問いが真」「実世界の事実」「前提が全部整合」の意味ではない。

前向き含意は、前件の支持がある場合だけ後件へ接続する。後件肯定から前件を逆算せず、前件不在を前件否定としない。連言の前件には全項が必要。選言の記載を一方の断定へ分解しない。矛盾から無関係な任意命題を導出する規則は持たない。

条件付きの問いは前件を局所的な仮定として導入して検討できる。仮定は根拠グラフに明記し、条件導出を閉じる。持続知識・会話上の事実として保存しない。

全称記載は登場項へ具体化する。全称の問いは、記載や問いにない内部の任意個体を導入して検討し、有限個の成功例を数えただけで全称化しない。存在記載は記載ごとの匿名証人へ分離し、別の存在記載の証人を勝手に同一視しない。全称包含だけから対象の存在を作らない。

反対命題も同じ導出器で処理する。全称命題の反証には具体的な前件と否定後件の組が必要。存在する連言の反証では、前向き規則と局所仮定から対応する全称否定が導ける場合も扱う。

この推論方式は、明示否定を持つ有限導出と仮定導入の組合せである。古典一階論理全体の決定手続き、特定多値論理の完全な公理系、一般因果推論、すべての正しい含意を発見する機構とは主張しない。選言除去・一般の対偶・等号推論・関数項・交互量化の一般処理は実装していない。未導出は、この導出方式で未確定という意味に限定する。

## 6. 根拠と回答

各導出ノードは式・作用・親ノード・出典・仮定範囲を持つ。支持と反証の双方があれば双方の根拠を残す。資料原文範囲、使用規則、具体化、条件適用の依存順から説明を構成する。

既存`回答意味IR`へ判定命題と導出手順を接続し、文章と表へ構成する。詳細化は前回の回答文をそれらしく言い換える操作ではなく、保持した元報告からの再構成である。

報告・回答の再構成検査は本文、データ、必須参照、根拠を照合する。自己整合検査であり、独立した真理判定や出典真正性の証明ではない。JSONの配列とPythonのtuple/listの輸送差は正規符号化で比較し、本文・値・出典の変更は許容しない。

## 7. 会話と利用

```text
資料「規則」を登録:すべての猫は哺乳類である。太郎は猫である。
資料「規則」から「太郎は哺乳類である」は言える？
根拠を説明して
主張を「太郎は鳥である」に訂正して
```

複数資料は`資料「A」と資料「B」から…`、全登録資料の明示選択は`全資料から…`。単一資料なら`この資料から…`も利用できる。資料更新は既存の`資料「規則」を更新:…`を使う。依存する直前成果は失効し、新しい問いは更新済み原資料を使って再導出する。

```bash
python tools/命題会話デモ.py
python tools/命題会話デモ.py --json
python -m minidora.製品版 --汎用
python -m minidora.製品版 --汎用 --serve
```

既定モードを置換しない。失敗した命題検討を旧Coreへ透過しない。外部取得の権限・挙動は従来どおりで、本命題経路自体は通信しない。

## 8. 上限と未完成範囲

単一の問いは4096文字、式256節点・深さ24、意味候補8個。選択資料8件、各本文32000文字・128記載、全体256記載。全称記載の同時変数は2個。推論の既定上限は項48・事実1024・根拠4096・操作50000・仮定深さ8。超過は途中結果を採用せず停止する。これらは論理処理の予算でありOSレベルのメモリ隔離ではない。

任意の日本語意味理解、資料中の任意の文章からの命題抽出、語義・類義語・省略補完、意味候補の自律解消、一般命題を使う公開Web調査、因果・類推・評価基準の生成、自由作文、未知アルゴリズム生成、汎用翻訳は残作業。回復機構・外部GET再実行の既存境界は変わらない。

検証は各作用と接続の不具合を戻すために行う。試験件数やこの仕様の項目名を、一般知能やGPT-4同等の完成証拠にしない。
