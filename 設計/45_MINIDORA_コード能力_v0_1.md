# MINIDORA コード能力 v0.1

日付: 2026-09-10
基点commit: `8815e66263edfff8ef1e1d343857672395318312`
対象: 開発一覧⑨の、限定Python関数の構造読解・生成・評価・試験。

## 1. 追加する作用

```text
構造化したアルゴリズム + 定数Data
→ Python ASTを構成 → コードを生成
→ 限定構文の検査
→ 指定入力を独自AST評価器で処理
→ 指定試験との一致／不一致
→ 既存多段解決器で、失敗候補から別の明示候補へ戻る
```

既存のPythonソースを入力して、関数・引数・分岐・反復・返却・呼出と原文範囲を読む経路も提供する。構造読解を、コードの全経路の仕様適合や意味理解の完成とは呼ばない。

生成は日本語の構造化アルゴリズムから行う。自然言語の自由な依頼を構造化する能力、未知アルゴリズムの発明、自動的な修正案の生成は今回追加していない。修正候補として明示した別アルゴリズムの選別は既存多段解決器を使う。

Core、HDS Compiler、既存の合成・多段解決・科学Module、GPQA正本、標準チャット入口、GUI-Shellは変更しない。新しい依存パッケージとネットワーク作用は追加しない。

## 3. Pythonの対応範囲

対象はモジュール直下の単一関数。通常の名前付き位置引数を最大16個扱う。関数内の単一変数への代入、整数の累算、if/else、for/else、break/continue、return、pass、先頭docstringに対応する。

式は整数・bool・文字列・None、list、文字列キーのdict、名前参照、添字参照、加減乗算・整数商・剰余、単項符号・not、短絡and/or、比較連鎖・包含、条件式を扱う。組込呼出はabs/len/min/max/sum/range/sorted/list/all/anyに限定し、キーワード引数を認めない。min/maxは単一の反復可能値または複数値、rangeは1〜3引数、その他は1引数とする。

累算は整数のみ。list += のaliasを通常の加算へ誤変換しない。文字列の%書式演算は数値剰余として受理しない。組込呼出名の引数・ローカル変数への上書きを拒否する。

未対応: float、真の除算、べき乗、slice、tuple、set、内包表記、lambda、再帰、別関数・メソッド呼出、属性アクセス、import、with、try、raise、while、yield、async、class、注釈、デコレータ、既定値、特殊引数、添字代入、append等。未実行の枝にある未対応構文も関数全体の評価前に拒否する。

完全なPython互換ではない。対応構文でも値型・規模によって未成立になる。returnなしの正常終了はNone、範囲外添字・0除算・未束縛名等は診断を返す。診断位置は最後に評価したASTの行であり、完全なPython tracebackではない。

## 4. 実行境界

製品コードは入力ソースをexec/evalへ渡さず、ASTノードを独自に評価する。許可された組込操作だけを内部で呼ぶ。対象コードによるOS操作、通信、外部オブジェクトへの属性参照は提供しない。

AST解析にはPythonのast.parseを使う。解析成功だけではPythonの全スコープ規則は検査されないため、別途、単一関数・反復内制御等の契約を確認する。AST構造・許可範囲・値・実行手数を検査する。

これはプロセスの隔離、悪意ある任意Pythonコードの実行サンドボックス、C実装を含む厳密なメモリ安全保証ではない。ast.parse自体がスタック・メモリを消費する。OSの強制終了・壁時計タイムアウトはない。利用者の入力を本物のPython実行環境で評価するAPIは作っていない。

## 5. 上限と可変値

ソースはUTF-8で32768バイト、ASTは2048ノード・深さ40。整数は絶対値相当256ビット、list/dict/rangeは2048要素、文字列は8192文字、文字Data合計65536バイト、値木4096要素・深さ16まで。反復積・結合は大きい値を確保する前にも検査する。rangeは範囲長を検査してから展開する。

評価手数は既定50000、設定上限200000。評価・反復・集約の処理を計数する。文字比較等のPython内部計算の命令数や経過時間ではない。分岐履歴は最初の128件のみを返し、完全な全ステップログとはしない。

入力の値型は正確に検査し、任意のユーザーオブジェクトや非有限数を受理しない。評価前に引数を複製し、結果も複製する。呼出し間の状態・入力の変異を共有しない。

停止コールバックは開始・終了と一定の評価間隔で検査する。既存Capability契約経由ではコールバックを内側へ渡す機構がないため、外側合成器の停止はModule呼出前後になる。

## 6. 構造化アルゴリズムとData分離

関数仕様の項目は`名前 / 引数 / 手順`。手順は`代入 / 返却 / 分岐 / 反復`、式は`参照 / 定数参照 / 算術 / 比較 / 選択 / リスト / 添字 / 呼出`を持つ日本語の辞書構造である。未知の項目や演算は捨てず不成立にする。

数値・文字列等の実値は別の`定数`Dataへ置く。生成関数には追加引数`定数`があり、コードはその辞書を名前で参照する。閾値を2から731へ変えてもコードは同じで、Dataだけが変わる。予約変数・組込名の上書きと定数欠落を拒否する。

生成に試験の期待値やベンチマーク正解は渡さない。生成結果に構造化仕様・定数・仕様とソースのhashを保持する。生成成功は構文境界を通ったことを表し、入出力の正しさは別の検証に任せる。

## 7. 試験と候補選別

コード検証には1〜32件の`引数 / 期待値`を渡す。生成コードを検証する場合、引数は明示的に定数辞書を含む。期待値に合わせて定数やコードを自動変更しない。

コードを独自評価し、型を保持した値を期待値と比較する。boolとintを同じにしない。一件でも不一致・未評価なら検証能力は不成立にする。各ケースの実値、診断、手数とソース・試験のhashを返す。試験数上限を超えた入力を黙って剪定しない。

既存多段解決器の目的検証にコード検証を指定できる。候補コードの構文が通っても、境界入力の試験が失敗した場合は採用せず別の明示候補へ戻る。候補が尽きれば保留し、試験を減らしたり条件を緩めたりしない。

有限試験の合格は全入力の正しさの証明ではない。コード候補の発見能力と候補を試験で選別する能力も区別する。

## 8. 検証例

目的: 閾値より大きい要素だけを二乗して合計する関数。

- 候補Aは「以上」を使用。空配列は通るが、境界値だけの入力で不一致。
- 候補Bは「超」を使用。指定した3試験をすべて通過して採用。
- 選別に使っていない`[-3, 2, 5, 8]`では89を返す。
- 候補Bを外した場合は保留。候補Aの誤ったコードを完成品として返さない。

```python
def 条件付き二乗和(数列, 定数):
    合計 = 定数['初期値']
    for 数 in 数列:
        if 数 > 定数['閾値']:
            合計 = 合計 + 数 * 数
        else:
            pass
    return 合計
```

コード自体と定数Dataを分けて返す。これは関数の内部機構を実際に生成し、入力を処理するもので、固定した回答文を返すデモではない。ただし候補アルゴリズムは人が明示したもので、任意の自由文から生成したとは呼ばない。

```bash
python tools/コード能力デモ.py
python tools/コード能力デモ.py --代替なし
python -m unittest discover -s tests -p 'test_コード*.py' -v
```
