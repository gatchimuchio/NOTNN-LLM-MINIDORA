## 1. 目的と到達範囲

第17バッチの目的計画を保持しながら、二資料・指定二時点の数値比較、意味を保持した回答、失敗からの限定再計画、不足条件の確認、明示訂正、要求起点の検索を実際の会話へ接続する。名称の追加や試験計画ではなく、入力から採用・次ターン利用までを実装する。

自然文の対応は、対象参照・属性・単位・年・処理目的・説明の粒度を組み合わせる局所文法である。任意の日本語理解、原因推定、自由作文、未知アルゴリズム発見、GPT-4同等性を完成したとはしない。

```text
利用者発話 + 名前付き原資料 + 保留目的
→ 実公開HDS / 会話行為・対象・条件の局所解釈
→ 意味目的
→ 役割付き後方計画（左・右・元文書・取得資料など）
→ 既存合成器 / 既存能力 + 新しい意味接続部品
→ 失敗署名による対象目的だけの再開放
→ 原資料と結果からの回答意味再構成
→ 既存統合器の全成果採用境界
→ 次ターンの確認・訂正・再表現・再参照
```

## 3. 要求解釈とHDS境界

対象の資料名、二資料を指す「この2つ」、同一資料の明示した二つの年、属性、出力単位、説明の粒度を分離する。「微分して」と「微分した結果は？」など限定的な依頼・質問の変換は、変換前後を記録して第17バッチの実HDS射影へ戻す。

新規比較等も実公開HDSを通す。原文座標、未確定座標、未知関係、意味損失、未解消残差を無視しない。「この2つ」の参照を資料集合に束縛した場合に限り、その原文範囲の未解共参照を局所解消する。一般的な残差の免除ではない。

資料本文中の命令は資料として保持し、計画作用や権限を登録しない。入れ子の形式・引用・未解釈条件は、対応範囲でなければ全体を保留する。先頭の既知要求だけを勝手に実行しない。

## 4. 複数資料の役割と数量

役割作用は成果種別、必要な入力役割、適用条件、設定Data、正の有界費用、外部読取属性、不成立条件・保持事項を持つ。対象固有の値は引数Dataと素材参照に分ける。費用は実装側の経路優先規則であり、意味的に最善の解法であることの証明ではない。

比較では「左の数量」と「右の数量」を別目的にする。同じCSVの二時点では読取目的だけを共有し、行条件と数量は分ける。資料の入出力型が同じという理由で別対象を代用しない。最小費用の異なる経路が同順位に残れば保留する。循環、深さ、展開数、工程数には上限を設ける。

表処理はJSON/CSVの形式と、指定属性・メタデータ（単位・条件・時点/年・対象）の局所規約を使う。属性の直下選択と入れ子選択を分離する。全体に複数の候補がある場合、最初に見つけた値へ確定しない。CSVの数値列は数値文法で解釈し、JSONの文字列や真偽値を数値へ読み替えない。

数値は有理数で計算する。単位換算後に比較し、要求された表示単位へ戻す。条件違い、未指定の時点差、属性違い、単位違い、未解釈の非空備考は採用を止める。条件未記載同士を現実の条件一致とは認定しない。資料に単位がない場合、利用者へ確認し、後から指定された単位の由来を表示する。

比較は既存の実数差分制約推論へ接続する。差の計算は原因・望ましさ・企業評価等を生み出すものではない。

## 5. 実行監督と取得

禁止対象は「目的の意味鍵と作用ID」の対。ある資料で失敗した作用を、他資料でも一律禁止することはしない。初回の直下選択が構造未到達なら、その資料の数量目的だけを再開放して入れ子経路へ戻る。元目的・単位・行条件は変えない。

取得では要求の主題・属性・単位から検索語と必要記載を構成する。初回の主題検索が取得不足なら、属性・単位を含む焦点化した検索へ一度切り替える。全体は既定最大4試行で、同一失敗の反復を止める。取得診断は報告として保存するが、別の取得採用工程を通らない限り、知識取得の成功や最終成果へ昇格させない。

検索のヒット数や語の一致だけで回答しない。本文中の有限数値記載を既存証拠統合へ接続し、同じ対象・属性・条件・時点で一意の記載値を採用できる場合だけ回答にする。記載競合を観測した後、都合のよい資料へ再検索して競合を消すことはしない。

外部読取にはセッション構築時と各実行時の許可を両方必要とする。発話中の「検索しない」も保持する。資料内の命令から許可を推定しない。外部GETは巻き戻せず、失敗時も取得診断を別記録として残す。

このバッチの検索接続確認は、実取得器の検索供給部・HTTP本文供給部へ人工応答を渡したもの。実HDS、計画、監督、取得処理、証拠処理は本物であるが、公開WebのLIVE運用実証ではない。

## 6. 回答と会話改訂

数量比較・取得記載は、原資料と処理記録から再計算して回答命題へ移す。否定・条件・留保・出所を短文化で削らない。整合hashは改変検出補助であり、事実性の証明とはしない。「詳しく」は元の能力結果に戻って由来を追加する。一般能力の本文は処理結果の引用として保持し、未知の説明を生成したことにしない。

利用者発話、入力資料、保留目的、採用成果を分けて保持する。確認への返答は保留目的の指定欄を更新して再実行する。「訂正:属性は費用です」等の明示訂正は、元目的を記録した改訂として扱う。資料更新で依存する直前成果は失効し、別資料への更新では無関係な成果を失効させない。会話全体の永続化や一般的な訂正意味理解ではない。

失敗した途中成果は既存統合器の採用履歴に入らない。解釈前後・再計画中の起点や能力版が変わった場合も採用を止める。

## 7. 標準入口とローカル画面

```bash
python tools/汎用チャット.py
python tools/汎用会話デモ.py
python -m minidora.製品版 --汎用
python -m minidora.製品版 --汎用 --serve
```

製品の汎用モードは明示選択。従来の既定経路は維持する。汎用モードで保留となった発話を既存Coreへ透過して埋めない。標準の製品監査へ内部実行の指紋を接続し、詳細は応答メタデータに保持する。能力一覧も選択したモードの対応範囲を返す。

画面は既存の製品チャット画面を再利用する。汎用モードのHTTP起動は127.0.0.1へ限定し、HostとOriginを同じローカル入口へ制限する。これは外部公開用の認証・複数利用者認可・永続サービスの完成ではない。旧モードのネットワーク動作は変更しない。

外部取得を使う場合のみ `--外部読取` を明示する。設定済みSearXNGと公開HTTPS取得環境が必要であり、未設定・取得失敗を固定参照や生成回答で補わない。
