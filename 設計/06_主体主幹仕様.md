# 主体主幹仕様 — MINIDORA v0.4

## 1. 目的

K3を主たる能力観測基盤とするMINIDORAへ、Llama 3で観測された自己一貫性の成立関係を、非ニューラル・監査可能な運用機構として保持する。

主体主幹はLLM模型中核そのものではない。

```text
MINIDORA v0.4
  = LLM模型核
  + 計算・参照・HDS等の運用能力
  + 主体一貫性機構
  + 採否 / 表面化
```

この式を物理部品数とは読まない。

## 2. HDS再構文化から抽出した観測候補

Llama 3では自己専用の永続stateを参照実装上に観測しない一方、次の循環が自己一貫性候補として観測された。

```text
assistant主体住所
  ↓
過去assistant出力の再入力
  ↓
履歴参照
  ↓
共通模型経路
  ↓
出力
  ↓
次turnへ帰還
```

MINIDORAでは、この「同じ主体を毎turn再構成する」性質を明示状態へ外在化する。

## 3. 主体状態

```text
主体状態 S_t := {
  主体ID,
  現在目的,
  判断基準,
  立場,
  選好,
  約束,
  仮説,
  未解残差,
  版
}
```

人格の完全記述ではなく、次の判断を拘束する現在状態だけを保持する。

## 4. 主体主幹の不変条件

1. `主体ID` は通常実行経路から変更できない。
2. Runtime実行は同じ主体状態を必要な運用文脈へ注入する。
3. 模型核 / 計算実行器 / P / 専門処理は主体状態を直接確定更新しない。
4. 主体変更は `主体更新提案` として差分を返す。
5. 実差分には理由を必須とする。
6. 理由なし変更は保留し、旧状態を維持する。
7. 理由付き訂正は許可し、旧版・新版・差分・理由・根拠を監査履歴へ残す。
8. 主体整合が必須の要求では、保留/失敗した候補を外部結果へ昇格させない。

## 5. 模型核との境界

```text
模型核
→ 言語状態に対する成立差

主体主幹
→ その候補・結果が現在主体状態と整合するか
```

模型核の成立差と主体選好・主体整合を同一視しない。

同じ模型核でも主体状態の違いにより運用採否が変わり得る。これは模型関係同一性ではなく運用同一性側の差として記録する。

## 6. K3基盤との接続

K3由来の系列・深さ・幅方向の処理再構成は能力補助側に残す。

```text
模型 / 能力処理
   ↓
候補 / 状態差分
   ↓
主体主幹Gate
   ↓
採否・外部結果
   ↓
理由付き主体更新
```

KDA state、AttnRes、expert routing等の観測構造を主体状態と同一視しない。

## 7. LLM成立規定との関係

主体主幹は `LLM-Constitutive-Specification` の追加成立条件ではない。

大規模言語模型の模型性は `設計/02_大規模言語模型成立契約.md` に従い、主体主幹なしでも模型核単体で監査できる必要がある。

主体主幹はMINIDORAの主体的一貫性・製品能力・長期運用を担う独自外周機構として評価する。

## 8. 受入条件

- 同一主体状態がturnを跨いで持続する。
- 理由なしの立場・判断基準変更を保留する。
- 理由付き自己訂正を許可し、監査履歴を残す。
- 模型核 / 計算実行器から主体更新を直接注入してもGateを迂回できない。
- 主体ID変更を失敗扱いにする。
- 主体整合に失敗/保留した候補を外部結果として採用しない。
- 主体主幹をLLM模型核の構成要素数へ数えない。

## 9. 状態

`IMPLEMENTED_PROVISIONAL`

主体的一貫性の単独因果をLlama 3のDense構造へ帰属したものではない。公開実装・K3との差分・HDS再構文化から得た実装可能な候補として維持し、能力は別測定する。
