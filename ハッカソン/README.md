# MINIDORA ハッカソン専用実装 v0.1

本ディレクトリはハッカソン提出・デモ用の運用境界を記録する。実装本体は `src/minidora/ハッカソン/` に置き、既存MINIDORA Coreを改変せず能力モジュールとして接続する。

## v0.1成立範囲

- 最低限の基本会話
- 既存 `ミニドラ.応答()` への一般質問委譲
- RSSによる当日主要ニュース取得
- 同一セッションでの「今日のニュースは？ → 要約して」
- 明示文章の決定論的抽出要約
- 応答ごとの追跡ID
- 入力、経路、外部参照、モジュール入出力、会話状態更新、最終応答の監査記録
- SHA-256 hash chainによる監査記録改変検出

## 重要境界

この実装の「なぜこの応答をしたか」は、後付けの自由生成説明ではなく、実際に通過した処理経路を記録する。

```text
入力
→ 経路選択
→ 外部参照 / 文脈参照
→ 能力モジュール
→ 応答構成
→ 会話状態更新
→ 監査ルートhash
```

外部LLMの自由生成をニュース要約経路へ混入させない。ニュース要約は取得済Dataからの抽出・圧縮だけを行い、参照外の事実を生成しない。

v0.1の監査台帳はプロセス内保存である。製品運用では `監査記録.監査辞書()` をCloud Logging / DB / WORMストレージ等へ永続化する。

## ローカル起動

```bash
python -m pip install -e .
python -m minidora.ハッカソン "こんにちは"
```

対話モード:

```bash
python -m minidora.ハッカソン
```

対話モードで同一セッションのまま次を実行する。

```text
> 今日のニュースは？
> 要約して
```

各応答末尾に `trace_id` が出る。ライブラリ利用時は `ハッカソンチャット.監査台帳.取得(trace_id)` と `検証(trace_id)` から経路・根拠・hash整合を確認できる。

## モジュール

| 実装 | 責任 |
|---|---|
| `チャット.py` | 能力経路選択、既存MINIDORA Core委譲 |
| `ニュース.py` | RSS外部参照、当日ニュース抽出 |
| `要約.py` | 自由生成を使わない決定論的抽出要約 |
| `会話状態.py` | セッション内履歴・直前ニュース保持 |
| `基本会話.py` | 挨拶・能力説明等の最低限会話 |
| `ガバナンス.py` | 実行経路台帳、段階hash、最終root hash |
| `型.py` | ニュース・応答・監査記録の型 |

## 試験

```bash
python -m unittest tests.test_ハッカソンチャット -v
```

外部RSSを使わず固定ニュース供給器を注入し、ニュース→要約、基礎Core委譲、基本会話、監査hash検証を再現可能に試験する。
