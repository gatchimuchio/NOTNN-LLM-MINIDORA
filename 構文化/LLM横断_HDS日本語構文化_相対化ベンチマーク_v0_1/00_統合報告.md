# LLM横断 HDS日本語構文化・相対化ベンチマーク v0.1
- 実施日: 2026-08-21
- 状態: 第一巡完了（公開可能範囲まで）
- 目的: 単一モデルの絶対記述ではなく、異質なLLMを同じ日本語HDS座標へ置き、差分によって基準自体を精密化する。
## 0. 結論
今回の第一巡で、旧来の「Dense/MoE」「local/global attention」のような粗い分類だけでは不足することが確定した。相対化の結果、少なくとも **系列方向・深さ方向・幅方向・未来予測補助・モダリティ前段・形成過程・展開後制御・観測深度** を独立に保持する必要がある。
最も強い再分類は、OLMo 3 と Qwen 3.6 の比較である。両者は粗視化すると「3局所系 + 1全体」の周期を持つが、OLMoの局所作用は sliding-window attention、Qwenの局所作用は linear/recurrent 型であり、**配置周期が同じでも作用子は異なる**。従って「いつ全体照合するか」と「局所をどう保持・更新するか」を別軸にした。
また、OpenAIとAnthropicの公開情報により、**可観測なサービス挙動をmodel weight単体へ帰属することはできない**ことが明確になった。OpenAIは model / inference / agentic harness を公式に分離し、Anthropicは同一underlying modelのFable/Mythosを外部classifier/fallbackの有無で別サービスとして成立させている。
## 1. 観測深度
- **D4**: weight全payload実読＋tensor全数監査＋公開設定/構造を照合
- **D3**: 公開weight/config/codeがあり、今回config/構造を直接観測。weight全量実読は未実施
- **D2**: 開発元の公式model/system card・engineering文書・公開挙動まで。内部weight/configは未観測
- **D1**: 製品/API挙動中心。内部構造への確定は行わない

K3 v2のみD4。Qwen3.6、Llama3、OLMo3、Apertus1.5、K2V2は今回D3。DeepSeek V4は公開paper/Transformers実装を深く観測したがweight全量実読はしていないため、D3相当の「構造公開・weight意味未読」として扱う。OpenAI/Claude/Gemini/GrokはD2。
## 2. HDS観測軸の更新
- **A0 観測深度** — 対象ごとの証拠密度を座標の一部として保持する。D4/D3/D2/D1を同一確度として扱わない。
- **A1 成立物境界** — モデル本体 / 推論runtime / agent harness / safety classifier・router / product tool integrationを分離する。
- **A2 系列方向の情報流** — 全系列attention / 局所window / recurrent・linear状態更新 / 圧縮長距離参照 / sparse選択を別作用として保持する。
- **A3 深さ方向の情報流** — 通常residual / AttnRes / mHC等を系列attentionから独立させる。
- **A4 幅方向の情報流** — Dense FFN / routed expert / shared expertを独立軸化する。MoEをattentionの一種にしない。
- **A5 未来方向・予測補助** — MTPやdraft/speculatorを主自己回帰出力と分離する。training補助とserving補助も分ける。
- **A6 入力表象・モダリティ前段** — text decoder本体とvision/audio encoder・tokenizer・adapterを分離する。
- **A7 形成過程** — pretraining / continued pretraining / SFT / preference / RL / agentic trajectory学習をruntime機構と分離する。
- **A8 展開後制御** — fallback、classifier、routing、tool orchestration、cache、approval等をモデル能力から分離する。
- **A9 版・時間境界** — 同名familyでも版を跨いで逆流させない。新情報は系列証拠として保持し、対象版へ無条件遡及しない。

## 3. 更新履歴（相対化で何が増えたか）
- **R0** — trigger: 旧Llama3/OLMo3等の単体構文化 / 更新: 記号化・系列変換・形成・実行時選択・評価・安全を分離。
- **R1** — trigger: 公開weight系と非公開frontier系を同一場へ置いた / 更新: A0 観測深度を追加。未知を性能差として扱わない。
- **R2** — trigger: OpenAI GPT-5.6 / Claude Fable-Mythos / 更新: A1/A8。モデル本体・推論runtime・agent harness・classifier/fallbackを分離。
- **R3** — trigger: OLMo3 vs Qwen3.6 / 更新: A2を「局所/全体」だけでなく「配置周期」と「局所作用子」に分解。window参照とrecurrent状態更新を別物化。
- **R4** — trigger: DeepSeek V4 vs K3 / 更新: A3。系列方向と深さ方向の情報輸送を直交軸化。mHC/AttnResをattentionへ潰さない。
- **R5** — trigger: Qwen/DeepSeek/K3 MoE比較 / 更新: A4。幅方向の専門経路選択を系列・深さ方向の選択から分離。
- **R6** — trigger: Qwen MTP / OpenAI speculative draft / 更新: A5。未来予測補助を主モデル因果列から分離し、training/servingの位置も保持。
- **R7** — trigger: Apertus1.0→1.5、Gemini/Qwen multimodal / 更新: A6。モダリティ前段の追加と中央decoder再設計を同一視しない。
- **R8** — trigger: Grok4.6のmulti-harness SFT/RL、各社deployment差 / 更新: A7/A8。形成時に使ったharnessと展開時harnessを分離し、能力成立の因果を保持。

### DeepSeek V4
- 区分: frontier architecture-public
- 観測深度: D3
- 中央構造: V4はV3のMLAをhybrid local + long-range attentionへ置換し、residualをmHCへ置換する公開実装仕様。
- 系列方向: 三系統: sliding-window、CSA（低圧縮＋indexer top-k）、HCA（高圧縮＋全compressed entry参照）。さらにlong-range branchとlocal sliding branchを併置。
- 深さ方向: Manifold-Constrained Hyper-Connections (mHC)。系列attentionとは別軸。
- 幅方向: MoE。詳細はV4系config/implementationに依存し、今回weight全量は未実読。
- 未来方向/補助: V4 paper系列の補助機構は別軸で扱う。今回、未確認部分を一般論で埋めない。
- モダリティ: 本稿対象はlanguage model core。
- 形成: advanced optimization techniquesをpaperが報告。
- 展開後制御: Transformers実装まで観測。production harnessは別。
- HDS上の意味: **K3のAttnResと並べることで「系列方向の参照」と「深さ方向の輸送」が直交することを強く相対化。CSA/HCAはさらに圧縮率・選択有無を別軸化。**
- 未解残差: 全weight意味分布 / expert固有意味 / production routing/harness

### Qwen3.6-35B-A3B
- 区分: frontier open-weight multimodal MoE
- 観測深度: D3
- 中央構造: config直接観測: hidden 2048、40 layers、full_attention_interval=4。26 safetensors shardが公開。
- 系列方向: layer_typesは linear ×3 → full ×1 の反復。linear側とglobal full attentionを周期配置。
- 深さ方向: 通常block depthとして観測。K3 AttnRes/mHC型の独立深さ輸送は今回configから確定しない。
- 幅方向: 256 experts、tokenあたり8 routed、shared expertあり。sequence作用と独立。
- 未来方向/補助: mtp_num_hidden_layers=1。主出力経路とは別の予測補助として保持。
- モダリティ: vision_configを別に持ち、vision depth 27、out_hidden_size 2048。text coreとvision前段を分離して記述可能。
- 形成: post-trained model weights/configが公開。
- 展開後制御: vLLM/SGLang等で可搬。productのQwen Plusとこのopen-weight個体を同一視しない。
- HDS上の意味: **OLMo3との比較が決定的。同じ「3局所系＋1全体」の周期でも、Qwenはlinear/recurrent状態更新、OLMoはsliding window明示参照。配置周期と作用子を分離する必要が出た。**
- 未解残差: 全26 shardのpayload意味解析 / 各expertの意味 / Qwen3.6 Plusとの内部同一性

### K3 v2 full-weight
- 区分: highest-depth MoE anchor
- 観測深度: D4
- 中央構造: 固定revision c5d1dd4c428bd1ce8b88c5044f3b6ccde9e3b721。96/96 shard、497,220/497,220 tensor、payload 1,560,860,324,864 byteを実読。

## 5. 相対化で得た主要差分
- **Llama3 ↔ K2V2**: hidden=8192、80層、Q64/KV8、FFN28672という大枠が近い。一方でcontext、vocab、RoPE、形成履歴が大きく違う。従って「能力差=中央architecture差」ではない比較基準になる。
- **OLMo3 ↔ Qwen3.6**: 3:1の局所/全体周期は似るが、局所作用子が sliding explicit relation と linear/recurrent state update で異なる。粗い位相だけでは同型判定できない。
- **Apertus1.0 ↔ 1.5**: 中央decoder architectureを維持しながらmultimodal front-end、continued pretraining、posttraining、thinking/tool能力を追加。能力拡張とdecoder刷新を分離できる。
- **Fable5 ↔ Mythos5**: 同じunderlying modelでも外部safeguard/classifier/fallbackの違いで可観測サービス挙動が変わる。deploymentをcoreから分離する直接例。
- **OpenAI GPT-5.6 stack**: 開発元自身がmodels / inference / agentic harnessを分けている。推論性能・agent性能をweight単体へ逆算しない。
- **DeepSeek V4 ↔ K3**: CSA/HCA等の系列方向選択とmHC/AttnRes等の深さ方向輸送は別問題。attention一語に集約しない。
- **Qwen/DeepSeek/K3**: MoEは幅方向の選択。系列方向の参照選択や深さ方向の選択とは直交する。

## 7. 打ち止め条件
全familyの全版を集めることは目的ではない。**新しい異質モデルを入れても既存座標へ矛盾なく置け、新しい独立軸が増えず、既存対象の再分類も要求しなくなった時点**を打ち止めとする。Llama4などは次の候補だが、今回の第一巡では意図的に未追加。

次にやるなら、R8まで更新された座標でK3/Llama3/OLMo3/Apertus/K2V2を再度blindに置き直し、旧構文化との差分を「対象差」「HDS更新差」「観測深度差」に分解する。特にK3は既にD4正本があるため、相対座標の変化だけを再評価できる。
