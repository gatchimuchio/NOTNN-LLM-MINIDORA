# MINIDORA v0.4 再構成記録

日付: 2026-08-27

## 目的

外部正本 `LLM-Constitutive-Specification` の `2026-08-27-成立規定-3` を上流基準として、MINIDORAをLLM成立5条件と構成再現7条件を分離した状態へ再構成する。

## 基準

- Repository: https://github.com/gatchimuchio/LLM-Constitutive-Specification
- commit: `306ff834e5ac7e7e958b513db723a24619c8895a`
- 正本: `規定/02_大規模言語模型成立.md`

MINIDORA自体を上流規定の成立証人には使用しない。

## 旧混線と再分類

- 旧`layer0.py`: 汎用命令インタプリタ → **計算実行器**
- HDS-IR: LLM模型中核ではなく意味Projection / 運用 / 監査
- 外部参照R: 外部Data
- 主体主幹: 運用主体性
- P: 計算計画の人間可読表現

## 現行模型核

```text
対象言語状態
→ 言語対応
→ 文脈付き内部状態
→ 状態分離・保持
→ 一般模型関係 / 形成済み関係 / 参照寄与
→ 未確定候補差の共同保持
→ 候補共同再照合・再作用・再結合
→ 終端成立差
```

### 初期v0.4

当初は意味語集合と `意味連続関係` を中核としていた。

これはLLM成立構造の責任分離には成功したが、規模再測定で関係方向・肯否・履歴順序・条件結合が成立差へ到達しないことを検出した。

### 関係域修正

`src/minidora/言語構造.py` を追加し、内部言語状態へ次を保持する。

- 意味語集合
- 意味語列
- 有向関係構造
- 肯否
- 条件結合

標準模型核は次の6関係作用を再利用する。

1. 意味連続
2. 順序連続
3. 有向関係整合
4. 肯否整合
5. 履歴近接
6. 条件結合

HDSは模型核へ導入していない。

### 構成再現v3

既存K3 D4構文化・10モデル横断構文化・能力保存作用則とGPQA実測を照合し、次を正式模型核へ再接続した。

- 問い専用関係とData関係を検索述語identityで接続
- 1参照内の複数独立関係差を保持
- 形成済み関係と一般作用を分離
- checkpointを再活性し候補共同再照合へ利用
- `except / least / incorrect`等を相対例外差として扱う
- knowledge choiceの終端を参照由来の正の一意差へ限定

## 計算境界

Compute IR / ABIに相当する日本語正本を次として確定した。

```text
日本語命令形P
↓
命令計算降下
↓
計算中間表現 v1
↓
計算実行境界 v1
↓
計算実行器
```

## HDS Compiler Pipeline

Meaning/Audit Architecture `v1.2` を維持したまま、Pipeline `v1.3` で責任を分離した。

```text
自然言語
↓
意味コンパイル
↓
意味HDS-IR
├─ R / K / J / 監査
└─ 計算計画
   ↓
 計算降下
   ↓
 計算中間表現 v1
```

意味IRへPと計算初期状態を入れない。旧 `コンパイル()` は互換窓口のみ。
