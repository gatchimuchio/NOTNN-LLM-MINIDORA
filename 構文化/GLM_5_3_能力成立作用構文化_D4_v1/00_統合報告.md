# 00 統合報告 — GLM-5.3 系 能力成立作用構文化 D4 v1

- 実施日: 2026-09-02
- 観測深度: D4
- 対象: GLM-5.3系 + GLM-5.2対照系

## 0. 結論

GLMからMINIDORAへ最も大きく持ち帰れるのは、新しい「専門家」や「attention部品」そのものではない。

K3で既に得た、

```text
局所更新
↔
大域再照合
+
共通作用
+
専門作用
+
checkpoint再作用
```

をさらに分解し、**参照の責任を「正本証拠」「検索索引」「参照計画」に分離できること**、および**複数状態laneを一つへ早期上書きせず制約付きで混合できること**がGLM側の主要追加成果である。

作用としてまとめると次になる。

```text
正本証拠を保持する
↓
検索専用の粗い索引を作る
↓
必要な参照IDを選ぶ
↓
選択結果を有限期間再利用する
↓
正本証拠を正確に再読する
↓
複数状態laneへ保持する
↓
制約付きで混合する
↓
局所処理を複数回進める
↓
条件成立時だけ大域再照合する
↓
共通作用 + 専門作用
↓
候補形成
↓
J/HDS
```

## 2. GLM-5.2 / 5.3 — DSAとIndexShare

GLM-5.2/5.3の疎attention系では、軽量indexerが参照候補を選び、その選択を複数処理段で再利用する構造が公開されている。

ここから分離できるのは、

```text
全文を保持すること
!=
全文を探すための索引
!=
今回どこを読むかという選択結果
```

である。

MINIDORAでは次へ射影する。

```text
M_ARCHIVE
= 参照記録の正本本文

M_INDEX
= 正本を探すための粗い検索表象

M_RETRIEVAL_PLAN
= 現在選択された参照ID集合 + 有効期限
```

IndexShareから持ち帰るべき本体は「4層」という数字ではない。

> 参照条件が変化していない間は、一度計算した参照対象を再利用し、毎段同じ検索判断を繰り返さない。

この作用をMINIDORAでは有限leaseとして実装した。

## 3. GLM-5.3-Flash — KDA / DSA hybrid

公開configではtext core 45層に対し、KDA系linear/state layer 34、DSA sparse-attention layer 11が配置され、概ね3 KDA + 1 DSAの周期を作る。

ここから持ち帰るべき作用は、

```text
安価な継続状態更新
!=
高価な広域参照
```

を分離すること。

K3でも3 KDA + 1 Gated MLAとして同系作用を観測済みなので、GLMで新規発見された原理とはしない。

GLM側の追加価値は、大域側がさらに「index → sparse selection → exact context read」へ細分化されている点にある。

## 4. IndexPool — 圧縮してよいものの境界

GLM-5.3-FlashのIndexPoolでは、検索用key側を複数から圧縮し、retrievalコストを下げる構造が使われる。

MINIDORAへの重要な射影は、

> **圧縮するのは検索索引であって、証拠正本ではない。**

という責任境界である。

したがってMINIDORAでは、4参照単位を標準bucket幅として検索語を統合しても、`参照記録.内容`は一切変更しない。

索引が選んだ後は必ずsource IDから正本を再読する。

## 5. mHC — 複数状態laneと制約混合

GLM-5.3-Flash configではmHCが有効で、`hc_mult=4`、Sinkhorn反復を使う制約付き混合が公開されている。

ここで観測できる本体は、

```text
一つの状態
→ 上書き
→ 一つの状態
```

だけではなく、

```text
複数状態lane
↓
read mix
↓
処理
↓
write mix
↓
複数状態laneを維持
```

という状態伝達である。

MINIDORAではlane 0〜3に「目的」「証拠」「仮説」「実行」等の意味を固定しない。

それはGLMから直接観測できないMINIDORA独自設計になるためである。

持ち帰るのは、

1. 複数laneを独立保持する。
2. 混合係数は非負にする。
3. 行・列を制約付き正規化する。
4. read/write混合を分けられる。

という作用だけ。

## 6. 共通作用 / 専門作用

GLM-5.xもshared expert + routed expertを持ち、初段dense後にsparse MoEへ進む。

ただしこの作用はK3のshared experts + routed expertsでより明確に取得済み。

したがってGLM由来の別実装は作らず、既存MINIDORAの、

```text
共通作用
+
専門作用routing
```

を再利用する。

## 7. effort

GLM-5.2/5.3にはreasoning effortの運用がある。

これもK3 MOPD由来のeffort制御と作用重複する。

MINIDORAでは`hds_effort`を正本とし、GLM専用effort controllerは作らない。

## 8. MTP

MTPは次token候補を先行して形成し、検証によって採用可能prefixを伸ばすための効率機構として扱う。

MINIDORAでは、

```text
DRAFT_AHEAD
↓
VERIFY_PREFIX
├─ 成立 → ACCEPT
└─ 不成立 → ROLLBACK
```

へ射影する。

これは判断主体や知能成立原理ではなく、生成効率補助である。

## 9. multimodal

GLM-5.3-Flashはvision pathを持ち、image/video入力を中央text処理へ接続する。

MINIDORAではvision networkをコピーしない。

```text
modality固有parser
↓
形成済み表象
↓
共通入力表象
↓
中央言語処理
```

というadapter境界だけを持ち帰る。

## 10. GLM-5.2→5.3 — 構造と運用政策

GLM-5.3はGLM-5.2と同じpretrained baseを基礎にしながら、post-trainingによって最終挙動が変化する。

ここからMINIDORAへ持ち帰るべき重要な境界は、

```text
何を保持・参照できるか
= topology / structure

いつ、どの作用を、どの予算で使うか
= operating policy
```

を同一視しないこと。

最終weightはpost-training後に異なるため、「5.2と5.3の最終weightが同じ」という意味ではない。

## 11. long-horizon feedback

GLM-5.2/5.3のpost-trainingでは、tool利用・subtask分解・multi-turn環境feedbackを含むlong-horizon trainingが公開されている。

weight/configだけからliteralなruntime命令列は観測できない。

しかしMINIDORAへは運用作用として、

```text
失敗
↓
失敗原因を分ける
├─ evidence/reference変化 → 参照計画破棄・再観測
├─ effort不足 → 予算引上げ候補
└─ 分類不能 → JへSUSPEND
```

を射影した。

## 12. 最終的なGLM追加成果

K3との差分だけに縮約すると、GLMの追加成果は次の6本が中心となる。

1. **正本証拠と検索索引の分離。**
2. **検索索引だけを圧縮する。**
3. **参照選択結果を有限期間再利用する。**
4. **複数状態laneを制約付きで混合する。**
5. **構造と運用政策を分離する。**
6. **外界feedbackで証拠状態が変わったら参照計画を無効化する。**

MTPとmultimodalは周辺能力・効率境界として追加する。

これらを現行MINIDORAへ`HDS能力経路V3`として還元した。
