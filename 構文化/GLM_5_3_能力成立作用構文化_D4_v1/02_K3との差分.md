# 02 K3との差分

## 1. 結論

GLMの成果をK3と並べたとき、GLMの全要素を新規機能として数えるのは誤りである。

K3で先に取得済みの作用を除くと、GLMでMINIDORAへ新たに持ち帰る中心差分は、**参照系の責任分離・参照計画の寿命・並列状態混合・運用政策分離**に集約される。

## 2. 差分表

| 観測作用 | K3 | GLM | 判定 |
|---|---|---|---|
| 選択的な時間状態更新 | KDAで直接観測 | KDAで再観測 | K3既存 |
| 局所更新と大域再参照の交替 | 3 KDA + 1 Gated MLA | 3 KDA + 1 DSA | K3既存を一般化 |
| 過去状態を残して後段から戻る | AttnRes depth checkpoint | retrieval plan再利用 | 同目的だが対象が違う |
| 共通作用 + 専門作用 | shared + routed experts | shared + routed experts | K3既存 |
| effort制御 | MOPD | reasoning effort | K3既存 |
| 最終採否の独立境界 | GRM構造類似 | critic/training gate | MINIDORA J既存 |
| sparse retrieval前の索引 | 明示独立なし | DSA indexer | GLM追加 |
| 検索索引だけの圧縮 | 明示独立なし | IndexPool | GLM追加 |
| 参照選択結果の有限再利用 | depth checkpointとは別 | IndexShare | GLM追加 |
| 複数状態laneの制約混合 | 系列/深さ/幅の別軸 | mHC | GLM追加 |
| 生成先行 + prefix検証 | 中心成果ではない | MTP | GLM追加・効率補助 |
| modality共通境界 | vision adapter | native multimodal path | K3既存境界を再確認 |
| 外界feedback後の再処理方針 | checkpoint再作用 | long-horizon post-training | GLMで運用政策として追加 |
| topology / policy分離 | 暗黙 | 5.2→5.3差で明瞭 | GLM追加設計境界 |

## 3. K3とGLMで「再利用」の対象が違う

K3 AttnRes:

```text
過去の処理深さ状態
→ 保存
→ 後段から再選択
```

GLM IndexShare:

```text
どの過去contextを読むかという検索決定
→ 保存
→ 複数処理段で再利用
```

MINIDORAでは両方を別責任として残す。

```text
PROCESS_CHECKPOINT
!=
RETRIEVAL_PLAN
```

## 4. K3とGLMで「圧縮」の対象が違う

K3 KDA:

```text
履歴作用差
→ recurrent stateへ圧縮
```

GLM IndexPool:

```text
検索用key/index
→ bucketへ圧縮
```

MINIDORAでは、

```text
作業状態圧縮
!=
検索索引圧縮
!=
証拠本文
```

と分離する。

## 5. K3の三軸とGLM mHC

K3 D4で観測した三軸:

```text
系列: recurrent state / global context
深さ: AttnRes checkpoint
幅: shared / routed expert
```

GLM mHCはこれと完全同型ではない。

mHCから追加で持ち帰るのは、複数の状態stream間でread/write寄与を制約付きに配分できるという状態伝達様式。

従って、K3三軸を4 laneへ機械的に割り当てない。

## 6. GLMがK3を補完する位置

K3は「途中状態を消さず再作用可能にする」ことを強く示した。

GLMはそのうち参照系について、

```text
何を保存するか
何を圧縮してよいか
何を再計算せず再利用するか
何が変わったら再利用を止めるか
```

を細かく分離できる材料を与えた。

このためGLM還元はK3置換ではなく、K3で得た再作用構造の参照側を細分化する位置付けとなる。
