# 06 Grok 4.6 — 能力成立作用構文化

- 観測深度: D2
- 区分: frontier closed agentic
- ライセンス: CC-BY-4.0

## B0 観測境界

core weight/config/architectureは非公開。公開情報から確認できるformation processとdeployment harnessを対象とし、内部系列・深さ・幅機構は推定しない。

## 観測事実

- 4.5系を基盤としてlong-running agent / visual-interactive workを強化。
- supplemental trainingにmodel-generated reasoning / technical data、高品質engineering data等を利用。
- SFT trajectoryをreasoning effort、agent harness、複数domainにまたがって再生成。
- agentic RLを複数environmentで実施。
- deploymentではAPI、Build workflow、multi-agent orchestration等を持つ。

## B1〜B7 core内部作用

**未観測。**

高いagent能力からmemory architecture、attention構成、latent planning loop等を逆推定しない。

## B8 形成作用

ここが本モデルの主要観測点である。

```text
model / harnessで課題を実行
↓
trajectoryを生成
↓
SFT / RLの形成材料へ戻す
↓
次のmodelへ行動傾向を固定
```

### 直接作用

harnessはdeployment時の外部道具であるだけでなく、**形成時の経験生成器**にもなりうる。

つまり、tool useや長期task decompositionの一部は、runtimeで毎回即興するだけではなく、trajectory trainingを通じて模型側の選択傾向へ戻される。

## B9 展開後制御

multi-agent orchestration、Build workflow、tool環境は模型外の実行系。形成時harnessと展開時harnessを同一視しない。

## 比較推定

Llama/K2やApertusと合わせると、能力形成は「architectureを決める」だけでは閉じない。**どの状態遷移を成功例として繰り返し通したか**が後続挙動へ残る。

これはMINIDORAが構造だけ再現しても性能が付いてこないことと整合する。ただし現行GPQA低下をGrok型training不足だけへ単独帰属はしない。

## MINIDORAへの作用射影候補

- runtime経験を監査可能なtrajectoryとして保存する。
- 成功/失敗trajectoryから、再利用可能な関係作用・探索順序・Gate条件の**改善候補**を形成する。
- 改善候補を自動採用せず、HDSの上位採否境界を維持する。
- deployment harnessそのものを模型中核へ混入しない。
- benchmark正解ラベルを直接模型規則へ焼き込まない。
