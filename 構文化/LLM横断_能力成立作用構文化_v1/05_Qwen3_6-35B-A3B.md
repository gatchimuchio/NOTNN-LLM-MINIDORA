# 05 Qwen3.6-35B-A3B — 能力成立作用構文化

- 観測深度: D3
- 区分: open-weight multimodal MoE hybrid
- ライセンス: CC-BY-4.0

## B0 観測境界

公開config/code/checkpoint構造を観測。全26 shardのweight意味解析、expert固有意味、product版との内部同一性は未観測。

## 観測事実

- 40 layers。
- layer scheduleは `linear ×3 → full attention ×1` を反復する。
- linear側はGated DeltaNet系のrecurrent / linear state updateとして実装される。
- 256 experts、tokenあたり8 routed expert、shared expertを持つ。
- MTP層を別に持つ。
- vision frontendをtext coreと分離して持つ。

## B1 状態保持

Gated DeltaNet側では、過去入力を毎回全件再参照する代わりに更新された内部stateへ履歴差を圧縮して渡す。

### 直接作用

過去の差を「現在の圧縮状態」として連続更新し、次の層・次位置へ再利用できる。

## B2 局所更新・参照

3層連続のlinear/recurrent作用が、状態を逐次更新する。

OLMoのsliding-windowとは異なり、直近raw token集合をwindow参照すること自体が主作用ではない。**履歴を状態更新へ畳み込む方式**として分離する。

## B3 大域再照合

4層ごとのfull attentionが、圧縮stateだけでは失われうる明示的な広域関係を再照合する経路になる。

### 直接作用

```text
圧縮状態更新
→ 圧縮状態更新
→ 圧縮状態更新
→ 全体再参照
```

という異なる作用を周期的に組み合わせる。

## B4 深さ輸送

標準block/residual系として前状態を後段へ渡す。DeepSeek V4のmHC型の独立multi-stream depth transportは現行configから確定しない。

## B5 幅選択

- shared expert: 多数入力へ共通作用を提供できる。
- routed experts: token状態ごとに一部専門経路を選択できる。

### 直接作用

同一層内でも「全入力に共通する処理」と「状態に応じて選ぶ処理」を併用できる。

expertの意味内容は未観測。

## B6 未確定差の共存

recurrent state、full attention結果、shared/routed expert出力は後段stateへ統合される。途中で固定ラベルへ離散確定する設計ではない。

具体的な候補仮説がどう符号化されるかは未観測。

## B7 未来補助

MTPは主出力経路とは別の未来予測補助として保持する。

### 作用上の意味

現在状態が将来位置にも整合する方向へ形成圧を与えうるが、これをLLM成立の必須条件とはしない。

## B8 形成作用

公開post-trained checkpointは上記構造へ具体的な関係を形成済み。architectureだけを模倣しても、その形成済み関係は得られない。

## B9 展開後制御

vLLM/SGLang等のruntimeはcore外。product版Qwenとの機能差もopen-weight checkpointのcoreへ無言転用しない。

## MINIDORAへの作用射影候補

- 毎回全Dataを舐め直す以外に、**更新可能な圧縮作業状態**を持つ。
- 圧縮だけに閉じず、周期的または条件付きでglobal/raw relationを再照合する。
- 共通作用と条件付き専門作用を分離可能にする。
- 将来整合性チェックを補助監査として追加できるが、主模型条件にしない。
- Gated DeltaNet / MoE / MTPそのものをコピーしない。
