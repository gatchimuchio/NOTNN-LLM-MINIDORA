# 11 MINIDORAへの作用射影候補

- 日付: 2026-08-26
- 根拠: K3を除く10モデルの能力成立作用構文化 v1
- 状態: 実装前候補。MINIDORA仕様へ自動昇格しない。
- ライセンス: CC-BY-4.0

## 0. 前提

現行MINIDORA v0.4はGPQA Diamondで次を観測した。

- 19 / 198 = 9.596%
- 回答118 / 198
- 回答時正答率16.102%
- retrieval empty 0
- Data compile failure 0
- K facts 101,554
- evidence facts 120,504

外部Data取得とHDS構文変換は動いている。一方、旧v0.6系よりK/evidenceが大幅に減少し、回答時精度も低い。

本ファイルはこの失敗をGPQA専用ruleで修正するのではなく、10モデル横断の作用観測からMINIDORA模型側の不足候補を抽出する。

## P0 — 最優先

### 1. 未確定状態の保留域

現行の `確定関係としてKへ入る / 入らない` の二値境界だけでは、弱いが後から有効になる関係を失う可能性がある。

必要候補:

```text
確定支持
弱支持
競合支持
条件付き支持
未解関係
反対関係
```

を**同じ事実として混ぜず、しかし捨てずに**後段へ渡す中間状態。

これは「弱い証拠も事実扱いする」ことではない。確定Kと未確定working stateを分離する。

### 2. 同一情報への複数回再作用

既存LLMではresidual、global attention、local/global周期、recurrent state、mHC等の方式差はあっても、前段状態へ後段から再作用できる。

MINIDORAでも、Dataを一回コンパイルして一回採否して終了するのではなく、

```text
Data
↓
関係候補A
↓
別Dataとの照合
↓
問題全体との再照合
↓
候補間競合との再照合
```

を可能にする。

### 3. 早期確定の遅延

最終Jまで必要のない確定を途中でしない。

- Kの「確定事実」と、推論中の「working relation」を分ける。
- 一つの候補が一時的に高得点でも、競合候補の反証探索を終えるまで最終回答へ固定しない。
- 逆に、曖昧だから即SUSPENDではなく、再作用可能な未確定状態として残す。

### 4. 候補競合を共同状態として保持

4択を4本の独立score計算へ完全分解すると、

- Aが成立するとBが弱くなる
- CとDが同じ根拠を共有する
- 3候補が成立し残り1候補が例外になる

という相対差を失いやすい。

候補集合全体を一つの競合状態として保持し、同一Dataが各候補へ与える差を同時更新する作用が必要候補。

## P1 — 高優先

### 5. 局所作業域 + 大域再照合

OLMo/Qwen/DeepSeekは実装形式こそ違うが、局所/圧縮更新と広域再接続を分ける。

MINIDORA候補:

```text
局所関係作業域
↓ 数段更新
大域問題状態と再照合
↓
必要なら元Dataへ戻る
```

これは3:1周期を固定する提案ではない。再照合条件は情報変化・競合・未解残差等から決める。

### 6. 関係形成工程

Llama↔K2、Apertus1.0↔1.5、Grokのformation観測から、architecture実装だけでは能力関係は形成されない。

MINIDORAには、世界知識をコードへ埋めずに、Data / experienceから次を形成する独立工程が必要候補。

- 再利用可能な関係
- 関係の適用条件
- 反対条件
- 典型的失敗signature
- 再照合順序

形成物には出典・version・再開放条件を持たせる。

### 7. 共通作用 + 条件付き専門作用

MoEは必須ではないが、Qwen/DeepSeekは共通pathと条件付き専門pathを併用する。

非ニューラル射影として、

- 共通言語関係作用
- 数量/因果/定義/時系列/比較等の条件付き作用

を分離可能にする。ただしbenchmarkカテゴリごとの手作業ruleにはしない。

## P2 — 補助

### 8. 未来整合性補助

MTP / speculative等は普遍条件ではない。

MINIDORAでは、形成した回答候補が後続の関係・条件と矛盾しないかを見る**未来整合性監査**として補助導入を検討できる。

### 9. modality adapter

Apertus/Gemini/Qwenから、modality能力と中央言語模型を分離する。

画像/audio等はまず明示された内部言語状態へ対応づけ、模型核は同じ関係作用を再利用する設計候補。

### 10. 外部長期状態管理

GPT/Grok等のsystem観測から、長期task state・tool orchestration・cacheは模型核外へ置く。

模型核の不足を巨大harnessで隠さず、system能力として別評価する。

## 実装してはいけない短絡

次を今回の成果から直接実装必須とはしない。

- neural network
- probability distribution
- sampling
- Transformer
- Attention
- sliding window
- DeltaNet
- MoE
- mHC
- MTP
- fixed 3:1 schedule

## 次のMINIDORA実装仮説

最小変更で検証すべき順序:

```text
現行確定Kは保持
+
未確定Working Relation Storeを新設
+
候補集合を共同状態化
+
局所→大域の再照合loop
```

その後に関係形成工程を独立追加する。

この順序なら、現在の「ハルシネーションを防ぐ確定K境界」を壊さず、捨てていた中間差だけを回収できる。

## 受入条件

1. gold labelを実装へ渡さない。
2. GPQA固有語や正解パターンを埋め込まない。
3. 未確定状態を確定Kへ無言昇格させない。
4. 同一入力・同一Dataなら決定論的に再現する。
5. 既存unknown / contradiction停止を壊さない。
6. 構造unit testで作用を確認してからGPQAを再実測する。
7. GPQA改善だけで採用せず、一般関係・自然言語・code等でも回帰確認する。
