## B1 状態保持

K3は単一のhidden stateだけではなく、少なくとも次を別に保持する。

```text
現在hidden / prefix_sum
KDA recurrent state
KDA q/k/v short-conv state
MLA past K/V cache
AttnRes block residual checkpoints
MoE shared/routed pathの中間出力
```

重要なのは、これらが一つの「採用済み事実」へ潰されず、処理段階に応じて別経路から再利用されること。

## B2 局所更新・参照

69 KDA layerが担当。

- q/k/vをshort convolution kernel=4で前処理
- recurrent stateを更新
- `A_log` / `dt_bias` / `beta` / gateを使う
- generation時にはlayerごとのrecurrent stateとconv stateをcache

作用としては、**過去履歴を圧縮状態へ連続更新する**。

## B3 大域再照合

24 Gated MLA layerが担当。

最初の92層では、

```text
KDA ×3 → Gated MLA ×1
```

を23回反復し、93層目もGated MLA。

MLAはcausal contextをQ/K/Vへ再展開して参照し、output gateで寄与を調整する。

作用としては、**圧縮更新された状態を定期的に広域文脈へ戻して再照合する**。

## B4 深さ輸送

AttnResが担当。

`attn_res_block_size=12`。

layer index 0,12,24,36,48,60,72,84でprefix stateをcheckpoint保存するため、93層では最大8 checkpointを保持する。

各layerのattention前 / MLP前で、

```text
checkpoint群 + 現在prefix_sum
```

を候補として並べ、正規化・projection・softmax重みで再混合する。

最終出力前にも同じ考え方で再混合する。

作用としては、**現在のdepth stateだけに拘束されず、過去depthへ選択的に戻る**。

## B5 幅選択

Stable LatentMoEが担当。

- experts: 896
- selected / token: 16
- shared experts: 2
- latent dimension: 3584
- expert intermediate: 3072
- first dense layer: 1

各tokenは896 expertから16を選び、重み付きで出力を合成する。shared expert出力も加える。

作用としては、**共通作用を残しながら複数専門作用へ分岐し、後で合流する**。

## B6 未確定差の共存

明示的な「仮説A/B」記号は観測していない。

ただし構造上、

- recurrent state
- depth checkpoints
- 16 routed experts
- shared experts
- current prefix
- periodic global attention

が並存し、途中出力は連続値として後段へ渡る。

従って、K3は途中差を一つの離散結果へ即時固定するより、**複数経路の寄与差を後段まで維持できる構造容量**を持つ。

## B7 未来補助

公開text configでは `num_nextn_predict_layers=0`。

従って本第二巡では独立Next-N predictorを能力成立作用へ採用しない。

第一巡で残したMOPD等の未解項目も、今回の結論へ無理に接続しない。

## B8 形成作用

K3 weight自体は形成済み関係を大量に保持するが、raw training全量は未観測。

確定できるのは、同じarchitectureを空の状態で実装しただけではK3の能力を再現できないこと。実weightには専門経路・attention projection・gate・AttnRes projection等の形成済み差が存在する。

したがって、

```text
作用機構
+
形成済み関係
```

を分けて扱う。

## B9 展開後制御

vLLM / SGLang等でserve可能だが、それらはK3 weight core外。

long-horizon agentic能力の可観測値にはtool orchestration等が関与しうるため、

```text
weight core能力
!=
serving runtime
!=
agent harness能力
```

を維持する。

## 作用連鎖

K3のruntime側作用を最小化すると、次のように読める。

```text
入力状態
↓
KDAで圧縮履歴更新
↓
Gated MLAで広域再照合
↓
AttnResで過去depth checkpoint再選択
↓
shared + routed expertで共通/専門作用
↓
更新状態を次layerへ保持
↓
複数回反復
↓
最終AttnRes
↓
出力差
```

実際にはB2/B3/B4/B5はlayer内で交差するため、これは説明用の直列化であり物理実行順を単純化した表示である。
