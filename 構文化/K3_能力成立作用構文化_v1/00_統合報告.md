## 0. 結論

K3の第二巡で最も重要なのは、**能力成立の途中で情報を一度の採否へ潰さず、系列・深さ・幅の三方向に別々の状態を保持し、後段で選択的に再結合する**構造が直接観測できることである。

K3では少なくとも次の三軸が直交して存在する。

```text
系列方向
KDA recurrent state
  ↓
3 KDA + 1 Gated MLA の周期
  ↓
圧縮更新と広域再参照

深さ方向
現在prefix_sum
  +
12層単位で保存されたblock residual
  ↓
AttnResが過去blockと現在状態を再選択・再混合

幅方向
共有expert
  +
896 routed expertsからtokenごと16 expert
  ↓
重み付き再結合
```

この三軸は同じGateではない。

- KDA gateはrecurrent state更新と出力寄与を調整する。
- Gated MLAは広域参照出力の寄与を調整する。
- AttnResは過去のdepth checkpointと現在状態の寄与を選択する。
- MoE gateは専門経路の寄与を選択する。

従ってK3におけるGateの主作用は、途中で「真 / 偽」「採用 / 廃棄」を決めることではなく、**複数の状態・経路を残したまま寄与量を変えること**である。

これは現行MINIDORA v0.4の性能失敗と強く接続する。現行MINIDORAは取得Data自体は198/198で得られ、Data compileも2698/2698成功した一方、確定K / evidenceへの昇格時に情報量が大きく減り、GPQA回答時正答率16.10%まで落ちた。

K3から直接得られる改善仮説は、**確定Kの安全境界を壊すことではなく、確定前の未確定状態を複数軸で保持・再作用できる領域を増やすこと**である。

## 2. 系列方向 — 圧縮更新と再参照の交替

93層のうち69層がKDA、24層がGated MLA。

1-based layerで、最初の92層は概ね次を23回反復する。

```text
KDA
KDA
KDA
Gated MLA
```

最後の93層目もGated MLA。

### KDA

KDAはq/k/vそれぞれにshort convolution kernel=4を持ち、その後recurrent stateを更新する。各KDA layerは独自のrecurrent stateとconv stateをcacheし、`A_log`、`dt_bias`、`beta`、gateを使って状態更新と出力寄与を制御する。

これはraw contextを毎回全量再走査する作用ではなく、**履歴差を圧縮状態へ継続的に織り込む作用**と読める。

### Gated MLA

Gated MLAはQ/K/Vをlatent projection経由で形成し、causal attentionで過去contextへ再参照する。config上はq_lora_rank=1536、kv_lora_rank=512、NOPE/RoPE成分を分離し、output gateを持つ。

したがって3層のKDAで局所的・連続的に更新された状態が、4層ごとにMLAによって**より広域の文脈へ再接続される**構造になっている。

ここで重要なのは固定3:1そのものではない。重要なのは、

```text
圧縮更新
!=
広域再参照
```

を別作用として持ち、交互に再作用できること。

## 3. 深さ方向 — AttnResによる過去block再選択

AttnResは通常residualより強い差分である。

configの `attn_res_block_size=12` により、layer index 0,12,24,36,48,60,72,84でprefix stateをblock residualとして保存する。93層では最大8個のdepth checkpointを保持する。

各layerでは、

```text
保存済みblock residual群
+
現在prefix_sum
```

を結合し、正規化した各候補へ学習済みprojectionでscoreを与え、softmaxで重みを作って再混合する。

この再混合はattention前とMLP前で別projectionを使う。全layer通過後にもoutput用AttnResで最終再混合する。

従ってK3のdepth transportは、単に前層へ加算し続けるだけではない。

> **前の深さ状態をcheckpointとして残し、現在の処理段階から必要な過去depthを再選択して戻せる。**

これは第二巡で得た「未確定差を後段から再作用できる」という作用を、D4で最も明確に示す部分である。

## 4. 幅方向 — Stable LatentMoE

configでは、

- experts: 896
- routed experts / token: 16
- shared experts: 2
- first dense layer: 1
- routed latent hidden: 3584
- expert hidden: 3072

である。

layer 1以降のMLP側はSparse MoEとなり、token状態からgate scoreを形成し、上位16 expertを選び、選択された16出力を重み付き和で戻す。同時にshared expert経路も加算する。

LatentMoEでは routed pathを7168 hiddenから3584 latentへdown-projectして専門処理し、再び7168へ戻す。

ここから直接言える作用は、

```text
全入力共通の作用
+
入力状態に応じた複数専門作用
```

を同じlayer内で共存させること。

一つの専門経路だけへhard switchする構造ではない。

## 5. 三軸が同時に存在する意味

K3は、

- 系列方向: KDA state / MLA context
- 深さ方向: current prefix / AttnRes checkpoints
- 幅方向: shared / routed experts

を別々に保持する。

つまり一つの情報差に対して、

```text
履歴として残す
過去文脈へ戻る
過去の深さ状態へ戻る
複数専門作用へ分岐する
共通作用も残す
```

という複数の再入口が存在する。

この構造を「KDA」「AttnRes」「MoE」という部品名で覚えるだけでは足りない。

能力成立作用としては、**情報差を一つの経路へ早期固定せず、異なる軸の再作用可能性を残している**ことが本体である。

## 6. 未確定差の扱い

K3内部で「弱い証拠」「仮説A/B」が明示的な記号として保持されている、とまではweight意味から直接確認できない。

しかし構造として、

- hidden stateは連続状態のままlayer間を通る
- KDA recurrent stateは更新後も次tokenへ残る
- AttnResは過去depth stateを捨てず保存する
- MoEは16専門経路を重み付きで併用する
- MLA outputもgateで寄与調整する

ことは直接観測できる。

したがって、**途中状態を二値化せず、複数の差を後段へ持ち越せる容量が大きい**ことは確定できる。

## 7. Multimodal作用

K3はMoonViT-V2系vision towerをtext coreから分離し、27層 / hidden 1024のvision表象をmultimodal projectorでtext hidden 7168へ接続する。

この構造から、multimodal能力を中央言語模型へ直接埋め込む必要はなく、**modality固有表象 → 共通内部状態**というadapter境界を持てることが分かる。

MINIDORAへはvision networkをコピーせず、異種入力を共通言語状態へ変換する責任分離として射影できる。

## 8. 形成・外部運用の境界

K3公開weightには形成済み関係が埋め込まれているが、raw training corpus / 全training trajectory / deployment harness全量はD4 weight監査からは観測できない。

従って、

```text
K3 weightから見えるruntime作用
!=
K3能力形成の全因果
!=
Kimi製品のsystem能力
```

として分離する。

## 9. K3からMINIDORAへ直接持ち帰れる原理

K3の部品をコピーする必要はない。

持ち帰るべき作用は次。

1. **確定前状態を捨てず保持する。**
2. **同一情報へ系列・深さ・幅の異なる作用から再アクセスできる。**
3. **途中Gateを真偽判定ではなく寄与調整として使える。**
4. **局所更新と大域再照合を分離する。**
5. **現在状態だけでなく過去処理checkpointへ戻れる。**
6. **共通作用と複数専門作用を同時に保持する。**
7. **最終確定を最後まで遅延できる。**

これらはK3固有部品ではなく、非ニューラル・決定論系へ射影可能な作用である。
