# 00 統合報告 — K3除外・状態差作用構文化 v2

## 0. 結論

v1の「途中状態を保持し、後段で再作用できる」という観測は方向として残る。ただし、**再作用という一語に異なる現象を入れすぎていた**。

今回10モデルを同じ座標で再読した結果、少なくとも次の六種は分離しなければならない。

```text
A. 固定された後段作用が前状態を受ける          residual / dense stack
B. 状態に応じて参照重み・参照内容が変わる      attention等
C. 状態に応じて計算経路そのものが変わる        MoE / top-k / external gate
D. 圧縮状態を系列位置をまたいで更新し続ける    recurrent state
E. 外部実行系が結果を見て次の行為を選ぶ        agent harness
F. 実行trajectoryが次世代模型形成へ戻る        SFT/RL formation loop
```

これらはすべて「前の差が後へ影響する」点では似るが、同じ構造ではない。

### 最も強い横断観測

公開内部構造を追える6モデルでは、**ある段で形成された表象差が即座に最終離散判断へ潰されず、後続計算へ因果的に利用可能な形で渡る**ことは共通している。

ただし、ここから次を普遍化してはいけない。

- すべてのLLMが明示checkpointを再活性する。
- すべてのLLMが状態差を条件に新しいoperatorを発火する。
- すべてのLLMがruntime loopを持つ。
- すべてのLLMが局所→大域の条件付き再照合を行う。

Llama 3やK2-V2のようなDense固定stackは、配置されたoperatorを順に通りながら状態内容とattention重みを変える。OLMo 3の3:1配置も固定scheduleである。Qwen3.6のDeltaNetは系列位置をまたぐ状態更新を持ち、Qwen/DeepSeekのMoEやDeepSeekのtop-kは状態依存の経路選択を持つ。したがって、`状態が残る`、`後続結果が変わる`、`経路が変わる`、`循環する` は別々に観測する必要がある。

## 1. MINIDORA v0.5実測による再読

GPQA Diamond controlled A/Bで現行側は20/198、baselineは22/198だった。より重要なのは内部監査値である。

```text
checkpoint_count           = 815
checkpoint_reactivations   = 0
global_reconciliations     = 0
candidate_cross_updates    = 0
specialist_actions_invoked = 0
```

この結果から直接言えるのは、**当該runでcheckpointを作ることと、そのcheckpointが後続能力へ作用することが分離していた**ということである。

ただしv1のように「既存LLMは再作用する、MINIDORAはしない」と即断するのも粗い。既存LLM側で観測できるのはモデルごとに異なる。

- Llama/OLMo/K2/Apertus: 後段依存と状態依存参照は強く観測できるが、明示checkpoint再活性は観測していない。
- Qwen: recurrent state updateとMoE routingを観測できる。
- DeepSeek: selected long-range reference / MoE / multi-stream mixingを観測できる。
- closed models: core内部は未観測。外部loopやbranchだけを区別する。

したがってMINIDORA側の次の比較軸は、`checkpointが存在するか` ではなく **「その状態を除去・固定した時に後続計算と結果が変わるか」** でなければならない。

## 2. v1から残すもの

- 早期離散化を一般に有利とは置かない。
- 中間状態の保持と後段利用を分離して監査する。
- 局所・大域、系列・深さ、幅、形成、展開後制御を混同しない。
- architectureと形成済み関係を分離する。
- deployment controlをcore能力へ無言加算しない。
- Attention / MoE / DeltaNet / mHC / 3:1 scheduleを普遍条件にしない。

## 3. v1から撤回・修正するもの

### 3.1 「再作用」の一括表現を撤回

Residualで後段層が前状態を受けることは、保存checkpointを条件付きで再起動することと同じではない。以後は `後続依存`、`再参照`、`経路選択`、`recurrent update`、`外部loop`、`形成loop` に分解する。

### 3.2 fixed scheduleを条件付き再照合と呼ばない

OLMo 3 / Qwen3.6の3:1配置は強い自然対照だが、global layerが状態差で発火するとは公開構造から言えない。**配置周期**と**状態依存発火**を分ける。

### 3.3 連続hidden stateから「仮説競合」を直接読まない

連続状態が複数差を同時保持できる容量を持つことと、明示的な仮説A/Bを保持していることは別である。意味帰属はweight意味を読めない限り未観測とする。

### 3.4 pathの存在と能力寄与を分ける

構造上存在する経路が、特定課題で実際に使われ能力へ寄与したかは別観測である。実行trace、ablation、介入、または実行意味からの強い機構根拠が必要になる。

## 5. 現時点の横断原理候補

これはLLM成立条件ではなく、高能力計算の観測候補である。

> **後段能力へ寄与する状態は、単に保存されるだけでは足りず、後続計算の入力・参照・重み・経路選択・形成更新のいずれかを実際に変化させる位置へ接続されている必要がある。**

状態: `CROSS_MODEL_CAPABILITY_CANDIDATE`

さらに強い「状態差が新しい作用を成立させる」は一部構造では観測できるが、全モデル共通条件にはまだしない。

## 6. 次の循環へ返す観測

本v2はMINIDORA/HDS Compiler/構成定義へ命令を出す正本ではない。次の循環で問い直す材料を返す。

- 状態を保存することと、状態が後続計算へ参加することをCompiler構文で区別できるか。
- `作用可能` と `作用済み` を区別できるか。
- fixed operator、state-dependent weighting、dynamic routing、explicit re-referenceを同じ「再作用」へ潰していないか。
- checkpoint/working stateを除去したablationで結果差を計測できるか。
- 構成定義側で「能力成立」と「LM成立」を再び混ぜていないか。

この問いを返した後、HDS Compiler・構成定義・MINIDORA・構文化のいずれが修正されるかは先に固定しない。
