# MINIDORA モジュール拡張成立実証 — 2026-09-02

## 結論

> **MINIDORAは、Coreを再学習・再訓練・大型化せず、外部の能力Moduleを接続することで実効能力を拡張できる。これは設計上の予定ではなく、GPQA Diamond 198問のcontrolled replayで実測済みである。**

この実証の主題は「科学Moduleを付けたらGPQAの点数が上がった」ことではない。

主題は、

> **MINIDORAの能力面が閉じた一枚岩ではなく、Coreと能力Moduleを責任分離したまま、Module接続によって能力を追加できることが成立した**

ことである。

GPQAのスコア上昇は、この構造が実際に作用したことを外部から観測するための証拠である。

---

## 1. 実証対象

MINIDORAの基本構造は次の責任分離を採る。

```text
Core      = 汎用作用
Data      = 外部化可能
Knowledge = 外部参照可能
Module    = 専門能力
Compute   = 汎用計算
HDS       = 制御
```

このとき検証したのは、次の一点である。

```text
同一Core
  + Module OFF
      ↓
  基準能力

同一Core
  + 既存Module ON
      ↓
  能力増加
```

Coreの再学習、重み更新、追加学習、大型化、GPQA専用Coreへの置換を必要とせず、Moduleの接続だけで実効能力が増加するなら、MINIDORAのモジュール拡張構造は実装上成立している。

---

## 2. 何を変更したか

接続したのは、リポジトリ内に既に存在していた `src/minidora/科学専門能力*.py` 群である。

接続には既存の `科学専門能力を通常MINIDORAへ接続` を使った。

この実証のために次は行っていない。

- MINIDORA Coreの再学習
- ニューラルネットワーク学習
- Transformer追加
- benchmark問題番号による答え分岐
- gold answerを参照するsolver
- GPQA正答表の埋め込み
- 未発火問題の推論結果の作り替え

科学専門能力が発火しない場合、specialist ON側は保存済みbaseline結果をそのまま返す。

したがってA/B差分は、Moduleが実際に発火したケースに限定される。

### Module ON — 既存科学専門能力を接続

GPQA Diamondは4択であり、全問一様ランダム回答の期待値は25%である。Module ONの全体正答率31.818%はこの水準も上回る。

## 4. なぜ「モジュール拡張成立」の証拠になるのか

この実測で重要なのは、63/198という絶対スコアそのものではない。

重要なのは、**能力増加の原因をModule接続へ局所化できていること**である。

### 4.1 Coreを能力追加のために作り直していない

baseline取得時点からReplay実行時点まで、測定前にFormal core責任範囲の差分を監査した。

```text
src/minidora/
tools/benchmark.py
tools/benchmark_formal.py
tools/gpqa_measure_current.py
```

Replay成立時には、baseline責任範囲が不変であることを確認している。

### 4.2 不発火時はbaselineを完全継承する

Moduleが答えを一意かつ支持可能に閉包できない場合、新経路は保存済みbaseline結果をそのまま返す。

したがって、Moduleが作用していないケースの改善をModule効果として数えていない。

### 4.3 55の異なる専門solverが独立に能力を追加した

55種類のsolverが各1ケースで発火した。

これは「一つの巨大GPQA solverを追加した」観測ではない。

```text
MINIDORA Core
  ├─ 量子系Module
  ├─ 相対論系Module
  ├─ 天文系Module
  ├─ 化学系Module
  ├─ 統計系Module
  ├─ 行列・構造系Module
  └─ その他の独立した科学作用
```

複数の独立能力が同じCoreへ接続され、必要な入力でのみ発火し、それぞれ結果へ寄与した。

これにより、MINIDORAにおける能力追加単位がCore全体の再構築ではなく、**独立Moduleとして成立しうる**ことが観測された。

---

## 5. この実証によって成立したこと

### 成立1 — 外部能力Moduleによる能力追加

MINIDORAは、既存Coreを保持したまま外部能力Moduleを接続し、実効能力を増加させられる。

### 成立2 — 再学習は能力追加の必要条件ではない

少なくとも今回実証した科学能力群について、能力追加のためにモデル再学習は必要なかった。

```text
学習済み巨大模型へ能力を焼き込む
```

だけが能力追加経路ではない。

MINIDORAでは、

```text
小さいCore
+ 必要な能力Module
```

という別の能力形成経路が実装上成立した。

### 成立3 — Core性能と接続済み能力集合は別物

Module OFFとONでCoreを能力追加目的に再構成していないにもかかわらず、観測性能は大きく変化した。

したがって、ある時点のMINIDORA benchmark scoreを、そのまま「MINIDORAが構成可能な能力上限」と扱うことはできない。

観測性能は、少なくとも次に依存する。

```text
Core
+ 接続済みCapability集合
+ Data / Reference
+ Compute
+ 制御
```

### 成立4 — MINIDORAは閉じた一枚岩ではない

今回のA/Bは、MINIDORAの能力面を外部から拡張できることを実際に示した。

したがってMINIDORAは、能力追加のたびに本体全体を再学習することを前提とする閉鎖模型ではなく、**能力を接続・分離・交換可能な構成として実装できる**。

---

## 6. この実証が意味しないこと

この記録から、次は主張しない。

- 任意のModuleが無条件に正しく接続できる
- 任意の未知分野へ自動的に一般化する
- GPQA Diamond 100%を既に実測した
- live外部参照再取得を含む最新HEADの正式スコアが31.818%である
- GPQA性能がそのまま厳密言語模型成立の証拠になる

今回確定したのは、より基礎的な一点である。

> **MINIDORAでは、Core外に分離された能力Moduleを接続し、そのModule由来の能力増加を実際の外部benchmark上で観測できる。したがってモジュール拡張経路は設計上の仮説ではなく、実装・実測済みである。**
