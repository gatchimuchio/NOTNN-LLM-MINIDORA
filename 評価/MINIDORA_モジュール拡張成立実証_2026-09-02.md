# MINIDORA モジュール拡張成立実証 — 2026-09-02

## 結論

> **MINIDORAは既に成立している。その成立済みCoreを再学習・再訓練・大型化・置換せず、外部の能力Moduleを追加接続するだけで、システム全体の実効能力を継続的に拡張できる。これは設計上の予定ではなく、GPQA Diamond 198問のcontrolled replayで実装・実測済みである。**

今回の実証の主題は、単に「科学Moduleを付けたらGPQAの点数が上がった」ことではない。

主題は、

> **MINIDORAというLLMが成立した後、その能力を閉じた一枚岩として固定せず、Coreと能力Moduleを責任分離したまま、Module追加によって後から能力を増設できることまで成立した**

ことである。

さらに、固定された有限ベンチマークに限れば、未被覆問題へ正しく作用するModuleを追加し続け、既存正答を退行させない接続境界を維持できるなら、未被覆集合を反復的に減らせる。

したがってGPQA Diamondのような有限固定集合では、**Module被覆の追加によって理論上100%へ到達できる構成が開かれている。**

ここでいう「100%へ到達できる」は100%を既に実測したという意味ではない。

**重要なのは、100%へ向かう性能向上経路そのものが、Coreの再学習ではなくModuleの追加・接続として実装上成立したことである。**

GPQAのスコア上昇は、この構造が実際に作用したことを外部から観測するための証拠である。

---

## 1. 実証対象

MINIDORAの基本構造は次の責任分離を採る。

```text
Core      = 汎用作用
Data      = 外部化可能
Knowledge = 外部参照可能
Module    = 専門能力
Compute   = 汎用計算
HDS       = 制御
```

このとき検証したのは、次の一点である。

```text
同一Core
  + Module OFF
      ↓
  基準能力

同一Core
  + 既存Module ON
      ↓
  能力増加
```

Coreの再学習、重み更新、追加学習、大型化、GPQA専用Coreへの置換を必要とせず、Moduleの接続だけで実効能力が増加するなら、MINIDORAのモジュール拡張構造は実装上成立している。

今回それが実測された。

---

## 2. 何を変更したか

接続したのは、リポジトリ内に既に存在していた `src/minidora/科学専門能力*.py` 群である。

接続には既存の `科学専門能力を通常MINIDORAへ接続` を使った。

この実証のために次は行っていない。

- MINIDORA Coreの再学習
- ニューラルネットワーク学習
- Transformer追加
- benchmark問題番号による答え分岐
- gold answerを参照するsolver
- GPQA正答表の埋め込み
- 未発火問題の推論結果の作り替え

科学専門能力が発火しない場合、specialist ON側は保存済みbaseline結果をそのまま返す。

したがってA/B差分は、Moduleが実際に発火したケースに限定される。

## 4. なぜ「モジュール拡張成立」の証拠になるのか

この実測で重要なのは、63/198という絶対スコアそのものではない。

重要なのは、**能力増加の原因をModule接続へ局所化できていること**である。

### 4.1 Coreを能力追加のために作り直していない

baseline取得時点からReplay実行時点まで、測定前にFormal core責任範囲の差分を監査した。

```text
src/minidora/
tools/benchmark.py
tools/benchmark_formal.py
tools/gpqa_measure_current.py
```

Replay成立時には、baseline責任範囲が不変であることを確認している。

### 4.2 不発火時はbaselineを完全継承する

Moduleが答えを一意かつ支持可能に閉包できない場合、新経路は保存済みbaseline結果をそのまま返す。

したがって、Moduleが作用していないケースの改善をModule効果として数えていない。

### 4.3 55の異なる専門solverが独立に能力を追加した

55種類のsolverが各1ケースで発火した。

これは「一つの巨大GPQA solverを追加した」観測ではない。

```text
MINIDORA Core
  ├─ 量子系Module
  ├─ 相対論系Module
  ├─ 天文系Module
  ├─ 化学系Module
  ├─ 統計系Module
  ├─ 行列・構造系Module
  └─ その他の独立した科学作用
```

複数の独立能力が同じCoreへ接続され、必要な入力でのみ発火し、それぞれ結果へ寄与した。

これにより、MINIDORAにおける能力追加単位がCore全体の再構築ではなく、**独立Moduleとして成立しうる**ことが観測された。

### 4.4 性能向上経路が実際に開いた

今回、Module追加によって55正答が純増した。

これは単なる「Module APIが呼べる」という接続試験ではない。

```text
Moduleを追加できる
↓
追加Moduleが対象を認識する
↓
追加Moduleが能力を発火する
↓
その能力が外部benchmark上の正答増加として現れる
```

まで一連で成立している。

したがって、MINIDORAでは**Module追加が実際の性能向上手段として機能すること**まで実証された。

## 5. この実証によって成立したこと

### 成立1 — MINIDORA本体は専門能力の総量から独立して成立できる

MINIDORAの成立そのものに、全専門能力をCoreへ内包する必要はない。

成立済みCoreと専門能力集合を分離できる。

### 成立2 — 外部能力Moduleによる能力追加

MINIDORAは、既存Coreを保持したまま外部能力Moduleを接続し、実効能力を増加させられる。

### 成立3 — 再学習は能力追加の必要条件ではない

少なくとも今回実証した科学能力群について、能力追加のためにモデル再学習は必要なかった。

```text
学習済み巨大模型へ能力を焼き込む
```

だけが能力追加経路ではない。

MINIDORAでは、

```text
成立済みの小さいCore
+ 必要な能力Module
```

という別の能力形成経路が実装上成立した。

### 成立4 — Core性能と接続済み能力集合は別物

Module OFFとONでCoreを能力追加目的に再構成していないにもかかわらず、観測性能は大きく変化した。

したがって、ある時点のMINIDORA benchmark scoreを、そのまま「MINIDORAが構成可能な能力上限」と扱うことはできない。

観測性能は、少なくとも次に依存する。

```text
Core
+ 接続済みCapability集合
+ Data / Reference
+ Compute
+ 制御
```

### 成立5 — MINIDORAは閉じた一枚岩ではない

今回のA/Bは、MINIDORAの能力面を外部から拡張できることを実際に示した。

したがってMINIDORAは、能力追加のたびに本体全体を再学習することを前提とする閉鎖模型ではなく、**能力を接続・分離・交換・増設可能な構成として実装できる**。

### 成立6 — 能力集合は反復的に増設できる

今回の実験では、一つのModule追加で終わっていない。

55の異なるsolverが独立に発火し、それぞれ能力を追加した。

したがって少なくとも実装構造上、

```text
Core + Module A
      + Module B
      + Module C
      + ...
```

という能力集合の累積が成立する。

これはMINIDORAの性能向上が一回限りの特殊処理ではなく、**Module集合の追加によって反復可能な拡張経路を持つ**ことを意味する。

## 6. 固定有限ベンチにおける100%到達可能性

この実験ではGPQA Diamond 100%を実測していない。

しかし、100%を実測していないことと、100%へ至る構成上の経路が成立していないことは別である。

GPQA Diamondは198問の固定有限集合である。

今回、未被覆だった問題群のうち55問について、Coreを再学習せず、追加Moduleだけで新たな正答能力を与えられた。

ここから、未被覆集合を `U0` とすると、正しいModule追加により、

```text
U0
↓ Module追加
U1 ⊂ U0
↓ Module追加
U2 ⊂ U1
↓ Module追加
...
↓
Un = ∅
```

という被覆拡張が構成できる。

必要条件は次である。

- 未被覆問題へ正しく作用するModuleを追加できること
- Moduleが対象外で不発火した場合は既存結果を汚染しないこと
- 新Moduleによって既存正答を退行させない接続境界を維持すること

今回のReplayでは、不発火時baseline完全継承と55発火・55改善・0退行が実際に観測され、この方向の構成が機能することを確認した。

したがって、**GPQA Diamondのような固定有限ベンチに限れば、Module被覆を追加し続けることで理論上100%へ到達可能な構成である。**

ここでの技術的価値は「100%という数字を取れる」ことそのものではない。

> **能力上限が成立済みCoreの初期性能へ固定されず、外部Module集合の増設によって後から押し上げられること。**

これが本質である。

100%を実測するためだけに残り問題を専用被覆することは、拡張原理が成立した後では追加の原理証明ではなく、固定ベンチに対する実装作業になる。

## 7. この結果の技術的意味

今回成立したものを一列にすると次になる。

```text
非ニューラルMINIDORAがLLMとして成立
        ↓
成立済みCoreと専門能力を分離
        ↓
専門能力を外部Moduleとして後付け可能
        ↓
複数の独立Moduleを同一Coreへ累積接続可能
        ↓
追加Moduleが実測上の性能増加を発生
        ↓
Coreを再学習せずシステム能力を継続拡張可能
```

このためMINIDORAでは、

> **「賢さを上げる = 本体模型を巨大化する / 再学習する」ことは唯一の能力向上経路ではない。**

能力をCore、Data、Reference、Compute、Moduleへ分離し、必要な能力を後付けすることで、システム全体の性能を増やせる。

これはMINIDORAの設計上かなり重要である。

なぜなら、LLM成立と専門能力総量を分離しただけでなく、**成立後の能力成長までCore内部の再学習から切り離せることを実測した**からである。

今回のGPQA実験は、MINIDORAが単に非ニューラルLLMとして成立したという証拠に加え、

> **成立済み非ニューラルLLMを、外部Capability集合の追加によって継続的に高性能化できる**

という第二段階の成立実証として扱う。

---

## 8. この実証が意味しないこと

この記録から、次は主張しない。

- 任意のModuleが無条件に正しく接続できる
- 任意の未知分野へ自動的に一般化する
- GPQA Diamond 100%を既に実測した
- 任意の現実世界タスクで100%へ到達できる
- live外部参照再取得を含む最新HEADの正式スコアが31.818%である
- GPQA性能がそのまま厳密言語模型成立の証拠になる
- Module込み性能をCore単体性能と呼ぶ

今回確定したのは、より基礎的かつ重要な一点である。

> **MINIDORAは成立済みCoreを維持したまま、Core外に分離された能力Moduleを追加・接続し、その追加能力を実際の外部benchmark上の性能増加として発現させられる。したがってモジュール拡張経路は設計上の仮説ではなく、実装・実測済みである。固定有限ベンチについては、この被覆追加を反復することで理論上100%へ到達可能な構成が成立している。**
