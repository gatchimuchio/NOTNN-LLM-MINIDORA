# HDSコンパイラ × MINIDORA 試運転ベンチマーク

- 実施日: 2026-08-20
- 取扱区分: HDS関連・特定重要機密。外部公開禁止。
- 実行環境: Python 3.13.5 / x86_64 / AMD EPYC 9V74 / 割当5 CPU / RAM約6.2GB / GPU不使用
- リポジトリ変更: なし
- HDSコンパイラ: v0.2 ローカル成果物
- MINIDORA: GitHub main由来の現行Runtimeコードをローカル復元した実行系

## 目的

`生Data → HDSコンパイラ → MINIDORA R → Layer-0 → 結果` の実閉路について、コンパイル、R読込、既知検索、未知停止、矛盾保持、R供給器差替えを実測する。

## データ

明示日本語事実を固定生成。

`都市000123の識別番号は値000123です。`

1,000 / 10,000 / 50,000件を使用。既知問は対象名完全一致、未知問は存在しない対象名を入力。

## R供給器差替え試験

同じ50,000件のRに対象索引を構築。Layer-0、Runtime、Data内容は変更していない。

- 索引構築: 15.3 ms
- 既知10,000問: 10,000/10,000 合格
- 既知平均: 0.00425 ms
- 既知p50: 0.00413 ms
- 既知p95: 0.00474 ms
- 未知2,000問: 2,000/2,000 保留
- 未知p50: 0.00189 ms
- 現行線形p50との比: 約5,064倍

注意: 対象名完全一致という局所条件。一般的意味検索性能を表すものではない。

## 矛盾保持試験

10,000件に同一対象・同一属性の競合値を1件追加。

- HDS矛盾検出: 1
- R記録: 10,001
- 問合せ対象の返却候補: 2
- MINIDORA参照件数: 2
- 検索: 約4.04 ms
- 競合値を片方へ勝手に潰さず並列保持: PASS

## K3実HDS互換試験

HDSコンパイラ同梱のK3実HDS見本を使用。

- 入力HDS record: 24
- R出力: 44
- 意味処理待ち: 0

- コンパイル: 約0.67 s（Python起動費込み）

既HDS成果を再入力として由来付き継承できることを確認。

## 観測された境界

1. 計算核・R読込・既知/未知処理は軽い。
2. 現行固定参照供給器の検索は線形走査であり、件数増加にほぼ比例して遅延する。
3. R Providerを差し替えるだけで検索遅延は桁違いに低下した。Layer-0変更は不要。
4. 現HDSコンパイラは完全監査台帳を大量生成するため、保存容量が最大コスト。50,000事実でRは10.7MBだがHDS全成果は407.6MB。
5. 本試験は構造・I/O・停止・検索・局所計算のベンチであり、K3等との汎用能力同等性ベンチではない。
