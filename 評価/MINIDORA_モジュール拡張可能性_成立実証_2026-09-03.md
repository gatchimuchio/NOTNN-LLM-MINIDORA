# MINIDORA モジュール拡張可能性 成立実証 — 2026-09-03

## 1. 結論

今回のGPQA Diamond実験で重要なのは、MINIDORAへ科学専門モジュールを付けた結果、単にベンチマーク得点が上がったことではない。

**MINIDORA本体を再学習・再訓練・巨大化・置換せず、外部専門モジュールを接続するだけで、システム全体の実効能力を追加・拡張できることが実装と実測で成立した。**

これはMINIDORAの基本設計である、

```text
最小汎用LLM核
+ 外部Data
+ 外部参照
+ 汎用計算
+ 必要な専門Module
```

という分離構造が、説明上の構想ではなく、実際に能力増加を起こす構成として成立していることを示す。

## 2. 実測事実

GPQA Diamond 198問に対し、保存済みFormal current個票へ、リポジトリ内に既存だった科学専門能力群を明示接続したReplayでは次の結果を得た。

```text
専門能力除外 baseline
  8 / 198
  4.0404040404 %

既存科学専門能力 ON
  63 / 198
  31.8181818182 %

差
  +55正答
  +27.7777777778 points
```

さらに、専門能力が発火した55問は次の通りだった。

```text
専門能力発火    55
改善            55
退行             0
```

回答した86問に限定した正答率は 73.2558139535 % だった。

4択GPQA Diamondの全問一様ランダム回答基準25%に対して、専門能力ONの全体正答率31.818%はこれを上回った。

詳細な測定条件・dataset hash・seed・solver一覧・Actions実行証拠は、
[`GPQA_Diamond_既存科学専門能力_Replay_2026-09-02.md`](GPQA_Diamond_既存科学専門能力_Replay_2026-09-02.md)
を参照する。

## 3. この実験で成立したこと

### 3.1 MINIDORA本体と専門能力は分離できる

GPQA科学能力をMINIDORA coreへ焼き込む必要はなかった。

専門能力は独立モジュールとして保持され、必要時に接続して能力を追加できた。

したがって、少なくとも今回実装された範囲では、

```text
MINIDORA成立
!= 全専門能力をcore内部へ保有
```

である。

### 3.2 能力追加にcore再学習を必要としない

今回の能力増加は、ニューラル模型の再学習、fine-tuning、重み更新、parameter増加によって得たものではない。

既存の独立した科学専門能力をactive pathへ接続したことで、8正答から63正答へ増加した。

したがってMINIDORAでは、

```text
能力追加
→ 必ずしもcore再学習を要求しない
→ Module追加・接続でも成立する
```

ことが実測された。

### 3.3 能力は後付けで増設できる

今回55種類のsolverが発火し、55問すべてを改善した。

これは、一個の巨大な万能処理器へ全能力を内部化しなくても、異なる局所能力を独立追加し、それらの集合としてシステム能力を増やせることを示す。

つまりMINIDORAの能力は、固定された単一塊ではなく、**追加可能な能力集合として拡張できる。**

### 3.4 観測ベンチスコアはcore単体の能力上限ではない

専門能力除外時4.04%から、既存専門能力接続だけで31.82%へ上昇した。

したがって、専門Moduleを除外した状態のベンチスコアをMINIDORAシステム全体の能力上限として扱うことはできない。

観測性能は、少なくとも次に依存する。

```text
Core
+ Data
+ Reference
+ Compute
+ 接続されているCapability集合
```

## 4. 100%到達可能性の意味

今回の実験ではGPQA Diamond 100%を実測していない。

したがって「MINIDORAがGPQA Diamondで100%を実測した」とは主張しない。

一方、**固定された有限ベンチマークに対する構成上の到達可能性**は別である。

GPQA Diamondは198問の有限集合であり、今回、既存能力モジュールを追加接続することで、coreを再学習せずに55問分の正答能力を追加できることが実測された。

この構造を保ったまま、未被覆問題に対して正しく作用する専門Moduleを追加し、既存正答を退行させない接続境界を維持できるなら、被覆は反復的に増やせる。

```text
未被覆集合 U0
↓ Module追加
未被覆集合 U1 ⊂ U0
↓ Module追加
未被覆集合 U2 ⊂ U1
↓
...
↓
未被覆集合 = 0
```

したがって固定有限ベンチに限れば、**モジュール被覆を追加し続けることで理論上100%へ到達できる構成**である。

これは100%という数値そのものを成果とする主張ではない。

むしろ重要なのは、100%へ向かう能力増加の手段が、巨大模型の再学習ではなく、**独立Moduleの追加・接続として開かれている**ことである。

## 5. この結果の技術的意味

この実証により、MINIDORAでは少なくとも次が成立した。

```text
非ニューラルLLM核が成立している
        ↓
その核を維持したまま
        ↓
外部Capabilityを追加できる
        ↓
追加Capabilityが実際に性能増加を起こす
        ↓
Capability集合の増設によって
システム能力を継続的に拡張できる
```

従ってMINIDORAでは、

> **「賢さを上げる = 本体模型を巨大化・再学習する」ことは唯一の経路ではない。**

能力をcore、Data、Reference、Compute、Moduleへ分離し、必要な能力を後付けすることで、システム全体として性能を増やせる。

今回のGPQA実験は、このMINIDORAの拡張原理が実際に動くことを示した最初の明示的実証として保持する。

## 6. 言わないこと

この実証から、次は直接には導かない。

- 現時点のMINIDORAがGPQA Diamond 100%を達成済みである。
- 追加した55 solverが未知の科学問題全域へ一般化済みである。
- 任意の現実世界タスクが自動的に100%解ける。
- 専門Moduleの性能をMINIDORA core単体の汎用性能として扱う。

この文書が固定するのは、

> **MINIDORAは成立済みのcoreを維持したまま、外部専門Moduleの追加・接続によって実効能力を増設でき、その能力増設が実測で確認された。固定有限ベンチでは、その被覆を追加し続けることで理論上100%へ到達可能な構成である。**

という技術的事実と、その構成上の帰結である。
