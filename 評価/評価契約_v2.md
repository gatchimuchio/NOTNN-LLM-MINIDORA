# MINIDORA 評価契約 v2

## 目的

GPQA Diamondの正本性能評価を、未知参照環境を含む汎用E2E性能へ固定し、評価条件・比較可能範囲・禁止主張を日本語正本として機械可読化する。

2026-09-09以後、保存済み参照結果、固定参照コーパス、再生束等を外部知識入力として用いた測定を、新しい正本性能値・回帰基準・性能比較値として採用しない。

## 1. GPQA正本は実参照E2Eのみ

外部評価識別子は外部互換値として `gpqa-diamond-e2e-live-v2` を保持する。

評価境界:

```text
GPQA Diamond 問題文 + 選択肢
↓
実行時に新規取得する標準参照資料
↓
MINIDORA 模型核 / HDS / 判断系
↓
回答
```

## 2. 固定参照資料禁止

正本GPQAでは次を禁止する。

- 固定参照コーパス。
- 過去実行で保存した検索結果・参照結果。
- 問題別に凍結した参照資料束。
- 再生用固定資料を外部知識入力として使う測定。
- 正解情報を利用して選別・整形した参照資料。

公式問題集合の同一性確認用キャッシュはこの禁止対象ではない。同一実行内の統制A/Bで、その実行中に新規取得した同一参照資料を対照系と現行系へ共有することは許可する。

## 3. 正本運用条件

```text
外部評価 = GPQA Diamond
全問題数 = 198
選択 = 0..197 全数
GPQA CSV SHA256 = 41d1213cd7a4998605a26c2798500652572007161b3a92817ba46b35befcd305
選択肢シャッフル種 = 0
OpenAlex = 無効
Wikipedia = en
参照方式 = 実参照のみ
同一実行内統制A/B = 必須
固定参照資料 = 禁止
```

固定するのは評価構成であり、検索結果そのものではない。

## 4. 正本機械可読契約

MINIDORA自身が定義する内部JSONは、最低限次の日本語鍵を持つ。

```text
契約形式
外部評価識別子
課題
評価種別
入力境界
参照方式
固定参照資料許可
条件指紋SHA256
入力スナップショットSHA256
正本全数実行
正本得点欄
同一実行内統制AB直接比較
実行間コード差直接比較
スナップショット得点時系列保存許可
主張可能範囲
禁止主張
```

内部区分値も日本語を正本とする。`GPQA Diamond`、SHA256、外部識別子等の外部固定値は例外とする。

旧英語鍵を必要とする外部消費者には境界変換で対応し、内部正本を英語へ戻してはならない。

## 5. 比較規則

- 同一実行内統制A/B差: 同一観測入力を共有するため直接差分として扱える。
- 別実行のE2E得点差: 性能スナップショットの時系列差として扱う。
- 別実行の得点差を、コード変更だけの純粋因果差として扱わない。

必要なコード因果監査は、GPQAとは別の局所A/B・機能受入・退行試験で行う。

2026-09-09採用の模型核正本性能セーブポイント:

```text
MINIDORA30

```

根拠資産の識別番号・ハッシュは履歴評価資料に保持する。

## 7. 能力モジュール込みシステム正本

模型核正本とは別に、能力モジュール込みシステム能力正本を保持してよい。効果の直接帰属は同一実行内の無効/有効差だけに限定する。

## 8. 過去再生評価

過去の固定再生結果は当時の実験・履歴証拠として削除しない。ただし現行GPQA性能、現行正本、将来のGPQA比較基準として再利用しない。
