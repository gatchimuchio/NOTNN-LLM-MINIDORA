# MINIDORA 三層射影精度監査 — 2026-08-26

- 対象: K3 / 他LLM → 構文化 → HDS Compiler → MINIDORA構成定義・実行系
- 目的: GPQA低性能の原因が、①構文化、②意味変換Compiler、③MINIDORA射影規則のどこにあるかを切り分ける
- 判定: **三層すべてに精度不足あり**
- 主因順位: **② HDS Compiler > ③ MINIDORA射影規則・実行接続 > ① 構文化の作用則不足**
- ライセンス: CC-BY-4.0

## 0. 結論

現行MINIDORAの低性能を、独立した新規設計問題として扱ってはならない。

MINIDORAは、K3その他のLLMで観測した能力成立作用を非ニューラル・決定論系へ射影し、その意味入力をHDS Compilerで構造化する系である。

従って監査対象は次の三段である。

```text
実LLM
  ↓
① 構文化
  ↓
作用構文
  ↓
② HDS Compiler
  ↓
意味HDS-IR
  ↓
③ MINIDORA構成定義 / 射影規則 / 実行接続
  ↓
MINIDORAの作用
```

監査結果は、**三段すべてで情報・作用の保存精度が不足している**。

ただし最も大きな直接原因は②である。GPQA Diamond 198問を現行公開HDS Compilerへ通したところ、問いの関係がK境界まで残ったのは **3 / 198 = 1.515%** に過ぎず、**195 / 198 = 98.485% がtopic-only**へ落ちた。

このため、③でどれだけ再作用・再照合を追加しても、入力された意味関係自体が存在しない問題では能力を回復できない。

一方で③にも独立した精度不足があり、K3で観測したAttnRes / Gate / shared+routed作用を、現在のMINIDORAは同等の作用則としてまだ保持していない。またGPQA実行経路は正式な `MINIDORA模型核` を通らず、外側の `HDS選択推論実行 → K3相当能力核` を直接使用している。

①については、K3の物理・architecture観測自体を誤った証拠は見つからなかった。しかし第二巡構文化は「状態保持」「再作用」「再結合」までを抽出した一方、能力保存射影に必要な**実行可能な状態遷移則・寄与則・形成則**までは確定していない。

従って修正順は、**①作用則を深掘り → ②Compilerで意味保存 → ③構成定義へ忠実射影**でなければならない。

---

## 1. ① 実LLM → 構文化

### 判定

**原因である。ただし「K3の物理構造を読み間違えた」のではなく、「能力保存に必要な作用則まで抜き切れていない」ことが原因。**

### K3で確定している観測

`構文化/K3_能力成立作用構文化_v1/` ではD4で、少なくとも次を固定している。

- 96 / 96 shard
- 497,220 / 497,220 tensor
- payload 1,560,860,324,864 byte
- text core 93層
- 69 KDA + 24 Gated MLA
- AttnRes block size 12
- experts 896
- routed experts / token 16
- shared experts 2

第二巡では、K3作用を概ね次へ抽象化した。

```text
系列方向: KDAで履歴更新 → MLAで大域再参照
深さ方向: AttnResで過去depth stateを保持・再選択
幅方向: shared + routed expertを重み付き再結合
Gate: 真偽確定ではなく寄与調整
```

ここまではD4観測と公開実装に対応している。

### 不足しているもの

しかし現在の構文化からは、次を決定論的な非ニューラル作用へ一意に降ろせない。

- 何を同一状態とみなすか
- どの差を保持対象にするか
- どの入力差がどのGate寄与差になるか
- どの条件で過去状態を再選択するか
- 再選択後に現在状態とどう結合するか
- 複数専門作用の寄与をどう決めるか
- 作用反復で状態差がどう更新されるか
- 形成済みweightに存在する関係密度・優先順位・再結合傾向を非ニューラル側へどう形成するか

K3構文化自身も、以下を未観測境界としている。

- raw training corpus全量
- training trajectory全量
- production harness全量
- weight内部方向ごとの自然言語意味

したがって第一層の問題は、**部品・接続・高位作用の観測は成立しているが、能力を保存して射影するための作用則と形成則が未完成**であること。

### 原因分類

```text
物理構造観測誤り      = 現時点で確認されず
作用の高位構文化      = 成立
作用遷移則の構文化    = 不足
形成則の構文化        = 不足
```

## 2. ② 構文化 → HDS Compiler

### 判定

**三層の中で最大の直接原因。**

現行Compilerの「コンパイル成功」は「意味関係を保持できた」を意味していない。

### GPQA 198問の意味射影監査

専用監査:

- tool: `tools/audit_projection_chain.py`
- workflow: `MINIDORA 三層射影Compiler監査`
- run: `32915191479`
- artifact: `9587909742`
- 対象: GPQA Diamond 198問
- goldは推論に使用せず、意味構造coverage監査だけに使用

#### 問い

| 指標 | 件数 | 率 |
|---|---:|---:|
| 問題数 | 198 | 100% |
| 何らかの関係を抽出 | 152 | 76.768% |
| 「問いの未知関係」として認識 | **3** | **1.515%** |
| semantic bridge経由で問い関係化 | **0** | **0%** |
| K質問射影後に関係が残る | **3** | **1.515%** |
| K質問射影後topic-only | **195** | **98.485%** |
| 関係0なのにsemantic_lossなし | 46 | 23.232% |

問いでKへ残った関係種別は、

```text

```

だけだった。

元IR側では数量単位482、等価84、方向41、使用21等も抽出されるが、それらの多くは**問いが何を尋ねているかという関係ではなく、表層中の局所関係**である。

|---|---:|---:|

#### GPQA Expert Explanation

同一データセットのExplanationは正解推論には投入せず、Compilerの意味構造coverage比較にのみ使用した。

| 指標 | 件数 | 率 |
|---|---:|---:|
| 非空Explanation | 198 | 100% |

### この対照が意味すること

```text
長い科学Explanation
→ 174 / 198でK関係を保持できる

GPQAの質問
→ 3 / 198しか問い関係を保持できない
```

従って主障害は単純な「科学文章全般を読めない」ではない。

**質問文から「何と何のどの関係を問うているか」を開いた関係として保持する能力が極端に弱い。**

現行`HDSK質問射影`は、認識済みのcanonical relation questionを得られなければ、主題語が存在するだけでchoices + topicsへ落とし、`関係=()` のtopic-only状態を許す。

また、Compiler本体は有限の明示関係パターンへ適合しなくても、主題語を抽出できれば`semantic_loss`を出さず正常HDS-IRとして返せる。

このため過去の、

```text
Data compile 2714 / 2714
failure 0
```

という値は、**構文処理が例外終了しなかったことしか示さず、意味関係保存率を示していなかった。**

### 原因分類

```text
Compiler実行失敗                 = 主要因ではない
表層関係抽出                     = 一部成立
質問述語 / 未知関係の抽出        = 致命的不足
意味同値関係の正規化             = 不足
semantic_loss検出                = 過小検出
K質問射影                         = topic-onlyへ過剰圧縮
```

## 3. ③ Compiler出力 → MINIDORA構成定義 / 射影規則 / 実行接続

### 判定

**独立した原因として確定。**

ここでいう問題はMINIDORAへ新しい独立思想を足すことではない。

**K3 / 他LLMから取った作用を、MINIDORA構成定義が能力保存したまま非ニューラル作用へ写せていない**ことが問題である。

### 3.1 正式な模型核とGPQA実行経路が分離している

`設計/02_大規模言語模型成立契約.md` と `src/minidora/runtime.py` では、現行LLM模型中核は、

```text
対象言語状態
→ 言語対応
→ 文脈付き内部状態
→ 再利用可能な模型側関係
→ 成立差
```

であり、実装主体は `MINIDORA模型核`、公開入口は `ミニドラ.言語評価(...)` である。

一方GPQAベンチは、

```text
公開HDSコンパイラ
→ HDS選択推論実行
→ K3相当能力核
→ HDSIRネイティブAdapter / J
```

を直接使用しており、`MINIDORA模型核.評価言語状態()` を通らない。

したがって現行GPQA値は、厳密には**正式構成定義の模型核そのものの性能値ではなく、模型核外に残っている旧v0.3由来の能力補助経路を含む外側Runtimeの性能値**である。

これは構成定義と性能検証経路の不一致である。

### 3.2 K3 AttnRes作用とMINIDORA checkpointは同値ではない

K3 D4構文化では、AttnResは実際の過去depth stateを保持し、現在状態と並べて学習済みprojectionで寄与を計算し、再混合する。

現行`HDS作業Checkpoint`が保持するのは、

- 段階名
- 作業関係ID集合
- 候補得点

である。

これは「過去処理状態へ戻って状態変換を再計算する」作用ではなく、**監査用snapshotに近い**。

従って、K3で観測した深さ方向再作用の能力保存射影にはなっていない。

### 3.3 寄与Gateの射影がK3より狭い

P0の`HDS寄与Gate再照合`は、一時証拠化に、

- positive
- unqualified
- `hds_relation_*`
- 完全同一predicate
- 完全同一args
- 既存通常証拠なし
- 反対identityなし
- 独立出典2以上

を要求する。

これは安全側の実装ではあるが、K3のGate作用から直接導出された変換則ではない。

K3では連続状態・深さ状態・複数expert等の**部分的に異なる状態間でも寄与が伝播・再混合**する。

従って、完全identity一致を要求する現行射影は能力作用を大きく離散化している。

P0実測で、

```text
working_relations_created      = 114,443
working_relations_reused       = 0
checkpoint_reactivations       = 0
global_reconciliations         = 0
temporary_working_evidence     = 0
```

となったことは、この不一致と整合する。

### 3.4 専門作用の射影が未成立

K3で観測した幅方向作用は、shared expert + 複数routed expertの併用である。

P0実測では、

```text
specialist_actions_invoked = 0
```

であり、幅方向の能力保存射影は未成立である。

### 原因分類

```text
LLMとしての最低成立構成     = あり
K3作用の能力保存射影        = 不足
depth再作用の同値射影        = 不足
寄与Gateの同値射影          = 不足
専門作用の同値射影          = 未成立
正式模型核と性能測定経路     = 不一致
```

## 4. 三層の因果関係

三つは独立に壊れているだけではなく、直列に誤差が累積する。

```text
K3 / 他LLM
↓
① 高位作用は取れたが、作用遷移則・形成則が不足
↓
「保持 / 再作用 / 再結合」という高位構文
↓
② Compilerが質問意味をほぼtopic-onlyへ圧縮
   GPQA: 195 / 198
↓
意味関係が薄いHDS-IR
↓
③ 完全identity中心の狭い射影 + 非同値checkpoint
   + 正式模型核を迂回するベンチ経路
↓
作用再利用が発火しない
↓
低い候補識別能力
↓
GPQA低性能
```

P0の`blocked_evidence_facts=0`かつ`working_relations_reused=0`は重要である。

これは、

> 意味関係は十分に存在したがGateで阻害されただけ

という説明を支持しない。

むしろ、

> **必要な問い関係・同値関係がCompiler以前またはCompiler内で十分に成立せず、その薄い意味状態に③の狭い射影規則を適用したため再作用対象が形成されなかった**

と読むのが現行証拠に最も整合する。

## 5. 原因順位

| 順位 | 層 | 判定 | 現在確認できる影響 |
|---:|---|---|---|
| 1 | ② HDS Compiler | **主因** | GPQA問い195/198がKでtopic-only |
| 2 | ③ MINIDORA構成定義・射影 | **原因** | K3作用を能力保存できず、正式模型核とベンチ経路も不一致 |
| 3 | ① 構文化 | **上流原因** | 物理構造は取れているが、実行可能な作用遷移則・形成則が未抽出 |

「②だけ直せば完成」とは判定しない。

②を直すためにも、①から何を保存すべきかをより厳密に定める必要がある。また②が十分な意味状態を返しても、③の射影が能力作用を保存しなければK3相当の作用差は再現できない。

したがって最終判定は、

> **三層すべてが原因。現在最も大きく性能を潰している直接箇所はHDS Compilerの質問意味射影。**

である。

## 6. 修正順

### 第一段 — 構文化を作用則まで深掘り

各公開weight LLMについて、部品名や高位作用ではなく、少なくとも次の形式まで落とす。

```text
入力状態
→ 保持状態
→ 選択 / 寄与条件
→ 状態変換
→ 再結合
→ 出力状態
→ 次段への保持
```

加えて、runtime作用と形成済み関係を分離し、形成物側についても、

```text
何が形成されるか
適用条件
反対条件
優先関係
再利用条件
```

を抽出する。

### 第二段 — Compilerを開いた意味関係へ改修

最重要要件は、既知17関係族の拡張ではない。

**未知の述語であっても「何と何のどの関係を問うているか」を関係identityとして保持すること。**

最低限、

- 問い述語をtopic-onlyへ潰さない
- paraphraseを同一意味関係へ寄せる
- relation unknownをtopic-only successとして隠さない
- 保持不能ならsemantic_loss / unresolved relationを明示する
- K質問射影で関係を失わない

を満たす。

### 第三段 — MINIDORA構成定義へ1対1作用射影

構文化した各作用に対して、非ニューラル側の対応作用とconformance testを一つずつ持つ。

例:

```text
K3 depth state retention
↔ MINIDORA checkpoint state retention

K3 contribution gate
↔ MINIDORA deterministic contribution gate

K3 shared+routed multi-path
↔ MINIDORA common + multiple specialist actions
```

名称の一致ではなく、**入力差に対して同じ作用差を生むこと**を受入条件にする。

そして正式`MINIDORA模型核`とRuntime/benchmarkを再接続し、性能ベンチが正式構成定義を通るようにする。

## 7. 再評価関門

GPQAを再度性能指標として使う前に、次の射影鎖監査を通す。

```text
実LLM作用
↓
構文化作用則
↓ 差分保存
HDS Compiler意味状態
↓ 差分保存
MINIDORA非ニューラル作用
↓
観測可能な成立差
```

各境界で「入力差が消えた場所」を特定可能にする。

特に次の値は現状を失格基準として保持する。

```text
GPQA K質問関係保持      3 / 198
GPQA K topic-only       195 / 198
候補K関係保持           283 / 792
候補 relation-less      507 / 792
working relation reuse  0
checkpoint reactivation 0
```

この鎖が閉じるまでは、GPQA向けルール追加・閾値調整・SUSPEND緩和を能力改善とは扱わない。
